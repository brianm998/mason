# 0040: Readings made while getting the pipeline unstuck (s60)

- **A base conflict goes to the agent rather than failing the task.** The alternative was to send the task back to develop with feedback from whichever step met the conflict. Since only agent steps fold in the base (test and landing use `prepare_worktree_only`, and landing has its own conflict path that already sends back), the simplest correct place is the develop step's own prompt. Explore and review do not merge, so they run on the branch as it is: nothing they do is judged against the base.
- **The note goes first in the feedback.** It is what the agent must do before anything else, and any earlier feedback (a red test, a reviewer) follows it unchanged.
- **One resolver for the test command.** `run_check`, landing's legacy suite and the test step must run the same command, or a red in one and a green in another mean nothing. `jobs::test_command` layers it the same way the step does (definition, overlay, runtime overrides, the task's overrides).
- **The develop tool timeout covers `test_timeout`.** `run_check` is already cut off at `test_timeout`. A shorter tool timeout only made the agent abandon a run and start another. Other tools answer in seconds, so raising the ceiling for a develop step costs nothing. Explore and review keep `tool_timeout_s`.
- **Load-sensitive tests: check the property, not the stopwatch.** These are not weaker:
  - The hand-off test proves admission is driven by the step ending: with every polling path an hour away, any prompt admission must come from the event. The 100 ms number stays a target, measured by `scripts/exit/s11.sh` on a quiet machine. A wall-clock bound inside `cargo test --workspace` on a shared machine measured the other workloads.
  - The e2e concurrency check now counts what the daemon itself counts. The old predicate counted test and landing steps, which hold no session by design.
  - The scheduling wait test still requires the activity to name the compile slot; it only waits for the event that sets it.
  - The deadlines that grew (the step host start, the self-test, landing_crash) are for things to happen eventually. None of them is an assertion about correctness, and each loop still ends the moment the thing happens.
- **Fewer worlds at once in a test binary**, rather than `RUST_TEST_THREADS` in `.cargo/config.toml`. The limit is only on the tests that start real daemons, so unit tests keep every CPU, and `cargo test --workspace` stays the command that MASON and CI run. CPUs / 4 (2 to 8) keeps an idle 36-thread machine as fast as before for every binary but `definitions.rs` and `landing_crash.rs`.
- **Numbers.** s60 and 0040 are above every number MASON had reserved (exit 57, decision 35), with a gap, because queued tasks take the next numbers when they are claimed.
