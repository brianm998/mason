# 0449: The endpoint is chosen once per attempt by RemoteDiscovery, not by the socket

`MonitorConnection` asks `discover` at the start of an attempt and every two seconds while connected. `RemoteDiscovery` answers the same endpoint until the attempt ends, so a Bonjour record appearing mid-session does not drop a working connection. After an attempt that never got a welcome it moves to the next of `Reach.order` (Bonjour match first, then the paired hosts); after one that did, it starts over. `DaemonInfo` gains `host`, and `MonitorSocket.open(info:)` (default: `open(port:)`) hands it to `PinnedSocket`, so loopback sockets and their fakes are unchanged.

A Bonjour record counts only when its `fp` equals the paired fingerprint; the pinning delegate still refuses any certificate that differs, so a wrong daemon is never connected to even by name. A 401 on the upgrade is read from the socket (`refusal`) and treated as revocation: retries stop, the token and the `UserDefaults` record are cleared, and the app shows the unpaired screen. Rejected: reading the Bonjour browse inside each attempt (the connection's `discover` is synchronous, so a cached, resolved list is read instead).
