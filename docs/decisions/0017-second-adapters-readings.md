# 0017: Readings made while building the second adapters (Stage 20)

Where the plan or design left room, Stage 20 chose the following. Any can be overruled.

- **One launcher, two dialects.** The plan's wording was to pull the process code out of `claude.rs`. The smaller change was kept: `launch_process` is a free function in `claude.rs` that takes a `Dialect` (`Claude` or `Codex`) and `ParseState` carries it, so `parse_line` picks the right parser and the step host's `attach_as` does the same. Claude's code path and tests are unchanged. A third CLI would be a third variant, or the time to move the launcher to its own file.
- **Codex's event format is from memory of its documentation.** `codex exec --json` prints `thread.started`, `item.completed` (`agent_message`, `mcp_tool_call`, `command_execution`, `file_change`), `turn.completed` with usage, `turn.failed` and `error`. Codex was not installed, so no fixture is a real capture; the four fixtures are labelled synthetic (`fixtures/codex/README.md`). A real capture should replace them.
- **Codex reports tokens but no cost.** `cost_usd` stays `None`, never zero. There is no cache-creation figure either.
- **Failure messages are mapped to the shared classes.** Codex has no status field on a failed turn, so the parser reads the message: "usage limit", "rate limit" or 429 is a hold (with "try again at X" rewritten as "resets X" for the shared classifier); "stream disconnected", "overloaded", "service unavailable" or `status 5xx` is a provider outage; anything else is a crash. A bare `error` line (such as "Reconnecting... 1/5") sets a provisional failure that a later `turn.completed` clears and `turn.failed` replaces.
- **Codex has no system-prompt flag**, so the contract's preamble leads the first prompt on stdin. A resume sends only the note: `codex exec … resume <thread> -`.
- **Codex's own sandbox follows the step**: `-s read-only` for read-only steps and `-s workspace-write` otherwise, with `approval_policy="never"` so it never waits for a human. The MCP bridge is passed as `-c mcp_servers.mason.*`, with no config file written.
- **Models and providers.** The built-in profiles name Claude models (`haiku`, `sonnet`). With `provider = "codex"` those mean nothing, so the model is the project's `model`, else the bottom of its ladder, else the CLI's own default. With Claude and a ladder but no model, the step starts at the bottom of the ladder.
- **The ladder is a project overlay key, not a definition key.** `provider`, `codex_bin`, `ladder` (models, weakest to strongest), `max_retries` (default 1, at most 5) and `sandbox` live in the local overlay file with `claude_bin` and `model`. Putting them in the definition would have touched the parser, validator and layers, which are protected files. The cost: a ladder is per project, not per profile. `ProjectCfg::agent()` reads them from `overlay_text` (so the struct, and tests that build it by hand, did not change).
- **When the ladder moves up.** After a step ends with no result (after its nudges) or a crash, and a rung above the model used exists: a fresh session (no resume, a new run key) on the next model. Not after a timeout (more model is not more time), a hold (a wait), a question (the owner's turn) or an acceptance. A model not on the ladder, or the top, changes nothing, as does an empty ladder. Each step starts again at the ladder's bottom, so one hard step does not make the next expensive.
- **Plain git is a type, not a `[host]` kind.** `PlainGit` declares every capability false and refuses each PR call for good, and `plain_host_kit` checks that (`host_kit` is unchanged and still refuses a host without PRs). It is not wired as `[host] kind = "plain"`: the landing configuration check (protected) only asks whether a host is present, so a plain host would let a PR mode pass. A project that lands on a bare repository has no `[host]` and uses direct mode, which is what the exit test does.
- **Jenkins.** A parameterised job takes `REF` and `SHA`. `POST …/buildWithParameters` answers 201 with a `Location` naming the queue item; the run id is `queue:N` until the queue item has an `executable`, then the build number is read from it. `result` of `SUCCESS` is green; `FAILURE`, `UNSTABLE`, `ABORTED` and `NOT_BUILT` are red (an unstable build is not a pass); `building` or no result yet is pending. The credential is a reference, sent as a header (basic auth with `user`, else bearer), through the same `Curl` as GitHub, which keeps it off the command line. `crumb = true` fetches a CSRF crumb before the POST. Per-job results are not read (`per_job_results = false`).
- **The generic adapter's text protocol is `CommandCi`'s.** The trigger prints the run id (or nothing: the commit is the id). The status prints `pending`, `green` or `red` with an optional second line of failed jobs. A URL half may also answer JSON `{"state": …, "failed": […]}`. Commands get `MASON_REF`, `MASON_SHA`, `MASON_RUN`; URLs have `{ref}`, `{sha}`, `{run}` percent-encoded. A URL trigger is a POST with an empty body; a status is a GET. `CommandCi` stays (the `command` kind and its tests), sharing `run_command` and `parse_status`.
- **Sandboxing is a wrapper, and a missing binary is an error.** `sandbox-exec` gets a profile that allows everything and denies `file-write*` except under the worktree, MASON's agent state directory, scratch space (`/private/tmp`, `/private/var/folders`, `/dev`) and the CLI's own directories in the home (`~/.claude`, `~/.claude.json`, `~/.codex`) plus the main repository's `.git` (a worktree's commits go there). `bubblewrap` binds the machine read-only with the same places writable and a private `/tmp`. The network stays on for both: the agent must reach its provider. Reads are not restricted, so this stops a runaway agent from changing other files, not from reading them. If `sandbox` names a binary that is not installed, the step fails; it never falls back to running without one. Default `none`.
- **The ssh test uses a shim.** `GIT_SSH_COMMAND` points at a script that drops the options and the host and runs the command locally, so `ssh://` URLs go through git's real ssh transport code and the real daemon's fetches and pushes, with no sshd. The script also sets `GIT_ALLOW_PROTOCOL=file:ssh` for the daemon, because some environments restrict git to `file`.
- **No limit or gate was changed.** `scripts/exit/s20.sh` is new under the protected `scripts/exit/**`.
