# 0083: Views index step runs once and cap history sections at 500 rows

Each row used to scan all step runs (typical time, state-since, progress) and all tasks (blocks), so a sidebar cost rows x runs, and every burst of events resent every landed and canceled task though those sections start collapsed. The views now build per-view indexes in `Ctx::new` and a history section (failed, landed, canceled) sends only its newest `HISTORY_ROW_CAP` = 500 rows, with `count` the true total. Chosen over paging or searching on the daemon because the monitors already filter the rows they hold and the owner rarely looks past recent history; the price is that client search cannot find older tasks in a capped section, which the stage note and the section header ("500 of 2000") say. A task past the cap still opens by id. The log tail on the task page is cached by journal size and modified time, not by an event counter, because journals are written outside the event log. No protocol change: clients compare `count` with `rows.length`. No gate, guard, budget or trust file changed.
