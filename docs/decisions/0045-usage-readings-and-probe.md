# 0045: Recording and showing LLM usage (s64)

Choices the ticket left open. The owner may change any of them.

- **History bound.** One reading per window per account is kept per 5 minutes, unless the window's state or reset time changed (that is kept at once). Rows older than 8 days are deleted on each write, so the table holds at most a week of trend plus a day of slack. No separate cleanup job.
- **Latest snapshot** is stored whole, as JSON, per account (`usage_latest`), written when an attempt ends or enters a provider hold. It is replaced, never merged: the newest report is what the provider last said.
- **Tokens** are stored per attempt (`usage_runs`, keyed by the run key: the first run, and each retry-ladder `…uN` attempt, are separate rows) with project, task, step, account and model. The model is the one MASON launched (the tier mapping's result); the stream does not name it, so an attempt launched with no model is shown as "(model not reported)". An attempt that reported no figures stores no row. Every figure column is NULL when unreported; sums are NULL unless at least one row reported that figure. Nothing is ever shown as 0 that was not reported.
- **Cost.** Stored whenever the stream gives `total_cost_usd`. Shown (in token lines and as spend) only for `api` accounts; on a plan the figure is notional (decision 0043).
- **"Current window"** is the account's shortest reported window (the 5-hour one for Claude), from its start (reset time minus its length; if the reset has passed, now minus its length). An account with no reported window has only the last-7-days figures.
- **Spend** for `api` accounts: today = since 00:00 UTC; this week = the last 7 days; this month = since the 1st 00:00 UTC. Against `monthly_budget_usd` when set.
- **Clock times are UTC** ("at 15:00 UTC"). The pure `usage_text` module has no time zone and the daemon has no zone dependency; the countdown ("in 2 h 14 m") is the part that matters locally.
- **Words are made by the daemon.** The view carries the age, reset, trend, overage and blocked texts so both monitors and the CLI word them identically. Ages are computed when the view is built; a view is rebuilt whenever the daemon pushes it, so an age can lag a minute on a screen that has had no event. Conformance therefore compares only the figures that do not move with the clock (names, percentages, states), never ages or countdowns.
- **Overage "available".** The adapter's overage model does not tell "off by choice" from "available": `Off` is shown as "overage: off", `Disabled(why)` as "overage: off (why)", `InUse`, `UsedUp`. "In use since when, and what it has cost" is shown only as far as the stream reports it; Claude's stream gives neither, so only "overage: in use" appears. A real in-use shape was not seen.
- **Windows not reported.** With a snapshot, only the windows it contains are shown (a plan without an Opus window shows none). With no snapshot yet, the adapter's windows are listed as "not reported yet": no percentage, no reset.
- **Top-bar line:** per account, the window with the highest percentage, else one that is not `ok`, with its label, percent when reported and the time to reset: "claude 5-hour 82%, resets 1 h 10 m". An `api` account shows "api-main spend $3.60 this month". Accounts that have reported nothing keep the old "n of m sessions".
- **"What MASON is doing about it"** is the fixed text "nothing" (`doing`); ticket 4 fills it.
- **Wire's Kotlin cannot read a field called `adapter`.** `ProviderStatus.adapter` (5) clashes with a member of every Wire message, so the Compose monitor had been printing an object, not the adapter's name. A new field `adapter_name` (20) carries the same value. Field 5 stays for older clients and the CLI.
- **Gates.** The conformance kit gains `usage-expected` and usage items; no check was removed or loosened.

## Reading usage without a session (`probe_usage`)

**No documented headless usage route was verified, for either CLI.** Nothing in this repository documents one, no `codex` binary is installed on this machine, and the Claude CLI was not run against a live account in this stage. So `AgentAdapter::probe_usage(billing)` exists as an optional method that returns `Ok(None)` by default, the daemon calls it for every account every 5 minutes and stores anything it returns, and **no adapter implements it**. Idle accounts therefore show the age of their last session's figures, which is the honest state.

For the owner to decide: the CLIs' own interactive `/usage` (Claude Code) and `/status` (Codex) screens are not a scriptable interface, and the only machine route known to exist is the undocumented usage endpoints that the CLIs call with the login token they store (the keychain item or `~/.claude/.credentials.json`, `~/.codex/auth.json`). **MASON does not read those tokens** and nothing here does. If the owner wants idle refresh, the options are to wait for a documented command from a vendor, or to approve reading that token explicitly (a security decision, with a threat-model note).
