# 0721: pick modules of the daemon `it` executable from a run-time coverage map

Status: accepted (`affected.rs`, `covmap.rs`, `scope.rs`, `jobs.rs`, `daemon.rs`; none is in `PROTECTED`)

**Decision.** `covmap.rs` records, per module of `crates/daemon/tests/it`, the `crates/*/src` files with a covered line. An idle job on the base branch (`covmap::pass`, started beside the debt loop, off when `debt_interval` is zero) builds `mason-daemon` with `-C instrument-coverage` into its own target directory under `<data>/covmap`, runs `it` one module at a time with `LLVM_PROFILE_FILE` set to the module's own directory (so the module's process and every `masond`/`step-host` child write there), merges with `llvm-profdata`, exports lcov with `llvm-cov`, and stores `covmap.kv` (module to files, the commit, the time, a hash of `main.rs`). It holds a `test-suite` lease behind every task and waits for the compile queue to be empty. It is due when there is no map, when `main.rs` differs from the one mapped, or when the map is a day old and `crates/daemon/src` changed since its commit.

`affected::select_with` takes the map. For a changed `src` file a module is picked when its covered set holds the file. A file no module's set names, and a module the map does not list, go through the name scan (#655) as before. A map made for another `main.rs`, older than 7 days, or absent is not used: the name scan alone decides. Module-file changes, `main.rs`, `support/` and the more-than-half rule are unchanged. The note reads "it: 7 of 82 modules, by the coverage map of <sha>" or "..., by name scan (no coverage map)".

**Name scan not unioned in.** With a map, the pick is the coverage pick plus changed module files, not also the name-scan pick. Coverage shows what ran; the scan only adds the modules that merely name the code, which is most of why it picks more. The cost: a code path only reached on some runs (timing, a failure branch) is missing from a map made from one run, and a module can miss a regression until the landing batch, which runs `it` whole. A daily refresh and the staleness rules bound that.

**Without `llvm-tools`.** The job logs once that it is missing and does nothing else; selection stays on the name scan. Nothing is installed.

**Not verified.** The attribution test and the exit script skip the attribution check on this machine, where `llvm-tools` is not installed, so the job's real build, profile merge and lcov export have not run; they are written from the tool documentation. That every child of the test support harness inherits `LLVM_PROFILE_FILE` (a child that clears its environment would write nothing). The daemon loop's lease and worktree handling were not run in a live daemon. Whether `-C instrument-coverage` builds of the whole daemon fit the time of an idle slot.
