# 0695: a batch suite killed at its limit is rerun once and never bisected; the limit is set on the suite

Context: the landing batch's `cargo-workspace` run is killed at the 1800 s default (the suite sets no `timeout`; `test_timeout_s` does not reach suites) and the kill became `Verdict::Red` with no failing tests. The ladder reran it, then bisected it: in b418 five subsets, each with less work, were green, and 228 min went by with nothing found.

Decision:
1. The limit is `timeout = "60m"` on `[suite.cargo-workspace]` in `.mason/mason.toml`, not a per-tier value in `landing.toml`. The suite takes 22-35 min on a quiet machine, so 60 min leaves headroom for load and still ends a real hang. A per-tier limit would need a new key through `run_local`/`run_suite`; the suite key already exists. The per-task narrowed runs are far shorter and are not affected in practice.
2. `OverRun` gains `unfinished`: the suites killed at their limit with no failing test named, each with the tests libtest reported as "has been running for over N seconds" that printed no result. A red with only such suites is a timeout. The ladder's `rerun-failed` rung reruns it whole once (the rerun takes the `test-suite` slot, which already waits out the cpu/thermal gates), and `blame-by-impact` and `bisect` are skipped for it. Green: the batch lands with the note "timed out once and was green on a rerun". A different red on the rerun continues down the ladder as before.
3. Timed out twice: if a test was still running at both kills and the suite has a `rerun` template, the batch is bisected on those names alone (`run_alone`; a run of such a test that is itself killed counts as still failing). Otherwise the batch is held with a "timed out twice" alert that names the tests still running; no task is parked or blamed.
4. `mason report` gains a `batches` block (total, landed, red, timed out, timed out twice), read from the batch notes, so timeouts are not counted as reds.

Consequences: a task that adds a hang is still found, by running that test alone on subsets. Not verified: a real 60 min run, and the load wait before the rerun is the existing slot wait, not a new one. A bisect subset without the hanging test runs zero tests under `--exact` and falls back to the whole suite, as the filtered bisect (#682) already does. The report counts by note text, so a batch whose note was overwritten by a later split note is not counted as timed out. Trust files changed (`.mason/mason.toml`, `landing.rs`, `suites.rs`) wait for the owner.
