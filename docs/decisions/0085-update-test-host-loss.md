# 0085: The update test's agent waits for a release, not for a clock

The self-update test lost its agent's step host because the fake agent slept 90 s and the update (build plus self-test) can take longer on a loaded machine; the host then exited with code 0, which is a correct end, not a loss. The takeover was not at fault, so no takeover change and no protected file is touched. The fix is in what the test observes: the agent stays mid-session until the test writes a release file, after the assertion that the same host is still running. Waiting longer, retrying or quarantining would have hidden the cause and left the test racing a clock. The assertion now reports each host's state, exit record, pids, heartbeat age and journal tail, and the daemon's log tail when `MASON_TEST_LOG` names a file, so a future red says what became of the host.
