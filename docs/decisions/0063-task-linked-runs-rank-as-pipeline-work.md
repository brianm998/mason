# 0063: A task-linked `mason run` ranks as that task's pipeline work (s77)

- **The daemon learns the task from `MASON_TASK`, sent by `mason run`.** `jobs.rs` already set it for script steps; it now also reaches the agent's session, so a `cargo test` the agent runs through `mason-queued` carries it. The id is only a name: the daemon looks the task up and uses *its own* record of the task's current step and priority, never anything the client says about them.
- **A task id can only lower a request's standing.** The best rank a request can have is interactive, which any caller gets by sending no task. A task id replaces that with a pipeline rank, which sorts after every interactive request, so naming a task is never better than omitting it. Naming someone else's task gains nothing either: the request takes that task's steps and priority but this request's own arrival time and sequence number, so it cannot take over an older task's place among equals, and the project's `priority_jump` is not applied, so it cannot skip the progress rule. An id that is not a task in a step is treated as no task (a person's request). A caller who wanted to jump the queue would simply omit the task, which is the existing interactive behaviour, not something this change adds.
- **Starvation.** Ranking is by steps remaining first. A task in `test` has fewer steps remaining than one in `develop`, so its waiting step is ahead of every run an agent in `develop` can queue, however many it queues. Runs from a task in `test` itself or later queue behind the earlier arrival. The remaining unfairness (an agent's runs rank ahead of tasks that are further from landing, and interactive callers still go first) is the existing progress rule.
- **Why this is safe for a budgets file.** `sched.rs` is a budgets file, but this change touches no limit, count, floor or timeout. It changes only the order in which waiting requests for the same resources are granted, and capacity checks, the CPU gate, the memory floor and the lease-reaping rules are untouched. Nothing is granted that did not fit before.
- **Label.** The default label of a run with a task is ``task N `cmd` ``, so `mason resources` says what asked. An explicit `--label` is kept.
- **`lease_open` stays interactive.** Existing callers and tests keep their meaning; the new path is `lease_open_as`.
- **Numbers:** s77 and 0063 were assigned by MASON.
