# 0148: the CI judge: only infrastructure reds are rerun

Starpipe (star's other pipeline) tells an infrastructure red from a real one and reruns only the first. MASON's red ladder reran every failed CI, so a real red waited a second 1 to 3 hour hosted-runner run before the task heard of it. Stage 153 (task 162) gives MASON the same split. It ships **off by default**: `[ci] infra_judge = true` turns it on, and the owner does that for star in the same change that turns starpipe's judge off, so the judgement never runs in two places.

**Where the judgement lives.** In the adapter (pure `ci_infra::judge`: conclusion, whether a step ran, the failed log, extra patterns), not in landing. The adapter reports each failed job as `JobFailure { workflow, job, infra }` on `CiState::Red` and `PrStatus`; an empty list means the host did not say, and landing then behaves as before. `crates/daemon/src/landing.rs` (PROTECTED, the red ladder) only reads the per-job answer.

**Rules.** `timed_out` and `startup_failure` are infrastructure. `cancelled` is infrastructure; with no step run it is labelled "never got a runner" (it is still red and still blocks landing: decision 0119-3 is unchanged). For `failure` the job's log is fetched, only for failed `failure` jobs, and matched case-insensitively as substrings against starpipe's `INFRA_LOG` phrases plus "The runner has received a shutdown signal" and "Temporary failure resolving". Substrings, not a regex, so no new crate; `[ci] infra_patterns` adds to the list and is refused without the judge. Anything else is real. A log that cannot be fetched counts as real: a rerun is the cost to avoid, and the rule only ever removes reruns.

**Log fetch.** `GET /actions/jobs/{id}/logs` answers with a redirect to a signed URL; it is read raw and the `Location` is fetched **without** the Authorization header. The last 256 KiB is judged. For PR checks the job id comes from the check run's `details_url` (`/job/<digits>`); with none, a `failure` is real.

**The ladder.** If every failed job is infrastructure: the rerun, as today. If any job is real: the flag is set, every remaining rung is skipped, and the batch's tasks go back at once with the real failure named. A rerun that is red for a real reason also stops the ladder. Notes per job: "pr-gate/macOS: <reason>, rerun" or "pr-gate/Linux: real failure, not rerun"; a rerun that goes green puts the infrastructure notes in the batch note.

**Open choices.** (1) Mixed red: not rerun, since rerunning the infrastructure job alone would not change the verdict and the real one is enough to send it back. (2) GitHub Actions only: `infra_judge` on Jenkins/generic/command is refused at load. Command CI can still report `infra: a, b` after its failed jobs (used by the exit test's fake CI); no such line means unknown, so nothing is judged. (3) The fake host does not judge PR checks.
