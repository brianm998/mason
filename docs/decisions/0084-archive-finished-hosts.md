# 0084: Finished step-host directories move out of the registry

`h/` is read in full by every `/status`, sweep, cancel, `session_for` and `render_logs`, and held one directory per host that ever ran (576 after three days). The sweep now moves `h/<id>/` and `h/<id>.in` to `t/<task>/hosts/` once the host's step run has closed, the host is not running, and the host stopped more than `host_grace` ago (a day; the exit script shortens it with `MASON_HOST_GRACE_MS`). The grace is there so a daemon that comes back later still finds them where it looks. An open run's hosts never move, so `reattach` and `run_command_once` are unaffected. `render_logs` and `session_for` read the live registry first and then the archive, without repeats, so a host moved between the two reads is still seen once. Moved directories are deleted after `retention_days` (`[daemon]` in `daemon.toml`, default 90, 0 keeps them for ever); `t/<task>/` itself stays. `a/<pid>-<n>/` is removed when older than the grace period and older than the oldest open step run, since a session of an open run is newer than the run's start. A move that fails (for example across file systems) is logged and tried again next pass; nothing is fatal. `pass` takes the time as an argument so tests inject the clock.

Age is taken from `exit.kv`'s `ended_ms`, else the latest of `started_ms`, `heartbeat_ms` and `hb` (a lost host), else the file's modification time. No gate, guard, budget or verdict logic is changed.
