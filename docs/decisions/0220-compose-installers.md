# 0220: The Compose monitor ships as a .deb and an .msi built by Compose's own packager

Compose's `nativeDistributions` now sets `targetFormats(Deb, Msi)` (no Dmg: the Swift app is the macOS monitor). Linux package name is `mason-monitor` so it cannot clash with the CLI's `mason` .deb; the icon is the brand `app_icon.png`, copied to `clients/compose/packaging/icons/` so the Gradle build does not reach into the Swift tree. Windows has a fixed `upgradeUuid` (it must never change, or Windows installs side by side instead of upgrading), a start-menu entry, a shortcut, and a per-user install so no admin rights are needed. The `.ico` is committed, generated by `packaging/make-ico.py` (256x256 PNG inside an ICO; regeneration commands are in the script header).

`packaging/name-installers.sh VERSION` copies Compose's output to the docs/RELEASING.md names (`mason-monitor_<ver>_<arch>.deb`, `MASON-Monitor-<ver>-windows.msi`) in `dist/`. Makefile targets `package-deb` and `package-msi` pass the version (`VERSION`, default the Cargo workspace version) as `-Pmason.version`.

**`mason://` is left out.** Compose Desktop registers URL schemes only for macOS (Info.plist); there is no Deb or Msi hook, so a scheme there would need hand-edited desktop files and WiX, which is not worth it yet.
