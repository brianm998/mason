# 0035: Deep and light tiers, the choices the ticket left open

Task #26. Each is the reading taken; change one and the others stand.

- **Built-in claude table.** `deep` low = sonnet at `low`; **medium = sonnet, no effort flag**; high = sonnet at `high`. `light` low = haiku; **medium = haiku**; high = sonnet at `low`. Medium reproduces what `deep`/`fast` always launched, so an upgrade costs nothing more. Nothing built in uses opus.
- **Built-in codex table.** No model anywhere (its CLI's default, as before). `deep` low/medium/high = `low`/`medium`/`high`; `light` low/medium/high = `minimal`/`low`/`medium`.
- **Files, lowest to highest.** built-in, `<config dir>/providers/<provider>.toml`, `[provider.<provider>]` in the project file; entry by entry (an entry is one tier and level, replaced whole). The provider file has `[deep]`/`[light]` tables with `low`/`medium`/`high` inline tables; the project file has the same under `[provider.claude]`, i.e. `[provider.claude.deep]`.
- **A bad provider file is ignored whole** (reported with every problem, in the daemon log when a step launches and in `mason doctor`); the built-in table stays for that provider until it is fixed. A bad entry in the project file drops that entry only. Problems are: unknown tier or level, unknown key, an effort the adapter does not have, an entry with neither model nor effort. `fast` is not a tier name in these files.
- **An entry without a model** means the CLI's default model; without an effort, no effort flag.
- **Precedence of the model**, highest first: per-task and runtime overrides (and the overlay's `[step.x]` table, as before), the step's or its profile's real `model`, the project's `model` key, the mapping, the ladder's bottom, the CLI's default. The profile's real model counts as explicit. Effort: an explicit real effort, else the mapped one. An override of the model keeps the mapped effort.
- **Effort values.** `low`, `medium`, `high` always mean the abstract level, even though Claude and Codex also have levels of those names; any other value is a real effort, kept as is and accepted only if the running provider has it. A later layer that names a level replaces an earlier real effort, and the reverse.
- **Profiles.** `agent = "deep" | "light" | "fast"`. A project `[agent.X]` may set `tier`, `model`, `effort`; with no `tier` its name is tried as a tier, else the step category's default tier (`deep` for developing, `light` otherwise).
- **Validation.** Errors for a real effort the running provider lacks (listing the allowed levels) and an unknown `tier`. Warnings (not errors) for an explicit model and for a provider-specific effort; logged when a project's definition loads and printed by `mason doctor`. Where the provider is unknown (offline checks) a real effort is not judged.
- **Reverse lookup.** `tiers::describe` gives `deep (Opus medium)`: tier, capitalised launched model, requested level. Extra words: `, replacing the mapped Sonnet`, `, moved up the ladder from Opus`, `, effort max` (launched effort differs from the mapped one), `CLI default` for no model; with no tier `opus (explicit model, no tier)`.
- **`fast`** stays a built-in name for `light`; the editor offers `light` and new agent steps default to it.
- **`provider` string versus `[provider.<name>]` table.** TOML cannot hold `provider = "codex"` and `[provider.codex]` together. A project file that has mapping tables names its provider as `[provider]` with `use = "codex"` (default claude); the plain string form keeps working and is what a project without mapping entries uses.
