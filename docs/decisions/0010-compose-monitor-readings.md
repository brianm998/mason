# 0010: Readings made while building the Compose monitor (Stage 13)

Where the plan or design left room, Stage 13 chose the following. Any can be overruled.

- **A Gradle project with two modules.** `clients/compose/core` holds everything that is not drawing (the connection, state, navigation, search, the conformance items, preferences, discovery); `clients/compose/app` holds the Compose views, the window and `monitor-tool`. It is the same split as the SwiftUI client's `MonitorCore` and `MonitorUI`, so a feature has the same shape in both, and the two are line-for-line comparable. Kotlin 2.1, Compose Multiplatform 1.7 for desktop, JVM 21 (the installed `gradle` is used; there is no wrapper jar committed).
- **The messages are generated by Wire in the build**, straight from `schemas/mason.proto`, so Kotlin cannot drift from the schema and no separate generator step exists (decision 0008 had left Kotlin ungenerated). The JSON encoding is Wire's Moshi adapter over the proto3 mapping; a test feeds it exactly what the daemon sends, including a field it has never heard of.
- **The design tokens are the same file**: `conformance tokens` writes `clients/compose/core/src/main/kotlin/mason/Tokens.kt` (it moved from the placeholder path), and the Compose theme reads colours and sizes from it exactly as the Swift theme does. Text scale reflows real text.
- **The same shortcuts**, with the platform's modifier: ⌘ on macOS and Ctrl elsewhere for back (`[`), forward (`]`), bigger (`+`), smaller (`-`), actual size (`0`), and shift+H for home. Collapse choices, text scale and mute are kept in the platform's own preferences store (`java.util.prefs`: plists, the registry, or files).
- **`monitor-tool`** has the same commands as the SwiftUI client's (`conformance`, `snapshot`, `answer`, plus `cancel` and `skip`, which the Swift tool gained in this stage), with the same output. Screenshots are rendered by the real composables on an off-screen scene (`ImageComposeScene`), so they need no display.
- **Conformance is the same machine check**, and now also a client-against-client check: the SwiftUI dump and the Compose dump are compared with each other, so whatever one shows at a checkpoint the other shows.
- **Parity file.** Every feature the SwiftUI client had is now done in Compose too, and the temporary platform reasons are gone; the pipeline editor is still todo in both, which is balanced. The feature check passes with 17 done in each.
- **CI** runs the Compose client on Ubuntu and macOS (`monitor-compose`, with the JDK and Gradle set up), no window opened. The Rust job skips `s13.sh`. **Windows is not in CI**: Compose Desktop supports it and nothing here is Windows-specific, but it has not been run there.
