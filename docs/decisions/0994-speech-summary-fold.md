# 0994: Three or more announcements are one spoken summary

Stage s1001. Thirty failures read aloud one by one took minutes. Decision: the daemon folds a claim's speech announcements into one line when there are `[speech] summarize_from` (default 3, `0` = off) or more, in `claim_at` and `daemon_speech`, so the Swift monitor, the Compose monitor and daemon speech need no change. The line comes from `summary_sentence` in core ("25 mason issues have failed; come have a look."), is queued as `summary:<client>:<now>`, and takes the most-counted kind (ties: decision, broke, info). Delivery is still recorded on every original alert. The backlog "N alerts are still waiting" line is skipped when a fold happens. A folding claim takes up to 200 waiting rows so the count is true. Setting is documented here and in `clients/features.toml` (speech-queue); `[speech]` keys: `daemon`, `command`, `preferred_client`, `stale`, `summarize_from`. Rejected: a settle delay for alerts trickling in over several claims (needs owner approval).
