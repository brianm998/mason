# 0062: Readings made while showing running sessions' tokens (s76)

- **`--include-partial-messages` is needed, and its lines are not output.** `assistant` events carry a start-of-message `output_tokens`; only each message's `message_delta` has the true figure. The flag makes about 80% of the stream `stream_event` lines, so `Progress::output` judges whole lines (the start of a line decides, `{"type":"stream_event"`) and leaves them out of `lines`, `bytes`, `done` and the live log. `marks` still advances by the real offsets. A line that began before a restored mark is still judged by its start, because the scan runs over replayed bytes too and only the counting waits for the mark. This depends on the CLI writing `type` first, as it does; a stream that changed that would be counted as output again, not lost.
- **Timing figures ignore skipped lines.** `last_output_ms`, the longest gap and `updated_at` move only on counted output, so the "typical" and "silent" figures from past runs mean the same as before.
- **The tally is cumulative per stream and a stream's figures only grow.** The journal is replayed from 0 after a restart, so the receiver replaces per stream, and keeps the larger of each figure so the replayed tally climbing from nothing never shows a lower figure than the stored one. A step run shows the sum over its streams, so resumed and retried invocations add up.
- **Cost is decided by the daemon from the account's configured billing, not by the adapter.** The adapter passes `total_cost_usd` as reported; the daemon offers it only for an `api` account (decision 0043). Codex reports no cost, so a Codex cell never has one.
- **Live figures come from the parser, not a new `AgentEvent`.** `ParseState` keeps the tally and hands over the latest on change; `Feed` (per stream) and the direct process reader report it to `SessionSpec::on_tokens`. `AgentEvent::Tokens` at `result` is unchanged, so `StepReport.tokens` and `usage_runs` are too.
- **`real_partial_messages.jsonl` is not a raw capture.** The figures are the measured ones (16/137, 5/851, result 4/988/7664/4503); the file was written by hand to that shape. The README in the fixture directory says so.
- **The fake agent's message figures add up to its result's.** First two messages are half of the fixed result each; later ones report none, so a live figure never passes the final one.
