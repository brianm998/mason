# 0554: skip views whose bytes did not change, and leave history bodies out by default

A per-session hash of each view kind's encoded bytes decides whether to send a view; the hash is dropped on a project change or a newly requested view. History-row bodies are left out unless `Subscribe.row_bodies` is set, which clients do only during body search, so an old client that never sends the flag loses body search over history rows (accepted: the fields are additive and no old monitor is made read-only). `state_since_ms` is the same figure `in_state_ms` was counted from (last run start, else enqueue), not `state_entered_at`, so the displayed time does not change for anyone; `in_state_ms` is rounded down to a whole minute to keep the sidebar stable. Not taken: a version bump (would force old monitors read-only) and a diff protocol (a much larger change).
