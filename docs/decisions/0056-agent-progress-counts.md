# 0056: Which figure an agent step shows, and where it comes from (s71)

- **One rule, in `Progress::choose` (core).** An agent step's figure is, in this order: the counts the agent gave with `report_progress` (`done` of `total`, its own `unit`, source `reported`); else its todo list (unit `plan steps`, completed of all, source `reported`); else its tool calls (unit `tool calls`, source `counted`). Output lines are kept in their own field and never set `done` on an agent record. A `history` total (the typical number of tool calls over past successful runs, five or more) is shown only when there is no real total. The monitors read `done_source` and `total_source`, so they are told which of these they are looking at.
- **Why reported counts win over the todo list.** The agent chose to say "3 of 7 files" in a call; the todo list is a by-product of how it plans. A total that changes (4, then 5) is allowed: the latest report replaces the earlier one. `done > total` is still refused.
- **The explore plan's acceptance criteria are not a count.** The ticket suggested "else the acceptance criteria, when the agent reports them met". Nothing tells MASON which criteria are met except the agent, and an agent that can say so can call `report_progress` ("all 5 criteria"). Not implemented; the prompt line suggests it.
- **The message.** The agent's own message from `report_progress` always wins in the run. Without one, the todo item in progress; without that, the latest tool call's summary. A summary is one line, at most 120 characters, and goes through `one_line`.
- **Redaction.** The ticket asked for "the way logs are". Step logs are not redacted anywhere in the code base, so there was nothing to reuse. `mason_core::progress::one_line` applies the word test the proposal redactor uses (long mixed tokens, `ghp_`/`sk-`), and also blanks the value of `NAME=value` where the name says key, token, secret or password, and what follows `Bearer`. It is a heuristic, not a guarantee. Summaries for tools MASON does not know are only "Using <tool>", never their arguments.
- **History apart from lines.** An agent step's history is kept under `<step> / tool calls`, with the tool-call count, so it never mixes with counts that came from lines or reports.
- **Tool calls are throttled like output** (one push a second); reports and todo lists are pushed at once. `report_progress` is pushed from inside the contract call, after its lock is released, so a report reaches the socket within the call and not at the end of the turn.
- **Codex declares `plan_reports = false`.** No Codex was installed where this was built and no capture of its plan updates exists. It still gets tool calls, reports and lines.
- **TodoWrite becomes an offered tool** in `--tools` and `--allowedTools` for every Claude step. It writes nothing; it is a list the model keeps in the conversation. Flagged for the owner in the submission.
- **`unit` on `report_progress`** is the one schema change to the contract: optional, 1 to 20 characters, default `steps`.
