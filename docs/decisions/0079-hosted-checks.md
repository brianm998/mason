# 0079: Checks run under a step host and are found again by (tree, command)

`run_check` and landing's re-test used `run_shell`, a child of masond polled from a job thread, so a restart orphaned the command, lost its output and its timeout. They now use `hostedcheck::run`, which runs the command as a step host and keys the run by the tree it runs on and the command. Same key in flight: attach. Same key finished and never given to a caller: give it. Otherwise: a new host. A result is given once; a later call on the same tree runs again, so an agent re-running a flaky test is not told the old answer. The tree key includes a hash of uncommitted changes, since agents check before they commit. `landing.rs` is a guard file: the re-test must still pass, and a lost or unreadable result counts as red; only its supervision changed.
