# 0452: the phone is a navigation stack over the Mac's own pages, and it does not speak

On a phone the sidebar is the first screen and a row pushes its page (`PhoneRootView`, a `NavigationStack` driven by `PhoneNav`). The phone views moved into `MonitorUI` (`Phone.swift`, `PhoneScreens.swift`) so they reuse the Mac's pages, which take a `compact` flag that stacks side-by-side parts into one column; the `MonitorPhone` product stays and re-exports `MonitorUI`. A page the Mac monitor has is on the phone unless it is in `PhoneLayout.phoneHasNo` (`PhoneLayout.hasPage` is false only for the pipeline editor). Health and Settings follow Usage under `PhoneLayout.morePages`, outside `sidebarOrder`, which Android's core holds equal. The top bar becomes a status line in the navigation bar (connection, paused, attention count; a tap opens the first task that needs the owner) with a menu for the project filter, add task, improve and mute. A count tile tap is the Mac's double click: the lone task, else the state's page, else a scroll to its section. The session-limit stepper sends the Mac's command through one function, `MonitorModel.stepSessionLimit(by:)`.

**Speech stays off on the phone.** The Mac speaks; the iOS app installs no speech sink and never calls `pulse`, so it never claims to speak to the daemon. Phones get notifications from the APNs tasks in this set. The Mute toggle stays (it is persisted and silences nothing here, but it keeps the setting in step with the Mac's).
