# s1000: the diagnosis model and effort are configurable, Opus at medium by default

Summary: The diagnosis session runs on `diagnose_model`/`diagnose_effort` from the project registration, else the provider file's `[diagnose]` table, else Opus at medium (Codex: its CLI's model at medium), and each diagnosis and `mason task show` print what it ran on.

- `crates/definition/src/tiers.rs`: `builtin_diagnose`, `parse_diagnose`, `resolve_diagnose` (field by field), `diagnose_text`, shared `bad_effort` wording; `parse_table` skips a `diagnose` key.
- `tiermap.rs`: `Effective.diagnose_file`, `diagnose_entry`. A bad `[diagnose]` voids the provider file, like a bad tier entry.
- `config.rs`: the two registration keys; a bad effort refuses the registration.
- `diagnose.rs`: `session_spec` builds the session; the stored row's args carry `ran_on` (no schema change). Rows made before this have none and print no line.
- Not verified: no real CLI was run with `--model opus`; the exit script checks the CLI's print lines by grep of source, not by running `mason task diagnosis` against a fixture daemon.
