# s1179: findings and diagnoses quote their evidence

Summary: A review finding and a diagnosis must quote lines from the diff, the named file at the head, the task text, the plan or the failed run's logs, and the contract refuses a quote it cannot find.

## Change

- `crates/adapter-api/src/contract.rs`: `quote` is required on each `submit_review` finding (1 to 5 lines) and on `submit_diagnosis` (1 to 10 lines). `quote_in` / `check_quote` match whitespace-normalised, blank-skipping, consecutive lines; line-number prefixes (`123→`, `123<tab>`) and diff `+`/`-` markers are tolerated.
- `crates/daemon/src/jobs.rs`: `review_validator` checks each finding's quote against the diff against the base, the finding's `file` at the branch head, and the task text and plan; a miss is refused with "not found in <where it looked>".
- `crates/daemon/src/diagnose.rs`: the diagnosis validator checks against the failure reason, task text and plan, round history, the whole test logs and the branch diff.
- `crates/daemon/src/reviewfindings.rs`: the quote is kept and shown under each finding in `mason task show` (`review_findings`), the send-back feedback and `feedback-history.txt`.

## Not verified

The Swift monitor does not render the quote itself (it shows the `review_findings` lines, which now carry it). Blocking findings are shown only in the feedback and history, as before. A diagnosis quoting code that the branch did not change is not found (only the diff is searched).
