# s632: Client-only changes no longer run every cargo test

Summary: The per-task test step and `run_check` drop the changed paths the impact map sends only to other suites (`clients/swift/**`) before narrowing a suite, so a client-only change runs the smoke set instead of all cargo tests.

## Why

Every task writes `docs/stages/` and `scripts/exit/`, which map to `cargo-workspace`. A path like `clients/swift/A.swift` has no owning cargo package, so `affected::select` returned `Pick::All` and the suite ran whole (#519 and others: ~2,095 tests per round).

## What changed

- `suites::split_for_suite` keeps a path for a suite when the impact map selects it or does not name it (and always under `.mason/`). `narrow_packages_for_step` and `run_check` (`jobs.rs`) narrow on the kept paths only. The step note names what was left out (`left_out_note`).
- `scope::narrow_for` with `smoke` and no paths left runs the smoke set alone; `run_check` reports a suite whose kept paths are empty or only docs as not run.
- `.mason/smoke-tests.txt` is in `affected::ignorable`, so changing it alone runs the smoke set.
- Unmapped root paths (`Makefile`) and `Cargo.toml` still run whole. The landing batch still runs everything.

## Not verified

- No end-to-end run in a scratch repository; the exit script runs unit tests only. No unit test of the `run_check` "not run" message itself: it reuses the existing branch with the new condition.
- Packages-mode suites (`{packages}`) with no kept paths still run whole.
- `run_check` failed here with "can't mix --doc with other target selecting options", the rendering fault #613 fixes; this change does not touch it.

## Trust

`crates/daemon/src/suites.rs` is protected. This only narrows the per-task step; the landing batch still runs the whole suite.
