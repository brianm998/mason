# s759: exit-scripts on a shallow runner

Summary: Remote snapshots carry `.mason/changed-files.txt` (and `.mason/base-sha`), and the exit-script helpers read it, so `exit-scripts` no longer fails `no-merge-base` on GitHub.

The runner's checkout has one commit and no base. `remote::snapshot` now computes the files that differ from the merge base with the base branch (dirty worktree included) where the history is, and overlays the file (the task's own copy is replaced). `run-changed-exit-scripts.sh` and `select-exit-scripts.sh` use it when present; locally nothing changes. I chose this over `fetch-depth: 0` because it needs no workflow change (no owner approval) and costs no runner time. `base-sha` goes in its own file, not `run.json`.

Trust: the two scripts feed a gate but are not in `PROTECTED`. No other script or suite uses merge-base/origin/develop during a remote run (grepped scripts/ and conformance tests).

Not verified: a real GitHub `exit-scripts` run after the fix (no URL recorded); the Rust snapshot test and a build were not run (testing was skipped for this task).
