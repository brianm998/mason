# s233: a host lost together with other tasks' hosts no longer uses up an agent step's restarts

Summary: An agent step's lost host does not count against its two restarts when another task's host was lost within 30 s of its last heartbeat (a daemon restart or mass kill), with a hard cap of eight losses per step run.

Four tasks (#245, #230, #191, #225) failed `develop` with "the step host was lost 3 times", every loss "signal unknown" (no parent saw the death), so the hosts were killed together by something outside the step: a daemon restart or the machine. Each such event used one of a task's two restarts, so a few restarts in a row failed tasks that did nothing wrong. The cause of the kills itself is not shown by the evidence; this change stops them from failing tasks.

`hosted::lost_with_others` compares a lost host's last heartbeat with that of every other run's lost host; `settle_all` (`jobs.rs`) counts only the others against `MAX_AGENT_RESTARTS`, and ends the step at `4 * MAX_AGENT_RESTARTS` losses regardless.

Not verified: the real mass-loss path (only the pure helpers are unit tested).
