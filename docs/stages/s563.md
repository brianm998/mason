# s563: isExpandedReadsEachKeyOnce counted the constructor's mute read

Summary: UiThreadTest.isExpandedReadsEachKeyOnce now baselines the preference read count after constructing the model, so the constructor's mute read no longer fails it while any extra read per isExpanded call still does.

**Cause.** `MonitorModel`'s constructor reads `KEY_MUTE` (Model.kt:223) and `CountingPrefs` counts every bool read, so the sum was already 1 before any `isExpanded` call and the assertion at UiThreadTest.kt:98 expected 1 more. `isExpanded` itself reads the section key once and caches it; no product code changed.

**Fix.** The test takes `base` after construction and asserts `base + 1` after 50 calls, and again after `setExpanded` and one more `isExpanded`.

**Tests.** `scripts/exit/s563.sh` runs `UiThreadTest`.

**Not verified.** Nothing beyond the Compose core tests.
