# s745: remote runs send the build separately

Summary: A suite's build goes to GitHub in `RunSpec.build`, run as its own `sh -c`, instead of being joined to the command with `&&` (which broke suites whose build and command both start with `cd`).

`run_remote` (suites.rs) and `remote_check` (hostedcheck.rs) set the field through `remote::with_build`; `shard_command` no longer carries the build, since the workflow runs the build once per shard first.

Not verified: no real GitHub run of `compose-clients` or `swift-clients`; the unit test covers `run_json` via `with_build`, not the two call sites with a live daemon. I relied on the task's statement that the workflow runs `build` as a separate `sh -c`.
