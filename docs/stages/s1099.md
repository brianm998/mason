# s1099: a red s798 names its own state (#1119)

Summary: `s798` passes its scripted agent a `src` directory to write into, fixing its red on CI, and a red `s798` now puts the task state and the last log line on its first failure line.

## Cause

`s798`'s agent wrote `src/a.rs` without creating `src`. The script made the directory in the seed repository, but git does not keep an empty directory, so the task's worktree had none. The write failed (`agent.sh: 1: cannot create src/a.rs: Directory nonexistent`), nothing was committed, no test was added, and `run_check` never had `needs_the_code` to name.

The `-- last 40 lines of s798` block of run 45581279465 (commit ff4fae6a) could not be read here (no network); its tail holds only `run_check never named the failing test`. The line above was read from this task's first check, [run 45629574732](https://github.com/brianm998/mason/actions/runs/45629574732), where `s798` was red the same way with only `fail()` changed.

## Change

In `scripts/exit/s798.sh`: the agent runs `mkdir -p src`, and `fail()` writes `FAILED: <message> (task state: <state>; last log line: <line>)` first, then the same dumps and exit code. The 240 s deadline, the wait loop and the assertions are unchanged ([decision 1088](../decisions/1088-s798-ubuntu-red.md)). No daemon code changed.

## Tests

`scripts/exit/s1099.sh` runs `s798`'s `fail` and the runner's `cause_of` against a fake `m`. `s798` itself runs on CI.

## Trust

`scripts/exit/s798.sh` is in `PROTECTED` (`scripts/exit/**`, `crates/daemon/src/protect.rs`), so this change is held for owner approval.
