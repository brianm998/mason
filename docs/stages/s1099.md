# s1099: a red s798 names its own state (#1119)

Summary: A red `s798` now puts the task state and the last log line on its first failure line, so the runner's `cause s798:` summary shows them; the Linux failure itself is not diagnosed or fixed.

## Cause

Not found. `CI/exit-scripts (ubuntu-latest, 3)` was red twice on run 45581279465 (commit ff4fae6a) because `s798`'s 240 s wait for `run_check` to name `needs_the_code` expired. The `-- last 40 lines of s798` block (task show, logs, masond.log tail) is only in the full job log, which could not be read here (no network). The ticket's log tail holds only the `cause s798:` line.

By reading, as recorded in the task's plan: the suite's `rerun` command prints the test name, the `light` path of `run_suites` selects the suite through the `src/**` impact entry, and the test config has no `[remote_runs]`, so no pickup timeout applies. s1061 and decision 0923 also list `s798` as undiagnosed.

## Change

`fail()` in `scripts/exit/s798.sh` writes `FAILED: <message> (task state: <state>; last log line: <line>)` first, then the same dumps and exit code. The 240 s deadline, the wait loop and the assertions are unchanged ([decision 1088](../decisions/1088-s798-ubuntu-red.md)). If the next red shows a defect in `crates/daemon`, that is a separate change.

## Tests

`scripts/exit/s1099.sh` runs `s798`'s `fail` and the runner's `cause_of` against a fake `m`. `s798` itself is left to CI.

## Trust

`scripts/exit/s798.sh` is in `PROTECTED` (`scripts/exit/**`, `crates/daemon/src/protect.rs`), so this change is held for owner approval.
