# s393: debts settle themselves

Summary: an open skip debt closes by itself when its suite (every suite of its step) is recorded green at a base that contains the commit its task landed, checked on every landing and once an hour, and the debts still open are run once each when the compile queue is empty.

## Why

On 2026-11-14 the review of four days of pipeline data found 82 open skip debts, none ever paid; 40 were star's ten build suites, each owed four times, most of them green on develop since. Paying one took `mason debt run <id>`.

## What changed

- `crates/store`: migration 37 adds `how`, `landed` and `tried_at` to `debts`; `pay_debt` takes the proof text; `set_debt_landed`, `debt_tried`, `suite_green_bases`.
- `crates/daemon/src/suites.rs`:
  - `settle_debts` closes a debt when each of its suites has a `suite_green` row at a base that contains the task's landed commit (git ancestry). It writes "<suite> green on <base> at <sha> since (base holds the task's commit <sha>)".
  - The landed commit is the task branch's tip, recorded on the debt in `after_landing` and again when first seen; a debt with none, or whose commit is not in the base branch's tip, never closes.
  - `run_idle_debts` runs each landed, untried debt through `pay` while the compile queue is empty and a slot is free, one at a time, settling between runs. A red run sets `tried_at`; it is not run again by this loop.
  - `spawn_debts` calls it every `debt_interval` (default one hour, first pass after at most a minute). `after_landing` runs `settle_debts` on every landing.
- `attention.rs`: the "debts" alert counts only debts a run found still red.
- `mason debt list` prints how each was paid (`how` is also in `GET /debts`).
- Tests in `crates/daemon/tests/testing.rs`: closes by itself, never on a base without the commit, red stays open and is run once.

## Not verified

"Rank below every task" is done by waiting for an empty compile queue before starting, not by a place in the broker's queue: `pay` takes no lease, so a debt run that has started is not preempted by a task arriving. The green that closes a debt is a run of the suite at the merge base of a later task (what `suite_green` records), not a run at develop's tip. Not run against star's real data.
