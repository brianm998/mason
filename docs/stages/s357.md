# s357: task and issue links look like web links in both monitors

Summary: every reference that opens a task's page or the tracker (task numbers, keys, titles, `blocked by #N`, issue numbers, CI labels, bare URLs) is now in a new link colour (`color.light/dark.link` in `clients/tokens.toml`), underlined, with the pointing hand on hover, drawn by one shared definition per app (Swift `TaskLink`/`WebLink`/`linkStyle()`, Compose `Link()`).

## Why

Many references open a page and nothing said so. The Swift `.link` button style is accent-coloured with no underline, Compose drew accent `Text` + `clickable` by hand, and no site set a hover cursor. The accent also tints selected rows, so a link could not be told from "selected".

## What changed

- `clients/tokens.toml`: `link` light `#0000EE`, dark `#8AB4F8`. `Tokens.swift` and `Tokens.kt` carry the two new constants (written by hand to match the generator, because `conformance tokens --write` could not be run in this session; a unit test compares the generator's output with both files). `theme.link` in `Theme.swift` and `Theme.kt`.
- Swift (`MonitorUI`): `LinkStyle`/`LinkLook`/`PointingHand` modifiers (`linkStyle()`, `linkLook()`, `pointingHand()`), `TaskLink` and `WebLink` views in `Components.swift`. Every `.buttonStyle(.link)` and `Link(...)` is replaced. `LinkedText` underlines its link runs and uses `theme.link`. The sidebar row stays one button, now with the pointing hand, and its key and title carry the link look. The CPU "More" toggle keeps a plain button look (accent, no underline).
- Compose: `Link()` (link colour, `TextDecoration.Underline`, `pointerHoverIcon(PointerIcon.Hand)`), `Theme.linked()` and `Modifier.pointingHand()` in `Pages.kt`. The hand-made accent sites in `Components.kt`, `Pages.kt`, `Sidebar.kt`, `LinkedText.kt` and `TopBar.kt` use them. The stage row, sidebar row and CPU legend row get the hand and a link-look name. `linkedString` is called with `theme.link`.
- Not links, by design: a reference to a task the monitor does not know stays plain text (`Linkify`). Pills, copy buttons, Approve and the "More" toggle keep their button look.
- Tests: `tokens.rs` (valid hex, link on background and surface at least 4.5:1 in light and dark, generated files equal the toml); `LinkedTextTests.swift` (underline and colour on link runs only, unknown `#N` plain, no `buttonStyle(.link)` in `MonitorUI`, offscreen render); `LinkedTextTest.kt` (colour and underline, grep guard against accent-plus-clickable text).
- Exit script `scripts/exit/s357.sh`.

## Trust

`scripts/exit/s357.sh` is a new exit script (protected path), as the task asked. `clients/features.toml` is not touched: client parity needs a matching entry on both sides and a gate change waits for the owner; no check needed it.

## Not verified

- **The cursor.** The pointing hand cannot be unit tested and none of this was seen on a screen. For inline `LinkedText` (Swift) and `linkedString` (Compose) the cursor over a link run is whatever the toolkit gives a text link; there is no per-run cursor code.
- **No Swift or Compose build was run in this session** (no network for the Swift package dependencies; Gradle was not run). The Swift and Kotlin edits were written by reading the surrounding code and are checked only by the pipeline's own test step. The phone app (`MonitorPhone`) has no link sites and does not depend on `MonitorUI`, so it got no change.
- No rendered snapshot of a task page, the sidebar or the landing queue was made; the offscreen test only checks that a link renders.
- `scripts/exit/s357.sh` runs the Swift and Kotlin tests only where `swift` and the Gradle wrapper are usable.
