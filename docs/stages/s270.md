# s270: paused banners collapse to icons, with a Resume button

Summary: Each paused banner in the Swift and Compose monitors gets a Resume button that lifts exactly that pause and an X that collapses it to its icon (icons gather in one strip, double-click expands, the choice is kept per device and pruned when the pause ends).

**Protocol.** `Banner` gained `project = 3` and `mode = 4` (additive). `views.rs` fills them for `paused` banners only (project empty for an "everything" pause); text, the `attention.rs` alert and the push-auth exclusion are unchanged. Swift code regenerated with `protoc`; Wire builds the Kotlin side.

**Clients.** `MonitorModel` (both) gained `resumePause(project, mode)`, `isPauseCollapsed` / `setPauseCollapsed`, `pauseRows()` (the layout: collapsed icons lead the first expanded pause's row, or share one icon-only row) and pruning of keys whose pause left the header. Collapse state is the bool `paused:<project>:<mode>` plus an index preference listing the set keys, because `Preferences` cannot enumerate keys. `BannersView`/`TopBar` draw the group once, where the first pause is.

**Tests.** `crates/daemon/tests/pause_banners.rs`; `PauseCollapseTests.swift`; `PauseCollapseTest.kt`. Exit script `scripts/exit/s270.sh`.

**Not verified.** The Swift and Compose code, and the Rust test, were written without a local compile or run (builds are only allowed through the shared queue). No rendered layout test exists: the row layout is tested as data (`pauseRows`), not as pixels or semantics trees; the tooltips, double-click and X button views were not exercised.
