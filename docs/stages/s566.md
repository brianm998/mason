# s566: the monitor-swift gate compiles its tests again

Summary: PendingTaskPageTests now applies its sidebar view through the public `apply(Mason_V1_ServerMessage)` instead of the internal `apply(Mason_V1_View)`, so the Swift test target compiles and `swift test` prints its summary again.

**Cause.** `clients/swift/Tests/MonitorUITests/PendingTaskPageTests.swift` (task #522) called `m.apply(v)` with a `Mason_V1_View`. That overload is internal (`Model.swift:1141`), and the file imports MonitorCore without `@testable`, so the test target did not compile and s12.sh step 1 found no "Executed N tests" line.

**Change.** The test wraps the view in a `ViewUpdate` inside a `ServerMessage` and calls the public overload (`Model.swift:1081`). Assertions unchanged.

**Checks.** Other test files importing MonitorCore without `@testable` were grepped for internal calls. The Swift tests were not run in this session; the monitor-swift CI job is the proof.
