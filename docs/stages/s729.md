# s729: one suite split across several GitHub runners

Summary: A suite with `shards = N` runs on N GitHub runners balanced by recorded per-test times, its shard outputs are merged and judged as one run, and a shard that never ran is made again alone.

Task #701, decision 0722.

- `crates/daemon/src/shards.rs` (new): `assign` (greedy by recorded median, deterministic), `hash_shard` (FNV-1a), `merge` (outputs in shard order, worst status), `merge_judged` (a shard that ran 0 of a non-empty list is red).
- `crates/daemon/src/remote.rs`: `RunSpec` gets `shards`, `only`, `shard_lists`, `shard_command`; `.mason/run.json` carries them; `poll` downloads `mason-run-K` per shard; `execute_sharded` runs only the shards without an artifact again (twice at most) and merges.
- `crates/daemon/src/suites.rs`: a whole, un-narrowed run of a suite with `shards` and `shard_command` goes out sharded, with lists from the store (`test_medians`, `passing_names`); `remote_ran` applies `merge_judged` with the suite's parser.
- `crates/testing` / `crates/definition`: suite keys `shards` (1 to 64) and `shard_command`; `shards` without `shard_command` is a definition problem.
- `.github/workflows/mason-run.yml` and `templates/github/mason-run.yml`: a matrix over `.mason/run.json`'s `matrix`, jobs named `run (K)`, artifacts `mason-run-K`, `fail-fast: false`. An unsharded run is unchanged (job `run`, artifact `mason-run`).
- `scripts/test-shard.py`: lists each test binary and the doc tests, keeps its shard's, runs them `--exact`.
- `.mason/mason.toml`: `shards = 8` and `shard_command` on `cargo-workspace`.
- Tests: assignment, merge and judging (shards.rs, suites.rs), sharded runs against an in-process fake GitHub (remote.rs), key parsing (testing_tables.rs). Exit test `scripts/exit/s729.sh`.

Trust: `.mason/**`, `crates/daemon/src/suites.rs` and `crates/testing/**` are protected; the owner must approve. The verdict logic is unchanged: the same parser and `min_tests` read the merged output; the only new red is a shard that ran none of its listed tests.

Not verified: no real GitHub run was made, so the workflow's matrix syntax (job `name` expression, `fromJSON` matrix, per-shard artifact names) and `scripts/test-shard.py` on MASON's own workspace (doc-test listing with `--config` runners, `RUSTDOC` wrapper, RUSTC_BOOTSTRAP for `--report-time`) are untested outside a three-test scratch crate. The fake GitHub binary (`fake-github`) was not extended; the 3-way matrix is answered by an in-process fake in `remote.rs` tests. A shard cancelled while queued is detected only after `pickup_timeout`. Rerun state is not kept across a daemon restart.
