# s633: after a lost step host, rerun only the cargo test executables that had not finished

Summary: when a cargo-workspace suite's host is lost, the fresh host runs only the test executables whose `test result:` line the lost run's log did not reach, and the verdict reads the finished blocks of the lost log plus the fresh output, so a red stays red and `min_tests` counts both.

## Why

A lost host (daemon restart, machine reset) sent a whole 15-30 minute run back to zero: #519's r3548 lost its host twice during a 2,095-test run.

## What changed

- `crates/daemon/src/resume.rs` (new): units of the workspace from `cargo metadata` (lib, bins, each integration target, doc tests), blocks of a cargo log, `plan` (done set, reused text, rerun groups rendered by `affected::render`), `template` (which commands qualify), `combine`.
- `crates/daemon/src/suites.rs`: `run_hosted_resuming` plans on a lost first host (and again after a daemon restart while the second host runs), runs the rendered command on `<id>-host1`, puts the reused blocks before the fresh output and forces a non-zero status when a reused block failed. `Ran::resumed` adds "lost host after 61 of 85 executables; reran 24" to the suite's note. A resumed run records no run time. Second loss in a row still fails the step.
- `crates/testing/src/model.rs`, `crates/definition/src/testing_parse.rs`: suite key `resume_after_loss` (a suite whose `dev_command` takes `{tests_for_change}` needs no key; the key makes the suite's own `command` with `--workspace` swapped for `{tests_for_change}` the template).
- Tests: `resume::tests` (cut-off log, red in a done executable, template rules), `resume_loss` (daemon `it`).

## Rules

Only a plain whole-workspace `cargo test --workspace ...` command qualifies (no target flags, no `&&`, `;` or pipes, not a narrowed run, no pty, no results file, no skip list). A target mid-run when the host died, or an unreadable log, runs again whole as before. If every executable had finished, everything runs again (the exit status is unknown).

## Trust

`crates/daemon/src/suites.rs` and `crates/testing/**` are protected (verdict logic): the verdict of a suite is now judged from two runs. Needs the owner's approval.

## Not verified

No real `cargo test` log was captured in this session (the shared build queue refused ad-hoc cargo): `Running` paths are matched as workspace-relative or package-relative from the format cargo documents and the repo's own fixtures. Not covered: narrowed (`narrow_packages`) runs, which rerun whole, and the daemon-restart-during-second-host path was reasoned, not run.
