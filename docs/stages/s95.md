# s95: the "step host was lost" repeat failure is the pre-s83 signature

Summary: Task #75's seven "the agent failed: the step host was lost before the agent finished" failures predate s83, which made a lost agent host a restart (at most twice, counted from the invocation directories) instead of a crash; no code change was needed, and this records the check and the one thing to watch.

The text "the agent failed: <detail>" is only produced for `FailReason::Crash`. Before s83 the hosted adapter's `Outcome::HostLost` had no daemon handling and the step failed as a crash. Today `hosted.rs` yields `Outcome::HostLost`, `runner.rs` maps it to `FailReason::HostLost`, and `settle_all` in `jobs.rs` records it, reaps the dead host and continues the step; only a third loss fails it, with text "the step host was lost N times (...)", which names every loss. The rows named in the task (#17, #27, #38, #41, ...) are the old signature.

The cause of the losses themselves (see 0047) was most likely the daemon running out of file descriptors, which 5110d9b addresses. If the new text "the step host was lost 3 times" appears in `step_attempts`, that is a fresh problem and the `step_host_losses` table has the reports.

Not verified: the stored rows themselves (the store is not available to this task).
