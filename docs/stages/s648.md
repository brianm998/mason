# s648: smoke lines can name modules of a test target

Summary: A smoke line may carry a test filter after `--` (`-p mason-daemon --test it -- landing_floor::`); it runs as its own cargo command, its build drops the filter and so never runs tests, and `.mason/smoke-tests.txt` now runs only `landing_floor::` of the daemon's `it` executable instead of the separate fast-tier target.

**Cause.** `add_smoke` knew no `--`, so a filtered line was run raw and `--no-run` landed after the `--`, passing it to the test binary.

**Change.** `affected::add_smoke` parses the filter and returns a filtered group as its own command, dropped when the change already selects that target whole. `scope::expand` cuts everything from `--` on in a build. A bare `--` or a filter on doc tests stays an unreadable raw line, whose build is also cut at `--`.

**Trust.** `.mason/smoke-tests.txt` is under `.mason/**` (PROTECTED): the owner must approve that edit.

**Not done / not verified.** Timing of smoke groups in `mason report` was not added. The exit script is a unit-test run, not the scratch two-module workspace of the ticket. I did not run `landing_floor::` against `it` to confirm the module name still exists.
