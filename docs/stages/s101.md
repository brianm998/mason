# s101: warn before the stage and exit-script numbers run out

Summary: `mason alerts` now carries a `numbers` alert, routed like `failed`, once 50 or fewer stage and exit-script numbers are left, instead of the first notice being a refused `mason task add`.

- `numbers::EXIT_WARN_LEFT` (50) and the pure `numbers::exit_warning(highest)` give the text: how many are left, the highest handed out, the ceiling, and that a fourth digit means changing `scripts/run-exit-scripts.sh` and `scripts/gen-status.sh`. Nothing is said with 51 left; "0 ... left" at the ceiling.
- `attention::alerts_now` raises key `numbers`, kind `numbers`, from `Daemon::exit_numbers_warning`, which reads only `all_reservations` (no git). It clears by itself if the ceiling is raised.
- `numbers` is routed like `failed` (`Routing::defaults`) and sounds as a break (`sound_for`).

Tests: unit tests in `crates/daemon/src/numbers.rs` (the 51/50/0 cases; a three-digit `Mine` names `docs/stages/s100.md` and `scripts/exit/s100.sh` and `check_added` holds files to it). Exit test: `scripts/exit/s101.sh`.

Not verified: delivery of the alert over push/email/speech channels (only routing and the alert list); the warning counts only reserved numbers, so a stage number that exists only on the base branch above the reservations is not counted until a task reserves one past it. `crates/daemon/src/attention.rs` is a trust file: this adds one alert and changes nothing about who may answer, but needs the owner's approval. The "every alert that means work has stopped" routed-kinds list was not present in this tree; whichever change lands second adds `numbers` to it.
