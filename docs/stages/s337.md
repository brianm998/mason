# s337: a failed task can be canceled

Summary: `mason task cancel N` now works on a failed task. Like any other cancel it keeps the branch unless `--delete-branch` is given, so `mason task revive N` can still bring the task back. Before this, the reducer refused Failed → Canceled, which went against DESIGN.md: "Cancel works from any non-terminal state", and failed is not terminal.

## Why

On 2026-11-14 three failed tasks had nothing left to do: star #255 and #310 were fixed on develop by #212, and mason #306's fix had already landed. None could be closed (`Illegal { from: Failed, event: "Canceled" }`, HTTP 409). Each stayed in the failed count, and in every check on the failed tasks.

## What changed

- `crates/engine/src/reducer.rs`: `Canceled` is allowed from `Failed`. Nothing is running in a failed task, so there is no step host to stop. Leases are released as for any cancel.
- `crates/engine/tests/matrix.rs`: the expected transition table has Failed → Canceled.
- `crates/engine/tests/behaviour.rs`: `cancel_from_every_non_terminal_state_stops_and_releases` now covers failed, and the new `a_failed_task_made_obsolete_is_canceled_and_can_still_be_revived` covers canceling a failed task and reviving it.
