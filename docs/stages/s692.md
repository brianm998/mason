# s692: a red landing batch reruns and bisects on its failing tests, not the whole suite

Summary: A red landing batch whose run named its failing tests now reruns just those tests (one at a time) and bisects with a build plus just those tests through the suite's `rerun` template, falling back to whole-suite runs when no names were read, the red was a build, or the suite has no `rerun`; the remainder still gets one whole-suite run before it lands.

**Cause.** `Rung::RerunFailed` and `pin_red` ran every red suite whole (`cargo-workspace`: 2,167 tests, 17-27 min) although the run had named the failing tests (batch #421: one rerun and five bisect runs, each the whole suite, one test failing in 3 s).

**Change.**
- `OverRun.failing` (suites.rs): suite -> failing tests, filled from the `Product` verdict of `run_over` (the persistent, unexcused failures). A build failure, a timeout or a red with no names has no entry.
- `suites::can_run_alone` and `suites::run_alone`: the filtered run. Each suite's `rerun` template with `{tests}` filled in; `serial` appends `--test-threads=1` when the template has a ` -- `. With `build`, the suite's `build` runs first. `rerun_failing` now shares the same code (`run_tests_alone`).
- Rerun rung (landing.rs): when every red suite has names and a `rerun` template (and the red is not the build floor), run those tests alone, serially. Still red: the ladder goes on to the search without a whole rerun. Green: the old whole-suite rerun still follows and decides, so nothing lands on a filtered run alone, and "red once and green on a rerun" is said as before.
- Bisect rung: each subset builds and runs only the failing tests. A subset whose filtered run is red with no names (build failure, run that could not tell) runs the whole suites as before. The progress line says "bisecting on N failing test(s)" and the closing batch note "(bisected on N failing test(s))".
- The CI-mapped local search (`[ci.local]`) is unchanged (whole suites).
- The remaining tasks still get a whole-suite run on the next `'outer` round before they land.

**Trust.** `landing.rs` is in `PROTECTED`: how a red batch is searched needs the owner's approval. What is verified before landing is unchanged.

**Tests.** `landing_split.rs`: 4-task batch with one culprit, exactly two whole-suite run logs and every `-bis` filtered log asked only for `integration`; `suites.rs` `alone_tests`: the eligibility rules and the rerun command.

**Not verified.** That the full test suite is green: only what `run_check` ran. A real `cargo-workspace` batch was not run, so the saving (6 whole runs to 2) is by construction, not measured. The `-bis` build logs (`-b0-`) show the build command, not the test name; only the test run's log shows the names. The bisect treats a subset that is green on the failing tests as green even if the whole suite would fail elsewhere in it; the final whole run of the remainder catches that, as it would any later red. The timeout case is left to the sibling ticket.
