# s1068: Compose settle waits on views, not events

Summary: The Compose conformance settle now waits until the model's last applied view reaches the daemon's seq (as step() and the Rust capturer do), and both capturers print a stderr line when they leave on the quiet fallback.

## Cause

`CI/monitor-compose (ubuntu-latest)` was red (run 45361042086): the dump differed from expected by one step at several checkpoints. Compose `settle()` tested `lastSeq`, which also moves on events and stale views (Model.kt:1095, 1100), so an event at seq N could end the wait before the seq-N view was applied.

## Change

`settle()` in `Tool.kt` tests `lastViewSeq >= target`. Both `Tool.kt` and the Rust `settle()` print `settle: quiet exit, ...` to stderr when the wait ends by fallback before the target. No deadline, compare rule or expected file changed.

## Tests

`scripts/exit/s1068.sh` greps for the above. Caveat: the new predicate is a hypothesis; on the next red, read the quiet-exit lines in the log. Gradle was not run here.
