# s470: CI archives the iOS app and uploads it to TestFlight

Summary: A new workflow `ios-testflight.yml` archives the iOS app with automatic signing through an App Store Connect API key and uploads it to TestFlight from `develop`, building unsigned with a warning when the secrets are absent; the owner's one-time steps are in `docs/ios-testflight.md`.

**Change.** `.github/workflows/ios-testflight.yml` (push to `develop` on `clients/swift/**`, and `workflow_dispatch`; `macos-15`; concurrency group `testflight`, cancel in progress). It reuses the `ios-setup` action, then either runs `make ios` unsigned (secrets or `IOS_BUNDLE_ID` missing, with a `::warning::`) or runs `xcodegen`, `xcodebuild archive` and `xcodebuild -exportArchive` with an `ExportOptions.plist` (`app-store-connect`, `upload`). Version is the workspace version, build number `github.run_number`.

**Trust.** `.github/workflows/**` is protected; this waits for the owner.

**Not verified.** `actionlint` is clean. The workflow was not run, not even with `act` (no macOS runner here), so the unsigned path is unexercised until it runs on GitHub, and the signed path needs the owner's secrets: the first real upload happens after the owner adds them. Whether `manageAppVersionAndBuildNumber=false` and the Release archive satisfy App Store validation (icons, export compliance) is unchecked.
