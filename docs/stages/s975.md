# s975: the owner's retry note reaches the reviewer, not only the next step

Summary: an owner's retry note is also kept per task and shown to the reviewer and later develop rounds as "Owner decisions on this task"; see decision 0968.

Verdict logic: the reviewer is now told that owner notes override the task text where they
conflict. That needs the owner's approval. `crates/daemon/src/prompts.rs` (protected) is not
edited: the notes block is appended in `jobs.rs` after the prompt is built.

## Built
- `ownernotes.rs`: per-task `owner-notes` file (JSON lines: time, step, note); append, list,
  clear, and the prompt block.
- `http::retry_task` keeps the note when the retry is not automatic (HTTP/CLI retry, a diagnosis
  applied by hand); `take_retry_note` is unchanged (one-shot).
- `jobs::agent_job` appends the block to every review prompt and to develop prompts that did not
  just receive the one-shot note. `jobs::cleanup` removes the notes on landing or cancel.
- `GET /tasks/{id}/owner-notes`, `POST /tasks/{id}/owner-notes/clear` (owner only),
  `mason task notes <id> [--clear]`, an `owner_notes` field in `mason task show`.
- Tests: `ownernotes::tests`, `owner_notes::*` (integration). Exit script `scripts/exit/s975.sh`.

## Not verified
- Nothing was run locally (tests run on GitHub via run_check) beyond what run_check reports.
  The `mason task notes` CLI and `task show` lines are not exercised by a test; the exit script
  covers the daemon path through the library and HTTP router, not the CLI binary.
- The explore prompt does not show the notes.
