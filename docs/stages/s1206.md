# s1206: every failed or stuck task gets a recovery agent

Summary: every way into Failed, a spent auto-retry loop and a stuck task now reach one entry point, `recovery::on_stuck`, which logs a decision and sends a session that repairs, asks with a card (recommended first) or hands off a stored recovery brief.

## Cause

Only the `Transition::Fail` call site in `jobs.rs` started a diagnosis, and only for code failures. A failed `ctx`, a job panic, an owner's rejection, a third outside failure and a stalled task got no agent. The diagnosis session was read-only, so "fix it" was always a whole new develop round, and a session that ended with no verdict left nothing behind.

## Change

- `crates/daemon/src/recovery.rs` (new): `on_stuck(task, Cause)` with the decisions `waiting`, `attached`, `session`, `card`, `handoff`; one `recoveries` row each. `Daemon::emit` and `emit_for_run` call it after any `StepFailed` (`recover_failed`), so no emitter has to remember to. The auto-retry loop calls it on `Due::GiveUp`; the health tick calls it for a `stuck:task:<id>` / `stuck:wait:<id>` finding that has stood one cooldown (`on_findings`).
- Job panic: class `Outside` (a pipeline bug is not the task's code), with a test hook `MASON_PANIC_AT=job`.
- `submit_diagnosis` gains the option actions `repair {summary, to_step}`, `unblock`, `release_holder`, and the verdict `handoff {brief}` in place of `options`.
- `repair`: a second, writable session (a develop step's contract: `run_check`, the protected-path and weakening guards, head must be the branch's tip) makes the change in the task's worktree, then the task is retried from `to_step` (default: the step after develop). Applied by itself once per `health::signature`; a second failure with the same signature gets a card. `decide` never applies anything for an owner's rejection (`card_only`).
- Hand-off: `recovery_brief` is kept in the `recovery_briefs` table, written by the daemon when a session ends with no verdict, hits its deadline or the per-task budget is spent. Alert kind `recovery_handoff` ("#N needs you: ..."), `mason task brief N`, `recovery` and `recovery_brief` in `GET /tasks/{id}`, and the brief fenced in the first message of `mason task open`.
- `failures:undiagnosed` no longer counts a task whose recovery row says why it waited, and a finding that stands past a cooldown is `record_bug`ed.
- Stuck (not failed) tasks: the session may only recommend `unblock` / `release_holder`, applied by itself, or hand off.
- Cards are stored recommended-first.

## Not done, and not verified

- The monitors (Swift, Compose): no brief view or "Open session with this brief" button, and no change to where "Other" is drawn. `Card` JSON already carries `other: true`; clients draw it.
- `stuck:*` findings still also feed the pipeline-wide health session (moving them out would break `tests/it/health.rs`).
- `recovery_brief` is a table, not a column of a task projection (tasks are rebuilt from events).
- The repair's `run_check` is the develop contract's; no test calls it through the fake agent.
- Nothing was run locally (the shell refuses `cargo test`); only `cargo check`. The tests are untested until `run_check`.
