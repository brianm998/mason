# s780: remote runs build warm and stop saving a cache per run branch (#770)

Summary: Remote runs restore one shared rust-cache key that only the base branch saves (a new warm-up workflow), build into the cached workspace target, set up only the toolchains `run.json` names, and delete a run ref's Actions caches with the ref; `mason doctor` warns near the 10 GB cache limit.

What changed:
- `mason-run.yml`: the suite's `$HOME/.cache/mason-target/<dir>` is a symlink to `./target`; rust-cache uses `shared-key: mason-run` and `save-if` develop only; Rust, Xcode and Java/Gradle steps run only when `.mason/run.json`'s `toolchains` names them.
- `mason-cache.yml`: on pushes to develop and daily, builds the workspace's tests into that target directory and saves the cache (`cancel-in-progress`).
- `run.json` gains `toolchains` (`swift*` -> swift, `compose*` -> java, else rust).
- The run-ref sweep and the normal ref deletion call `DELETE /actions/caches?ref=` for each ref they delete; `mason doctor` reads `/actions/cache/usage` and warns at 80% of 10 GB.

Not verified: that a remote run now logs `Cache restored` and no `Downloaded` lines. That needs the warm-up to have run once on develop after landing. The symlink and `save-if` behaviour of rust-cache was not run on GitHub. Trust: `.github/workflows/**` is protected, so this needs the owner's approval.
