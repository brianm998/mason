# s488: the agent's own cargo builds into the task's build directory

Summary: MASON now writes an untracked `<worktree>/.cargo/config.toml` with `[build] target-dir` set to the task's expanded `task_cache`, so the agent's own cargo builds share the task's directory instead of making a second copy of the workspace in `<worktree>/target`.

**Cause.** The task directory existed only as a `--target-dir` flag in the project file's `test` command. The agent's `cargo fmt/clippy/test/build` used `<worktree>/target`, a second cold build per task. `CARGO_TARGET_DIR` is not an option: sccache hashes every `CARGO_*` variable.

**Change.** `taskcache::write_cargo_config` (crates/daemon/src/taskcache.rs) expands the project's `task_cache` for the task, applies the same path rules as removal (`check_path`), and writes `.cargo/config.toml` (first line marks it as MASON's; the path is TOML-escaped by `cargo_config_text`). It adds `/.cargo/config.toml` to `git rev-parse --git-path info/exclude`, so `git status` stays empty and the dropped-line and marker checks never see it. It does nothing when the project has no `task_cache`; it leaves a tracked `.cargo/config.toml` (or an untracked file that is not MASON's) alone and logs it. It is called from `prepare_locked` (the develop step's worktree) and `prepare_worktree_only`. A config-file `target-dir` is not an environment variable, so sccache keys do not change.

**Not done.** The landing worktree and base-check checkouts do not get the file: they are built by MASON's own commands, which already pass `--target-dir`, and they have no task number at that point. Removing a leftover `<worktree>/target` was optional and is not done. The project file's `--target-dir` flag stays (same directory; it is protected configuration and was not touched).

**Tests.** Unit tests in taskcache.rs with real temporary git repositories: the file exists, names the expanded directory and `git status --porcelain` is empty; a tracked config is kept byte for byte; a refused directory writes nothing; the TOML text escapes spaces, quotes and backslashes. The no-`task_cache` case is the early return in `point_cargo_at_task_cache` and is covered by inspection only, not by a test (it needs a Daemon).

**Measured (before only).** sccache before the change, on 2026-11-16: Compile requests 91337, Cache hits 32257, Cache hits (Rust) 14536, Cache misses (Rust) 9646, hit rate 76.92 %. Worktree `target/` sizes before: 19, 6.2, 4.4, 15, 4.2, 5.1, 2.6, 2.9 GB (from the task text).

**Not verified.** The after numbers (one task's worktree `target/` size and sccache hit counts once agents run with the file) were not measured: they need a task run after this lands. That cargo honours the file in a MASON worktree was reasoned from cargo's config lookup, not run. Interactive cargo builds were refused in this session, so the code was compiled and tested only through `run_check`.
