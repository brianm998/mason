# s561: masond sends a view only when it changed, leaves history-row bodies out unless asked, and sends a state-since time

Summary: masond skips a view whose encoded bytes equal the last one sent to that session, sends history-row bodies only when the client sets `Subscribe.row_bodies`, and gives each row `state_since_ms` (with `in_state_ms` rounded to whole minutes) so clients count the time in state themselves.

**Cause.** `send_views` sent every view of every rebuild, rows carried up to 2,000 characters of `body` (about 860 KB of a 1.2 MB sidebar with 479 history rows), and `in_state_ms` grew between rebuilds so the sidebar could never be equal.

**Change.**
- `ws.rs`: per session, a hash of each view kind's encoded bytes (seq left out); an equal hash is not sent. The seq still advances, so resume is unchanged. The hashes are cleared when the subscription changes project or asks for a view not asked for before, so a view a client dropped and wants again always arrives.
- `Subscribe.row_bodies = 7`: false (the default) sends the Landed, Canceled, Failed and Deferred rows with an empty body; active sections keep theirs. Both monitors set it while the search box has text and "body" is ticked, and re-subscribe when that changes.
- `TaskRow.state_since_ms = 27`: when the row's state began (the same figure `in_state_ms` was counted from). Both monitors count the time from it with their clock offset on the one-second tick, and fall back to `in_state_ms` when it is 0. `in_state_ms` is rounded down to whole minutes for older clients. All fields are additive; the protocol version is unchanged.
- `Client::subscribe_full` in `mason-protocol` carries `row_bodies`; `subscribe_spans` asks for them (true).

**Tests.** `tests/row_bodies.rs` (bodies off and on, `state_since_ms`, whole-minute `in_state_ms`), two in `tests/protocol.rs` (an unchanged view is not resent, a changed one is; 500 canceled tasks, the sidebar once, under a quarter of the size without bodies), Swift and Kotlin tests for the duration and the body-search subscription.

**Not verified.** `mason.pb.swift` was edited by hand in protoc-gen-swift's style (protoc hung on this machine), not regenerated. The exit test uses 500 canceled tasks, not landed ones (same history section and cap). The Swift and Kotlin code was not compiled or run here. Old clients that never send `row_bodies` now get history rows without bodies (their body search finds only active rows). A view that changes every time (for example a CPU history that moves with the clock) is still sent every rebuild. The dedupe tests assume the minute does not turn mid-test (`in_state_ms` is rounded to minutes).
