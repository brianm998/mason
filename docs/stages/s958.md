# s958: the Swift monitor opts out of App Nap

Summary: The Swift monitor holds one `latencyCritical` process activity (and `NSAppSleepDisabled` in the bundle) for its whole life, so its main thread is no longer throttled to priority 4 when its window is behind another app.

On 2026-11-22 every monitor thread sat at `4T` while compile jobs ran at 20-46, so a 300 ms SwiftUI update waited seconds for a core and alerts came late. `MonitorCore/AppActivity.swift` holds `userInitiatedAllowingIdleSystemSleep` + `latencyCritical` through an injectable `begin`, once; `Session.init` in `App.swift` calls it. It never sets `idleDisplaySleepDisabled`, so the display still sleeps. This is a desktop on mains power, so napping saved nothing. `bundle-monitor.sh` also writes `NSAppSleepDisabled`, for bundled builds; the bare `swift build` binary relies on the code path.

Not verified: `ps -M` priority of a monitor behind another app for 10 minutes on a loaded machine (not checked on the pipeline host); local `swift build` and `swift test` are refused in this shell, so the build and the AppActivity test were not run by me.
