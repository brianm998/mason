# s262: a develop agent's run_check ranks as develop work, behind tasks already in test

Summary: The compile (and other test-step) slots a develop agent's `run_check` queues for are now ranked by the agent's own step, not by the test step whose commands it runs. A task that has reached its test step therefore goes ahead of every develop check, whatever their priorities, because steps remaining sorts before priority.

## Why

On 2026-11-13, with compile at 3 slots, four mason tasks in test (#230, #232, #277, #288) waited while develop agents kept getting compile slots. `CheckSlots::swap_for` ranked a check as the test step (decided on 2026-11-11, `5e012882`), so a check and a real test step had the same steps remaining. The tie went to priority (#284, #287 and #289 were high) and then to filing age, so #277 and #288 were 16th and 21st in line behind most develop agents. Tasks nearly done got no advantage.

The 11-11 decision was made because develop agents ran out of time while their check waited about 8 hours. Since then the queue wait of a check is added back to the agent's deadline (`DeadlineExtra`, `TestChecks::extra`), so ranking the check lower no longer costs the agent its time.

## What changed

- `crates/daemon/src/jobs.rs`: `swap_for` ranks the check with `check_rank_step`, which returns the agent's own step. The resources it asks for are unchanged (the test step's `uses`).
- Test: `a_develop_check_ranks_behind_a_task_already_in_test` (a high-priority develop check filed earlier sorts behind a normal test step filed later, with the real `Rank` and `steps_remaining`).

## Not verified

No integration test drives a develop check and a test step through the broker together: the fake agent plays one script for every task, so a task cannot be made to skip its check. A develop check now waits behind landings, test steps and interactive work; if checks wait long, the agent's deadline is extended by the wait, but the agent's session stays parked meanwhile. Requests already waiting keep the rank they were queued with until masond takes over and the jobs queue again.
