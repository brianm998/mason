# s244: the outside-holder sched test no longer races a parallel fork

Summary: `a_slot_held_outside_the_broker_is_not_granted_again` failed in full lib runs because a slot lock is not released synchronously with the drop; the test now retries a bounded number of times, and the product code is unchanged.

## Why

The test drops a `Locks::take` holder and expects the next `lease_poll` to grant. The slot is a flock, which the kernel frees only when every copy of the fd is closed. A child forked by a parallel test can hold a copy between fork and exec, so the slot stays locked briefly and `second` stays Waiting. Alone, nothing forks, so it passed.

## What changed

- `crates/daemon/src/sched.rs`: after `drop(held)`, poll up to 500 times with 10 ms sleeps until Granted, then assert Granted. No elapsed-time assertion. The Waiting-before-drop and "held outside the queue" asserts stay.

## Not verified

The cause is inferred from the code, not reproduced by printing the lock state on a failure.
