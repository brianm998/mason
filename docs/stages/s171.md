# s171: the digest groups waits by what was waited for

Summary: `WaitStarted` now carries an optional `class` (`compile`, `test-suite`, `llm:<provider>`, `exclusive`, `cpu`, `disk-stall`, `disk-floor`, `pause`, `outside-pipeline`, `environment`, ...) and `mason digest` totals waits per project and class (count, total, longest with its task, share of task time) instead of per full wait text.

Task #190. Decision 0166 records the choices.

**What changed.** `EventKind::WaitStarted` gained `class: Option<String>`; the codec writes it as a trailing field, so old payloads decode with `None` and old logs replay unchanged (no fixture was touched). `mason_core::wait_class` returns the recorded class, or reads one off the start of the text for an old event, with `other` as the fallback. Where a wait starts the class comes from the request: the broker's `Wait::class()` (resource or gate, from the cause), passed to the emit site through `Broker::wait_class` for the length of the `on_wait` call; fixed classes for pause, approval, git and environment waits. The digest replay was split into `Replayer` (feed events, finish) so it can be tested without a daemon, and counts each wait once (clipped to the window). The digest's `wait_by_reason_ms` is replaced by `wait_by_class`, a list of rows. Time in a queue and time waiting for the owner, which are task states and not `WaitStarted` waits, stay in the totals as the classes `queue` and `owner` with no count.

**Not verified.** I could not build or run anything directly (the build queue refuses direct cargo from this session and `mason run` lost its daemon part-way), so what I know about compiling and the tests comes from `run_check`, reported in the submission. The exit script `s171.sh` runs an in-process daemon test (`crates/daemon/tests/wait_classes.rs`) and reads the digest JSON; it does not run the `mason digest --days 1` command, so the CLI's printed table was not seen. `mason health` has no waiting-by-reason section in this tree, so only the digest changed. The share is the class total over the time tasks spent in a state (the same base as the `wait_share` detector), not over wall-clock time. The 6.0 h and 18.5 h figures in the ticket were not reproduced.

**Protected files edited.** `crates/daemon/src/sched.rs` and `crates/scheduler/src/explain.rs` (budgets: only report which resource or gate a wait is for; no limit or order changes), `crates/daemon/src/suites.rs` (one field at one emit site; no verdict change), and the new `scripts/exit/s171.sh`. These wait for the owner's approval.
