# s1109: approaches tried and dropped reach later rounds

Summary: `submit_change`, `submit_close` and `report_progress` take an optional `tried` list of approaches an agent gave up and why; later develop and review rounds and the diagnosis read it as a fenced block, and `mason task show` lists it under each run.

## What changed

- `contract.rs`: `tried` is an optional array of `{approach, why_dropped}`, at most 10 entries of at most 300 characters per text. A bad shape is refused with the entry and field named. `set_on_tried` hands the list of each accepted call to the daemon.
- `tried.rs` (new): one file per step run, `tried-r<run>.json` in the task's folder, written before the agent is told the call was accepted. The latest non-empty list of a run replaces an earlier one; a call without `tried` leaves it.
- `prompts.rs`: `tried_block` lists every run's entries, newest run first, at most 3000 characters of entries (the oldest are left out and counted), each on one line, inside a data fence. `develop_prompt` takes it beside the feedback (`Earlier`); packs may place `{tried}`, and get it appended when they do not.
- The built-in review prompt gets the block too (appended in `jobs.rs`), so the tool description ("the reviewer reads this") is true. The diagnosis prompt gets the same block.
- `GET /tasks/{id}` has `tried`; `mason task show` prints each entry under its run.

## A round that fails without submitting

The contract's only report from a step that does not submit is `report_progress`, so `tried` is accepted there. A round that dies without ever calling it leaves no notes. `request_exploration` and `ask` do not take the field; an agent that is about to use them can send the list with `report_progress` first.

## Trust files, for the owner

- `crates/adapter-api/src/contract.rs`: new optional field, its caps, and the callback. No existing check changes.
- `crates/daemon/src/prompts.rs`: a new fenced block for agent-written text. The existing fence's text is unchanged (its formatting moved into `fence`, which both use).

## Not verified

- No real Claude or Codex session was run with the new schema (`maxItems`, `maxLength`); only the fake agent.
- The explore prompt, built in or from a pack, does not get the block, and the owner chat draft does not either.
- The monitor apps do not show the entries.
- A daemon restart in the middle of a step was not exercised for the new files.
