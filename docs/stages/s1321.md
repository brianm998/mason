# s1321: `stuck:long` does not count capacity waits

Summary: a task that only queued for a GitHub runner, a node or a slot no longer raises
`stuck:long` (decision 1311).

## Change

- `TaskFact` has `capacity_wait_ms`; `mason_core::health::capacity_wait_ms` totals it from the
  wait events since the task entered its state.
- The time rule of `stuck:long` uses the working time and is quiet during a pool wait. The
  check-round rule is unchanged.
- The finding's evidence shows both times.

## Exit test

`scripts/exit/s1321.sh`.

## Not verified

- Nothing was run against the live daemon or its log, so the effect on `interventions_per_landed`
  and the cost of the new query on a large log are not measured. The query scans the `events`
  table (no index on kind or time) once per health report.
- A current wait longer than `wait_ms` still skips the task's other checks, the round rule
  included, as before.
