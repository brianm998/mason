# s117: a develop step no longer spends its time limit waiting in the check queue

Summary: A develop step's time limit now grows by the time its agent spent queued for a `run_check`, so waiting for a test slot no longer counts against the step.

**Cause addressed.** "The step ran out of time" on `develop` (19 attempts, tasks #72-#100) came from agents sitting inside `run_check`; the whole-invocation deadline kept running while the agent was only queued for a test slot. `TestChecks` now measures the queue wait (`swap_for_test`) and adds it to a shared `DeadlineExtra` that the Claude, hosted and fake adapters' deadline watchdogs consult.

**Not fixed.** The journals also show run_check calls stranded across a masond takeover (the bridge never got a reply); that hang is separate and still unfixed. This change only stops queue time from consuming the budget.

**Not verified.** No test was added for the extension; only the project's test check was run.
