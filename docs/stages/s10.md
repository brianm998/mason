# Stage 10: Attention and overrides

## Built
- **Decision cards (`adapter-api/card.rs`)**: the shape (one-sentence ask of at most 200 characters, why, 2 to 4 complete options with exactly one recommended, at most 10 lines of evidence, links, an optional key), the strict parser that lists every way a card does not fit, the deterministic fallback that always fits and loses nothing, acceptance of a rewriter's replacement, and the hash answers are tied to.
- **`ask` enforces the shape without ever losing a question**: a card that does not fit is rejected as written, offered to the project's optional `card_rewriter` command, and rebuilt deterministically if that fails; the agent is told what was wrong. The card records its origin and problems.
- **Answers** (`daemon/attention.rs`, `POST /tasks/{id}/answer`): tied to the card's hash (a stale one is refused), counted only from the owner's identity (anyone else is refused and counted apart), taken as an option number, a label or free text, and delivered to the resumed agent so it is not asked again.
- **A question about the same thing is acknowledged, not asked again** (card `key`), recorded as an acknowledgement.
- **Overrides**: cancel, skip test, retry from step (as before), plus `land-now` and `force` (recorded as override and debt; they act from Stage 14), pause and resume (per project or global; `all`, `claims` or `landing`; always with an expiry), and `task open` (resumes the agent's session in the worktree when the step is idle). One piece of API middleware records every one, with who and an optional why.
- **Alerts tied to live conditions** that clear when the condition clears, with a history; **the "interventions per landed task" metric**.
- **CLI**: `mason task answer|land-now|force|open`, `mason pause [list]`, `mason resume`, `mason alerts [--all]`, `mason metrics [--days N]`, global `--as` and `--reason`; `mason task show` shows the card (ask, why, numbered options, evidence, its hash, and how it was rewritten if it was). **Store (migration 6)**: interventions, pauses, alerts.
- `docs/decisions/0007-attention-readings.md`, `scripts/exit/s10.sh`.

### Tests
- **Card rules (8 unit tests)**: every rule of the shape with a card that breaks it; the fallback on a pasted log as the question, on nothing at all, and on a very long single sentence; a rewrite that must itself fit; hashes follow the text; answers pick options.
- **Daemon end to end (14)**: a good card untouched and an answer resuming the task (the agent is told the decision); a bad card rebuilt, with the agent told; a project's rewriter used first, and a failing one falling back; stale, wrong-identity, missing-option and empty answers refused (and counted correctly), and an answer working once; free text as "Other"; the same key asked again acknowledged; claims paused and lifted, a pause running out by itself, a single project paused alone, `all` holding the next step; alerts raised and cleared with history; the metric (including no ratio before anything lands); owner identities; opening a session.
- 348 tests across the workspace; all exit scripts s00 to s10 pass.

## What testing found
- **Two global flags collided with the commands that already had them.** `--reason` belongs to `reject`, `skip` and `land-now` as well as being a general option; the first version swallowed it and `task reject --reason` lost its reason (an existing test caught it). The global form is now accepted only before the command, and those commands read their own after it.
- **The stand-in agent counts turns per prompt, not per run**, so a script meant to start with a bad question did it for every task. The exit script uses one project per script.
- The middleware that records interventions first held a reference to the request across an `await`, which made the whole handler non-`Send`; it now reads the two headers it needs and lets go.

## Not done or not run
- **The triage agent** is Stage 22, as the plan says.
- **Answers from a tracker comment** need the tracker adapters (Stage 15 onward); only the CLI (and later the monitors) can answer.
- **Owner identity is a name, not a credential** (see decision 0007). It stops an agent or an outside comment from answering, which is the failure the design names; it does not stop a local user who claims to be the owner. Authenticated clients arrive with the protocol stage.
- **`all` pauses at the next step boundary only.** It does not interrupt a running agent turn.
- **Nothing in the pipeline asks the owner about a gate yet**, so the acknowledgement path is exercised by an agent asking twice, not by a real gate failing again.
- **`task open` was checked up to the point of launching `claude`**: the daemon side (finding the session and idleness) is tested; I did not launch an interactive session from the CLI in a terminal.
- **Land now and force do nothing** until Stage 14, as the plan allows.
- **No real model** rewrote a card: the rewriter is a command, tested with scripts.
