# Stage 1112: review findings have a severity; only blocking ones send a task back

Summary: Every review finding is now `blocking` or `minor`, only a blocking one sends the task back, and minor ones are kept as advice in the feedback history, `mason task show` and the monitors.

Cause: `submit_review` findings had no severity, any `changes` verdict sent every finding back as equal-weight text, and the review prompt did not say what is worth a send-back.

Change:

- `crates/adapter-api/src/contract.rs`: each finding needs `severity`; `changes` needs a blocking one; `approve` may carry minor ones and is refused with a blocking one. The tool description states the rule, so a prompt pack that does not mention severity still gets it.
- `crates/daemon/src/prompts.rs`: the default review prompt lists what is blocking and what is not a finding.
- `crates/daemon/src/reviewfindings.rs` (new) and `jobs.rs`: send-back feedback marks each finding; an approval's minor findings go to `feedback-history.txt` and to the next develop round, if one happens.
- `mason task show` (`review` lines), the task detail JSON (`review_findings`), `TaskDetailView.review_findings` (25) and a "Review findings" section in both monitors.

Decision: docs/decisions/1101-review-severity.md.

Tests: contract, prompt and findings unit tests; `crates/daemon/tests/it/review_severity.rs` runs scripted review sessions to landing. `scripts/exit/s1112.sh` runs them.

Not verified: no real reviewer agent was run, so the effect on send-back counts is unknown. The two monitor sections were not rendered or screenshotted, and the Kotlin client was not built here. `mason task show`'s printed lines are not asserted; the JSON they print is.
