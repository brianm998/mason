# s471: Waiting requests reserve only what they lack

Summary: A waiting request now reserves only the resources it is short of (the first in line also keeps its other units), and build-less suites no longer hold the step's `compile`, so compile slots no longer idle behind test-suite waiters.

## Built
- `crates/scheduler/src/plan.rs`: `Blocked::add` reserves short resources only; first in line for them also reserves the rest (decision 0464).
- `crates/daemon/src/suites.rs`: `run_needs` drops the step's `compile` for every suite.
- Planner tests in `crates/scheduler/tests/properties.rs`: the 8-mixed/3-compile case, no starvation, the 25-waiter overnight ledger, exclusive still blocking.

## Not verified
Not run on the live daemon; `mason resources` output was reasoned from the plan's causes, the tests check the causes.
