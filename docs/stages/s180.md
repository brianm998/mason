# s180: a probe that gets through lifts the account hold at once

Summary: A probe whose session shows output (tokens, text or a tool call) lifts the account hold straight away instead of when the session ends, and the credentials hold text says logging in alone does not lift it.

**Cause.** `holds::session_ended` was the only place a good probe cleared the hold, and it runs after the whole session. A develop probe can run for an hour, so the account stayed blocked after the owner had logged in.

**Change.** `SessionSpec::on_live` (adapter-api) is called by the runner's `drive` once per `drive` call (so `resume` too) on the first `Tokens` with output > 0, `Text` or `ToolCall`; `Model`/`Usage` alone do not count. `jobs.rs` wires it to the new `holds::probe_ok`, which releases the probe and clears a non-manual, non-budget hold. `session_ended(.., true)` and `observe_end` are unchanged, so an accepted session that is refused later puts the hold back. `describe_with` takes the probe owner: "checking now with task #N" while it runs, otherwise "logging in does not lift it: the hold lifts at the next successful check (in X), or `mason account release <name>` now". The `credentials` alert in `notify.rs` says the same.

**Tests.** `crates/daemon/tests/holds.rs` (`a_probe_that_gets_through_lifts_the_hold_before_its_session_ends`, refused-probe backoff doubling, accepted-then-refused), unit tests for the three `describe` texts. `credentials.rs` now looks for "claude /login" instead of "log in again" in the alert text.

**Not verified.** Nothing was run locally before the run_check. `scripts/exit/s95.sh` does not assert the old text, so it is unchanged. Output-token-only liveness is in the runner but has no dedicated test; the integration tests use `Text`.
