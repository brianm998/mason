# s996: the local fallback takes runs only onto a machine that can start them

Summary: A run GitHub has not picked up comes back here only when this machine would grant its lease at once (queue counted, hold settled, lease taken before the GitHub run is cancelled).

Task #1025, decision 0989. On 2026-11-22 nineteen agent checks fell back at once behind a heat hold.

- `place::LocalLoad::no_room` counts requests already waiting for the needed slots: room is a
  free unit beyond them.
- `sched::settled_hold`: a CPU or heat hold stays active until clear for `compile_settle_s`
  (`State::held_seen`, set by every `cpu_gate`), read by `load_reading`.
- `Broker::try_acquire_beside` (never queues). `remote::site_for_run`'s room function takes the
  lease before the run is cancelled (`try_take_fallback`); `fallback_lease` and
  `fallback_lease_for_batch` use that lease. A run that cannot get one stays on GitHub.
- `Broker::acquire_as` returns `Cancelled` when its request is gone from the ledger.
- The pickup clock starts at the run's `created_at` (`pickup_clock_from`).

verified: a real masond against a fake GitHub (`scripts/exit/s996.sh` runs the unit tests only);
whether `favor-remote` is safe again on the owner's machine.
