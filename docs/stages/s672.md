# s672: proposed and stuck tiles fill red only while one of their tasks is shown

Summary: The proposed and stuck count tiles keep their red border and count whenever the count is above zero, but fill with the red tint only while the main view shows one of their tasks; failed and the rest are unchanged.

What changed
- `MonitorModel.tileShowsCurrentTask(_:)` (Swift `MonitorCore/Model.swift`, Compose `core/Model.kt`): page is a task page whose id is a row of the sidebar section with the tile's state.
- `CountTile` (Swift `MonitorUI/Components.swift`, Compose `ui/Components.kt`): for `proposed` and `needs_attention` the background is the attention tint only when `wants` and the helper is true.
- `clients/features.toml` `count-tiles` description updated (trust file; the status values are unchanged).
- The phone tile is left as it is: tiles and the task page are never on screen together there.
- Decision: `docs/decisions/0665-tile-fill-marks-shown-task.md`.

Tests: helper cases in `MonitorCoreTests.swift` and `MonitorCoreTest.kt`; offscreen ImageRenderer fill checks in `CountTileTests.swift`; `tileFillsOnlyWhenShown` in `TopBarTest.kt`; `scripts/exit/s672.sh` (greps that the four sites use the helper).

Not verified
- The Compose `CountTile` fill itself is not rendered in a test, only the rule and the model helper.
- Whether unrelated sidebar updates redraw every tile was not measured; only the proposed and stuck tiles read the sidebar section.
- The Swift and Kotlin tests may not have been run here; see the submission.
