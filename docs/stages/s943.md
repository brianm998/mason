# s943: a landing batch holds slots only for suites that run on this machine

Summary: see decision 0936. A batch out on GitHub held a `test-suite` slot for 48+ minutes on
2026-11-22, and an exclusive request from another project waited for it.

Owner approval for the protected files `crates/daemon/src/landing.rs` and
`crates/daemon/src/suites.rs`: given in the session that started this work on 2026-11-22 ("Yes,
start it"). `crates/scheduler/**` and `crates/daemon/src/sched.rs` are not touched.

## Built
- `remote::suite_goes_remote`: the placement question for a suite no task owns, one function
  with the run's own `executor_for` call.
- `remote::BatchOwner` (first task, its rank, members, runs, whether a wait ends when they leave),
  `remote::batch_lease` (slots taken as the batch, beside its lease) and
  `remote::fallback_lease_for_batch` (the fallback of a suite the batch holds nothing for).
- `landing.rs`: `Runner::owner` (the rank and wait rule `hold` used inline; `hold` now uses it),
  `by_placement`, `hold_suites`. `run_local` (main batch run), `run_alone` and the post-land run
  hold only the slots of the suites that stay here, and pass a `suites::BatchCover` (the batch and
  what its lease holds) in place of `_lease.is_some()`. `suites_needs` is `pub(crate)`.
- `suites.rs`: `Who.covered` became `Who.cover: Cover`; `BatchCover` is made per suite in
  `run_over` and `run_alone` (`covered` only if the lease holds that suite's slots). In
  `run_hosted_resuming` a covered fallback takes nothing (s911), an uncovered batch suite's
  fallback takes `fallback_lease_for_batch`, and an uncovered batch run that goes here (a late
  placement change, a baseline, a build) takes `batch_lease` of the suite's needs first.
  `suites/base_red.rs` passes `&who.cover`.
- Tests: `batch_remote_hold::a_batch_whose_only_suite_runs_on_github_holds_no_local_slot_while_it_is_out`,
  `batch_remote_hold::an_exclusive_request_is_granted_while_a_batch_is_out_on_github`,
  `batch_remote_hold::a_batch_with_a_local_and_a_remote_suite_holds_only_the_local_suites_slots`
  (real daemon and git, a fake GitHub that never answers; each check follows the run reaching
  it), `fallback_lease::a_batch_suite_falling_back_here_takes_its_slots_ranked_as_the_batch`
  (real broker, a debt-ranked request queued first), `suites::batch_cover_tests::a_batch_cover_holds_only_what_the_lease_holds`.
  Exit test `scripts/exit/s943.sh`. The s911 and s924 tests are unchanged.
