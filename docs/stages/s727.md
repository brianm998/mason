# s727: per-task choice of where to run: `mason task add --run-on github|local` (#699)

Summary: A task can choose where its compiles and tests run with `mason task add --run-on github|local` or later `mason task run-on <id> github|local|default`, stored as the task override `run_on`, read before the global switch, shown as "runs on: GitHub (task choice)" in `mason task show` and the task detail, and refused in tracker and agent filings.

**What exists.**
- `layers::check_override` accepts the task-wide key `run_on` (`github` or `local`; any other value is refused with a message naming both). It returns an empty step name, so `resolve` never applies it to a step.
- `POST /tasks` takes `run_on` and writes the override right after the filing; `POST /tasks/{id}/run_on` (`mason task run-on`, owner only like `priority`) sets it or, for `default`, removes it. The generic task and runtime override routes refuse the key and point at `run-on`.
- `place::task_choice` reads the override live (no new field, event or migration), so `place::decide` (#698) already puts it before the global switch; a change applies from the next suite or check and a run in progress is not moved.
- `place::effective_line` gives "runs on: <place> (task choice|global switch)" for `mason task show` and the `run_on` member of the task detail.
- `filing::refuse_run_on_claim`: a `run_on` key in a body's front matter is refused for the owner's filing, a tracker import (held with the reason in the pending list) and an agent proposal.

**Trust.** `layers.rs` and `filing.rs` are protected files; the key only changes where a run happens, never what judges it.

**Not verified.** Nothing was built or run by the author: cargo is only reachable through the check queue, and `scripts/exit/s727.sh` was written to follow s722 but was not run here. The exit script's third step sets a held task (`--after`) to `local` before it starts instead of moving a task between two rounds. The suite rules still win over the task's choice (a `remote = false` suite or a device stays here), as in the #698 table. No monitor picker.
