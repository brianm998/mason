# s978: a lint red that names a file one task added parks that task without a bisect

Summary: `lint_files` now reads the repository guards' `<path>: <message>` and `<path>:<line>: <message>` lines, for paths in the batch's union diff only, so the existing file blame parks the one task that added the file instead of bisecting.

**Cause.** `lint_files` knew only rustfmt's `Diff in` and clippy's `-->` lines; `check-exit-guards.sh` prints `<path>: <message>`, so a guard red named no file and the batch bisected.

**Change.** `lint_files(output, known)` takes the union of the member footprints' files (`Runner::union_files`); a guard line blames only a path in that set. `blame_by_files` is unchanged. Unit test and a landing integration test (`a_guard_line_naming_a_file_one_task_added_parks_that_task_without_a_split`). No guard script was edited: check-spdx.sh's `missing ... in <path>` form is matched by CI-watch fixtures, so reordering it was left alone.

**Not verified.** I could not run cargo here (shared build queue); the tests were not run before submission. The exit script runs the two tests rather than a real daemon with the scripted agent, and does not check the batch log for bisect rounds. The landing test does not count suite runs.
