# s928: CI watch keys jobs by the workflow's name

Summary: the base-branch CI watch named a job by the run's `name`, which is the commit message when the workflow sets `run-name:`; it now uses the workflow's own name (`CI/windows`), and saved state keyed by a commit message is dropped and rebuilt.

## Built
- `crates/adapters/src/github.rs`: `GitHub::workflow_name` finds the name by the run's `workflow_id`, else its `path`, in `/actions/workflows` (read once, again only on a miss). Used by `base_runs`, `workflow_file_runs`, `status_detail` and `progress`. A run with neither field, or an unreadable list, falls back to its `name`.
- `crates/daemon/src/ci_watch.rs`: `migrate_keys` runs each pass (decision 0921).

## Not verified
- Against live GitHub; only recorded responses. PR check-run readers (`:349`, `:432-461`, `fold_checks`) read check runs, not workflow runs, and were left alone.
- Tests were run through `run_check`, not here.
