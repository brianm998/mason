# Stage 2: Core domain and reducer

## Built
- `crates/core`: ids and `Timestamp`, the eleven `State`s, `Activity` / `WaitReason`, `Task`, the entities (Project, StepRun, Wait, Decision, Verdict, Batch, Proposal, Alert, Override, Debt), and the `Event` / `EventKind` / `Effect` vocabulary. No dependencies.
- `crates/engine`: `World` (deterministic state, id counters, invariant checker) and the pure `reduce(&World, &Event) -> Result<(World, Vec<Effect>), ReduceError>`. Depends only on `mason-core`.
- Transitions from Part 4's diagram, including `queued`→`developing` (explored flag) and `developing`→`exploring` (no failure charged), self-releasing blockers (with cycle refusal), not-before times (released by `Tick`), retry to any step (catching up with the base first), and cancel from every non-terminal state.
- Activity is recomputed for every task after every event in one place, so state and activity change together.
- `scripts/check-pure.sh`, `scripts/exit/s02.sh`, `docs/decisions/0001-state-diagram-readings.md`.

## Exit test
`bash scripts/exit/s02.sh` passes locally (22 behaviour/matrix tests in `mason-engine`, plus purity checks): core has no dependencies, engine depends only on core, no IO/clock/thread/random/async references in either `src/`, and the checker rejects a planted clock read.

Tests (all with no IO and a simulated clock):
- `matrix.rs`: all 11 states × 18 event kinds (198 pairs): legal exactly where the diagram says, correct target state, invariants hold, input world never mutated.
- `behaviour.rs`: happy path, explored route, blockers (release on merge and on no-change close, not on cancel, cycles refused), not-before, retry targets and ordering of effects, cancel effects, stale answers, pause/resume, waits, determinism, and a 20,000-event random run asserting invariants after every accepted event and an unchanged world after every refusal (about 700 accepted).
