# s98: finished step hosts move out of the registry

Summary: The sweep moves the host directories of closed step runs from `h/` to `t/<task>/hosts/` after a day, deletes them after `retention_days` (default 90), and removes ended sessions' `a/` directories, with logs readable from both places.

What changed
- `crates/daemon/src/hostarchive.rs`: `pass(cfg, world, now)` (called from `sweep_once`) moves, expires and cleans; `task_hosts` reads live plus archived hosts of one task.
- `Registry::scan_where` reads only directories whose name passes a filter; `render_logs`, `session_for` and `stop_hosts` use it or `task_hosts`, so they no longer read every host.
- `DaemonConfig::host_grace` (a day; `MASON_HOST_GRACE_MS`) and `retention_days` (`daemon.toml` `[daemon] retention_days`; 0 keeps for ever).
- Decision: `docs/decisions/0084-archive-finished-hosts.md`.

Tests: `crates/daemon/tests/hostarchive.rs` (move after a day, recent stays, open run stays, logs and session identical after a move, retention with an injected clock, retention 0, `a/` cleanup, a failing move is counted and retried, `daemon.toml` parsing); `scripts/exit/s98.sh` (real daemon: landed task's hosts move, `mason logs` still shows them, a running second task's host stays and `mason status` counts 1).

Not verified
- "After a restart an open run still re-attaches" is tested by showing that the open run's hosts stay in `h/` and `latest_invocation` (what reattach uses) finds them; no test restarts a daemon across a pass.
- The `a/` rule (older than the grace period and than the oldest open run) is reasoned, not tested against a real agent that runs for days.
- A move across file systems (a `t/` on another volume) fails and is retried each pass; there is no copy fallback.
- Hosts whose id does not parse as `t<task>r<run>-…` (landing and batch hosts) are not moved and still accumulate.
