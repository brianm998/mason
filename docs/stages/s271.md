# s271: a debt run, a ledger rerun and a landing batch write in the project's test command

Summary: `{project_test}` in a suite's commands is now written in by `run_suite` itself, so every caller gets the project's `test` command, not only the test step. Before this, `mason debt run` on mason's own test step failed at once with `sh: {project_test}: command not found`, and no debt for that step could be paid.

## Why

On 2026-11-13 the owner skipped the test step of 24 mason tasks (debts #57-#80), meaning to run one full set of tests on develop once they had landed, and pay the debts with it. `mason debt run 58` ran the `cargo-workspace` suite as the literal command `{project_test}` (exit 127). The test step writes the command in (`with_project_test` in `run_once`); `pay`, `ledger_run` and `run_over` call `run_suite` with the suite as the definition has it.

## What changed

- `crates/daemon/src/suites.rs`: `run_suite` writes the project's `test` command into a suite that names `{project_test}`, using `jobs::test_commands` for the suite's project. A suite that already has it (the test step's) is unchanged. A project with no `test` command makes the suite fail with the same message the test step gives. `uses_project_test` is shared with `with_project_test`.
- Test: `paying_a_debt_writes_in_the_projects_test_command` in `crates/daemon/tests/testing.rs`.
- `docs/decisions/0255`-`0259`: their Trust lines said none of their paths was in `PROTECTED`. Each added an exit script under `scripts/exit/**`, s260 changed `sched.rs` and s263-s264 changed `suites.rs`, all protected. The owner had asked for each change; the lines now say which paths are protected and quote the approval.

## Not verified

`run_over` (a landing batch's suites) and `ledger_run` take the same path, but have no test of their own here. mason's landing is direct, so `run_over` did not run its suites for mason.
