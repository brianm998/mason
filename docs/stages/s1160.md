# s1160: nodes report their base, and `mason node sync` repairs it

Summary: A node now reports whether it set a job's `origin/<base>`, a failed or missing base is a node failure rather than a red for the task, and `mason node sync` and `mason node show` repair and show node mirrors from the coordinator.

## Cause

A `set_origin_base` error was only printed on the node and the job went on (`node_run.rs`). A base the coordinator could not resolve was left out of the job without a word (`node_exec.rs`). Nothing on the coordinator could look at or repair a node's mirror.

## Change

- The node keeps `base_state` in each job and reports it as `base` in the job's status: `set <name>@<sha>`, `failed: <why>` or `not sent`.
- The coordinator records the base it sent in its run record, and logs when it has none.
- A finished run's text ends `base: set <name>@<sha>` after `ran on node X`.
- A failed or unsent base ends the run as a node failure that names the cause and `mason node sync`. The job is cancelled. A check or suite goes to the next place; a check's result names the failure. A nodes-only project gets "no result (infrastructure)" and is retried.
- `mason node sync NAME --project P [--base B]` (`POST /nodes/sync`; node routes `PUT /node/mirror/{project}` and `POST /node/mirror/{project}/base`).
- `mason node show NAME` (`POST /nodes/show`; node route `GET /node/mirrors`).
- `docs/nodes.md`: "A node's git state".

## Tests

- `node_run`: a base the mirror cannot set is reported in the job's status.
- `node_exec`: an unresolved base is recorded as `not sent`; which states are node failures.
- `tests/nodes.rs`: two daemons on loopback; a deleted `origin/main` with a leftover lock file fails the run as a node failure, `mason node sync` restores the ref once the lock is gone, `mason node show` lists it.
- Exit script: `scripts/exit/s1160.sh`.

## Not verified

- Nothing was run against a real second Mac (Marmot) or a real network.
- A job re-sets a merely deleted ref by itself, so the failing case is provoked with a leftover `.lock` file. What made the ref missing on trd (#1187) is not known.
- A test step's suite that falls back from a node to this machine names the failure in the daemon log only, not in its result text: that is in `suites.rs`, a protected file, left unchanged.
- `mason node sync` of a very large history against the command line's 120 s wait.
