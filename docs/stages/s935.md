# s935: a src/ change selects the crate's unit tests by module

Summary: see decision 0928. A change under a crate's `src/` ran the crate's lib and bins whole (about 632 tests for mason-daemon); the per-task step now runs only the changed module's unit tests and its referrers'.

## Built
- `affected.rs`: `unit_filters` finds the changed module (`src/foo/bar.rs` is `foo::bar::`) and every other module whose text names it (word scan, declaration and `use` lines stripped; names a `use` line in `lib.rs` or a `mod.rs` brings out of it count too).
- `Group` gains `unit_modules`, `unit_lib`, `unit_bins`; `render` emits `-p pkg --lib --bins -- covmap:: affected::` as a group of its own, apart from any `it` module filter.
- Whole lib, as before: `lib.rs`, `main.rs`, `src/bin/`, a declaration-only `mod.rs`, `macro_export`, a glob re-export, a crate root or binary with unit tests that names the module, `build.rs`, or a pick of more than half the lib's modules.
- The note reads `mason-daemon lib: 3 of 97 modules, by name scan`.
- Doc tests unchanged.

## Trust
Only `affected.rs` changed (not protected); `suites.rs` untouched. Only the per-task step narrows; the landing batch and the scheduled full test still run everything.

## Not verified
- The unit tests were run only through `run_check`; no real daemon task branch was narrowed.
- The scan is by word, so a module reached only through a name the scan cannot see (a macro-generated path, `include!`) would be missed in a per-task step; the landing batch still runs it.
