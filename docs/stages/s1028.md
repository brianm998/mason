# s1028: conformance capture waits for the daemon's seq

Summary: The Compose and Swift conformance tools now read the daemon's seq from GET /status before each capture and wait for the model to reach it, as the Rust capturer does.

## Cause

`CI/monitor-compose-macos` was red (run 45005421555): the Compose dump showed views from later steps than the expected dump. Compose settle only waited for 1.5 s of quiet and the Swift one for 300 ms, so a slow runner could capture at the wrong point.

## Change

`settle` in `Tool.kt` and `Tool.swift` asks `/status` for the seq, waits until `lastSeq` reaches it (60 s hard limit fails), with the 1.5 s quiet fallback.

If red persists, the next suspect is how the Compose model applies view removals.
