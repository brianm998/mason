# s455: CI builds the iOS app for the simulator when clients/swift changes

Summary: A new `iOS` workflow (`monitor-ios`, macos-15, 25 min) runs `make ios` on pull requests and develop pushes that touch `clients/swift/**`, cancelling superseded runs.

The job lives in `.github/workflows/ios.yml`, not `ci.yml`, because a path filter applies to a whole workflow and `ci.yml` must run on every change. Concurrency group `ios-${{ github.ref }}` with `cancel-in-progress`. Setup (Xcode pin to `/Applications/Xcode_16.4.app` with `xcode-select`, XcodeGen install and cache, SwiftPM `.build` cache keyed on `Package.resolved`) is the composite action `.github/actions/ios-setup`, which the TestFlight task can reuse.

Trust: `.github/**` is protected; the diff waits for the owner.

**Not verified.** The workflow was not executed (it can only run on GitHub), so the job has not been seen green. Whether Xcode 16.4 is on the macos-15 image, and whether the cached XcodeGen copy (binary plus share/) works after restore, are from the image's documentation and were not tested. The Package.resolved cache only helps if the build resolves into `clients/swift/.build`; the Xcode build uses `ios/build` for derived data.
