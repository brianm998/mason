# s212: a daemon restart's lost hosts are not the task's failure

Summary: A step host lost at a daemon restart is recorded but no longer counts toward an agent step's two restarts, and the launch-agent example sets `AbandonProcessGroup`; adopting a running landing batch at startup (step 3) is not done and waits for the owner.

**Done.**
- Step 2: the daemon appends its start time to `<data>/daemon-starts` (`hostloss::note_daemon_start`). `settle_all` (jobs.rs) does not count a lost invocation toward `MAX_AGENT_RESTARTS` when its last heartbeat (or, with none, the time it was seen gone) is within the 120 s before a daemon start (`hostloss::is_restart_loss`). Several hosts lost at one start are all judged against the same start: one event. A host lost mid-run still counts. The loss is still recorded and shown.
- Step 1: `docs/examples/com.example.mason-daemon.plist` carries `AbandonProcessGroup = true`. `mason service install` (#230) does not exist on this base, so nothing there was changed; it must write the same key.

**Owner's one-line plist change** (`~/.config/mason/com.brianm998.mason.plist`): add `<key>AbandonProcessGroup</key><true/>` to the top-level dict, then `launchctl bootout` and `bootstrap` it. I did not touch the installed agent.

**Not done: step 3** (adopting an unfinished batch at startup, cancelling the abandoned run). `landing.rs` and the store's `abandon_batches` path are PROTECTED; it waits for the owner.
