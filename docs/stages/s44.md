# s44: the self-hosting weekly cap counts only work MASON starts for itself

Summary: `per_week` in `[self]` counts agent and outside tasks only; the owner's own filings and tasks cancelled before any step started are not counted, and `mason self` shows the split.

Task #10. The cap guards a loop where MASON files work for itself; it was throttling the owner's own backlog (an import of their issues was refused at "10 self-tasks were filed this week").

## Built
- `selfguard::count` (pure): of the tasks enqueued in the last week, trust `Owner` and tasks cancelled with no attempts are "yours" (not counted); the rest count. `Usage { status, yours }`, `usage()`; `status()` and `check()` keep their signatures and strict meaning.
- `check_as` / `check_filing_as`: the week limit does not apply to `Owner` trust; cooldown, `max_open` and `max_steps` always do.
- HTTP `POST /tasks` (files as Owner) and the tracker import (Owner if the author is an owner name, else Outside) use `check_filing_as`. `GET /self` adds `yours_not_counted`; `blocked` is what the owner would meet.
- Refusal: "N self-tasks were filed this week and the limit is L: N of the T are agent or outside tasks, which count; Y of yours do not".
- `mason self`: "N of L this week (M of yours not counted)". No monitor reads `/self`, so no monitor changed.

## Tests
Unit tests in `selfguard.rs` (count; refusal at 10 counted; other limits still stop the owner). Integration tests in `crates/daemon/tests/selfguard.rs` (flood of agent/outside proposals refused while the owner files; cancel-before-start frees a slot; max_open and cooldown still stop the owner). Existing tests unchanged. Exit test: `bash scripts/exit/s44.sh`.
