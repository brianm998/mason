# s670: the restart token test no longer ends its step on a fixed sleep

Summary: The restart-in-the-middle token test now holds its step on a release file that the test writes once the restarted daemon shows (4, 50), instead of a fixed 9 s sleep that a loaded runner could overrun.

**Cause.** `slow_develop` ended the step after `sleep_ms 9000`, while the test slept `PERSIST_MS + 1500` and then killed and restarted the daemon. On a loaded runner the step could land during that wait, and "the restarted daemon never showed the tokens" fired. This is the likely cause of the s486 failure in CI; its output was not in the log tail.

**s299.** Not reproduced: `scripts/check-spdx.sh` passes on this tree. The CI output for s299 was not available, so its cause is not established; the full s299 run was not made here.

**Fix.** The test uses `gated_develop` with a release file under the temp dir and writes it after the restarted daemon has shown the tokens. No timing assertion was added.
