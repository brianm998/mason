# s1070: runner units go landing, check, test step, debt; debts capped at `debt_units`

Summary: GitHub runner units (`gha`, `gha-macos`) are granted landing first, then agents' checks, then test steps, then debt payments (urgent first, then the longest wait), and debt payments together hold at most `[remote_runs] debt_units` (default 4) units.

## Cause

`gha` waiters used the local slots' rank (a test step before a check, a debt like a test step in its band by age) and nothing limited debts' share of the pool.

## Change

- `Rank::check()`, `Rank::runner_kind()` and `Rank::for_runners()` (crates/scheduler/src/rank.rs). `plan()` orders a request that asks only for runner units (`is_runner_request`) with `for_runners`; aging lifts only within a kind. Everything else keeps the old rule, so local slots still put a test step before a check (s262).
- `jobs.rs`: a `run_check`'s request is marked `.check()`.
- Debts already ranked in their own band below all task work (`Rank::debt`), for local slots too; unchanged and now tested.
- `debt_units`: `[remote_runs] debt_units`. A debt also asks the `gha-debt` pool (size `debt_units`) for its `gha` units, so debts together never hold more. `pay_with` caps a debt suite's `shards` at `debt_units` before the shard lists are made.
- `Wait.runs_ahead` and the wait text name the kinds ahead.
- After merging #820 and the dead-end fix: `Giver::shrink` and `Giver::ask_again` move a debt's `gha-debt` share with its `gha` units (sched.rs). Without it a debt that gave its units back kept the cap, never read as given back (`regain` skipped the rerun), and a rerun asked without the cap. A rerun keeps its kind rank and its first wait start (tests in sched.rs).

## Not verified

`mason resources` (crates/cli) lists `gha-debt` as another pool and has no per-kind line of its own; the wait texts carry the kinds. Only the scheduler tests and the unit tests were run (on GitHub via `run_check`); no live GitHub run.
