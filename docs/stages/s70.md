# s70: Test, command, script and plugin steps report real progress

Summary: Test steps count passed tests as the output arrives (against the last green run's count, else the suite's minimum), suites and script steps can append JSON progress lines (`progress`, `MASON_PROGRESS_FILE`), plugins on protocol 2 send `step.progress`, and approval steps say what they wait on.

Task #41, the third of four on live step progress (after s45/s49). It feeds the record that s45 built; showing it is ticket 4.

## What was built

- **Live test counts** (`crates/testing/src/live.rs`, `parse.rs`): `LiveCount` cuts output into lines and counts passed, failed and skipped with the per-line functions the full parse now shares. TAP, nextest, pytest, xctest, Swift Testing, Gradle and regex. The verdict is still the full parse.
- **Daemon** (`suites.rs`): one sub-count per selected suite (`tests`, done = passed, total = last green count for this base as `expected`, else `min_tests` as `minimum`); the step's count is their sum. The count is rebuilt from the log after a restart. A suite's `progress` file is tailed (`progress.rs` `FileTail`). The store keeps `suite_green` (migration 20).
- **Script steps** (`jobs.rs`): `MASON_PROGRESS_FILE`, same format. Approval steps set the message "waiting for the owner".
- **Plugins**: protocol 2, `step.progress` notification; protocol 1 plugins keep working. The conformance kit checks a plugin's notifications; the example plugin (`docs/examples/plugins/migration-check`) sends them.
- **Protocol**: `SOURCE_EXPECTED`, `SOURCE_MINIMUM`; Swift regenerated.
- Docs: `docs/step-progress.md`, `docs/plugin-protocol.md`; decision 0055.
