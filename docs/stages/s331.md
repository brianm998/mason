# s331: installer offers a `mason()` shell function

Summary: `scripts/install.sh` can, on an explicit yes or `--profile`, add a marked `mason()` function to the login shell's profile that runs the daemon's current runtime.

**What.** `--profile`/`--no-profile`, a `[Y/n]` question when stdin is a terminal, profile file by `$SHELL`, block replaced in place. See docs/install.md and decision 0325. `scripts/exit/s331.sh` runs it in a temp HOME against a fake release.

**Not verified.** `mason init` and `mason doctor` were not changed (the install script is the only place). The prompt was exercised only through `MASON_INSTALL_PROMPT=1` with piped input, not a real terminal. Under `curl | bash` stdin is the pipe, so the question is not asked there; use `--profile`. zsh was checked only for file choice, not by running zsh. Linux paths were not run on Linux.
