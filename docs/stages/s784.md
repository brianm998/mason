# s784: the base's own cargo-workspace red in batch #491

Summary: Batch #491's three base reds are traced to their panics; `mason remote <word>` now rejects an unknown subcommand before it needs masond, and the unmapped-file test ignores the three files a remote run's snapshot adds; the third red (landing_yield) is not established.

Source: the batch's stored logs, `t/batches/491/b491-r1-bis2-2-n-cargo-workspace.log` (the alone
run; the same three panics are in `b491-r1-0-u-cargo-workspace.log`), base `56b70881`. The
daemon's `batch_runs` row names the same three tests as "still red on its own".

Causes and fixes:

- (3) `crates/cli/src/main.rs` found the daemon (`client::find`, line 583) before it rejected an
  unknown `remote` word (line 673 on origin/develop), so on a runner with no masond the error
  was "masond is not running". It passed on the owner's Mac only because a daemon was up. The
  word is now checked before the daemon is looked for.
- (2) `crates/daemon/src/remote.rs:517,530` (and `run.json`) put three files into the snapshot
  commit a remote run tests; `git ls-files` there lists them and no `[impact]` glob maps them.
  `unmapped_report` now leaves them out, as it already did `.mason/mason.toml`. No glob was added,
  because that would have made a run-only file select suites.
- (1) Not established. On GitHub it failed five times in the full run (always `left: 2`), but
  alone it passed twice, and once it timed out after 900 s waiting for the first run to start. A
  second red run before the batch yields could come from the suite's immediate rerun of its
  failing tests (`suites.rs` `rerun_failing`, whole suite when it has no `rerun` template), but
  that does not explain the passes. The test now prints the working directory and pid of each red
  run (`reds` file) in its failure message, so the next failure says which runs there were. What
  would settle it: that listing from a failing run, or the daemon log of the test's scratch world.
  No ignore, skip, quarantine or weakened assertion was added.

Run: fmt and the three tests through `run_check` on GitHub (2 and 3 green; 1 green alone twice
and red once as above). cargo test was not run locally.
