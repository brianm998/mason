# Stage 122: start image until the daemon answers

Summary: Both desktop monitors and the phone show the start image with the real connection status (looking for the daemon, connecting, reconnecting) until the first header arrives, and never again after it.

**What changed.** `RootView` (Swift and Compose) and `PhoneRootView` show a start view while `model.header == nil`. The header is never cleared, so later disconnects use the existing banners. The image is `brand/start_image.png`, shown whole (fit, no crop), decorative (`accessibilityHidden(true)` / `contentDescription = null`), at most `mascot_start_width` (new token, 480) times the text zoom. The status line is "Looking for the daemon…" (not yet connected, no failed attempt), "Connecting…" (welcome received, no header yet) or the existing "Daemon restarting, reconnecting…". No progress bar, no minimum display time. The phone fits the image to the screen width on a plain deep-blue ground. `Mascot.brand(id)` loads brand images in both clients; unknown ids give nothing. `clients/features.toml` gains `mascot-start-image` as done in both. `Items.swift` / `Items.kt` are untouched.
