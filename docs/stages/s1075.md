# s1075: the macOS exit-script fallback no longer hangs on its watcher

Summary: The exit-script runner's no-timeout(1) fallback now kills the script's process group and leaves no watcher holding the output pipe, and exit-scripts-macos gets a 90-minute job limit.

## Cause

On macOS the fallback watcher `( sleep N; ... ) &` inherited the pipe into `tee`. Killing the subshell left its `sleep` running, so tee never saw EOF and the shard sat until the 60-minute job limit (CI/exit-scripts-macos (3), run 45361042086).

## Change

See docs/decisions/1064-exit-watcher-pipe.md. Trust files: scripts/run-exit-scripts.sh, scripts/exit/**, .github/workflows/ci.yml need owner approval.

scripts/test-shard.py added `--doc` to every shard run, so a narrowed run (`-p x --test y`) failed with "can't mix --doc with other target selecting options". It now runs doc tests only when no target is selected, and a `--doc` selection runs only them.

## Tests

scripts/exit/s1075.sh forces the fallback with MASON_EXIT_FALLBACK=1; hang guard only, no timing assertion.

scripts/exit/s101.sh was already stale: commit 24398fbd5 raised the exit-number ceiling from 999 to 9999, but the script still started at 960, so no warning appeared. It now starts at 9960 and asserts the same 39 left, highest and ceiling.
