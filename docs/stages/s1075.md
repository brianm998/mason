# s1075: the macOS exit-script fallback is testable, and narrowed test shards run

Summary: The exit-script runner's no-timeout(1) fallback can now be forced and tested with MASON_EXIT_FALLBACK=1, and a narrowed test shard no longer passes `--doc` beside a target selector.

## Cause

On macOS the fallback watcher `( sleep N; ... ) &` inherited the pipe into `tee`. Killing the subshell left its `sleep` running, so tee never saw EOF and the shard sat until the 60-minute job limit (CI/exit-scripts-macos (3), run 45361042086).

## Change

`develop` fixed the hang while this task was open (decisions 1063, 1065, 1066, 1068) and raised the macOS job to 90 minutes. This task adds the `MASON_EXIT_FALLBACK` test switch and a comment on the job limit; see docs/decisions/1064-exit-watcher-pipe.md.

scripts/test-shard.py added `--doc` to every shard run, so a narrowed run (`-p x --test y`) failed with "can't mix --doc with other target selecting options". It now runs doc tests only when no target is selected, and a `--doc` selection runs only them.

`s729.sh` compared `wc -l` output to `0` as a string, which fails with the BSD `wc` that pads its count; it now compares numbers.

Trust files: scripts/run-exit-scripts.sh, scripts/exit/**, .github/workflows/ci.yml need owner approval.

## Tests

scripts/exit/s1075.sh forces the fallback with MASON_EXIT_FALLBACK=1: a passing script, an over-limit script with a child holding stdout, a killed runner, and the narrowed shard. Hang guard only, no timing assertion.
