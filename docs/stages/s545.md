# s545: Daemon test waits fail at once when they can no longer succeed

Summary: The shared daemon-test wait helpers now give up as soon as the awaited event cannot happen (task settled in another state, scratch daemon exited), keeping the 900 s floor for waits that can still succeed.

See `docs/decisions/0538-test-waits-fail-early.md`.

What changed (`crates/daemon/tests/support/mod.rs`)
- `wait_loop` is the one loop under every wait; `Poll::{Done, Pending, Never(why)}`. Its deadline and pause are injected so its unit tests (`wait_tests`) use a fake clock and assert on poll counts and messages, not elapsed time.
- `wait_for` keeps its signature and the 900 s floor. New: `wait_poll` (condition may return `Never`), `wait_for_exact` (no floor), `wait_state_settled(d, t, want, secs, settled)` with a caller-declared settled predicate. `wait_state` is `wait_state_settled` with none: it fails at once on any other terminal state, "task 3 reached Landed while waiting for Failed".
- Every wait checks, about once a second, whether a scratch daemon (`Masond`) this test thread started has exited and is still unreaped (a crash or panic; a test that stops a daemon reaps it). It fails with "the test daemon (pid N) exited while waiting" naming the wait.
- `update_release.rs` private `wait_for` now calls `wait_for_exact` (still 120 s, 200 ms) so it gets the daemon-exit exit.
- `tests/early_exit_demo.rs`: a deliberately failing scenario, off unless `MASON_EARLY_EXIT_DEMO=1`; `scripts/exit/s545.sh` runs it and checks the message.

Waits by timeout count (24 h to 2026-11-17 07:45, 33 of 194 runs) and what covers each now
- "the second outside failure" (10), "both to go back" (9), "the base-red wait" (8), "it to land after the rerun" (8), "both to wait" (8), "the approval wait" (7): plain `wait_for` closures. Covered only if the scratch daemon died (the in-process `Daemon` tests have no process to exit). Not covered otherwise: they need a `wait_poll` / `wait_state_settled` with a per-test "can no longer happen" predicate, which was not added to the roughly 509 call sites.
- "task N to reach Failed" (6): `wait_state`: covered when the task is in another terminal state (it already panicked on that before; the message now says "reached X while waiting for Y"). Not covered when the task is parked in a non-terminal state (held, waiting for the owner): that needs the `settled` predicate at the call site.

Not verified: that the sampled red runs would now fail early (no call site was converted to `settled`); daemon-exit detection uses `ps` and so cannot tell a crash from a signal the test sent and has not yet reaped; clippy and the full `cargo test --workspace` were not run by me. #466 and #473 were not merged here.
Exit test: `bash scripts/exit/s545.sh`.
