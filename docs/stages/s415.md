# s415: the dropped-line audit keeps a line the task moved to another file

Summary: when a task's merge with the base resolves a conflict, the audit (decision 0117) checks that every line the base landed is still in the result. It looked only in the file the base added the line to. Now a line missing from that file is also kept when it is, trimmed, a whole line of another file the task changed beyond that base commit. That covers a line moved during a file split.

## Why

Star #417 splits `gui/starTests/starTests.swift` into one file per test class. While it was in flight, other tasks landed new test classes in that file. Each time it merged them, the agent moved the new class into its own file, as the task asks. The audit called those lines dropped, sent the task back three rounds running, and failed it on 2026-11-14. All 11 lines of the last merge were in the branch, in `gui/starTests/NewestCompleteFrameTests.swift`.

## What changed

- `crates/landing/src/audit.rs`:
  - `unkept_or_moved` takes the texts of the files the task changed.
  - `unkept` calls it with none.
  - `audit` gathers those texts from `base..result`.
- Tests:
  - `a_moved_line_must_be_whole_and_in_another_file` (unit).
  - `a_line_the_task_moved_to_a_file_it_split_off_is_kept` and `a_dropped_line_found_only_in_a_file_the_task_did_not_change_is_still_dropped` (`crates/landing/tests/audit.rs`).

## Not loosened

A move must match a whole line exactly, after trimming. The token-window match is not applied in other files. Only files the task's side changed are searched, so the same text sitting in an untouched file does not hide a drop.
