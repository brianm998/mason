# s760: runner-pool holds of finished or orphaned GitHub runs (#787)

Summary: Runs adopted from before a restart are checked against GitHub: finished ones free their runner units and lose their ref, and checks nobody can collect are cancelled.

After a takeover the broker adopts every hold whose record has not ended, and nothing ended the
records of runs GitHub had finished or whose task had moved on, so the pool filled with ghosts.

- `remote::reap_hold` asks GitHub (by run id, else head SHA) about an adopted run. Completed:
  its ref is deleted, its record is marked `released` (the broker counts that as ended, so the
  units are given back) and the hold file goes. A cancelled run's record is removed. A run still
  going, or one GitHub cannot be asked about, is kept.
- A released record stays attachable: `execute` clears `released` and collects the result from
  GitHub as before, so a re-sent call does not lose it.
- `remote::unwanted` picks adopted runs nobody can collect: a check (`tNrR-check-...N`) whose
  task's open run is another or none, a check superseded by a higher number of the same prefix,
  a `task N` step run of a task with no open run. `remote::cancel_hold` cancels them, deletes the
  ref and ends the record and hold.
- `remote::reap_adopted` runs both, off-thread, from the compile-watch loop beside
  `hostedcheck::stop_unwanted`: at start and every `hung::EVERY` after.

Not done / not verified: `mason resources` does not show the GitHub state beside each adopted
hold; live (non-adopted) runs of a task that lands are still stopped by their own thread's stop
check as before, and a newer check does not cancel an older one this daemon is still collecting;
debt runs are only freed by GitHub state, not when the debt is closed. Nothing ran against real
GitHub, and the tests were not run here (testing was skipped for this task); they use the fake.
The machine-level exit check (`gha` in-use matches GitHub) is manual.
