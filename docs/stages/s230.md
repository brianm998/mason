# s230: the known-red ledger

Summary: The quarantine table is now also a ledger of tests seen red at the base: the first sighting adds an entry and files one fix task, a later sighting only refreshes it, the fix task's own step is not excused for its tests, and only a run that executed and passed a test lifts it.

Task #280. Decision 0225.

- `crates/store`: migration 29 adds `source`, `fix_task`, `first_base`, `last_seen_ms`, `note` to `quarantine`; `ledger_seen_red`, `ledger_set_fix`, `ledger_reopen`, `ledger_lift`, `ledger`. `quarantined()` returns only owner entries, so a ledger entry excuses nothing by itself.
- `crates/testing/src/gates.rs`: `is_test_name` (no source lines or prose) and `check_ledger_source`; `check_quarantine` is unchanged for owner entries.
- `crates/daemon/src/basecheck.rs`: `record_red` (entry + one fix task, deduped as before), `own_tests`, `follow_up`; `excuse` records and refuses to excuse a fix task's own tests.
- `crates/daemon/src/suites.rs`: `Baseline` and `Product` with excused base failures record entries; the fix task's own tests are removed from the base list; `after_landing` runs the fix's ledger tests once at the new tip (`ledger_run`): green lifts, red reopens and files a follow-up that links the landed fix; a debt run (`pay`) lifts what passed.
- `GET /quarantine` and `mason quarantine list` show source, fix task, age, last seen; an attention item `known_red` appears when an entry is over 7 days old and its fix task is not moving.
- Tests: store ledger test, `is_test_name` test, the baseline daemon test checks one entry and one fix task. `scripts/exit/s230.sh`.
