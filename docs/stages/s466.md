# s466: the iOS app registers for push, sends its token to the daemon, and opens the task on tap

Summary: The iPhone/iPad app now asks once (with an explanation screen) for notification permission, sends its hex APNs token and sandbox/production env to the daemon it is paired with (re-sending when the token changes, deleting it on Forget or when switched off), opens the task's page when a notification is tapped, and shows a foreground banner only when that item is not already on screen.

## What changed

- `clients/swift/Sources/MonitorCore/Push.swift`: `PushEnv` (compile-time: `DEBUG` is `sandbox`, otherwise `production`), `PushPayload` (the `mason` dictionary to a `Page`: task page for a task id, Home for none or an unknown kind; foreground-banner rule), `PushRegistrar` (explanation once, token send and re-send on change or new pairing, off/on, DELETE, test), `PinnedPushTransport` (pinned HTTPS with the bearer token, tries each daemon name), `PushPrefs`.
- `RemoteSession.unpair()` sends `DELETE /devices/self/push` before clearing the token and pairing when a registrar is set. A revoked token (401) skips the DELETE.
- `ios/MasonIOS/MasonIOSApp.swift`: `AppDelegate` (device token, banner decision, tap to `MonitorModel.go`; the phone's `PhoneNav` follows the model's page), explanation sheet, re-send on each active scene.
- `PairingViews.swift`: Settings has "Notify this device" and "Send a test" (`POST /notify/test` with channel `apns`; the daemon allows owners only, and it sends to every registered device, not just this one).
- Tests: `Tests/MonitorCoreTests/PushTests.swift`. Exit script `scripts/exit/s466.sh` checks the entitlement, the registration call and the test file are in place.

## Not verified

- A real notification on a real phone, and a real token reaching a real daemon over TLS (`PinnedPushTransport` has no test; it is the pinning code of `Pairing.pair` used for another path). Owner check.
- `make ios` and the Swift tests were not run by me directly (builds go through the shared queue); only what `run_check` reported.
- The release entitlement stays `development`; the TestFlight export must set `production` (as the entitlement file already says).
- A "Send a test" from a viewer device is refused by the daemon; the screen shows the daemon's error.
- Nothing runs XCUITests or shows anything on screen.
