# s248: the cargo suite runs its test executables four at a time, and a scoped check takes its own small lane

Summary: `scripts/test-parallel.py` lists the workspace's test executables and runs them side by side (default four), then the serial group, then the doc tests, printing each executable's output as one block in cargo's own format; scoped `run_check` calls take a `test-small` resource instead of `test-suite`.

Decision 0243 records the choices and the spike.

**What changed.**
- `scripts/test-parallel.py`: Python 3 standard library only, run as `python3 -I`. It builds with `--no-run --message-format=json`, runs each executable in its package directory with `CARGO_MANIFEST_DIR` set, prints `     Running <src> (<exe>)` and the executable's whole output as one block, then runs the targets named in `.mason/serial-tests.txt` alone and cargo's `--doc` run last. It prints a one-line summary and exits non-zero if any executable or the doc tests failed, or none was found.
- `.mason/mason.toml` (protected): the `cargo-workspace` suite's `command` and `dev_command` run the runner around `{project_test}`; `build`, `dev_build` and `rerun` are unchanged; `min_tests = 100` is kept. `[resource.test-small] count = 2` is declared.
- `crates/daemon/src/jobs.rs` (protected): `small_lane`. A `run_check` whose suite command was narrowed (`changed`, `tests` or `packages`) takes `test-small` in place of `test-suite` when the definition declares it. Full checks and the test step keep `test-suite`.
- `scripts/exit/s248.sh` (protected): a fixture workspace with a passing test binary, a failing one and a doc test.

**Not verified.** See decision 0243 for what was measured; the test step itself was not run through MASON's pipeline, so the daemon has not yet run the suite with the new command. The `test-small` lane is unit-tested for the choice only; no integration test queues a scoped check behind a full run.
