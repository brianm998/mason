# s248: scoped checks get a small lane, and a runner for parallel test executables exists but is off

Summary: a scoped `run_check` takes a `test-small` resource instead of `test-suite` when the definition declares it, and `scripts/test-parallel.py` can run the cargo suite's test executables side by side, but the suite does not use it.

Decision 0243 records the measurement and the decision.

**What changed.**
- `crates/daemon/src/jobs.rs` (protected): `small_lane`. A `run_check` whose suite command was narrowed (`changed`, `tests` or `packages`) takes `test-small` in place of `test-suite` when the definition declares it. Full checks and the test step keep `test-suite`. Two unit tests.
- `.mason/mason.toml` (protected): `[resource.test-small] count = 2`. The `cargo-workspace` suite's commands are unchanged; a comment says how to point them at the runner.
- `scripts/test-parallel.py`: the runner. It runs the executables N at a time, then the serial group (`.mason/serial-tests.txt`), then the doc tests, with each executable's output as one block under cargo's own header; non-zero exit on any failure.
- `.mason/serial-tests.txt` (protected): the five targets that failed in the 4-way run and passed alone.
- `scripts/exit/s248.sh` (protected): the runner on a fixture workspace with a passing and a failing test binary and a doc test.

**What the measurement said.** The 4-way run took 3191 s against 3204 s sequential, with 12 failures against 1 (decision 0243). The suite therefore stays sequential.

**Not verified.** The runner has not run the real suite under a machine with headroom. `small_lane` is unit tested for the choice only; no integration test queues a scoped check behind a full run. One 4-way run only.
