# s1177: diagnosis card on failed tasks, context field on every decision card (#1046)

Summary: Both monitors lead a failed task's page with the diagnosis card, show "Diagnosing on …" while one runs, offer Diagnose when none exists, mark failed rows "diagnosis ready"/"diagnosing", and every decision card gains an optional "Add context" field sent as `context`.

## Cause

`DecisionCardView` sent a bare option number and had no way to add context; the Failed page put the action buttons first and said nothing about a running or ready diagnosis.

## Change

- Protocol: `Answer.context` (4), `Command.diagnose` (24), `TaskRow.diagnosis` (33), `TaskDetailView.diagnosis_running` (27). The daemon (`ws.rs`, `views.rs`) forwards `context` (omitted when blank), posts `/tasks/{id}/diagnose`, and fills the two views.
- MonitorCore (`DiagnosisCard.swift`) and Compose core (`DiagnosisCard.kt`): `AnswerRequest` (option/Other/multi with context), `FailedPage` (card / diagnosing / buttons), `diagnosingLine`, `diagnosisBadge`.
- Swift UI, Compose desktop and Android: the context field, the Failed page order, the collapsed "Other actions" row, Diagnose, the row badge (not on the Android phone list).
- `monitor-tool answer ... --context TEXT` in both tools.
- `clients/features.toml` (protected): `decision-card-context`, `failed-task-diagnosis`. Owner approval needed.

## Not verified

Tab focus order and Enter/Shift-Enter in the context field were not exercised in a window. Tests run through `run_check` and the exit script.
