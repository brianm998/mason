# s485: APNs provider token cache keyed by the signing key

Summary: APNs provider-token reuse now keys on the signing key as well as key id and team, so the daemon's apns tests no longer verify each other's JWT and the flaky test is unquarantined.

`crates/adapter-api/src/apns.rs` kept one provider token in a process-wide `static CACHE` and reused it for any request with the same key id and team id, whatever the key. The four tests in `crates/daemon/tests/apns.rs` share one key id and team id but each write their own key, so whichever sent first cached its token and the others reused it. `a_push_reaches_owner_devices_with_a_jwt_that_verifies_and_skips_viewers` verifies the signature against its own key, so it failed when another test ran first.

The cache now also compares a SHA-256 digest of the key text (the text itself is not kept). `crates/daemon/tests/apns.rs` is unchanged. A unit test covers two keys with the same kid and team.

Exit test: `scripts/exit/s485.sh`.
