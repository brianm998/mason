# s1159: a coordinator with a long host name can be removed from a node

Summary: a coordinator whose name is over 60 characters goes by its start and a short hash of the whole of it, so a node can find and remove it by that or by the full host name.

## Cause

- `pair` kept only the first 60 characters of the coordinator's name, and `remove_coordinator` matched the full name exactly, so removal answered 404. A GitHub macOS runner with a 62-character host name showed it.
- `a_node_that_goes_away_...` shut the node's listener down once the node counted the job. The coordinator could still be waiting for the reply to its job request, and then failed with "no node had room".

## Change

- `node_serve::coordinator_name` (decision 1148) is used for the name the coordinator sends, and by `add_coordinator` and `remove_coordinator` on the node.
- The goes-away test first waits until the coordinator lists the run as running on node b.
- Tests: two unit tests in `node_serve.rs`, one test in `tests/nodes.rs` that pairs a 62-character name over TLS, and the pairing test now checks the removal's reply.

## Not verified

- No run on a host whose real name is over 60 characters; the tests make up such names.
- The test race was not reproduced; the new wait follows from reading `node_exec::start` and `follow`.
- A coordinator paired before this change under a cut name is removed by the name `mason node coordinators` lists, not by the full host name. Pairing it again stores the new name.
