# s1159: the node-goes-away test waits for the coordinator to follow the job

Summary: the node-goes-away test waits until the coordinator lists the run as running on node b before it stops the node's listener.

## Cause

- `a_node_that_goes_away_...` shut the node's listener down once the node counted the job. The coordinator could still be waiting for the reply to its job request, and then failed with "no node had room".
- The 60-character name half of #1193 landed on develop as 8aec915bd (`coordinator_key`) and is not redone here.

## Change

- The goes-away test first waits until the coordinator's run view shows the run as running on node b.

## Not verified

- The race was not reproduced; the wait follows from reading the code.
