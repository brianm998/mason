# Stage 21: Proposals and self-improvement

Summary: Agents file proposals with duplicate rejection, required evidence and per-task and per-day caps; policy decides proposed or queued, and routing sends each to the project or to MASON. The owner approves, rejects and edits in the CLI and both clients, and the "Improve the pipeline" box runs on a branch (a fork's, without write access) with a redacted, confirm-only upstream publish.

## Built
- `crates/core/src/proposal.rs` (pure): similarity, evidence rule, policy, caps, routing, redaction.
- Migration 15, the `proposals` table and store methods.
- `crates/daemon/src/proposals.rs`: filing from `file_proposal` (called from `jobs.rs`), approve/reject/edit, `GET /proposals`, `POST /proposals/{task}/{approve|reject|edit}`; views carry source, severity, route, evidence and allowed actions.
- `crates/daemon/src/improve.rs`: the improve task, fork branch, channel `branch:<name>`, preview/confirm publish, polling the upstream PR (merged: back to main; rejected or conflicting: carry-the-patch proposal).
- CLI: `mason proposals`, `proposal file|show|approve|reject|edit|publish|poll`, `improve`.
- SwiftUI and Compose: proposal rows and detail with evidence, approve, reject, an edit sheet, and the Improve box; `clients/features.toml` rows.
- `scripts/exit/s21.sh`, decision 0042.

## Exit test
`bash scripts/exit/s21.sh` ends with `s21 OK`. It shows the duplicate and evidence-free refusals, the caps, owner approve/reject/edit, an improvement with fork access running through develop and test and landing on `mason/improve/7` of the fork while main lacks it, the channel `branch:mason/improve/7`, a redacted preview (planted client name, path and function absent), `--confirm` refused before a preview and after publishing, the PR text free of the planted values, and the channel returning to `main` on merge.

## What testing found
- The first redaction left the tail of a client path (`app/Pay.swift`) and a call (`chargeCard()`) in the preview. Redaction now takes the whole path token under a client root and replaces calls with `[code]`; a unit test covers it.
- The script's build command did not quote the binary directory, so it broke in a checkout whose path has a space. It is quoted now.
