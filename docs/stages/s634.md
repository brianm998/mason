# s634: per-test durations for the cargo suite, and a slowest-tests list

Summary: The cargo-workspace suite now runs libtest with `--report-time`, the regex parser reads each test's `<N.NNNs>` time, the store keeps the last 10 times per test, and `mason report` lists the 20 slowest tests with their share of the suite.

**What changed**
- `.mason/mason.toml` (`[suite.cargo-workspace]`, owner approval needed): `command` and `dev_command` run `{project_test} --config 'target."cfg(unix)".runner=["env","RUSTC_BOOTSTRAP=1"]' -- -Z unstable-options --report-time` with `RUSTDOC=scripts/rustdoc-bootstrap.sh`; `pass_regex`/`fail_regex` accept an optional ` <N.NNNs>` suffix. `build`, `dev_build` and `rerun` are as on develop. `min_tests` is kept, and a FAILED line still matches `fail_regex`, so no failure turns into a pass.
- Why the variable is never given to cargo: the first two test rounds of this task ran out of time. `anyhow`, `thiserror` and `proc-macro2` declare `rerun-if-env-changed=RUSTC_BOOTSTRAP` (seen in their fingerprints in the target dir), so each change of the variable reruns their build scripts and recompiles nearly everything that depends on them. With it on cargo (round 1: on the run only; round 2: on build, run and rerun) the suite's commands, the other steps and the in-test `cargo build` of `tests/support::bin()` kept changing it, and recompiles landed inside the timed run. Now only the test executables get the variable (the cargo `runner`) and so does the doc-test harness (`scripts/rustdoc-bootstrap.sh` as `RUSTDOC`). The two `bin()` helpers (`crates/daemon/tests/support`, `crates/adapters/tests/common`) remove it before they call `cargo build`, so no compile ever sees it.
- `crates/testing` (protected, owner approval needed): `Case` gains `ms: Option<u64>`; the regex parser fills it from a trailing `<N.NNNs>`. Lines without a suffix parse as before.
- `crates/store`: table `test_times` (migration 39), `record_test_times`, `slowest_tests`; the median is over the newest `TEST_TIME_RUNS` (10) times of a test.
- `crates/daemon/src/suites.rs`: after a finished run is judged, each case with a time is recorded, whole or narrowed.
- `mason report` / `GET /report`: `slowest_tests` (top 20 by median) printed as "slowest tests".

**Not done / not verified**
- Not run by hand here (the shell sends cargo through the build queue): `scripts/exit/s634.sh` checks, on a scratch crate with a doc test, the exact runner/`RUSTDOC` form and that every result line carries a time and matches `pass_regex`. That the whole-workspace run no longer recompiles was not timed; the fallback in the ticket (a guard in `crates/daemon/tests/support`) was not built.
- "Share of their executable's time" is the share of the sum of the medians of all tests recorded for that suite; the regex lines do not name the executable. Per-executable shares need the light-run lane's store table.
- The monitor's suite page does not show the list yet.
- The flaky-rerun paths do not record times.
