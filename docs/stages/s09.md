# Stage 9: Testing system (completes M2)

## Built
- **`crates/testing` (`mason-testing`, pure)**:
  - **Model:** `Suite`, `Environment`, `When`/`Binding`, `ImpactMap` (globs to suites; an unmapped path runs everything), `Signature`.
  - **Parsers:** JUnit XML, TAP, xctest, Swift Testing, cargo-nextest, pytest, Gradle, Playwright (JSON), Cucumber (JSON) and a regex fallback.
  - **Verdicts:** `judge` (green requires proof), `classify` (environmental, quarantined, flaky, baseline, product, in that order), `closing` (`unproven < unverified < untested < verified`).
  - **Gates:** negative control, assertion-weakening scan, acceptance table, quarantine with owner and expiry, flaky-to-quarantine candidates.
  - **Environments:** the lifecycle as commands for local and Docker Compose.
- **Definition**: `[suite.*]`, `[environment.*]`, `[binding.*]`, `[impact]`, `[signature.*]` and a test step's `suites` and `gates`, with every reference validated.
- **Store (migration 5)**: evidence per tree hash and suite, baselines per merge base (failing tests and every test name), the flaky log, debts, quarantine, closing verdicts.
- **Daemon `suites.rs`**: a test step runs the selected suites; reuses green evidence; brings the environment up and down; runs commands in step hosts (reattachable, with the suite's timeout starting only after its resources are held); parses and judges; classifies a red (rerun, baseline in a throwaway worktree, signatures, quarantine); waits out environmental failures charged to no task; runs the gates; records the closing verdict and the notes that explain it. Force skips work before and during a run. Debts can be paid by running the suite on the base tip, and deferred ones run after landing.
- **CLI**: `mason task skip`, `mason debt list|run`, `mason quarantine list|add|remove`, `mason test parse <parser> <file>`; `mason task show` shows the closing verdict and debts. **HTTP**: `/tasks/{id}/skip`, `/debts`, `/debts/{id}/run`, `/quarantine`.
- `docs/decisions/0006-testing-readings.md`, `scripts/exit/s09.sh`.

## Exit test (M2)
`bash scripts/exit/s09.sh` passes (about 70 s). In a real `masond` with two projects (alpha explores first, beta does not) and a shared `compile` class:
```

alpha #0 (4 steps) started at 1793981868598, beta #1 (3 steps) at 1793981866506
  tests     verified: checks: green, with proof
== 2. a vacuous pass is caught and goes back to development
task #2 ran: develop test develop test land
(it ran 1..0 and exited 0; that is not a pass)
== 3. a flaky failure is classified on rerun
task #3 ran: develop test land
  tests     unverified: checks: passed only on a rerun [checks: flaky, passed on an immediate rerun: flaky_one]
== 4. a baseline failure is excused
  tests     unverified: checks: failures excused (baseline or quarantine) [checks: excused, also failing at the merge base (db27b19b0f): legacy]
== 5. a force skip stops a running suite, keeps the green lane, records a debt
the running suite was stopped and the task landed 1s after the skip
  tests     unverified: checks: green, with proof; slow: skipped by force, a debt was recorded [slow: skipped by force while it ran]
  debt #1 suite:slow open (runs after landing)
#1 task #5 suite:slow             paid (deferred)  not worth two minutes
```
then the testing crate, the definition tables and the daemon testing tests.

### Tests
- **A fixture for every parser, with a green, a red and a vacuous pass for each** (10 parsers, 30 fixtures). Every vacuous pass is a run whose tool exited 0 with nothing failing, and every one is red, even with `min_tests = 0`. A table test fails if a parser has no fixtures.
- Verdict, classification (each class, each order, mixes), closing ranking, every gate, quarantine rules, impact map and bindings, glob matching, environment lifecycle.
- **Definition tables (4 tests, 15 refusals)**: every reference must exist, every mistake is named by key.
- **Daemon end to end (14)**: green with proof and evidence kept; a vacuous pass sent back and then landing (no failure charged); flaky classified on rerun; baseline excused while a new failure is not; impact map selecting nothing (`untested`) and an unmapped path running everything; identical code never testing twice (the suite's own counter shows one run); a force skip stopping a running suite, keeping the green lane, recording a debt that the deferred run then pays; an environmental failure as a wait charged to no task; quarantine; the assertion scan, acceptance and negative-control gates each sending a task back and then passing; a bad definition refused while the old one runs.
- 327 tests across the workspace, all exit scripts s00 to s09 pass.

## What testing found
- **A suite that printed fewer tests than its minimum was a "vacuous pass" in my own first gate test** (min_tests copied from another test): the check caught the author, which is the behaviour wanted.
- My first Swift Testing reader treated "recorded an issue ... Expectation failed" as a failed test; it now requires `passed after` or `failed after`. nextest's `SKIP [        ]` has an empty time field; the reader no longer needs one.
- `echo -n` is not portable between shells: a test fixture of mine wrote "-n" into a file. Test scripts use `printf` and `:`.
- A `$(...)` in an exit script runs in a subshell, so a counter incremented inside it was lost and two tasks got the same mode file. The helper now returns the id in a variable.

## Not done or not run
- **Real tool output.** The fixtures are written from the tools' documented formats, not captured from a run of each real tool (no Swift, Gradle, Playwright or Cucumber toolchains were used). The first real project in Stage 27 will test them; the `mason test parse` command checks a real file against a parser in one step.
- **Docker Compose** is covered by its generated commands, not by running Docker. The environment lifecycle is exercised with local environments.
- **`development`, `batch`, `after_landing` and `schedule` bindings** have no consumers yet (`run_check` is not wired to `development`).
- **No alert system for environmental failures** yet: the wait text and daemon log are all there is. A step waiting out an environmental failure keeps the resources it holds.
- **`gate` steps** still do not run; the gates are options on a test step.
- **Progress sources and artifacts** are declared on a suite and validated, but nothing reads or collects them until the monitor stage.
- A deferred debt run uses the suite as the base's *current* definition names it.
