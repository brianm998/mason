# s123: state icons in tiles, sidebar, Home and phone

Summary: Each ticket's state now shows its mascot icon in the count tiles, the top bar's need-you indicator, sidebar headers and rows, Home stage headings, decision cards and the phone, on both desktop clients.

- `StateIcon` (SwiftUI, `Components.swift`; Compose, `Mascot.kt`) draws a state's icon at the 20 pt token (24 pt when large) times the text zoom (`theme.mascotIconSmall` / `mascotIcon`). It is decorative (`accessibilityHidden(true)` / `contentDescription = null`), untinted, and draws nothing, taking no room, for an unknown state.
- Count tile: an overlay offset outside the top-left corner (Swift `.overlay`, Compose a zero-size layout), so the tile's width does not depend on it; it takes no clicks, and tap / double-click handling is unchanged.
- Top bar: the red circle is replaced by the `needs_attention` icon; the red text stays. Decision-card title gets the same icon.
- Sidebar: icon after the section chevron; on rows it ends the time and cells line, the model text truncates first (time and cells are fixed).
- Home: stage headings carry their state's icon. Phone: 20 pt (Dynamic Type scaled) in tiles and section headers, 24 pt trailing on rows.
- No new tokens: `mascot_icon_small` and `mascot_icon` already exist. `clients/features.toml` only gains `mascot-state-icons` as done in both. `Items.swift` / `Items.kt` are untouched.

Tests: `MonitorUITests/CountTileTests.swift` (new target) checks a tile's width is equal at counts 0, 42 and 999 and unaffected by the icon. Exit test: `scripts/exit/s123.sh` (source check).

Not verified: I could not build or run anything here (builds go through the queue), so the Swift and Kotlin changes, the new width test and the conformance run were not run by me; the Compose tile overlay has no UI test (no Compose UI test setup exists), and nothing was looked at on screen or on a phone, including how a very tight sidebar row looks.
