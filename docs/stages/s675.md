# s675: a killed daemon test no longer leaks its /tmp scratch world and step hosts

Summary: Scratch worlds hold an `owner.lock` flock for life, the orphan sweep stops hosts of and removes roots whose owner is gone (never a held root), and blocking fixture loops end when their test process does.

**Cause.** `Scratch::new` made its root with `tempfile`, whose `Drop` is the only remover, and `sweep_orphans` acted only when the root no longer existed. A test killed by SIGKILL left both the root and the hosts polling for a `release` file for ever.

**Change** (`crates/daemon/tests/support/mod.rs`, `tests/it/`)
- `claim(root)` takes an exclusive non-blocking `flock` on `<root>/owner.lock` and writes the pid after the lock is held; `Scratch` keeps it for its life.
- `sweep_now` lists `/tmp/ms*`: a root is dead when its lock is free with a pid written; hosts and daemons named by `--dir`/`--data-dir` under a dead or deleted root are killed as before (strictly `/tmp/ms*`, never by name), then the root is removed, `owner.lock` last so a cut-short removal is finished by the next sweep. A root with no (or an empty) lock over a day old is removed only when no process's command line names it, and nothing is stopped for it. Held roots, and younger lock-less roots, are never touched.
- The once-per-binary sweep before the first world stops processes synchronously but removes roots on a background thread, so no test waits on deleting thousands of leftover roots (the earlier rounds of this task ran out of the test step's time; the sweep's disk work held every world of the binary behind its `Once`).
- `blocking_loop` builds the fixture `while` loop with `kill -0 <test pid>`; used by `takeover_drain.rs` and `update.rs` (the only two loops).
- Tests in `tests/it/orphans.rs`: killed owner, held root, young lock-less root, loop ends with its test, `scratch_root_of` shapes. Exit script `scripts/exit/s675.sh`.

**Not verified.** I did not run the exit script by hand (it builds and runs two daemon tests). The unit tests passed under `run_check`. I did not prove that the earlier rounds' timeouts came from the sweep's removals rather than machine load; moving them off the critical path is the change I could make. A lock-less root over a day old is removed even if a very old test binary still used it. Non-unix builds only get stubs.
