# s675: a killed daemon test no longer leaks its /tmp scratch world and step hosts

Summary: Scratch worlds hold an `owner.lock` flock for life, the orphan sweep stops hosts of and removes roots whose owner is gone (never a held root), and blocking fixture loops end when their test process does.

**Cause.** `Scratch::new` made its root with `tempfile`, whose `Drop` is the only remover, and `sweep_orphans` acted only when the root no longer existed. A test killed by SIGKILL left both the root and the hosts polling for a `release` file for ever.

**Change** (`crates/daemon/tests/support/mod.rs`, `tests/it/`)
- `claim(root)` takes an exclusive non-blocking `flock` on `<root>/owner.lock` and writes the pid after the lock is held; `Scratch` keeps it for its life.
- `sweep_now` lists `/tmp/ms*`: a root is dead when its lock is free with a pid written, or it has no (or an empty) lock and is over a day old. Held roots, and younger lock-less roots, are never touched. Hosts and daemons named by `--dir`/`--data-dir` under a dead or deleted root are killed as before (strictly `/tmp/ms*`, never by name), then the root is removed.
- `blocking_loop` builds the fixture `while` loop with `kill -0 <test pid>`; used by `takeover_drain.rs` and `update.rs` (the only two loops).
- Tests in `tests/it/orphans.rs`: killed owner, held root, young lock-less root, loop ends with its test, `scratch_root_of` shapes. Exit script `scripts/exit/s675.sh`.

**Not verified.** I did not run the exit script by hand (it builds and runs two daemon tests). The unit tests and a full `run_check` passed. A lock-less root over a day old is removed even if a very old test binary still used it. Non-unix builds only get stubs.
