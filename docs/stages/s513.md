# s513: Rust build outputs and the monitor app are signed

Summary: on Intel Macs the linker now signs every Rust output ad hoc (`.cargo/config.toml`), and the monitor build signs `MASON.app`, so an unsigned Mach-O can no longer crash `syspolicyd` when deleted mid-scan.

## What changed
- `.cargo/config.toml` (new): `[target.x86_64-apple-darwin] rustflags = ["-C","link-arg=-Wl,-adhoc_codesign"]`. A config entry, not an environment variable, so sccache keys do not depend on how cargo is called. Inert on arm64.
- `crates/daemon/src/update.rs`: the swift monitor build runs with `SIGN_APP=1 SIGN_IDENTITY=-`, or `MASON_SIGN_IDENTITY` when set (a Developer ID).
- `scripts/exit/s513.sh`: builds a tiny crate with the config and runs `codesign -v` on it.

## Not verified
- The one-time full rebuild and sccache refill were NOT measured; the rustflags change invalidates every cached Intel artifact once.
- #474 may also write `<worktree>/.cargo/config.toml`; the two must be merged into one file.
- Landing and self-update use the same checkout so they pick the config up; not exercised.
- The monitor was not built here, and `codesign --verify --strict` on `MASON.app` was not run.
- The exit script was not run (cargo is blocked in this session's shell; the test step runs it).
