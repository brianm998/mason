# s427: a timeout after a daemon restart still says the step was mostly waiting

Summary: A step's timeout reason now also reads the queue-wait credit kept in the task folder (s417), so a run whose daemon restarted is still classed as waiting, not as a code failure that repeats.

## Why

53 `develop` failures carried the bare reason "the step ran out of time". The in-memory wait total (`WAITS`) is lost on a restart, so `timeout_reason` could not say "mostly waiting" and `FailClass::classify` counted them as code failures.

## What changed

- `crates/daemon/src/jobs.rs`: `timeout_reason` takes the larger of the in-memory total and `deadline-credit-r<run>.txt`.
