# s598: a red Compose CI names its failing test, and the tests stop polling a clock

Summary: scripts/exit/s13.sh no longer hides Gradle's exit status and prints each failing Compose testcase, and the Compose connection tests wait on signals from their fake sockets instead of sleeping against a deadline.

CI/monitor-compose went red at e3c4e085 and the log tail names no test (it is only cache cleanup). The same symptom was met in s572, which lengthened deadlines. The step in s13.sh piped Gradle through `head -5 || true`, so the failing name was lost. Now the status is kept and `FAILED:` lines come from the TEST-*.xml files. The tests that drive a real connection thread (MonitorCoreTest Rig tests, RefusedLinkTest) wait on a shared `Signal` that the fake sockets and discover callback trigger. No assertion changed and Connection.kt is untouched. The failing test itself could not be read from the run (no network here); decision 0591.
