# s709: CI/windows red on develop from verbatim tempdir paths in the github adapter test

Summary: The github adapter test's fake world now strips the Windows `\\?\` verbatim prefix from its canonical tempdir path, so `git clone` of the local remote no longer fails with "hostname contains invalid characters".

**Cause.** `fake_world` (crates/adapters/tests/github.rs) used `std::fs::canonicalize`, which on Windows returns `\\?\C:\...`. Git reads that as scp-style `host:path`. Both `the_fake_host_passes_the_host_kit` and `the_fake_host_merges_what_is_queued_...` call `fake_world`; fakehost.rs clones the same path.

**Change.** A test helper `plain_canonical` removes the prefix when a drive letter follows it; elsewhere it returns the canonical path unchanged. No dependency added; no source file changed.

**Not verified.** No Windows host here; the next CI/windows run is the check. A later Windows-only failure in `checks_of` (sh + `git archive | tar` with a `C:\` path) would be a new finding.
