# s1055: nodes can be found, paired with and polled (multi-machine nodes, phase 1)

Summary: A `masond` with `[node] serve = true` listens for paired coordinators only (mutual TLS, pinned fingerprints, no tokens), a coordinator pairs with it by code and polls whether it takes work, and `mason node ...` and `docs/nodes.md` set it up; no job runs yet.

The node listener (`node_serve.rs`) requires a client certificate and lets `/node/*` through only for a fingerprint in `<data>/node/coordinators.json`; `/node-pair` takes a code. `POST /node/status` carries the coordinator's settings for the node (`[nodes.default]`, `[nodes.<name>]`), which the node keeps in memory and combines across coordinators by the strictest value. Whether the node accepts work is a pure function of readings and settings (`why_not`), table tested. The coordinator side (`nodes.rs`, `node_client.rs`) browses mDNS, reads `[nodes] static`, pairs, and polls every `status_every_s`; the `nodes` store table (a new additive migration) holds the paired nodes. The owner's switch is `node.toml`, off by default, with `node-changes.log`.

Not verified here: mDNS on a real network (only the TXT parsing is tested), the Apple Silicon heat readings (the pressure level from `notifyutil` is added as a source; the Studio has not been looked at), and the LaunchDaemon setup in `docs/nodes.md` on the Studio.
