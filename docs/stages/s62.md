# s62: LLM usage from every adapter in one shape

Summary: Every agent adapter reports usage as one `UsageSnapshot` (limit windows with utilization and reset, overage, whether work is blocked, API spend), read from the stream and never estimated, and the runner keeps the latest one.

## What was built

- `crates/adapter-api/src/usage.rs`: `UsageSnapshot`, `Window` (id, label, length, utilization only when reported, `resets_at`, `ok`/`warning`/`blocked`), `Overage` (not offered, off, disabled with reason, in use, used up), `Blocked` (window, overage used up, account disabled, rate limit, unreported; with `until`), `spend_usd`, `observed_at`, `session_id`, and `UsageModel` per `BillingKind`. `RateLimitInfo` and `AgentEvent::RateLimit` are gone; `AgentEvent::Usage` replaces them. `AgentAdapter::usage_model(billing)` defaults to nothing.
- Claude reads every `unifiedWindows` entry, the overage fields and each window's status; the rules are in `docs/decisions/0043-usage-snapshot-readings.md`. Subscription model: `five_hour` "5-hour", `seven_day` "Weekly", `seven_day_opus` "Weekly (Opus)", with utilization and overage, no spend. API model: no windows, spend.
- Codex: no windows declared. A limit message gives a snapshot with `blocked: Unreported(text)`.
- `StepReport.usage` holds the latest snapshot, stamped with `observed_at` by the runner (replacing `rate_limits`).
- The fake agent has `FakeAction::Usage` and `with_usage_model`.
- Conformance checks usage (see below).

## Exit test

`bash scripts/exit/s62.sh`: `tests/usage.rs` (12 tests), the runner tests that keep the last snapshot, and the conformance suite (the fake and the Claude stand-in pass; two negative tests show the kit catching promised windows never emitted and an invented utilization). Full output: the script ends `s62 OK`.

## What testing found

- The real captures give five_hour 0.23/0.24 and seven_day 0.6 with their resets, overage `Disabled("org_level_disabled")`, not blocked.
- Outcome classification of the existing fixtures is unchanged; the old assertions were kept in the new shape.
- Gate change: the conformance kit gained usage checks (adds checks, loosens none). The Claude harness's usage-limit scenario now replays `synthetic_usage_windows.jsonl` (all three windows) instead of `synthetic_usage_limit.jsonl`, which stays for the parser tests.

## Codex

No `codex` binary is installed on this machine (`which codex` found nothing), so no capture was made and the CLI's version is unknown. Whether recent versions emit a primary/secondary window in `codex exec --json` is **not verified**. The usage model declares no windows and the failure-text path is the only source. If a capture later shows windows, add it as a sanitized fixture, parse it, and list the windows in the model.

## Not verified

- Codex's real output (above).
- Overage `InUse` / `UsedUp` and API billing shapes are synthetic: only the `rejected` / `org_level_disabled` overage and `apiKeySource: none` appear in real captures. The `apiKeySource` value on an API account is an assumption.
- Nothing was run against a live Claude CLI in this stage.
- Nothing yet stores or shows the snapshots (ticket 3).
