# s71: Agent steps report real progress

Summary: Agent steps now show real progress while they run: the counts the agent gives with `report_progress` (pushed at once), its own todo list as "plan steps", and its tool calls with a one-line, redacted description of the latest; one rule picks the figure.

## Built

- **adapter-api:** `AgentEvent::Plan { items }` (`PlanItem { text, status }`, statuses pending, doing, done), `AgentCaps.plan_reports`, `SessionSpec.on_agent_event`. `report_progress` takes an optional `unit`; the contract keeps every accepted report with its counts (`ContractState.reports`) and calls `set_on_progress` when one is accepted, after its lock is released.
- **runner:** `drive` hands each `ToolCall` and `Plan` to `on_agent_event` as it arrives. The runner holds no daemon type.
- **Claude:** `TodoWrite` gives a `Plan` (`in_progress` is doing, `completed` is done); `TodoWrite` is in `--tools` and `--allowedTools`. Tool calls get summaries ("Editing <path>", "Running <command>", "Reading <path>", "Searching for <pattern>", "Running check <name>"). **Codex:** `plan_reports = false`; its tool summaries are shortened the same way.
- **core `progress.rs`:** `agent_report`, `agent_plan`, `agent_tool`, `choose` (the rule, decision 0056), `one_line` (one line, at most 120 characters, secrets blanked).
- **daemon:** `progress_agent`, `progress_agent_report`, `progress_agent_event`; wired in `agent_job`. Agent history is kept under `<step> / tool calls`.
- **Prompts:** one optional line in the three built-in prompts. `prompts/` in the repository holds no default packs, so there was nothing to add there.
- **fake agent:** the scripted Claude stand-in takes `{"todo": [...]}` and `{"tool": {...}}`; `FakeAdapter` has `Plan` and `Tool` actions. `demo.rs` is unchanged: it already seeds todo and sub-count records.
- **Conformance:** scenarios `Plan` (a declared `plan_reports` must emit `Plan`) and `Progress` (counts 1 of 4, 2 of 5 reach the contract unchanged). Claude, Codex (stand-in CLI) and the fake pass.

```
   1 of 4 files, 'reading the files': on the socket 43 ms after the call
   2 of 4 files, 'editing the files': on the socket 40 ms after the call
   plan steps 3 of 7, now: 'Wire the daemon'

```

The step ran against a real `masond` with the scripted stand-in CLI (`fake-claude`); the WebSocket client is `scripts/exit/fixtures/s71/wsclient.py`. The silent agent's last message is "Using submit_change" because `submit_change` is its final tool call.

## What testing found

- The stand-in CLI writes the `tool_use` line before the contract call is made, so the runner sees the `ToolCall` for `report_progress` first. Tool summaries for tools MASON does not know are therefore only "Using <tool>", not their arguments, and a tool summary never replaces a message the agent set.
- No existing log redactor was found to reuse (decision 0056).
