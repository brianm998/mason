# s330: a repeated reminder does not pile up while muted

Summary: only the newest announcement of an alert waits in the queue, and an unmuted monitor is never handed a reminder for an alert it already heard, so unmuting no longer replays every missed reminder round.

## What changed

- `crates/store/src/notify.rs`: `enqueue_announcement` expires earlier untaken announcements of the same alert run (key prefix `alert:<key>:<since>:`). `take_announcements` is a backstop: it hands over at most one row per alert run (the newest) and expires reminder rows for a run that already played once.
- Tests: store `a_later_round_replaces_the_untaken_earlier_one_of_the_same_alert`; daemon `reminders_queued_while_muted_do_not_replay_when_unmuted` and `a_never_heard_alert_plays_at_most_once_after_unmute_however_many_rounds_passed`.

## Not verified

The optional spoken summary ("6 tasks still failed") was not added; the visual alert list still shows everything. The daemon tests use one alert (the pause alert), not six; the per-key logic is the same for each key. Not run against a real monitor.

## Daemon summary

`claim_at` counts the reminder announcements waiting before the take and the ones handed over after it; when two or more were dropped (alerts already heard) it queues and plays one line, "N alerts are still waiting." The earlier note that no summary was added is superseded. The summary is not covered by a test.
