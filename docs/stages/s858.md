# Stage 858: progress-view redraw proved by observation

Summary: The RowRedrawTests progress-view render counts are replaced by a deterministic MonitorCore observation test, so CI/monitor-swift no longer depends on SwiftUI updates inside ImageRenderer.

## Cause
On the current runner image the s811 analysis no longer holds: the run prints `0 progress views`, so the `> 0` progress-view assertions fail: testAProgressPushEvaluatesOnlyItsProgressViews, testBurstForRunningTasksRedrawsOnlyTheirProgressViews, testRecordedStreamEvaluatesRowsInProportionToRowChangingMessages. On the run of this change (GitHub run 44978538415) the progress-view count was 2000, so those assertions did not fail there; the runner differs per run. Three failures remain in DiskSectionTests, unrelated to progress views: testSideBySideAtAWideWidthWithDiskRightOfCpuAtThreeToTwo (DiskSectionTests.swift:108 and :111, colour probes of the rendered CpuDiskRow) and testStackedAtANarrowWidthCpuFirst (:119, `CPU on top at full width`). They are pixel-colour probes of ImageRenderer output and are not changed here.

## Change
The three assertions are removed with comments pointing to decision 0851; the new MonitorCoreTests test replaces them. s858.sh runs both. Green is confirmed only by the next develop CI run (monitor-swift).
