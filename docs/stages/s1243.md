# s1243: exit-scripts checks split on nodes and keep passes between reruns

Summary: an agent's `exit-scripts` check ran out of its 90 minutes off this Mac (88-90 min, 4 to 39 scripts `not run: out of time`) because a node ran the whole selection as one job and kept no passes. Decision: `docs/decisions/1233-exit-scripts-split-on-nodes.md`.

- `crates/daemon/src/node_split.rs` (new): a suite with `shards` that runs a check on a node is one node job per shard (`MASON_SHARD`, `MASON_SHARDS`, the suite's shard command), run by a few workers, merged with `shards::merge`. Also the kept-passes helpers and the out-of-time note.
- `hostedcheck.rs`: `node_check` splits; both it and `remote_check` send the kept passes, keep the new ones, and add the note.
- `node_exec.rs`: `attempt_noting` (the same try, telling when a node has the job).
- `scripts/run-changed-exit-scripts.sh`: with `MASON_EXIT_TREE_KEY` and `MASON_EXIT_PASSES` it skips listed passes and prints `MASON-EXIT-KEY` for each pass.
- Tests: `node_split` unit tests, `exit_runner_budget.rs`, and two in `tests/nodes.rs`.

Not verified: a run on the real marmot node; the real `exit-scripts` suite through a node (the node tests use fake shard commands, the runner script is tested on its own); a node whose status has no `jobs` (width then 1). Nothing was run by me: tests go through run_check.
