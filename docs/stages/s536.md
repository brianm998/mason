# s536: A task waiting for the base-run lock says so

Summary: Taking the one-base-run-at-a-time lock when another task holds it now emits a `WaitStarted` (class `base-run`) naming the holder, what it runs and for how long, and a `WaitEnded` when the lock is ours. Before, the waiter showed "running, no output for N min" with `wait: null`.

See `docs/decisions/0529-base-run-wait-visible.md`.

What changed
- `crates/daemon/src/basecheck.rs`: `BaseRunLock` (replaces the bare `Mutex<()>`) remembers its holder (task, what, since); `take_with` takes two closures so it is testable without a `Ctx`; `take` is the `Ctx` wrapper. The guard clears the holder on drop. A poisoned mutex is still recovered with `into_inner`.
- The three takers use it: `basecheck::excuse`, `suites/base_red.rs` `profile`, `exhausted.rs`. What is held and for how long is unchanged.
- `crates/core/src/entities.rs`: `wait_class` maps "Waiting for the base check" to `base-run`.

Wait text: "Waiting for the base check: #452 is running `cargo-workspace` at 7f5d57d (22 min)"; with no holder recorded, "Waiting for the base check: another task is running one (holder unknown)".

Not verified: a live daemon run (the wait on a real contended base run was not reproduced); the monitors show the wait text as given and no monitor code was changed; the full `cargo test --workspace` was not run.

Exit test: `bash scripts/exit/s536.sh`.
