# s1120: a check given back by a node runs under the slot its task already holds (#1149)

Summary: A check that a node or GitHub gives back now runs under the slots its own lease already holds instead of queueing for a second one, which at low limits deadlocked the local queue; what it still lacks goes ahead of other step starts, and a remaining self-deadlock is raised as an alert and explained in `mason resources`.

## What happened

On 2026-11-25, with `compile 1`, a `run_check` took the compile slot, went to a node, was given back and then asked the broker for another compile slot while still holding the first. 26 tasks waited behind it.

## What changed

- `remote::fallback_lease_under` takes the check's grant. It asks only for what that lease does not hold; when it holds everything, nothing is asked and the run goes on under it.
- What is still asked for while a local slot is held is ranked by `Rank::holding`: after a landing, ahead of all other pipeline work. No CPU, disk, heat or limit gate is skipped.
- `Grant::give_back` keeps a lease that holds no runner units, so a run that was given a local slot and then went to GitHub does not lose it on the way back.
- A check with no suite placement (a project without suites) is now ranked as its task's, found from the run id, not as a run no task owns.
- The scheduler's `self_deadlocks` finds a resource whose every unit is held by leases that each wait for more of it. The daemon logs it once and raises `deadlock:<resource>` (kind `stalled`) with the limit that would unblock it.
- `mason resources` explains such a wait as "Waiting for a slot its own agent holds (#N): compile".

## Not verified

- No live run against a real GitHub or a second Mac. The node in the test is a scratch daemon in the same process, and its job is cancelled to make it give the check back.
- The test does not make GitHub give the check back after the node does; both reach the same line in `hostedcheck::collect`.
- The test calls `hostedcheck::run` with a lease in the grant, as `run_check` does; it does not drive an agent through the `run_check` tool.
- `mason resources` output was checked in the broker's snapshot, not in the CLI's text.
- A landing batch's check and the red-develop watch's check still hold their local lease outside the grant, so a node giving one of those back still asks for a second slot. Filed as a proposal.
