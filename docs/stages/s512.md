# s512: one fix task per test class and base commit

Summary: Reds of one test class on one base commit now file a single fix task naming all of them, and a later red of that class joins it instead of filing another.

On 2026-11-16 five Kotlin reds (MascotTest, TopBarTest) on 12cfa63f83 filed #479-#483, each doing a cold build.
`basecheck::record_red` now groups the tests that need a fix by `class_of` (text before the last `::`, ` > `, `/` or `.`) and files one task per group via `file_group`. The task body carries a `Test class: ... at base ...` line; a later red with the same class and base finds that open task and is pointed at it. Names with no class stay one task each. The CI-watch path files through the same `record_red`.

Not verified: a joining red cannot be added to the task's text (there is no event that edits a task body), so it is only linked through the ledger and the excuse line, not listed in the body. Class detection is a heuristic on the name; formats I did not see in a real log may not split.
