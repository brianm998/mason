# s551: the CI watch never files the same red run twice

Summary: A red job is filed again only for a run newer than the one its last ticket covered (and, if that ticket landed a change, of a commit at or after the landing); landed and closed tasks of the last 7 days count as covering a run they cite, and the held-back reason shows in `mason status` and the monitor banners.

What changed
- `crates/core/src/ci_watch.rs`: `JobState.covered` (newest run a ticket covers) and `landed_ms`; `RunRef.at_ms`; `Ctx.recent` / `Ctx.landed` (tasks over within the lookback, passed in with the clock); the long-red rule skips a job whose `last_red.run <= covered`, or whose run predates the landing of a merged ticket; a recent over task whose body cites the run (or, for a long red with no history, whose title names the job) is recorded as the ticket and nothing is filed; `held_back` / `held_text`.
- `crates/daemon/src/ci_watch.rs`: `recent_tasks` (7-day `LOOKBACK_MS`; state_entered_at is the landing/close time), state encode/decode of the new fields, `held_back` in the view.
- `crates/daemon/src/ci_schedule.rs` (`classify_and_file`): a scheduled run's groups are held when a recent over task cites that run.
- `crates/daemon/src/views.rs` banner and `crates/cli/src/main.rs` status line: "<job> still red on run R; #N covered it; waiting for a newer run".
- `crates/daemon/src/proposals.rs`: agent proposals similar to a task that landed or was canceled in the last 7 days are refused (before, only live and recently rejected ones were).
- Decision: `docs/decisions/0544-ci-watch-one-ticket-per-red-run.md`.

Other auto-filers: "bugs filed by the daemon" (`mason status`, `crates/daemon/src/http.rs:253`) is a count of recorded bug rows, not a task filer, so there is nothing to dedupe. Proposals did not look at landed/closed tasks (`proposals.rs` duplicate loop) and now do.

Item 3 (explore agent "duplicate of #N" / "already_done" closes): the closed task's own body cites the run, and a closed task within the lookback covers that run, so no close text is parsed.

Tests: core unit tests (landed ticket and no new run files nothing over ten passes; newer run after landing files once; newer run of a commit before the landing is held; task citing the run is recorded; no recent task files; gate freeze holds while held back); `crates/daemon/tests/it/ci_watch.rs` (ten passes then a newer run; state lost but closed task cites the run; the view text); `scripts/exit/s551.sh`.

Not verified
- The exit test closes the task (Canceled) rather than landing it; a Landed state needs a whole landing. The merged-landing rule (run created before the landing is held) is covered only by the core test.
- "Commit at or after the landing" is approximated by the run's creation time against the landing time, not git ancestry.
- Title-only matches hold a long red only when the watch has no history (`covered == 0`); a title match alone never blocks a newer run.
- The proposals change and the scheduled-run check have no dedicated test; the monitor shows the reason as a banner, not in a separate panel.
