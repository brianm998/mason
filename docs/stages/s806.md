# s806: A `suites` schedule: a full test that runs every suite whole on the base tip, here or on GitHub, without a CI workflow

Summary: a `kind = "suites"` schedule runs every listed suite (default: the Test step's and the landing tiers') whole on a clean checkout of the base tip through the same per-suite run a debt payment uses (GitHub shards when remote is on, this Mac when off), at `at` / `when_quiet` and only when the tip is not fully tested, as work below every task, recording each green at the commit so debts it covers close, filing a red (naming the range since the last green full test) or a flake (Low), and recording the verdict in `full_tests`.

Task #783. Decision 0799.

## Built

- **Schedule kind** (`schedule.rs`): `suites` joins `KINDS`; it takes `at`, `every`, `when_quiet` (as #782) and `suites = [...]`, and no `workflow`/`ref`/other `ci` keys. `CiSpec` gained `suites`.
- **The run** (`suites.rs`): `run_whole` runs the listed suites on one commit in a clean worktree. Each suite goes through `run_suite` (quarantine, immediate rerun of a red test, judge, executor), like `pay_with`. `hold_below_all` takes the Test step's resources with the lowest rank there is (`gha` units when remote is on), and the daemon's one-payment-at-a-time lock. A green is recorded at the commit by `run_suite` (`suite_green`) and `settle_debts` runs after, so every debt it covers closes (#774). A red is put in `suite_red`. A suite already green at the commit is not run again unless forced.
- **The schedule** (`ci_schedule.rs`): `run_suites` / `suites_as` use #782's triggers, record and `decide_full` (running, nothing on record, tip tested, only no-suite paths changed), write the `full_tests` row, then file: a red suite `Normal` with the failing tests, the suite's note and `range_note` (commits and tasks since the last green full test); a flaky suite `Low`. Open tasks with the same title are not duplicated.
- `mason schedule run <name>` (and `--force`) work as for `ci`; `mason status` and `mason schedule list` show the full-test line for `suites` schedules too.
- **Tests** (no timing assertions): schedule parsing; `crates/daemon/tests/it/suites_schedule.rs`: runs once and a green settles a debt, a quiet trigger on a tested tip runs nothing, a red is recorded and filed with the range, an unknown suite name ends the row, the run waits behind a task for the compile slot, with remote on the run reaches GitHub and holds no compile slot.
- **Exit**: `scripts/exit/s806.sh`.

## Not verified / limits

- Tests ran on GitHub through `run_check`; the exit script was not run by me.
- The flake path (red, green on the rerun, ticket `Low`) has no test of its own: it needs a suite with a `rerun` template.
- With remote on the test only shows that the run reaches GitHub and holds no local slot; the shard count and a real runner were not exercised. The `gha` hold is the same code a debt payment uses.
- A suite whose run is excused (quarantined tests failing) counts as set aside, not red, and records no green; the full test's verdict is then green. A daemon restart mid-run leaves a row that the next run marks cut off.
- `pay_with` was not changed to call `run_whole`; both call `run_suite`. A later cleanup can share the worktree-and-loop part.
- Trust: `crates/daemon/src/suites.rs` is in `PROTECTED` (verdict logic), so this waits for the owner's approval.
