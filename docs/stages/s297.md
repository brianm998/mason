# s297: decision cards can take several answers

Summary: A decision card can set `multi_select`; the owner answers `mason task answer 12 1,3` (or ticks checkboxes in either monitor, Space toggles, Return sends) and the agent gets the chosen labels joined with "; ", with Other unchanged.

## Why

A question that needs several answers (which suites to skip, which files to keep) could not be one card: the protocol's question had no multi-select flag (decision 0018), so agents asked several questions or squeezed choices into Other.

## What changed

- `crates/adapter-api/src/card.rs`: `Card::multi_select` (read by `parse`, kept by `fallback`, written by `to_json` only when true, so old cards and their hashes are unchanged; a non-boolean is a problem) and `Card::pick_many` ("1,3" or "1 3": numbers in card order, out of range, repeated and empty lists refused).
- `crates/adapter-api/src/contract.rs`: the `ask` schema advertises `multi_select`.
- `crates/daemon/src/attention.rs`: on a multi-select card a list of numbers answers with the labels joined by "; "; a bad list is a 400; other text is still "Other: ...".
- `schemas/mason.proto`: `DecisionCard.multi_select = 7` (additive); `views.rs` fills it; the Swift bindings were regenerated with protoc.
- `crates/cli/src/main.rs`: usage and help show `1,3`; a test covers the argument.
- Conformance: a multi-select card also offers `send` to the owner; both clients' `Items` do the same.
- Monitors: `MultiSelection` in `CardInput.swift` / `CardInput.kt`, checkboxes and a send button in `Components.swift` / `Components.kt`, Space and Return keys, a tick list on the phone's task screen. `clients/features.toml` has the new feature.
- Tests: card unit tests, two daemon tests in `tests/attention.rs`, the CLI test, Swift and Kotlin core tests. Exit test: `scripts/exit/s297.sh`.

## Trust

Waiting for the owner: `contract.rs` (ask schema), `clients/features.toml`, `scripts/exit/s297.sh` (new). Nothing is weakened.

## Not verified

- The Swift and Compose code was not built or run here; only the Rust side was.
- The Kotlin bindings come from Wire at build time and were not generated here.
- No monitor was looked at on a screen; the phone card was not rendered.
