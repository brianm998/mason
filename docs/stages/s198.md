# s198: a waiting mason run request is reaped when its process dies

Summary: masond drops a waiting `mason run` request when its process is gone (outside requests now record their pid too), and only after 120 s of silence when no pid is known, so a late poll on a loaded machine no longer costs a caller its place in line.

**Built.**
- `http.rs` `lease_open`: the `--pipeline` branch calls `lease_set_pid`.
- `sched.rs` `Broker::pass`: a waiting lease with a pid is reaped only when `pid_alive` says no; with `pid == 0` after `UNPOLLED_WAITER_REAP` (120 s), logged with `tracing::warn!` (lease, label, silent seconds). The granted branch is unchanged.

**Tests.** Unit tests in `sched.rs` (live pid survives a 600 s gap, exited child reaped, no pid reaped only after 120 s); `tests/lease_pid.rs` for the outside pid.

**Not verified.** The stall itself (a blocked disk under the state lock) was not reproduced.
