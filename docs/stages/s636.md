# Stage 636: kill test waits for the rate-limit window

Summary: The hold-across-a-kill test waits for the stored rate-limit window to pass before asserting the account is "ok".

Cause: the fake agent's rate-limit event stores a snapshot that stays blocked until the reset (HOLD_S after the event). A plain session emits no usage event, so nothing replaces it, and `usage::view` (crates/daemon/src/usage.rs) reports "blocked" until then. The test lifted the hold at now+2 and asserted "ok" as soon as both tasks landed, which fails when landing is fast.

The test was not run in the explore session; it is run by scripts/exit/s636.sh.
