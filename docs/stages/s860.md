# s860: the develop deadline extender counts from the step's launch

Summary: a develop agent that kept committing was never given progress time after a daemon restart, because the extender measured elapsed time from the daemon process's start while the host's limit counts from the step's launch; it now counts from the recorded launch.

## Cause
`run_agent` in `crates/daemon/src/jobs.rs` called `Extender::tick(started.elapsed(), ..)` where `started` is this process's `Instant`. After a restart (the daemon self-updates often) the tick saw a young step, never reached "deadline near", and granted nothing (`+0h00m00s for progress`), while the host killed the agent at launch + budget + credit. Ten tasks failed this way (#659, #655, #751, ...) with 2h49m-style notes below the budget. #799 fixed only the note.

## Built
- The extender thread uses `already + started.elapsed()`, where `already` is the time since the recorded launch minus this process's own elapsed (`launch_elapsed`).
- Decision 0853. Exit script `scripts/exit/s860.sh` runs the deadline unit tests.

## Not verified
- No restart end-to-end; the existing `deadline` and `launch_elapsed` tests were run.
