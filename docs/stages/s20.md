# Stage 20: Second adapters

Stage 19 (d30b93f, "plugins and extensions") is in this branch's history, so nothing here is based on a stale base.

## Built
- **Codex agent adapter** (`crates/adapters/src/codex.rs`, `bin/fake-codex.rs`, `fixtures/codex/`). Runs `codex exec --json` with `-C <worktree>`, `-s read-only|workspace-write` by step, `approval_policy="never"`, `-m`, `model_reasoning_effort`, the MASON MCP bridge as `-c mcp_servers.mason.*`, and the prompt on stdin; resumes with `codex exec … resume <thread> -`. Capabilities: resume, MCP, usage reports. The provider's environment variables are `OPENAI_*` and `CODEX_*`; `OPENAI_BASE_URL` goes through the same loopback guard as Claude's endpoint. `fake-codex` is `fake-claude`'s script format printing Codex events and calling the contract socket.
- **Parser dialects.** `claude::ParseState` carries a `Dialect`; `hosted::attach_as` follows a step host's journal in either. `launch_process` is shared. Claude's behaviour and tests are unchanged.
- **Jenkins** (`jenkins.rs`): trigger a parameterised job with `REF` and `SHA`, follow queue item to build, read `result`. Credential as a header from a reference; optional CSRF crumb.
- **Generic build adapter** (`generic.rs`): a trigger and a status, each a command or a URL. `[ci] kind = "generic"` with `trigger`/`trigger_url`, `status`/`status_url`, optional `token`, `cwd`. `CommandCi` remains, sharing `run_command` and `parse_status`.
- **Plain git** (`plain.rs`) and `kit::plain_host_kit`: a host with no features. `host_kit` is unchanged.
- **Agent profiles with a retry ladder.** Project overlay keys `provider = "claude"|"codex"`, `codex_bin`, `ladder = [weakest, …, strongest]`, `max_retries` (default 1), `sandbox`. `builtin::next_up` picks the rung; `runner::worth_a_stronger_model` says when; `jobs.rs` retries from a fresh session. Empty ladder: nothing changes.
- **Sandboxing** (`sandbox.rs`): `sandbox-exec` profile and `bubblewrap` argv, applied by both agent adapters; `sandbox = "none"|"sandbox-exec"|"bubblewrap"` (default `none`).
- **Daemon wiring**: `config.rs` (agent keys, `jenkins` and `generic` CI kinds), `services.rs`, `jobs.rs` (adapter by provider, models, ladder).
- `scripts/exit/s20.sh`, `docs/decisions/0017-second-adapters-readings.md`.

## What testing found
- The first run of the exit script stalled at landing: `window = "20m"` in `landing.toml` is a batching delay, not a harmless default (Stage 19's script has it because its task waits at an approval step). It was removed from this script; no code changed.
- This environment sets `GIT_ALLOW_PROTOCOL=file`, which made the push over `ssh://` fail with "transport 'ssh' not allowed". The script sets `file:ssh` for the daemon; MASON's landing code is unchanged.
- A step that crashes on its first invocation and is then retried needs a different run key from the first, or `reattach` would find the dead session. The retry uses `<key>u<n>`.
- Worktree commits write into the main repository's `.git`, which a sandbox must allow; that path is added to the sandbox's writable set.

## Not done, and not verified
- **The Codex event format is unverified.** Codex is not installed here; the parser and `fake-codex` were written from the documented shape of `codex exec --json`, and the four fixtures are synthetic. The flags (in particular where `-C`, `-s` and `-c` go relative to `resume`) were not run against a real binary. Nothing here proves it works with the real CLI.
- **Codex suspend and resume are unmeasured**: the Claude spike measured that a session survives a long check; nothing equivalent exists for Codex.
- **No real Jenkins, GitHub, ssh or sshd.** Jenkins is checked against responses written in the shape its JSON API documents. The ssh test goes through git's ssh transport with a shim that runs the command locally; real host keys, agents and sshd were not involved.
- **The sandbox was exercised live only with `sandbox-exec`** (a unit-style run of `sh`, not the whole daemon under it). `bubblewrap` has argv tests only. A daemon run with `sandbox = "sandbox-exec"` was not tried, so a missing write permission for some real agent CLI is possible.
- **Scheduler accounting**: `sched.rs` (protected) still bills agent steps to the LLM account named `claude`, including Codex steps. Not changed.
- `PlainGit` is not selectable as `[host]` (see decision 0017). The `Generic` URL form uses `Curl` in the daemon; it is tested only on recorded responses.
- No test was removed, ignored or loosened and no limit raised.
