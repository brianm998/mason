# s830: remote checks give an answer: shard narrowed runs, retry no-result runs, let a skip end a check (#873)

Summary: a narrowed remote check, test step or debt of more than one test target (or over `shard_over_s`) is split across `shards` runners, the exit scripts are split by `weights.txt`, a run that ended without a result (no runner, refused push, runner limit with no failing test) is retried by MASON itself before the agent hears of it, and a skip of the task's testing ends its waiting or running checks at once.

Requested by the owner on 2026-11-21 (#873).

## Built
- **Sharding a narrowed run.** New suite keys `shard_dev_command` (the `dev_command` template with the shard runner in front of each cargo command) and `shard_over_s` (default 600), parsed in `crates/definition/src/testing_parse.rs`, held in `crates/testing/src/model.rs`. `suites::narrowed_shard` / `decide_narrowed_shard` split a narrowed run of more than one target (or package), or one whose recorded target times are over `shard_over_s`, into the suite's `shards` jobs; with nothing to split it with and a recorded time over the runner limit it says why in the check's lines. The test step (`narrow_packages_for_step`) and the agent's `run_check` (`jobs.rs`) both use it; `run_remote` no longer refuses a narrowed command, and the other narrowings (test units, batch union) set `shards = 0` so they still run on one runner. `hostedcheck::remote_check` shards a suite's own command (whole or narrowed) from its place suite.
- **Exit scripts.** `scripts/run-changed-exit-scripts.sh` reads `MASON_EXIT_SHARD=i/n` and runs its share of the selected scripts, assigned heaviest first onto the lightest by `scripts/exit/weights.txt` (the assignment of `run-exit-scripts.sh`). `exit-scripts` has `shards = 4` and a `shard_command` that passes `MASON_SHARD/MASON_SHARDS`.
- **No result is not a failure.** `remote::run_retrying`: a miss (`remote::no_result`: any environmental failure, or a run cancelled at the runner limit that names no failing test) is retried once on GitHub under a new run id, after a 15 s backoff when the push was refused. After a second miss a project whose effective `fallback` is local runs it here; otherwise `run_check` gets "no result (infrastructure): ...", never "FAILED". Each retry is shown in the check's `current` text and in the result's output. Waiting time is already credited as GitHub time by `remote_credited`.
- **A skip ends in-flight checks.** The agent's check specs carry a `stop` that asks `skip_for` for the suite, step or all of the task's testing. `remote::execute` cancels the GitHub run on it; the local host's stop thread ends a local run; `remote::fallback_lease_until` ends the wait in the local fallback queue. `run_check` then returns the same "Not run: the owner skipped testing" text as a call after the skip.
- Tests: fake-GitHub tests in `remote.rs` (`a_run_nobody_picks_up_...`, `a_refused_push_...`, `a_run_cancelled_at_the_limit_...`, `two_misses_...`, `a_red_run_is_a_result_...`, `a_skip_while_a_run_waits_...`, `a_narrowed_run_of_three_targets_...`), `suites::narrowed_shard_tests`, `fallback_lease::a_skip_ends_the_wait_for_this_machines_slots`, `testing_tables::narrowed_shard_keys_parse`. Exit test `scripts/exit/s830.sh`. Decision 0823.

## Differences from the ticket
- A narrowed run's shard lists are the whole suite's recorded tests, balanced by their recorded times; the daemon does not know which tests a narrowed target holds. Each runner lists its executables and takes its share (a test in no list goes to its hash shard). The lists therefore do not equal "the narrowed set", and `RunSpec.partial_lists` stops a shard that holds none of them being judged red.
- Exit-script shards are assigned on the runner, not by the daemon, because the selection is made from the change's files there.
