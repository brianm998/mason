# s945: a landing configuration that is refused is not retried as an outside failure

Summary: A "landing is not configured" verdict (for example an unknown key in .mason/landing.toml) is now classed as a failure about the code instead of an outside one, so the land step is no longer retried over and over for an error no retry can fix.

**Cause.** `FailClass::classify` (crates/core/src/task.rs) treated every `landing failed: ` reason as Outside, including the `landing is not configured: ...` verdict from `landing.rs`. A refused configuration is refused again each time, so the retries (8 over tasks #771, #772, #804, #834, #875) wasted slots.

**Change.** That one reason is classed Code. Test added in `fail_class_tests`.
