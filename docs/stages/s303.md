# s303: a dropped device lease unlocks explicitly

Summary: `DeviceLease` now calls `unlock` on its flock before closing, so a duplicated or forked copy of the fd can no longer keep a device held after the lease is dropped (fixes the flaky `a_name_glob_from_the_definition_never_leases_pipeline_slot_1`).

## Why

flock belongs to the open file description. When another thread forked while a lease was open, the child kept the description and the re-take after `drop` failed, so `unwrap()` panicked at `targets.rs:332`.

## What changed

- `crates/devices/src/lease.rs`: `Drop` calls `File::unlock`; test `a_dup_of_the_lock_fd_does_not_keep_the_device_after_drop`.
