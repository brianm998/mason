# s1235: retry a develop push the remote rejects transiently

Summary: `promote()` pushes again, after each wait of `network_backoff` (10 s, 30 s, 90 s), when the remote answered `[remote rejected]` with no refusal text and the base has not moved. Batch and direct landing both get it. See decision 1225.

## Cause

`crates/landing/src/promote.rs` pushed once; any error with an unmoved base became `PromoteError::Git` and failed every task of the batch (#1247).

## Change

- `promote()` takes `push_backoff`; `Batch` and `DirectLanding` carry it, and the daemon passes `network_backoff`. The editor passes none (one try).
- The refusal list moved to `mason_landing::promote::refused`; `net::refused` calls it.

## Not verified

Not run against GitHub itself, only against bare repositories with a pre-receive hook. The exit script runs the landing tests, not a full daemon batch.
