# s798: a fast track still builds the change and runs the tests it adds (#812)

Summary: Under `mason task skip --all`, `run_check` and the landing build floor still build the change and run the tests it adds by name (new `#[test]` fns, new exit scripts), and `submit_change` refuses once when the plan names source files and the diff has no source in it.

On 2026-11-21 #803 and #806 landed with only tests and docs: their code edits did not apply, every `run_check` said "Not run: ... Nothing was built or tested", and the floor only proved the (unchanged) tree compiled.

What changed
- `newtests.rs` (new): reads the tests a diff adds (`#[test]`/`#[tokio::test]` fns, `scripts/exit/*.sh`), for the worktree (`in_worktree`, untracked files too) and for a merged range (`in_range`); `planned_sources` reads the source files a plan names under **Change**/**Cause**.
- `jobs.rs`: `run_check` under a skip runs `run_suites(.., light = true)`: each selected suite's `build`, then only the suite's `rerun` with the new test names (`--exact` removed, as a diff gives bare fn names), or the exit-script suite whole when exit scripts were added. fmt and every other test are not run. A skip no longer ends a light check's wait for a slot. The "Not run" text says the result is green or RED and which build and tests ran. `change_validator` takes a `PlannedChange` and refuses a source-free diff once (see below).
- `landing.rs`: `new_tests` runs after a green floor, for the tasks whose testing was skipped only (their footprint files), and on red records the files that add the failing tests in `lint_files` and sets `floor_red`, so the existing by-file blame parks only that task.
- `crates/cli/src/main.rs`: `mason task skip` usage and the `--all` message describe the fast track.

Submit warning: refused once when the plan (task body plus `plan.json`) names at least one source file under **Change** or **Cause** and the diff touches none of them and touches no other source file (tests/, docs/, scripts/ are not source). A `notes` value lets the next submit through; the warning and the note are written to `source-free-note-r<run>.txt` in the task directory and logged as a tracing warning.

Tests: `newtests` unit tests; `a_diff_with_none_of_the_planned_source_files_is_refused_once_and_accepted_with_a_note` (jobs.rs); three `a_fast_tracked_*` tests in `tests/it/suite_builds.rs` (red naming the test, red build, green naming the build and test); `tests/landing_new_tests.rs` (a skipped task with a failing new test is parked, the other lands); exit script `scripts/exit/s798.sh`.

Not verified
- Nothing was compiled or run in the author's shell (local test and check commands are refused there); only `run_check` on GitHub ran it.
- Test names are matched as substrings, so a new test whose name is a substring of another test also runs that one.
- A filter that matches no test exits green; the light check does not require a test to have run.
- The source-free note is kept in a file and the log; nothing in the monitor shows it to the owner yet.
- #785 (narrowed batch tests) had not landed on this branch, so the diff reading is not shared with it.
- Trust: `jobs.rs` (`run_check`, `submit_change` acceptance) and `landing.rs` (the floor) are verdict logic; the owner approved this in chat on 2026-11-21. It checks more, never less.
