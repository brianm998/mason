# s1057: a node that fails, or is turned off, costs no task anything (multi-machine nodes, phase 3)

Summary: Turning a node's switch off lets its running jobs finish and takes no new ones (or, with `on_switch_off = "cancel"` or `mason node stop-jobs`, ends them so the run is placed again), a node that goes away is given up on after `lost_after_polls` and its orphan is killed when its lease runs out, a restarted coordinator takes up the job its record names, and the failure table of the plan is a test for each row.

The coordinator's executor is now `start` (snapshot, bundle, the job started, the record kept) and `follow` (poll, tail, collect, ack); a record from before a restart makes `execute` skip to `follow`, whatever state the node is in now, since a node that has since turned its switch off still has the job. A node that cancels or fails a job is `Fail::Environmental`, so the run goes where a run goes that found no node: here, with the slots a local run holds. `nodes::alerts` says what needs saying (a node that went away, one on another protocol or with another certificate). A run that waited too long for GitHub (`favor-remote`) goes to a node with room before it takes this machine's slots.

Needs the owner: `nodes::alerts` is not yet in the alert table, because `attention::alerts_now` is a protected path that the plan's approved list does not include. The one line is `out.extend(crate::nodes::alerts(d));` beside `crate::ssh_keys::alerts(d)`.

Not verified here: the spill from the GitHub queue to a node end to end (its parts are: the room function and the caller's order), and the node restarting with a job still running under its step host (a restart of the whole daemon was not driven; the same code runs from `Jobs::resume`, and a finished job read back from disk is tested).
