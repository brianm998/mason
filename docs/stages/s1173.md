# s1173: the monitor says why a held queued task waits

Summary: A queued task kept back by the file hold or the check-queue hold now says so in the monitor's `why_waiting` and `activity` (same text as `mason task show`), instead of "Waiting for an LLM session to be free".

`Daemon::queued_wait_text` (file_hold.rs) holds both sentences; `http::task_json` and `views.rs`
(`why_waiting`, `TaskRow.activity`) all use it. The file-hold sentence names the other task and
file and says how long the hold lasts and how long is left. The LLM-session sentence remains only
for a task with no hold. Swift/Compose clients were not inspected here; they show `why_waiting`
and `activity` as given by the daemon as far as the task text says.

Not verified: no end-to-end daemon test of a real file hold (needs git repos); only the sentence
builders are unit-tested. The lapse is given as time left ("ends by itself in 1 h 12 min"), not a
clock time, as the daemon has no local-time formatting. Tests were not run locally.
