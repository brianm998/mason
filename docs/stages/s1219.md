# s1219: test steps past their stuck:wait bound on the gha pool

Summary: Records why develop test steps wait behind landings and checks on the gha pool, and asks the owner whether an over-bound test step should be promoted. No code changes.

## Cause

Runner units are ranked landing, check, test step, debt (`crates/scheduler/src/rank.rs:206-228`, `crates/scheduler/src/plan.rs:626-637`). The aging rule lifts a request only within its own kind; a test at `rank.rs:466-467` asserts that an aged test step still ranks after a check. #1127 was third in line behind one landing run and one check and waited 320 min against a 164 min bound.

Position discrepancy: `build_wait` counts every ranked-ahead request on the same resource (`plan.rs:963`, `sched.rs:1988`), so landings and checks count toward the bound, while depth is per class. Decision 0605 says "in class".

## Change

Docs only. Decision 1209 holds the question.

## Owner question

See decision 1209: (a) keep the order, (b) reserve one unit for the oldest over-bound test step, (c) lift an over-bound test step above checks but not landings. Recommended: (a).
