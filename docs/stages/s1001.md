# s1001: three or more announcements become one spoken summary

Summary: The daemon folds three or more waiting speech announcements into one summary line ("25 mason issues have failed; come have a look."), for both monitors and daemon speech, controlled by `[speech] summarize_from`.

- `summary_sentence` (core/notify.rs): pure; groups by kind, names the project when all agree, lists at most three kinds then "and N others".
- `fold_for_speech` (daemon/notify.rs; a first batch of 20 is extended to 200 only when it folds) used by `claim_at` and `daemon_speech`; delivery recorded on the original rows; the backlog line is skipped when folded.
- Sentences (from the unit tests, not run by me): 25 failures in one project: "25 mason issues have failed; come have a look." Mixed 20 failed, 4 needs_you, 3 approval: "27 mason issues need you: 20 failed, 4 need a decision, 3 waiting for approval; come have a look."
- Trickling alerts (two at a time over several claims) are not folded and I added no settle delay. I did not observe whether a mass failure arrives in one claim; it is queued in one `tick_at` pass by reading.
- Swift and Compose monitors: I did not read them for re-splitting or re-wording.

Alerts carry no project, so the summary never names one in the daemon (the core function does when given one). Not verified locally (the shell refuses cargo); the scoped notify tests passed through `run_check`. The first attempt lacked the daemon half entirely, which is why its exit script failed; s125 failed with `bad revision 'origin/develop'` on the runner, which I could not cause or fix here. The setting is not in the settings UI (`settings.rs`). When the claim's backlog line is skipped because of a fold, the dropped-reminder count is not mentioned.
