# s246: a task is not charged for a red its merge base has too

Summary: a suite whose build fails, whose run proves nothing, or whose red run names no test is compared with the same suite at the merge base; when the base is red the same way the task waits in its test step (wait class `base-red`) instead of being sent back, one urgent task is filed, and the step runs again once the base is green.

Decision 0241 records the choices.

**What changed.**
- `crates/testing/src/basered.rs`: the pure part. `first_error` finds the first error line of an output, `normalise` strips paths, line and column numbers, hex ids and digits, `same_red` says whether the base is red the same way, `title` and `is_title_for` name and find the filed task.
- `crates/store`: migration 29 adds `build_error`, `vacuous`, `red`, `first_error` and `complete` to `baselines`, and a `base_red` table (one row per waiting task). `BaseProfile`, `BaseRedWait` and their methods.
- `crates/daemon/src/suites/base_red.rs` (protected path `crates/daemon/src/suites.rs` owns the module): the suite at the base (build, then run, once per base and suite, cached), the filing with its dedup against open tasks and tracker issues, and the wait loop. `suites.rs` runs the test step in a loop: a cleared wait folds the base in (the step's own `prepare`) and runs it again. A wait recorded in `base_red` is found again after a restart without running the suite.
- `crates/core/src/entities.rs`: the class `base-red`, also read off the text of an old wait.
- `crates/daemon/src/config.rs`, `main.rs`: `base_red_poll` (default 60 s; `--base-red-poll-ms`).
- `crates/daemon/tests/base_red.rs`, `scripts/exit/s246.sh`.

**Not changed on purpose.** A red with named failures that all fail at the base is still excused, as before (decision 0241). The check applies to suites steps that build first (the per-suite lease path, which is what this repository's definition uses); a step whose suites hold one lease for the whole step behaves as before.

**Not verified.** The restart path (a `base_red` row found again) is read, not killed-and-restarted. `mason task show` was not run against a real daemon: the wait text and the excuse note go through the existing wait and `.excused` paths.
