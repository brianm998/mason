# s684: an `[impact]` entry can override broader ones

Summary: an `[impact]` value may be `{ suites = [...], override = true }`, which replaces less specific entries for the paths it matches, so a narrow `= []` finally takes a path out of a broader glob.

Decision 0677 records the choices.

**What changed.**
- `crates/testing/src/model.rs` (protected): `ImpactMap` gains `overrides`; `select` uses only the most specific matching overrides (segments with no wildcard, then literal-prefix length; ties union) and ignores plain entries less specific than them. Plain entries at least as specific still add. Maps with no overrides select exactly as before.
- `crates/definition/src/testing_parse.rs`: parses the table form; `suites` is required and `override` must be a bool. `override = false` is a plain entry.
- `crates/definition/src/validate.rs`: unknown suites in overrides are refused; a plain `= []` that a broader non-empty entry covers warns (not refuses).
- `untouched_by`, `split_for_suite` and the landing callers all call `select`, so they follow without edits.

**Semantics.** For a path: if any override glob matches, take the overrides of highest specificity and the plain entries at least that specific; otherwise the union of plain entries as today. No match at all still selects everything.

**Not verified.** The warning's "broader entry covers it" test is a heuristic (one sample path of the empty glob against the broader glob), so it can miss some overlaps. Star's map is not changed here. No docs/examples file shows an impact map, so the semantics are documented here and in the decision.
