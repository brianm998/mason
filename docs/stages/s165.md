# s165: reruns run only the tests that failed

Summary: When a test command is red and `test_reruns` is set, MASON reads the failing test names (libtest, XCTest, pytest, nextest), reruns only those if `rerun_filter` says how, and calls the step flaky (green, recorded in the `flaky` table) when no test failed in two runs; any test failing in every run keeps it red and is the only one named.

**Built.**
- `crates/daemon/src/rerun.rs` (pure): `failing_names` (libtest `test X ... FAILED`, pytest `FAILED path::name`, plus `mason_testing`'s XCTest, Swift Testing, pytest and nextest parsers, used read-only), `command` (the filtered command), `check_filter`, `ran_them`.
- `rerun_filter` in the project overlay: `"cargo"` appends `-- --exact <names>` (or ` --exact <names>` if the command already has ` -- `); a template with `{tests}` has it replaced by the shell-quoted names. See decision 0160.
- `jobs.rs` `command_job`: after each exit-status red the whole log is read for names; the tests failing in every run so far are kept; empty means flaky and green; names unreadable in the first or a later red means today's behaviour ("red every time").
- Every test that failed in some run but not in all is recorded in the `flaky` table (suite = the step's name, with the task), as the suites path does. `mason health` now lists flaky tests of the last 7 days (it showed none before; `mason digest` showed only a count).
- A filtered rerun that exits green but never prints the names it was given ran nothing, so it proves nothing: the next run is the whole command; on the last run the step is red and says so.

**Tests.** `crates/daemon/tests/e2e.rs`: `a` then `b` failing is green with both in the `flaky` table; `a` failing twice is red and the failure names only `a`; with `rerun_filter` the rerun's arguments are only the failing name. Unit tests in `rerun.rs`. The existing "red every time" test covers red twice with no readable names. No timing assertions.

**Exit test.** `scripts/exit/s165.sh` (both scenarios of the ticket).

**Trust.** This changes a verdict: red twice by exit status becomes flaky when no test failed twice. Any test failing in both runs keeps the step red. It touches no file under `crates/testing/**` and not `suites.rs`; `scripts/exit/**` is protected only for the new script.

**Not verified.**
- A real `cargo test --workspace` rerun with `rerun_filter = "cargo"` was not run; the filter is checked as text only. Doc-test and nextest names may not round-trip through `--exact`; the "ran none" check catches a filter that matched nothing.
- No pre-existing project's `test_reruns` setting was changed (owner configuration).
- The later tickets ("never test the same tree twice", "a red that also fails at the merge base") are not started; the names are in `rerun::failing_names`.
