# s718: s668 no longer inherits the CI job's shard

Summary: s668 clears the inherited MASON_EXIT_* selection variables and pins its own shard, so the exit-scripts job passes on every shard (it failed on shard 5/6).

Cause: `.github/workflows/ci.yml` (exit-scripts job) sets `MASON_EXIT_SHARD=<n>/6` for the runner and every script it starts. `scripts/exit/s668.sh` ran the runner on three fake scripts (default weight, landing on shards 1-3) inheriting shard 5/6, so nothing ran, the runner exited 0 and s668 reported "runner exited 0 with failing scripts".

Change: s668 unsets MASON_EXIT_SHARD, _PLAN, _REPEAT, _DEFAULT_WEIGHT, _WEIGHTS up front and passes MASON_EXIT_SHARD=1/1 on the inner run. No assertion changed. s718.sh runs s668 under the CI environment on shards 5/6, 1/6 and 6/6.

Not verified: s178 and s210 also failed in run 44785902186; the log tail does not show why, and the full job log was not available here. They are not explained by this change.
