# s685: map the paths that ran every suite whole, and list unmapped files

Summary: The `[impact]` table now names `.github`, `packaging`, `scripts`, `.cargo`, `.mason` data files and other paths that used to run every suite whole, `mason definition check` and the daemon's definition load list tracked files no glob matches, and the test notes name the unmapped path.

What changed:
- `.mason/mason.toml` `[impact]` (owner approval needed, protected path). Each choice follows what reads the file: `ci.yml` is read by `crates/conformance/tests/ci_gates.rs`, `templates/**` by the cli tests, `clients/mascot.toml` by the conformance crate, `.cargo/**` and the smoke and serial lists by the cargo suite; the rest (`.github/**`, `packaging/**`, `.gitignore`, `.mason/landing.toml`, `site`, `spikes`, `deny.toml`, `LICENSE*`) is read by no suite.
- `ImpactMap::first_unmapped` and `unmapped_by_dir` (`crates/testing/src/model.rs`).
- `mason definition check` prints `unmapped  <dir>: ...` lines (`crates/cli/src/definition.rs`); the daemon logs a warning per top-level directory at definition load (`crates/daemon/src/defs.rs`).
- The whole-run note is "an unmapped path runs everything (<path>)" (`Sel::why` is a `String` now).

Not done / not verified:
- The project page does not show the unmapped list; only the log and the CLI do.
- `scripts/*.sh` also maps `scripts/install.sh` to `exit-scripts`: globs are a union, so `[]` for that one file cannot subtract it. The cost is the small exit-scripts suite.
- `scripts/package/**` is mapped to swift-clients as the ticket says; nothing was run to check that suite reads them.

Tests: unit tests in `crates/cli/src/definition.rs` (lister on a fixture, real `.mason/mason.toml` selects `Some` for every listed path, no tracked file but the definition is unmapped); `scripts/exit/s685.sh`.
Decision: `docs/decisions/0678-map-unmapped-paths-and-list-the-rest.md`.
