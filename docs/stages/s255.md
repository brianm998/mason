# s255: the digest has the numbers the reviews counted by hand

Summary: `mason digest` (and `--json`) now shows, per project, the p90 beside the median claim-to-land time, send-backs per landed task by reason class, retries by failure class (by hand and automatic), the test step's run times, and says "not recorded" for what the store does not hold.

Decision 0250 records what is and is not recorded.

**What changed.**
- `crates/core/src/introspect.rs`: `p90` (nearest rank) and `send_back_class` (`test_red`, `build_red`, `conflict`, `weakening`, `other`, from the reason a `SentBack` event records), with unit tests.
- `crates/daemon/src/introspect.rs`: the event replay also notes send-backs by class, retries by the task's failure class and whether the daemon made them (`Retried.auto`, s247), and how long each test-step run took (its start to the event that ended it). `digest` adds `per_project`, built by `per_project_numbers`; a red the base has too is counted from the `base-red` waits (s246), since it sends nothing back. A unit test feeds a synthetic event list.
- `crates/cli/src/main.rs`: `mason digest` prints a "By project" block; the JSON carries the same numbers.

**Not recorded, and said so in the output.** The run time of each suite, how long `run_check` calls took, and how many `run_check` calls a task made: none is stored in the database or the event log (suite timings exist only inside step logs). The test step's whole run time is recorded and is shown instead.

**Not run.** The unit tests, the exit script `s255.sh` and the `mason digest` command were not run (the owner asked for building and linting only). The code compiles and is clippy-clean.
