# s231: a timed-out fetch no longer fails the develop step when there is no last-known base

Summary: When `git fetch --prune` times out and the project has no remote-tracking base ref yet, `prepare` now waits the failure out (retrying the fetch with backoff, nothing charged to the task) instead of failing the step.

**Cause.** `prepare` in `crates/daemon/src/jobs.rs` returned an error when the fetch failed and `origin/develop` did not exist locally. A 300 s fetch timeout is the network's, not the task's, yet it failed tasks #241, #253 and #198 with one signature.

**Change.** A timed-out fetch with no last-known base goes through `wait_out_environment` (up to 15 minutes, retrying `fetch_remote`). Other fetch errors still fail at once.
