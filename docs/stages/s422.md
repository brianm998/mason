# s422: a develop agent's `run_check` may run while the machine drains

Summary: s385 lets work with an expected run time take a slot while the machine drains for an exclusive request, if that work will be done before the holders are. A develop agent's `run_check` queued with no expected time, so it never qualified. Now each suite build and run a check queues for carries that suite's estimate from the test step's recorded times (`suite_estimate`, phases `build` and `run`). A check's build is incremental, so the estimate errs long. The one-command path, with no suite, still carries none.

## Why

At 07:55 on 2026-11-15 the owner saw the CPU mostly idle with many MASON tasks unfinished. All 6 compile slots were free while about 20 develop agents waited for one:
- Star #417's `test-gui` was first in line for the whole machine.
- Four MASON test steps held `test-suite`. Their end was known: `cargo-workspace` runs up to 29 minutes.
- A MASON `run_check` build takes up to 5 minutes and would have fit, but without an expected time backfill could not admit it.

## What changed

- `crates/daemon/src/jobs.rs`:
  - `CheckSlots::swap_for` and `CheckSlots::acquire` take `expected_ms`, through `Broker::acquire_expecting`.
  - `TestChecks::estimate` reads the suite's estimate.
- `crates/daemon/src/landing.rs`: a `SplitRun` type alias. s394 left a `clippy::type_complexity` error on develop, so every agent's `cargo clippy -D warnings` failed. No behaviour change.
- `crates/cli/src/main.rs`: `answer_tests` moved to the end of the file. s297 left `clippy::items_after_test_module` failing.

## Not verified

There is no new test. The backfill rule itself is tested in s385 (`crates/scheduler/tests/properties.rs`), and this change only passes an estimate to it. It is checked live: compile slots in use while the machine drains.
