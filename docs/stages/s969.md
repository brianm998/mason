# s969: an owner retry or Land now forgets the cached red landing runs of the task

Summary: see decision 0962. Task #841's red landing result came from a bad batch build; three
later batches reused it, and the owner's retry and Land now could not make anything run again.

Owner approval for the protected files `crates/daemon/src/landing.rs` (the `cached_run` doc
comment only) and the new gate `scripts/exit/s969.sh`: given in the session that started this
work on 2026-11-22 ("Clear red, fix code"). `crates/scheduler/**` and
`crates/daemon/src/sched.rs` are not touched.

## Built
- `mason-store`: `Store::forget_red_batch_runs(project, task)`.
- `http.rs`: `RetryAsk::forget_red`, `forget_red_runs` (one INFO line with the count); the retry
  endpoint, `land_override` (land-now only) and `land_now_batch` call it.
- `diagnose.rs`: a diagnosis applied by hand (`auto` off) asks for it; an automatic one does not.
- `landing.rs`: the `cached_run` doc comment.
- Tests: `forgetting_a_tasks_red_runs_keeps_greens_and_other_tasks` (store, rows for #841 alone,
  with others and at another head go; green, #84, #8410, #1841 and another project's #841
  stay); `landing_forget_red::an_automatic_re_submit_reuses_the_red_result`,
  `landing_forget_red::an_owner_retry_from_land_runs_the_suite_again`,
  `landing_forget_red::land_now_on_a_task_with_a_cached_red_runs_the_suite_again` (real daemon,
  git and suites; a counter file counts the runs of the red suite). Exit test
  `scripts/exit/s969.sh`.

## Needs the owner's approval

- `scripts/exit/s969.sh` is a new gate under `scripts/exit/**`.
