# s668: develop's CI finishes: repeat counts, a script limit, weighted shards

Summary: CI runs the repetition exit scripts twice instead of 10-20 times, kills any exit script over 900 s with a named `FAILED … (over 900 s)`, assigns scripts to shards by weight, and splits the workspace tests into two legs; no script is dropped.

**Cause.** In the 16 CI runs of 2026-11-18/19, exit-script shards 1, 4 and 2 were cut off at 60 minutes in 15, 14 and 11 runs and `test` at 40 minutes in 13-14. s170 alone took 43 minutes; shards were every n-th script, so one slow script filled a shard.

**Change.**
- `MASON_EXIT_REPEAT` sets the count in s80, s99, s169, s170, s482, s497 (defaults unchanged). CI push runs use 2; the nightly schedule leaves it unset.
- `scripts/run-exit-scripts.sh`: per-script limit `MASON_EXIT_SCRIPT_LIMIT_S` (CI 900, nightly 3600), `sNN: N s` after each script, weighted greedy sharding from `scripts/exit/weights.txt` (unknown scripts weigh 60), `MASON_EXIT_PLAN=1` to print a shard. `scripts/refresh-exit-weights.sh` rewrites the weights from CI logs.
- `ci.yml`: `test` is two legs per system (`--workspace --exclude mason-daemon`, and `-p mason-daemon`), 45 minutes each.
- Exit test `scripts/exit/s668.sh` (no timing assertions).

**Not verified.** The CI run itself: shard totals and leg times at the new settings are estimates. `weights.txt` holds the full-count times read from the logs, so CI shards (repeat 2) are lighter than weighted; refresh it after the first green run. The macOS fallback for the limit (no `timeout`) was not exercised here beyond s668 on this Mac, which has no `timeout`.
