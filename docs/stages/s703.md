# s703: change-based test selection narrows a directory test target to the modules a change affects

Summary: A change now selects only the `mod <name>;` modules of a directory test target (such as the daemon's `it`) that reference it, rendered as a filtered group `-p mason-daemon --test it -- a:: b::`, instead of the whole 553-test executable.

**Change** (`crates/daemon/src/affected.rs`). For a `tests/<dir>/main.rs` target, `dir_target` lists its `mod` files (a `#[path]` include such as the shared harness is not a module) and `select` asks `references` per module text. A changed module file (or file under its subdirectory) selects that module; `main.rs`, any other file under the directory and a `#[path]` file it includes (found through the existing reader rule) select the target whole. More than half the modules selected: whole. `Group.modules` holds the filters; `render` emits a filtered target as its own group and drops it when the target also runs whole (by the group, a package run, or the smoke set); `add_smoke` merges a smoke filter on the same target into it.

**Resume** (`resume.rs`). A lost run of a narrowed command has no unit plan (`template` is `None`), so the whole command, filter included, runs again; a filtered group in a rerun plan keeps its filter through `expand`. Tests added; no code change was needed.

**Not verified / limits.** The note lists the modules through the group text (`-- a:: b::`), not as "7 of 84 modules". Libtest filters are substring matches, so `resume::` also runs `host_resume::` (more tests, never fewer). The exit script uses cargo's own output, not the MASON parser. Not run against the real daemon `it` target.
