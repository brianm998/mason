# s1144: a short network outage fails nothing (#1185)

Summary: A network outage of a few minutes no longer fails a landing batch or uses up test rounds: pushes are retried, a batch that still cannot push waits for the network, a suite red only for want of it is run again and then fails outside the code, and the host raises one "network outage" alert.

## Cause

`push_candidate` and the promote push ran once, and any error failed every task of the batch. `remote.rs` did retry, but its list of transient errors had no name-resolution or no-network message. A suite that could not fetch its inputs counted as a red round (2026-11-25: batch #763 and trd #1009).

## Change

- `crates/daemon/src/net.rs` (new): the matchers (`is_network`, `is_transient`, `log_failure`, `refused`), `retry` with an injected sleep, and the host's record of network failures. `remote.rs` `push_transient` uses it.
- Landing: the candidate push, the promote (`Batch::finish_with` as a whole, which holds its fetches and its push), the pull-request branch update and its fetches, and ref deletes are retried after 10, 30 and 90 s. When the waits are used up the batch ends as `yielded` with a note "waiting for the network: ..." and its tasks go back into the queue. No batch of the project starts until a fetch of the base works (looked at every 15 s; every 10 min after a suite held it). A ref that could not be deleted stays recorded and is deleted when a daemon next starts.
- Test step: a command or build that failed, names no failing test, was not stopped at a limit, and whose last 40 log lines carry a network message is run again twice, 30 s apart. Then the step fails with class `outside` ("suite `x` could not reach the network ..."), which `autoretry.rs` retries. No round is used.
- A landing batch's suite that stays network-red holds the batch the same way. A deferred debt or whole run gives up with an error instead of recording a red; a ledger rerun leaves the entry in place; the post-land tier leaves the freeze as it is.
- Alerts: three network failures inside `burst_window` (events the daemon met plus tasks failed for them) are one `network-outage` entry, and those tasks get no `failed:` alert while it stands.

## Tests

`cargo test -p mason-daemon net::`, `autoretry::`, and `--test it net_outage::` (real git, a pre-receive hook that answers as ssh without DNS does). `scripts/exit/s1144.sh` runs the last.

## Not verified

- No real outage was made: the remote's hook prints ssh's message, and the suite prints curl's.
- The pull-request modes' branch update during an outage has no test.
- Not covered: the build floor, the lint check, the landing fast tier and new-tests check, a project without suites (its `test` command), the improvement flow's push to a fork, and a task worktree's own fetch. A network failure there is judged as before.
- A suite whose log mentions one of the messages near its end while failing for another reason, with no failing test named, ends `outside` after three runs instead of using a round.
- The outage record is in memory: a restart forgets it.
