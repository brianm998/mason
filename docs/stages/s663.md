# s663: make the fast-tier landing test independent of the clock

Summary: the skipped-batch fast-tier landing test now forms its batch by size, writes the skip debt before admission and waits for the first batch to finish, so it no longer flakes under load.

## Why

`a_skipped_batch_whose_unit_tests_pass_lands_and_a_batch_with_testing_does_not_run_the_tier` flaked in four unrelated tasks. It used `window = "2s"`, wrote the skip debt after admission, and created the second task as soon as the first reported Landed, while the first batch's thread was still tearing down in the same repo.

## What changed

Only `crates/daemon/tests/landing_fast_tier.rs`: `max_size = 1` and a 20 minute window; the debt is written through `task_with` before admission; the test waits (`wait_for`) until `running_batches` is 0 before creating the second task. No timing assertions.

## Not verified

The cause was reasoned from the code, not reproduced. Repeated runs were left to the pipeline.
