# s662: Compose monitor task numbers are links

Summary: Every task number the Compose monitor prints (wait lines, batch lines, lease and hold lines, sidebar rows, finding proposals) is now a `LinkedText` link to that task's page, and a source-scan test stops plain `Text` from naming tasks again.

**Change.** `Pages.kt`: home stage rows, section-page rows (the key is now link-styled and the detail line is `LinkedText`), Landing batch lines, "Landing now" batch line, finding "(proposal #N)", `leaseDetail` and the queue-hold lease line. `Sidebar.kt`: the wait line moved out of the row's click target; it is `LinkedText` whose non-link part still opens the row's own task. On home stage rows the line stays inside the row's clickable; a link click is handled by the text first.

**Tests.** `TaskNumberLinksTest` (link of `#613` in a held row, batch line, source scan with an allowlist of non-task ids: debt id, finding id, issue, PR, batch id). The scan is line based, so a `Text(` call split over several lines is not seen.

**Not verified.** Clicking a link inside a clickable home row or the sidebar was not exercised in a running UI (no UI test run); that a link press wins over the parent click is Compose's documented behaviour. The Swift sibling and `clients/features.toml` were not touched (no parity row added).
