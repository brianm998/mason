# s399: A lost agent host resumes the agent's own session

Summary: an agent step whose host is lost is resumed in its own provider session (when the journal has the id) with a note naming the time of the loss, and a resumed session that reaches its own end no longer leaves earlier losses counting toward MAX_AGENT_RESTARTS.

Task #410. Decision 0392.

## Built
- Resume with the session id after a lost host was already in `jobs::settle_all` (s83); this stage keeps it and changes two things there.
- `hostloss::interrupted_note(at_ms)` now says "Your process was lost at <UTC time>" and tells the agent to check the worktree and continue.
- `settle_all` remembers how many lost invocations existed when a resumed session ended other than by another loss; those are skipped when counting toward `MAX_AGENT_RESTARTS` later in the same step run (e.g. a signaled-CLI retry followed by a loss).
- Fresh session when no id is known or the transcript is gone: unchanged.

## Not verified
- The forgiveness path has no test of its own: with the fake agent a resumed session that ends normally returns from `settle_all` at once, so the skip only matters after a later loss in the same call, which I could not provoke deterministically.
- Codex resume after a host loss is the same code path (`runner.resume`); not run against a real Codex.
- Nothing was run against a real reboot or real providers.
