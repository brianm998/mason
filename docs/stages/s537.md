# s537: the Swift monitor caches images, task links and the voice list

Summary: The Swift monitor builds each mascot image once (in `Mascot`), linkifies each text once per sidebar/task revision, and asks the OS for its voice list once, instead of redoing all three on every redraw.

**Cause.** `body` called `Mascot.illustration`/`bannerIcon`/`brand` (file read, PNG decode, new `NSImage`), `MonitorModel.linkify` (scanning every sidebar row per `#n`) and `availableVoices()` (an XPC round trip).

**Change.**
- `Mascot` keeps a lock-protected cache keyed by file set and size for `icon`, `bannerIcon`, `illustration` and `brand`; `StateIconCache` now just forwards. `Mascot.imageLoads` counts builds. The UIKit branch shares the cache.
- `MonitorModel` keeps a set of known task ids and a per-text `[LinkSegment]` cache, both dropped when `sidebar` or `taskDetail` changes (`linkRevision`). Counters: `linkifyPasses`, `isKnownTaskCalls`.
- `Announcer.availableVoices()` keeps the sink's list after the first call; `SystemSink` loads `speechVoices()` once and looks the chosen voice up by name in it.

**Not verified.** I could not build or run Swift here (the shared build queue refused `swift build` in this session), so the new tests in `MascotTests`, `LinkedTextTests` and `SpeechTests` have not run on my side. The voice list is cached on first use on the main thread, not loaded off-thread as the ticket suggested (the sink protocol is main-actor); it is one call instead of one per redraw. The offscreen ten-redraw exit test is covered by the counter tests, not by a rendered run; `--mascot-check` was not run.
