# s254: an explorer can close a task that is already done or a duplicate

Summary: the explore step has a terminal tool `submit_close` (already done, duplicate of a task, or not a problem, with evidence); the task then waits in a veto window as a decision card ("Close #N: <kind>: <evidence>", Close now / Reopen and explore) and is closed with no change when the window ends, at once on "Close now", or reopened into exploring.

Decision 0249 records the choices.

**What changed.**
- `crates/adapter-api/src/contract.rs` (protected): `submit_close` in the explore step's tools and terminal tools, its schema and its validation (`kind`, `evidence`, and `duplicate_of` for a duplicate).
- `crates/daemon/src/closer.rs`: `ask` (called when a step ends with an accepted `submit_close`: it writes the pending close and asks the card as a `QuestionAsked`), the card, the closing reason, `expire` (a loop that closes what has waited out its window) and the window by trust: 24 hours for the owner's own tasks, 2 hours for tasks filed by MASON's agents (`close_window_owner`, `close_window_agent`, `close_tick`, short in tests).
- `crates/daemon/src/attention.rs`: an answer to a task with a pending close: "Close now" emits `ClosedNoChange`; any other answer reopens it, resuming in the first exploring step with the owner's words.
- `crates/store`: migration 35, `explore_closes` (one row per task), so a restart keeps the window.
- `crates/daemon/src/jobs.rs`: the agent step's end handles `submit_close`.
- `scripts/exit/s254.sh` (protected).

**Not run, and known gaps.** Nothing was run: no unit test, no fake-claude integration test (the brief names three: close after the window, close now, reopen), no exit script. Tasks that MASON itself filed with the owner's trust (the base-red and flaky tasks) get the owner's 24-hour window; only tasks filed with the agents' trust get 2 hours.
