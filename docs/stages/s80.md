# s80: hold tests no longer race the stale-reset rule

Summary: The two holds tests now express the usage-limit reset relative to when the fake agent emits it, so a loaded machine can no longer make it stale.

The tests set the reset to `now()+14` (and `+25`) at test start. Under load the daemon observed the limit after that time had nearly passed, and dropped it as a stale text, storing a hold with no `until_ms`. The daemon was right; the fixture was fragile. `fake-claude` now accepts `resets_in` in `rate_limit` and computes `resetsAt` at emission; the tests check the stored hold against a range and wait for the stored reset.
