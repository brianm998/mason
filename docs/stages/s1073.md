# s1073: Swift settle waits on view seq

Summary: The Swift monitor-tool's settle now waits on `lastViewSeq` (moved only by views and snapshots) instead of `lastSeq`, which events also move, as Compose already does.

## Cause

Hypothesis, not confirmed by a run. `MonitorModel.apply` moves `lastSeq` on `.events` (Model.swift:1293), and `settle()` (Tool.swift:135) treated `lastSeq >= target` as the views having arrived. The daemon sends events before views of the same seq (crates/daemon/src/ws.rs:334-337, 407-413), so a capture could show the previous step. Compose fixed this in decision 1057 (Model.kt:1102, Tool.kt:50-101).

## Change

`lastViewSeq` in Model.swift, set by `.view` and `.snapshot`, reset on a snapshot-resume welcome. `settle()` uses it; `step()` already settles with the daemon seq as floor. Test: `testLastViewSeqMovesOnViewsNotOnEvents`.

## Check

If s49 step 2 still differs at checkpoints 6-9 after this, the settle race is ruled out and it is a Swift client bug: compare the Swift and Compose dumps for the same checkpoint.
