# s78: a landed task's build directory is removed

Summary: A project can name a task's build directory with `task_cache`; it is removed when the task lands (off the event loop, outside the repo lock, and only if the path passes the safety rules), and the reconcile sweep removes the ones a restart or a miss left.

## Why

On 2026-11-08 the data volume hit 100%: `~/.cache/mason-target.noindex` held 212 GB, 29 directories of landed tasks, 130 GB freed by hand. `cleanup()` removed the worktree and branch only, and MASON did not know where the build directory was.

## What changed

- `task_cache` (project file, optional, must contain `{task}`): `crates/daemon/src/config.rs`, documented in `docs/examples/mason-self.project.toml`.
- `crates/daemon/src/taskcache.rs`: expansion (`$HOME`, `${VAR}`, `~`, `{task}`), the path rules, removal on a thread of its own, and the sweep part.
- `jobs::cleanup` releases the repo lock first, then starts the removal if the task is `Landed`. Canceled and failed tasks keep theirs.
- `sweep_once` removes landed tasks' leftovers every pass (no two-sighting rule, no bug filed: it is housekeeping), skipping any task with a running job.
- Tests: unit tests for each refusal in `taskcache.rs`; `crates/daemon/tests/taskcache.rs` (landing, canceled kept, no setting, sweep removes, sweep leaves live). Exit script `scripts/exit/s78.sh`.

## Not verified

- The owner's own project file (`~/.config/mason/projects/mason.toml`) is outside this repository and was not edited; add the `task_cache` line there, matching the test command.
- A failed (not canceled) task's directory is kept by construction (only `Landed` removes) but has no test of its own.
- `remove_dir_all` on a real multi-GB directory was not timed.
- The "contains a worktree" rule checks the daemon's worktree, landing and data directories as a whole, not each worktree.
