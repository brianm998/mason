# s818: favor-local runs here until this machine is overloaded

Summary: `favor-local` now reads this machine's load (an active thermal or CPU hold, no free `compile`/needed slot with requests already waiting, or a local wait over `[remote_runs] spill_after`, default 120 s) and starts the run on GitHub when it is overloaded and GitHub has a free `gha` unit; otherwise it runs here, and every placement says why.

Task #832. Decision 0811.

## Built
- `place::LocalLoad` (held, free, waiting, oldest_wait_ms) with the pure `overloaded` and `from_reading`; `place::Spill` carries it with GitHub's room and `spill_after`.
- `place::balance` uses them for `favor-local`: GitHub only when overloaded **and** GitHub has room, else here ("favor-local, 2 compile slots free", "favor-local, this machine held for heat (die 99 °C)", "..., and GitHub is full too, so it queues here").
- `Broker::load_reading` (`sched.rs`, protected): a read-only accessor over the ledger snapshot and the existing thermal/CPU readings. No gate, limit or hold changed.
- `place::place_of` keeps a `favor-local` placement for the run (`STICKY`, forgotten when `hostedcheck::run_with` ends) so the several calls one run makes agree; `place::keep_or_move` moves a run placed here to GitHub once it has stood longer than `spill_after` while a hold is active and GitHub has room.
- `[remote_runs] spill_after` (seconds, default 120) in `config.rs`.
- Tests: place.rs table tests (`favor_local_spills_only_when_overloaded_and_github_has_room`, `a_favor_local_placement_says_why`, `a_queued_local_run_moves_when_its_wait_passes_spill_after_under_a_hold`, `a_load_is_built_from_a_scheduler_reading`) and `definitions::favor_local_spills_to_github_only_while_this_machine_is_full`. Exit test `scripts/exit/s818.sh`.

## Not verified / not done
- A queued run is **not** pulled out of the broker queue: `keep_or_move` is evaluated at the next placement call of that run (after its queue wait, in `collect`), so it then runs on GitHub but has waited and briefly held the local slot. Abandoning the queue request mid-wait (`jobs.rs` `swap_for`) is not wired.
- "GitHub has room" reads the `gha` (and `gha-macos`) pool in the broker; whether that counts every job on the account depends on #819, which I did not check.
- Landing batches, base runs and debts (no task) and whole-step placement (`plain_place`) carry no load reading, so `favor-local` keeps them here.
- No real masond with a fake GitHub: the daemon test and exit script drive `executor_for` against a real broker with held leases, not a check over a fake GitHub. Tests were run only through `run_check`.
