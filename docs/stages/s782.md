# s782: Full test record: last fully tested base commit, 01:00 and quiet triggers, only when the tip is not tested

Summary: a `full_tests` record (base commit, trigger, times, verdict, link) lets the `ci` schedule run the full test at its `at` time and after `when_quiet` quiet minutes, and only when the base tip is not already fully tested (or changed only paths no suite reads), with `mason schedule run --force`, a status line for the last full test and the next trigger, and red tickets that name the commit range and landed tasks since the last green.

Task #782. Decision 0775.

## Built

- **Rules** (`crates/core/src/full_test.rs`, no I/O, no clock): `decide` (running, nothing on record, tip tested, only no-suite paths changed, start), `QuietTimer` (fires once per quiet spell), `busy_state`, `next_text`, `tasks_in` (task numbers from merge subjects).
- **Store**: a new last migration, `full_tests`; `FullTestRow`, `add_full_test`, `finish_full_test`, `full_tests`.
- **Daemon**: `schedule.rs` parses `when_quiet` (a `ci` key; quiet-only schedules need no `at`/`every`). `ci_schedule.rs`: `dispatch_as` (record first, then the CI host's check, `force` skips both, writes the row), `follow` finishes the row (green, red, cut off, with the run's link), `range_note` for red tickets, `full_view`/`full_views`. `introspect.rs`: the tick looks at each quiet schedule's project (`project_busy`) and fires the trigger; `run_now_forced`. `http.rs`: `force` on `/schedules/run`, `full_tests` in `/status`.
- **CLI**: `mason schedule list` prints the line, `mason status` prints it per schedule, `mason schedule run <name> --force`.
- **Tests** (no timing assertions; the clock is a parameter): core: quiet timer (busy, 29 quiet, admitted, 30 quiet fires once, an hour more does not, busy then quiet fires again), busy states (proposed, deferred, needs attention, failed are quiet), decision (tip tested, README only, crate file, in flight, nightly after a quiet run on the same tip), next text, tasks from merge subjects. Store: rows survive a reopen, newest first, a run in flight at the restart can be finished. Daemon: all triggers through one rule against a fake host, a reload with a run in flight is followed and not dispatched again, force, a red run is recorded red with the range in its tickets, a project with only proposed tasks is quiet and a queued one is busy. Schedule parsing of `when_quiet`.
- **Exit**: `scripts/exit/s782.sh`.

## Not verified / limits

- Tests ran on GitHub through `run_check`; the exit script was not run by me.
- The monitor's home page (Swift) was not changed; it can read `full` from `/schedules` and `full_tests` from `/status`.
- A red ticket's task list is those landed in the range whose changes select any suite, not only the failing one: the impact map is per path, and a CI job name is not mapped to a suite.
- Tasks are found from merge subjects (`mason/<project>/t<N>`); a landing that does not merge by branch name is not counted.
- The quiet timer is in memory and starts over after a restart. "A landing batch forming" is covered by its tasks being in `landing`; no separate batch check was added.
- Only the `ci` kind records full tests; MASON's own runs (a `suites` kind) come later.
