# s754: the monitor shows what the agents are doing and what is on GitHub (#763)

Summary: Home's Active models says how many agents are working and how many wait on GitHub checks, here or for a slot, and shows the GitHub runner pool in use by checks, test steps, batches and debts.

## Cause of the empty list

`views::home` listed only tasks that held an `llm` slot. With remote checks on, an agent gives its slot back while its `run_check` waits on GitHub, so every such agent dropped out of `active`. Nothing in the clients was wrong. I did not find a reconnect fault after a takeover and did not test one, so there is no reconnect test; this is untested, not ruled out.

## What changed

- `schemas/mason.proto`: `ActiveModel` has `state`, `place`, `runs_on`, `run_url`, `resource`; new `PoolUse`, `RemoteRun`, `RemoteSummary`; `HomeView.remote`. Swift code regenerated with `protoc`.
- `remote::RemoteHold` records the kind (`check`, `test_step`, `batch`, `debt`) and the task of each run in flight; `views::Ctx::home` reads them. No new polling: the run link comes from the run's record.
- `mason status` (text and `--json`) gets `agents:` and `on GitHub:` lines and the state on each `active:` line.
- Swift and Compose: `ActiveSummary` (same words in both), the home section, the detail page with a link per run.

## Not verified

- No test was run by me (tests run on GitHub). The Swift and Compose code and the Rust changes were not compiled by me either, and the UI was not looked at.
- A task that holds no slot and has no open check shows as a waiting agent only if its step has started; a queued step still does not appear (an existing test requires that).
- Debts and landing batches are told apart by the run id prefix (`debt`, `ledger`); a landing check counts under batches.
- Android is marked todo in `clients/features.toml`.
