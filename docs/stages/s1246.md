# s1246: `mason prompts eval` replays past read-only steps under two prompt revisions

Summary: `mason prompts eval [--project P] [--step S] [--against REV]` reads cases from `.mason/evals/<step>/*.toml` on the base revision, builds each case's prompt at the base and at the candidate revision, runs both sessions read-only in one detached worktree at the case's recorded head, and has a grader session judge each result against the case's expected statements. It prints both verdicts, the judgement with quotes, tokens, and a last line `base passes N/M, candidate passes N/M`; the result is kept in `<data dir>/evals/<candidate sha>.json`. `mason prompts eval add <task> --step S --expect ...` writes a case from a finished task. The owner-approval hold for a change that touches `prompts.rs`, `contract.rs`, `diagnose.rs` or `.mason/prompts/**` links the latest result for that head, or says there is none.

Code: `crates/daemon/src/prompts_eval.rs` (cases, rendering, sessions, grading, report), `crates/cli/src/prompts.rs` (arguments, adapter), `crates/daemon/src/selfguard.rs` (card note).

Tests (in `prompts_eval.rs`, fake adapter): both prompts come from the given revisions and both verdicts and the judgement are recorded; a case whose head is gone is skipped with a reason; a case written from a task parses back; the grader's reply and the approval note are read.

Not verified:
- No real Claude or Codex session was run; only the fake adapter. The real adapter is built without a step host or sandbox.
- Runs do not take `llm:claude` broker slots: the CLI runs in its own process, the broker lives in the daemon. They are never started by the test step or landing, but the "low priority slot" part of the ticket is not done.
- The built-in prompt text (`prompts.rs`, `contract.rs`, `diagnose.rs`) of a revision can only be rendered by that revision's binary: without `--base-bin` / `--candidate-bin` (each a `mason` built at that revision, run as `mason prompts render`) both sides use this binary's defaults and only `.mason/prompts` packs differ.
- The three seed cases (trd #1112 round 2, a star review, a diagnosis) are not written: they need the owner's task data and a trd/star checkout, and `.mason/**` needs owner approval.
- `scripts/exit/s1246.sh` and the full workspace tests were not run by hand; see the run_check result.

Trust: `.mason/evals/**` falls under protected `.mason/**`; `selfguard.rs` (the approval hold) is edited and may need owner approval. No gate reads eval results.
