# s204: task detail: issue and CI references are links

Summary: The task detail page links every known `#N` to that task's page and every CI reference (the batch pull request, a failed check, a bare URL) and the tracker issue to the default browser, in both clients, from one tested `linkify` function each and a new additive `ci_links` field the daemon fills from the host.

**Built.**
- Protocol: `CiLink {label, url, kind}` and `TaskDetailView.ci_links = 22` (additive). Swift code regenerated with `protoc` as `scripts/gen-clients.sh` does; Kotlin comes from the Wire build.
- Adapter: `JobFailure.url` is the check run's `details_url` (GitHub Actions jobs: the job's `html_url`). The fake host returns a job per failed check (with a URL) only when its state directory holds a file `with-jobs`, because jobs make the landing judge each one; its pull requests now have `https://fake-host.example/pr/N` URLs.
- Daemon: `landing.rs` records `PR #N` (kind `pull_request`) when a batch pull request opens and each failed job's URL (kind `check`, labelled with the job name) against every task of the batch, in `ci_links.json` in the task's directory (`record_ci_links`, `ci_links_of`; only http(s) URLs are kept). `views.rs` sends them in the task detail. Kind `run` is accepted by the clients; nothing records one yet (the command CI has no run page).
- Clients: `Linkify` in `MonitorCore` and in `clients/compose/core` turns text into plain, task and URL segments. `#N` is a task only when the model knows N (sidebar rows, or the open task's blockers, blocks, debts, proposal filer) and it does not follow `PR`, `pull request`, `Batch`, `debt`, `issue` or `run`; the `(#N)` of "the pull request's checks (#N)" is the pull request. A `CiLink` label links only when its URL is http(s). `LinkedText` (Swift: `AttributedString` with `openURL`; Compose: `LinkAnnotation`) is used for why-waiting, failure, tests, plan (over the Markdown styling), body, log, step launch lines, proposal evidence and filed-by, decision card and approval text, debts (the debt's own `#id` is not linked) and the landing page's debts and freezes. Task links call `model.go`; URLs open through the system (`OpenURLAction.systemAction`, `LocalUriHandler` in `runCatching`). Body, log, plan and evidence stay selectable. A "CI" line and "issue #N" (browser, when `issue_url` is set) are shown on the page; Swift showed the issue nowhere before.
- `clients/features.toml`: `task-detail-links`, done in both.

**Tests.** Adapter: `a_failed_checks_details_url_is_carried_into_its_job_failure` (new fixture `pr_red_urls.json`). Daemon: `a_red_batch_pull_request_gives_the_task_detail_ci_links` (fake host). Core: `LinkifyTests` (Swift), `LinkifyTest` (Kotlin): known and unknown `#N`, `PR #7` with and without a `CiLink`, a check name, a bare URL, `Batch #3` and a debt `#4`, a non-http URL ignored. UI: `LinkedTextTests` (Swift, offscreen), `LinkedTextTest` (Compose, annotated strings).

**Trust (owner approval).** `clients/features.toml` (gates: client parity) gains one entry. `crates/daemon/src/landing.rs` (guards) gains the recording of links; it changes no verdict, ladder step or gate. `scripts/exit/s204.sh` is this stage's own exit test. No golden event log under `crates/daemon/tests/fixtures/` changed. The fake host's pull-request URL changed from `fake://pr/N` to `https://fake-host.example/pr/N` so clients could open it; `crates/daemon/tests/editor.rs` asserted the old prefix and now asserts the new one.

**Not verified.**
- Nothing was opened in a browser and no window was shown; clicks were never exercised, only the links the strings carry. `OpenURLAction` / `LinkAnnotation` click handling is as documented, not observed.
- Real GitHub: only a recorded response was used; a real run's `details_url` / `html_url` forms were not seen.
- Older daemons send no `ci_links`; the clients then show no CI line (not run against one).
- A check name is linked wherever it appears as a whole word in the page's text, including prose that merely contains it.
