# s546: Affected tests per task, the whole cargo suite once per landing batch

Summary: A task's `run_check` and test step now run only the test targets its change can affect (a static source scan, `{tests_for_change}`) plus a smoke list, and MASON's landing gets a `batch` tier that runs the whole `cargo-workspace` suite once per batch with a 10 min window.

See `docs/decisions/0539-affected-tests-per-task-whole-suite-per-batch.md`.

What changed
- `crates/daemon/src/affected.rs` (new, pure selection plus smoke parsing); `crates/daemon/src/scope.rs` (`Narrow`, `expand`, `narrow_for`); `suites.rs` `narrow_packages_for_step` and `jobs.rs` `run_check` use them.
- `crates/definition/src/validate.rs`: `dev_command` / `dev_build` may carry `{tests_for_change}` instead of `{packages}`.
- `.mason/mason.toml`: `cargo-workspace` uses it with `narrow_packages = true`; `.mason/smoke-tests.txt` (owner-edited); `.mason/landing.toml`: batch tier, ladder, `window = "10m"`.
- Tests: selector unit tests with fixture diffs (test file, leaf `src`, `support/` and `Cargo.toml`, undecidable reference, docs only, dir targets, metadata parsing); `expand` tests; a landing test on the fake runner that a red the base shows too blames nobody (the existing `landing_split` tests cover the batch-tier red being split and the culprit alone being sent back).

Window: 10 min is a proposal. The suite takes 22-35 min and tasks reached landing about every 2.4 h on 2026-11-17, so many batches will still be small; raise it if the measures below show batches of 1-2.

Measurements. Before (from the ticket): 194 full check runs in 24 h to 2026-11-17 07:45 for 10 landed tasks; a green run 22-35 min; 6 test-suite slots. After: **not measured**. It needs at least a day live: check runs per task, slot-minutes per landed task, batch size, red-batch rate.

Not verified
- No live daemon run and no day of measurements.
- The generated cargo commands (`--lib --doc`, `--bins`, `--test` combinations) were reasoned from cargo's documentation and run only through the check tool; the scan's precision on the real workspace was not measured.
- Bisection of a red batch still re-runs the whole batch suite on each subset. Running only the failing tests on each member's branch (the ticket's local culprit finding) was not added: it needs failing test names carried through `OverRun`.
- The exit test checks the config and runs the unit and landing tests; it does not run a fixture workspace through a live daemon.

Exit test: `bash scripts/exit/s546.sh`.
