# Stage 153: CI judge: infrastructure reds are rerun, real reds go back at once

Summary: With `[ci] infra_judge` on, MASON reads each failed GitHub Actions job as infrastructure or real, reruns CI once only when every failed job is infrastructure, and sends a real red back at once; off by default.

**What was built.** `ci_infra.rs` (pure classifier, starpipe's `INFRA_LOG` plus the shutdown-signal and name-resolution phrases); `JobFailure` and a `jobs` list on `CiState::Red` and `PrStatus`; GitHub fetches failed jobs' logs (redirect followed without the token) when `infra` is set; `[ci] infra_judge` / `infra_patterns`; the red ladder in `landing.rs` skips every rung when a job is real and notes each job. Decision 0148.

**Files, and why each is needed.** `landing.rs` is PROTECTED (the red ladder): it records the per-job notes and stops the ladder on a real red; **it needs the owner's approval**. `service.rs` carries the per-job reasons. `github.rs` fills them. `fakehost.rs` parses an optional `infra:` line (command CI). `jenkins.rs` only gets empty `jobs`. `config.rs` and `services.rs` add and pass the settings. `crates/testing`, `suites.rs`, `crates/landing`, `deny.toml` and workflows are untouched.

**Tests.** Unit tests per rule in `ci_infra.rs`. Recorded GitHub responses (`tests/github.rs`): `timed_out`; shutdown-signal and "Temporary failure resolving" logs; compile error and XCTest assertion are real; a mix; never got a runner; unreadable log; judge off makes no log request; the log request after a 302 carries no Authorization. Daemon test `ci_infra.rs` on the fake CI: "runner lost" is rerun once and lands (2 triggers); a test failure is sent back with 1 trigger. A config test. Exit test: `scripts/exit/s153.sh`. No timing assertions.

**What ran.** I ran, through `mason run --needs compile`, the `mason-adapters` tests, the new daemon tests, `landing_modes` (unchanged, passing) and the new config test. I did not run the full workspace, clippy or the exit-script runner myself; the pipeline's `tests` check does.

**Not verified.** No live GitHub: the log redirect is checked on recorded responses only, so the real signed-URL answer and `curl` not following redirects are assumed. PR-mode judging (check runs) is covered only through the shared `judge_job` path, not by a recorded PR test. The infrastructure phrase list is substring matching of starpipe's regexes, not the regexes themselves.
