# s508: a killed develop run does not count against the task

Summary: when a task's test step is red and the suite has a `rerun` template, develop is asked about only the failing tests (not a full suite run); a run that is killed or reads no names is retried once, and if it is still unknown the round is not counted against the task and the note says so.

## Why

On 2026-11-16 #452 failed after three red rounds on `every_state_and_event_pair`, which was red on develop too. The full-suite run on develop (`t452r3267-b-cargo-workspace`) ended `code=-1 signal=15`; `baseline_noted` turned that into "no baseline", and `classify` treated no baseline as "not red on develop".

## What changed

- `crates/daemon/src/suites.rs`: the worktree-and-run part of `baseline_noted` is now `run_on_base`. `failing_at_base` runs the suite's `rerun` command with only the persistent failing names, once more if the run did not finish or read no names. Still unknown: `run_suite` returns `Excused` with a note ("not counted against the task") instead of `Product`. A suite without `rerun`, or with a cached whole-suite baseline for the base, behaves as before.
- Tests: `a_develop_run_that_is_killed_does_not_count_the_round_against_the_task`, `a_develop_run_of_only_the_failing_tests_that_fails_the_same_test_excuses_it` (`crates/daemon/tests/testing.rs`). Exit script: `scripts/exit/s508.sh`.

## Not verified

- The targeted run's results are not cached per base (they cover only some tests).
- The "unknown" outcome lets the step go on with closing verdict `unverified`; no fix task or ledger entry is made for it.
- `check_at_base` (last-round and repeat checks) already ran only the failing tests, three times; unchanged, so s416's `Origin` split is untouched.
