# s793: the s748 and s750 exit tests now really hold the slots

Summary: The s748 and s750 exit scripts give their slot holder a fifo on stdin kept open on fd 3, so the hold lasts until the script closes it instead of ending at once on /dev/null.

**Cause.** A background job's stdin is /dev/null in non-interactive bash, so `mason hold` printed `granted` and exited. Phase 1 of s748 failed at `kill -0 "$holder"`; in s750 phase 2 nothing was held, so it could not prove a local run waits for `compile`.

**Change.** `hold_slots()` in both scripts makes a fifo, starts the hold with it as stdin and opens fd 3 on it (as s155's `start_hold`). The release lines and `cleanup` close fd 3 before killing the holder. No assertion changed; no daemon code changed.

**Second cause.** With a real hold, phase 2 still failed: task 1's agent made the same commit as task 0, so its `run_check` was answered from the green tree cache (`cmdreuse`) at once, never queued for `compile`, and the agent ended. The scripted agent now writes `pwd` into hello.txt, so each task's tree is its own. Same in s750 (its test step reused the tree the same way). No daemon code was wrong or changed.

**Verified.** Ran `bash scripts/exit/s748.sh` and `bash scripts/exit/s750.sh` locally: both print `passed`. The holder is alive at `kill -0`.

**Not verified.** s787 (a different task's test, #799) also failed in the GitHub run and still fails locally in phase 1 ("the step did not stay in develop"); it is not touched here. `scripts/exit/**` is protected, so this needs the owner's approval.
