# s793: the s748 and s750 exit tests now really hold the slots

Summary: The s748 and s750 exit scripts give their slot holder a fifo on stdin kept open on fd 3, so the hold lasts until the script closes it instead of ending at once on /dev/null.

**Cause.** A background job's stdin is /dev/null in non-interactive bash, so `mason hold` printed `granted` and exited. Phase 1 of s748 failed at `kill -0 "$holder"`; in s750 phase 2 nothing was held, so it could not prove a local run waits for `compile`.

**Change.** `hold_slots()` in both scripts makes a fifo, starts the hold with it as stdin and opens fd 3 on it (as s155's `start_hold`). The release lines and `cleanup` close fd 3 before killing the holder. No assertion changed; no daemon code changed.

**Not verified.** I did not run s748 or s750 locally (tests run on GitHub). If a phase is still red with a real hold, the defect is in #759/#761 code (`goes_remote`, `pool_needs`, `hold_for_debt`) and is not fixed here. `scripts/exit/**` is protected, so this needs the owner's approval.
