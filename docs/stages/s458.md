# s458: the iPad monitor is the Mac layout in landscape, smaller, with touch-sized controls

Summary: The iPad root is the Mac's `RootView` with the iPad's feature flags (no agent sessions, read-only pipeline graph), a 0.9 default text scale, 44 pt hit areas, a touch-draggable sidebar handle and long-press equivalents for hover tooltips.

## What changed

- `MonitorCore/PlatformFeatures.swift`: `agentSessions`, `graphEditing` (`.mac` all on, `.iPad` both off), `iPadTextScale = 0.9`, `minTouchTarget = 44`.
- `MonitorModel.init(preferences:defaultTextScale:)`: the default applies only when no scale is stored, so the user's preference is kept. `MasonIOSApp` passes 0.9 on an iPad, 1.0 on an iPhone.
- `RootView(model:features:)` puts `features` in the environment. The iPad passes `.iPad`.
- Features off, the controls are absent, not disabled: `ActionButtons.offered` drops `open_session`; `EditorPage` shows only the read-only Graph (no tab picker, Undo/Redo/Discard/Simulate/Apply, palette or inspector; nodes do not select or drag).
- Touch: `touchTarget()` (min 44 x 44 frame plus `contentShape`, a no-op on the Mac) on the top bar, sidebar rows, pills (action buttons), copy buttons and the limit steppers. The sidebar handle gets a 44 pt overlay strip with the same drag (the layout width is unchanged). `.help` became `.hint`: `.help` on the Mac, a long-press context menu on iOS. Hover cursors stay for a pointer on the Mac.
- Landscape only on iPad comes from the existing `UISupportedInterfaceOrientations~ipad`. Split View at half width is a compact class, which `RootChoice` already maps to the phone layout.
- Tests: `IPadLayoutTests` (scale default, fit at both sizes, home and task page render, session and edit controls absent).

## Text scale choice

0.9, the starting point named in the ticket. The top bar fit measure and the sidebar `fit` are asserted at 1366 and 1180 pt at that scale.
