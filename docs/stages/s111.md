# s111: notice a hung agent: alert on long silence, then stop and resume it

Summary: An agent that produces no output and has no contract call in flight raises an alert after `agent_idle_alert_s` (default 45 min) and is stopped and continued through the lost-host path after `agent_idle_stop_s` (default 90 min), counting toward the two restarts.

Settings `agent_idle_alert_s` / `agent_idle_stop_s` in the project file (0 = off). `ContractHandle::call_in_flight` makes a running `run_check` not silence. `hosted::attach_as` runs the watcher (`watch_idle`) and leaves a `silent` note in the host directory; `lost_invocations` counts such invocations, `settle_all` resumes with a silence note. The alert is `silent:<run>` in `attention::alerts_now` (a trust file: one alert added, nothing about who may answer changes). See decision 0097.

Tests: `crates/daemon/tests/idle.rs` (alert and clear; stop and resume; third stall fails; slow `run_check` triggers neither), `scripts/exit/s111.sh`.

Not verified: the real claude/codex CLIs going silent (only the scripted agent); the direct non-hosted adapter path has no watcher; the default limits against real runs beyond the 35.8-minute figure in the task; behaviour of the stop on a machine so loaded that an agent is silent at startup for longer than the limit (tests use limits of seconds).
