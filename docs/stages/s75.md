# s75: Release or reassign a blocker: unblock, block, revive, and the monitor buttons

Summary: The owner can now free a task held by a cancelled or failed blocker, add blockers to one that has not started, and revive a cancelled task, with `mason task unblock | block | revive` and matching buttons in both monitors; for tracker-imported tasks GitHub stays the source of truth, with the owner's release kept until the relationship on GitHub changes.

## What was wrong

A task blocked by a cancelled or failed task stayed held forever: nothing the owner could do released it or pointed it at another blocker, and `mason task retry` does not revive a cancelled task (the reducer refuses `Retried` from `Canceled`).

## What was built

- **Events** (additive): `BlockersChanged { task, released, added }` and `Revived { task }` (core, reducer, codec, `views.rs`). New `ReduceError::NotABlocker`. The matrix test grows from 11 x 21 to 11 x 23 pairs; none removed.
- **Store**: migration 21, `tracker_overrides`, `tracker_relationship` (+ `_seen`), with accessors. Written by the daemon, not rebuilt by replay, like `tracker_deps`.
- **Daemon**: `blockers.rs` (release, block, revive, origin, the held line, the alert text); `POST /tasks/{id}/unblock | block | revive` (403 non-owner, 409 past queued or not revivable, 422 cycle naming the path); ws `Command.unblock | block | revive`; `allowed_actions` gains `block`, `unblock`, `revive`; the tracker sync respects releases and additions and lapses releases when GitHub's relationship changes. The dead-blocker alert is now made from the world in `alerts_now` (kind `blocked`) and clears by itself.
- **CLI**: `mason task unblock <id> [--from A,B | --all]`, `mason task block <id> --after A,B`, `mason task revive <id>`, all with the owner's identity as `approve` takes it; `mason task show` prints the held line with the commands, each blocker's origin, and says `revive` puts a cancelled task back.
- **Protocol**: `Command` 16, 17, 18; `TaskRow.blocker_links = 24` (`BlockerLink`). `mason.pb.swift` regenerated with `scripts/gen-clients.sh` (`protoc` and `protoc-gen-swift` were installed).
- **Monitors** (parity): Release per blocker, Revive or Retry on a dead one, Add blocker with a task picker, owner only; conformance items `blocker:` and `add-blocker:`; `features.toml` `task-release`.
- Decision record `docs/decisions/0061-blocker-release-readings.md`.

## Tests

Reducer: release one of two keeps it held, release all makes it claimable (wakes the scheduler), a cycle is refused naming the path, a started task is refused, a non-blocker release is refused, retry on a cancelled task is refused, revive only with a kept branch, a replay test. Codec round trips (25 kinds). Store accessors. Tracker (recorded relationships): a release survives later polls and lapses on a change, an addition survives GitHub edits, origins are marked. Daemon: HTTP and ws refuse a non-owner, cycle 422, started 409, alert once and cleared. Swift and Kotlin core tests for items, commands and the picker.

## Exit test

`scripts/exit/s75.sh` against a real `masond` and `fake-github`, command steps standing in for the agent: the five scenarios pass (output: `s75 OK`).

## Not verified

See the decision record: the apps were not launched, so the new controls were not seen on screen; no real model, no real GitHub. One Compose test (`aStalledDaemonShowsReconnectingNotAnError`, a timing test) failed in a full Gradle run and passed alone; it does not touch this change.
