# s295: introspection findings are proposed or queued by severity and cost

Summary: `[proposals.introspection]` (keys `low_small`, `low_large`, `high_small`, `high_large`, each "proposed" or "queued") decides whether an introspection finding waits for the owner or runs; the proposal records the rule that decided it, and the weekly analyst's task is recognised by its schedule row instead of its title.

Decision 0289 records the choices.

**What changed.**
- `crates/core/src/proposal.rs` (pure): `Impact`, `Cost`, `IntrospectionPolicy` (default: everything proposed) and a `Policy.introspection` field, with tests for the mapping and the keys.
- `crates/core/src/introspect.rs`: `Finding` gains `impact` and `cost`; `estimate(rule)` sets them for detectors; an analyst `Draft` may give `severity` (low or high) and `cost` (small or large), absent means high and large, anything else is refused with a reason naming the field.
- `crates/daemon/src/proposals.rs`: `parse_cfg` reads the nested table (unknown keys and bad values are load errors); `Filing.estimate` makes `file` take the disposition from the table; the row's `severity` is low or high for findings and `decided_by` names the rule (`proposals.introspection.low_small`, or `proposals.agent_normal` / `agent_blocks` otherwise). `row_json` returns `decided_by`; `mason proposal show` prints it.
- `crates/store`: migration 36, `proposals.decided_by`. Additive.
- `crates/daemon/src/introspect.rs`: `ingest_analyst` reads the file only for the task recorded as `last_task` of the `analyst:<project>` schedule row, so a renamed analyst task is read and a task that merely carries the old title is not. The analyst prompt describes `severity` and `cost`.
- Duplicate, evidence and cap rules and `selfguard.rs` are untouched. `scripts/exit/s295.sh` is new; no existing exit script changed.

**Detector findings are estimated high and large for now**, so the `queued` option reaches only analyst findings until the rules estimate cost.

**Behaviour change to know about.** Introspection findings used the `agent_normal` setting before; they now follow `[proposals.introspection]` only, which defaults to proposed. A project that set `agent_normal = "queued"` and relied on that for findings must set the new keys.

**Not verified.** The `cargo test` runs below were done through the pipeline's check, not by hand here; nothing was run against a live daemon, and the monitor does not show `decided_by` yet (the settings-page task follows). The tracked stray file `crates/daemon/src/introspect.rs-e` (merge-conflict markers, not compiled) was left alone.
