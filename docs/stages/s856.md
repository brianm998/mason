# s856: a GitHub run is one wave of jobs

Summary: a remote run now starts by pushing its snapshot ref and dispatching the run workflow on it with the runner and shard list as inputs, so there is no `plan` job and the run waits for a runner once.

Task #824. Decision 0849.

## Built
- `.github/workflows/mason-run.yml` and `templates/github/mason-run.yml`: `workflow_dispatch` with inputs, no push trigger, no `plan` job; a first step refuses inputs that differ from `.mason/run.json`.
- `remote::execute`: push, then `dispatch` (inputs from `dispatch_inputs`, derived from `run_json`); `State.dispatched`; a restarted daemon finds the run by SHA and dispatches only if none exists. A refused dispatch deletes the ref and fails environmentally. `snapshot` refuses a base workflow of ours that runs on push.
- `runref::dispatches`, new `workflow_problems` (needs dispatch, no push trigger), `GitHub::workflow_active`, and a doctor finding for it.

## Tests
- `execute_pushes_the_ref_then_starts_the_run_once_with_the_runner_and_shards_of_the_spec`, `a_restarted_daemon_finds_the_run_by_its_sha_and_does_not_start_it_again`, `a_dispatch_github_refuses_leaves_no_ref_and_no_record`, `the_run_workflow_is_one_wave_that_refuses_inputs_that_differ_from_run_json` (daemon); `the_dispatch_trigger_is_read_in_each_form` and the changed workflow_problems tests (adapters); doctor tests.
- Exit test `scripts/exit/s856.sh`.

## Not verified
- No real GitHub run: that `workflow_dispatch` on a branch ref runs the file from that ref, and that the first-step check works, are untested outside the file-text test. GitHub only dispatches a workflow it already knows from the default branch, so the new workflow must land on the base branch before runs use it; until then runs fail environmentally (doctor says so).
- The doctor cannot test the token's Actions write permission without dispatching.
