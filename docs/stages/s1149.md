# s1149: pages/deploy red on develop

Summary: `pages/deploy` fails because GitHub Pages is not enabled for the repository with GitHub Actions as its source, which is an owner setting, so no code changed and the check stays red until the owner enables it.

Cause

The `actions/configure-pages` step (`.github/workflows/pages.yml:29`) calls "Get a Pages site" and gets Not Found: "Please verify that the repository has Pages enabled and configured to build using GitHub Actions". Reported in run 45746796254 on commit 54bf7408f9bc441d348cfb18634768a63236d4f6. s226 already lists the setting as an owner action (`docs/stages/s226.md`).

Owner action

1. Set Settings > Pages > Source to GitHub Actions.
2. Run the `pages` workflow again from the Actions tab (it has `workflow_dispatch`).

The red on `develop` will not clear until this is done. Landing this note does not fix it.

Optional follow-up

Add `enablement: true` to the `configure-pages` step in `pages.yml`. That file is a protected path and needs the owner's approval. Whether the workflow's `GITHUB_TOKEN` may enable Pages was not verified, so the change is not made here. See `docs/decisions/1138-pages-site-not-enabled.md`.
