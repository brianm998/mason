# s1175: a busy task is flagged, and one waiting health session no longer blocks the loop

Summary: The health check raises `stuck:long:<id>` for a task in one state for hours or on more than six check rounds however busy it is, a health session waiting for the owner no longer blocks new ones (and times out after `needs_owner_ttl_m`), and health-sourced proposals bypass the weekly self-task cap.

See decision 1165. Not verified here: the exit script's daemon run (it needs a real clock past six hours, so it seeds check rounds instead); the `restart_round` action against a live agent.
