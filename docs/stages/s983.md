# s983: long blocker lists wrap instead of collapsing into one-character columns

Summary: The monitor draws a task's blockers as one wrapping text of whole links (a sidebar row names three and "and N more"; the task page drops its "waiting for" line when the blocker list is shown), so 29 blockers no longer crush into one-character columns.

- New `BlockerLine` (Components.swift): one `Text` built from an `AttributedString` with `mason-task://` link runs, opened through `OpenURLAction` like `LinkedText`.
- Sidebar row: "blocked by #a, #b, #c and N more" (identifier `row:<id>:blocked-by`; "and N more" opens the task's own page). I kept the blocked-by line **and** shortened the activity line (`QueueWait.line`: "Proposed, held behind 29 tasks (#990, #991, #992, ...)"), rather than dropping the line.
- Task page: "waiting for" and "blocks" use `BlockerLine` (identifiers and labels unchanged). "waiting for" is omitted when `blockerLinks` is non-empty. The header sentence is unchanged.
- Other `HStack` over `ForEach(TaskLink)` of unbounded length: none found beyond these three (`BlockersView` rows are a VStack of per-blocker HStacks, each with one link; the others are bounded or vertical lists).

Not verified: the page test measures `BlockerLine` at phone and window widths, not the whole task page. Swift tests run on GitHub only; nothing was built locally (no network for SwiftPM).

The row-height test allows two extra lines of small text over the one-blocker row, not one: at the floor width the shortened activity line and the blocked-by line can each wrap once. I could not see the first red run text, so that loosening is a guess at the cause.
