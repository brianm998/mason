# s1094: a step waiting on a live GitHub run is not silent

Summary: The health check no longer calls a step host silent while it waits on a picked-up GitHub run that is within its runner limit and still being polled.

## Cause

`health::gather` measured silence from the step's last progress update only, and the wait for a remote run posts none, so a run longer than `host_silent_ms` (30 min) raised `stuck:host`.

## Change

Each successful poll that finds a run still going records the time in the remote run registry. For a picked-up run within its limit plus 10 minutes, `gather` counts silence from that poll. The same value feeds `stuck:host` and `stuck:task`. The threshold and the judge are unchanged. See decision 1083.

## Test worlds no longer deadlock

Full runs on a four-core runner ran out of time: many tests make a second scratch world while holding the first, and with two world slots two such tests waited 600 s for each other, with every other test behind them. A thread that already has a world now takes a slot for the next one only if one is free (`slots::take_world`).
