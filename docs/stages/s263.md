# s263: a skip ends a suite's wait for its slot

Summary: A suite (or its whole step) skipped by force while it waits for its build or run slot now stops waiting at once and takes no slot; its run reports "skipped by force" straight away. Before, the skip was only checked once the slot was granted and the build had started.

## Why

On 2026-11-13 the owner skipped #288's test step because it was about to run 1,705 tests. The skip was recorded (debt #57), but the step was in line for a compile slot, and `jobs::acquire_needs` only stopped waiting if the task's run closed. So #288 waited until a slot came, started its build, and only then saw the skip, holding a compile slot other tasks were waiting for.

## What changed

- `crates/daemon/src/jobs.rs`: `acquire_needs_while(c, needs, wanted)`, whose wait also ends when `wanted` says no. `acquire_needs` calls it with `|| true`.
- `crates/daemon/src/suites.rs`: `lease_suite` waits for a suite's build and run slots with the suite's own skip check (`Who::check`). A skip before or during the wait gives `Leased::Skipped`: the build is not run and `run_suite` reports the skip without holding anything.
- Test: `a_skip_ends_the_wait_for_a_build_slot_and_takes_no_slot` in `crates/daemon/tests/testing.rs`. The only compile slot is held outside the step for the whole test; the step is skipped while it waits, and the task lands with the slot still held outside.

## Not verified

The step-wide lease (a test step whose suites have no `build`, which holds one lease for all of them) still waits without looking at skips; mason's own test step builds per suite, so it is covered. The skip check runs on the broker's liveness check, every 400 ms per waiting step, and reads the debts table each time.
