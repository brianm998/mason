# s401: a develop agent that keeps committing gets more time, and a timeout says how its time went

Summary: a develop step's deadline grows by a quarter of its budget each time it is about to end and the agent has committed or produced output since the last look, up to one extra budget in total; a step that still runs out of time says in its failure note how long it waited in queues, worked, and sat silent.

## What was measured, and what was not

The task asked for a measurement of the develop steps that ran out of time since s363. **I did not do it.** This session had no access to the daemon's store, events or journals, only the source tree, so I cannot say whether queue time (which s363 now credits) was the whole cause. What I did instead is make the next timeout answer the question itself: the failure note now carries the breakdown, so the first timeout after this lands is the measurement.

## Change

- `crates/daemon/src/deadline.rs`: `Extender` (pure; clock, branch head and an output counter are passed in) and `timeout_note`.
- `DeadlineExtra` keeps queue credit and progress grants apart (`waited`, `progressed`; `get` is the sum, so both adapters' watchdogs are unchanged).
- `jobs.rs`: a develop step runs a one-second ticker that calls the extender with `git rev-parse HEAD` and a count of agent output chunks and events. A grant is made within 120 s of the end (or a quarter of a short budget). Each grant is budget/4; the total is capped at one budget, so working time is at most twice the budget plus queue credit.
- The timeout note reads: elapsed of budget, queue credit, progress grant, waiting, working, silence at the stop, commits on the branch.

## Not verified

- No real-agent run; the extension is exercised with the fake agent only.
- Lease waits (`get_lease`) are not credited and not measured; the note says so.
- Output counts as progress, so an agent looping with output but no commits is extended until the cap. The cap bounds it; if that proves too generous, drop output from the signal.
- "Silent" counts from the last agent event or output chunk seen by the daemon; a reattached session restarts the clock.
