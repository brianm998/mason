# s1074: the exit-script runner reaps what a script leaves behind

Summary: run-exit-scripts.sh runs each exit script in its own process group and ends the group when the script ends, so a leftover child or watcher `sleep` can no longer hold the output pipe and stall a shard.

## Cause

Each script's stdout is a pipe into `tee`, which reads until every process that inherited it has gone. In run 45361042086, on macOS (no timeout(1)), s06 printed `s06 OK` but its recorded time was 3601 s: the killed watcher's `sleep 3600` was orphaned with the inherited stdout pipe, and the job was cancelled before s11 ran. Any child a script leaves running with stdout inherited stalls the runner the same way.

## Change

The watcher's stdio goes to /dev/null and its `sleep` is killed first (also s1068). Each script now starts in its own process group with stdin from /dev/null; when it ends, the runner sends the group TERM, then KILL after about 2 s. INT, TERM and HUP are passed on to the group. `exit-scripts-macos` keeps the timeout-minutes 90 that s1077 set.

s06's cleanup reaps its step host with `step-host-ctl reap` (output silenced, `s06.sh:12`); the group reap is the backstop for what stays in the script's group, such as a daemon it started. A step host has its own session, so only the script's own cleanup ends it.

## Tests

`scripts/exit/s1074.sh`: no watcher `sleep` left, FAILED and `(over N s)` reporting, and a script that leaves `sleep 600` behind (with a limit and without).
