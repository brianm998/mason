# s560: Swift monitor views follow only the data they show, and unchanged writes do not redraw

Summary: The Swift monitor's `MonitorModel`, `LiveState`, `CpuModel` and `TaskProgress` are `@Observable`, views take the model as a plain `let` (`@Bindable` where they bind), and daemon-fed writes (`lastResult`, `connected`, `header`, `home`, `usage`, …) are skipped when equal, so an announce claim or an identical view redraws nothing.

**Change.** `ObservableObject`/`@Published` became `@Observable` (Observation framework); caches, revision counters, closures and `liveScroll` are `@ObservationIgnored`. `@ObservedObject var model` became `let model` (57 sites). `apply` writes only when the value differs. State that lives outside the model (pause-collapse preferences, the announcer's settings) is read through `prefsRevision` / `announcerRevision`, which replace `objectWillChange.send()`. `RemoteSession` follows `model.connected` with `withObservationTracking` instead of `$connected`. The top bar's usage lines are their own view (`TopBarUsage`), so a new usage view does not re-evaluate the bar. `RowView`'s `Equatable` short-circuit is kept.

**Tests.** `FollowOnlyWhatTheyShowTests` counts body evaluations of `TopBar`, `SidebarPane`, `SectionHeader`, `HomePage` and `RowView` offscreen: a usage view, announce claims and repeated identical views redraw nothing; one changed header redraws the bar and no row, pane or home page. The Combine-based counters in the model and row tests became `ChangeCounter` (Observation).

**Not verified.** No release build was run by hand, so the owner's 100% CPU case was not re-measured. Views not on screen in the tests (editor, settings, devices pages) were converted mechanically and compile, but their redraw behaviour was not counted. The iOS app target (`ios/MasonIOS`) was edited (`@State` for the model) but not built here.
