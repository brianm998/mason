# s579: the merge-in-progress test checks its own setup

Summary: The fixsync test for a merge in progress now runs its conflicting merge with an identity and no editor or prompt, and asserts MERGE_HEAD and an unmerged entry exist before calling sync, reporting the merge's output if the setup fails.

Test-only change; `merge_clean`, `Reds::sync` and `BaseFold` are unchanged. The Linux failure was not reproduced here, so the setup is made deterministic and self-diagnosing: if it still fails on CI, the message now says whether the merge or the code under test is at fault.
