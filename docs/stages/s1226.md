# s1226: a read-only session confirms blocking review findings before a send-back (task 1134)

Summary: when a review step submits `changes`, the daemon first runs a short read-only validation session (Read, Grep, Glob; `validate_model` default Sonnet, `validate_effort` default medium). It answers `confirmed` or `not_confirmed` for each blocking finding. At least one confirmed: the task is sent back with only the confirmed findings blocking. None confirmed: the review counts as an approval, every finding a minor note marked "not confirmed by validation", and `review_overruled` goes to the health log. A failed or out-of-budget session leaves the reviewer's verdict unchanged.

**Built.**
- `adapter-api/src/contract.rs`: `StepKind::Validate` (read-only), tool `submit_validation` (terminal), its checks.
- `daemon/src/validate.rs`: prompt (task and plan fenced as data, diff, findings; says `not_confirmed` is an acceptable answer), session, `resolve`.
- `jobs.rs` `finish_agent_inner`: runs the validation before a `changes` verdict concludes.
- `config.rs`: `[review] validate` (default true), top-level `validate_model` / `validate_effort`, like `diagnose_model`.

**Tests.** `tests/it/review_validate.rs` (one of two confirmed, none confirmed, session gives no verdict, `validate = false`); unit tests in `validate.rs` and `contract.rs`.
