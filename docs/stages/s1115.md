# s1115: the node doctor finds cargo where jobs do, and docs/nodes.md setup gaps

Summary: `mason node doctor` looks for tools on the `PATH` a job gets (so rustup's `~/.cargo/bin` counts) and names `rustup default` when no toolchain is chosen, and docs/nodes.md gains the missing default toolchain, plist `PATH`, `mason` wrapper (now written by `export-runtime`), firewall path and export command.

## Cause

The doctor ran a bare `cargo` on its own `PATH`, which under `sudo -H` and the LaunchDaemon lacks `~/.cargo/bin`. Jobs add that folder, so a working node refused all work.

## Change

- `node_run::job_path` builds the `PATH` for both a job and the doctor. The doctor passes no shims (they only wrap `caffeinate` and `xcodebuild`).
- The doctor runs `cargo`, `xcode-select` and `java` from `$HOME` with that `PATH`. `gather_in` takes the environment, for tests.
- `mason node export-runtime` also writes `<out>/mason`, the node user's wrapper.
- docs/nodes.md: sections 1.2, 1.3, 1.5, 1.7 and 1.8.

## Not verified

- Nothing was run on a second Mac: no node set up from the revised guide, no real rustup without a default, no LaunchDaemon, no `sudo install`, no firewall command.
- The firewall path is the app's launcher, as the task asks. The launcher execs `runtimes/<sha>/masond`; whether the application firewall judges that binary instead was not checked.
- The coordinator's export command was not run (it is a signed cross build).
- The integration test skips its no-cargo case on a machine that has a `cargo` in a system folder.
