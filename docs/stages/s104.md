# s104: say when no notification channel works with no monitor open

Summary: `GET /notify` and the claim answer carry `reaches_without_monitor`, and `mason doctor`, `mason notify status` and both monitors' notification settings say once when no push, email, webhook or daemon speech would reach the owner with no monitor open.

Out of the box only an open monitor can get the owner's attention, and nothing said so. `Settings::reaches_without_monitor` is true when push, email or a webhook is set up, or daemon speech is on with a command. `mason doctor` warns when it is false and shows the `[speech]` and `[ntfy]` lines that fix it; `mason notify status` prints the same one-line sentence; the monitors read the flag from the claim answer they already poll and show the line on the sound and speech settings only when it is false. A routed remote channel that is not set up is no longer written to `deliveries` as a failure on every alert.

Tests: `crates/daemon/tests/notify.rs` (each configuration; no failed delivery rows), doctor unit tests in `crates/cli/src/doctor.rs`, `SpeechTests.swift`, `SpeechTest.kt`, `scripts/exit/s104.sh`.

`clients/features.toml` is unchanged: the line is part of the existing speech-settings feature.

Not verified: the line's appearance in either running app (only the cores are tested); the Kotlin test was not run if gradle was unavailable here.
