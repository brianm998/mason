# s115: Alert when the whole pipeline stops moving

Summary: A `stalled` alert is raised when tasks are outstanding and neither the event log nor any running step has moved for `[stall] after` (default 30m, 0 off), naming the likeliest reasons, routed to every channel.

- `attention::stall_check` is a pure function over the tasks, the last event time, the running steps' last output times, the clock and the threshold. Outstanding work excludes proposed, failed, finished, owner-waiting, blocker-held and paused tasks, and tasks waiting for a future `not_before`.
- `alerts_now` reads the last event's timestamp (store reader), the live progress records and the scheduler snapshot. No git, no repository lock. It sits in the attention thread, which already runs apart from the definitions thread (s88).
- The text gives the quiet time, the task count, then the disk alert text, active account holds and up to three distinct scheduler wait explanations.
- Routed like `daemon_down` (all six channels at once); sounds as "broke"; in both monitors' default speech lists and settings labels.
- `scripts/exit/s115.sh`; daemon test `tests/stall.rs`.

Not verified: the Swift and Kotlin monitor changes were not built. A monitor that already saved a speech list does not gain `stalled` automatically (the one-time migration marker has already been set); the owner can tick it, and the daemon's own routing is unaffected. The exit script drives the alert list through `alerts_now` in a real-daemon integration test (as s85 does), not through the `mason alerts` CLI, and uses `after = "1s"`, not `"2s"`. The "scripted agent goes quiet" case is covered by a task that cannot start (disk below floor), not by an agent that stalls mid-step.
