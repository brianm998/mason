# s484: the APNs token cache is keyed on the key

Summary: The APNs provider-token cache now also compares a SHA-256 fingerprint of the key, so parallel tests (or a changed key) no longer get a token signed by another key.

## What changed

- `crates/adapter-api/src/apns.rs`: `Cached` holds a key fingerprint; `cached_jwt` reuses a token only when fingerprint, key id, team id and age match. New unit test for two keys with the same ids.
- `docs/decisions/0477-apns-token-cache-per-key.md`, `scripts/exit/s484.sh`.

## Trust

No protected paths touched.

## Not verified

The diagnosis was made by reading the code; the pipeline's test step is the check.
