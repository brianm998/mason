# s777: a run_check on GitHub builds and tests in one run (#771)

Summary: A run_check that goes to GitHub sends the suite's build and the tests as one run (`RunSpec.build` plus `command`), so one runner compiles once; a red build still reads "Building the tests failed" with its output.

`jobs.rs` (`check_unskipped`): when the check goes remote and no build run is already pending, the separate `{prefix}build` run is skipped and the build is carried in `CheckSpec.build`, which `hostedcheck::remote_check` puts in `RunSpec.build`. Local checks keep the build-then-tests split (decision 0130). If a folded run falls back to this Mac, the local command is `(build) && (tests)`.

`result.json` gains `phase` (`build` or `run`), written by `.github/workflows/mason-run.yml` and its template; `remote.rs` reads it into `Finished.phase` and `CheckOutcome.phase`. The daemon uses it to word a red build as before and to call `record_build_green` / `record_build_red` for the tree (a pass or a `run` phase is a green build; only an explicit `build` phase is red; no phase records nothing).

Trust: the workflow change is in a protected path and needs the owner's approval. Without it `phase` is absent and a red folded run reads as a test failure, with the full output.

Not verified: I could not build or run anything here (cargo is refused in the shell). The unit tests and `scripts/exit/s777.sh` were not run by me beyond `run_check`; the workflow's bash edit was not run on a real runner, and the exit script was derived from s748 without being executed.
