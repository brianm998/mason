# s706: a remote executor, so a suite or check can run on GitHub Actions and give the same result (#697)

Summary: A suite run or a `run_check` can now be executed by a GitHub Actions workflow instead of on this Mac and returns the same `Ran` / `CheckOutcome` (so the same code judges it), through a snapshot commit with the base branch's workflow and a `run.json` written from the pinned definition; nothing selects it yet (every run answers `Local`) until #698.

**What exists.**

- `crates/daemon/src/remote.rs`: `executor_for` (the one function that answers `Local` for every run; a test can force a project with a `[remote_runs]` section through `MASON_TEST_FORCE_REMOTE=1` in the daemon's own environment), `snapshot`, `execute` and `run_or_fallback`.
- Snapshot: a temporary `GIT_INDEX_FILE`, `read-tree HEAD`, `add -A`, then the overlay (every file under `.github/workflows/` removed, the base branch's `mason-run.yml` blob put back, `.mason/run.json` written), `write-tree`, `commit-tree -p HEAD`. The worktree, its index and `HEAD` are never touched. The record `<id>.remote` keeps the snapshot's SHA beside the `tree_key` the evidence is filed under.
- Run: push to `refs/heads/mason/run/<project>/<id>` (never forced), find the run by head SHA, poll with `Poller` (ETag on the run, backoff on errors), take the `mason-run` artifact (`output.log`, `result.json`, `results/**`), write the log and the results file where a local run leaves them, delete the ref after green, red, cancelled or abandoned runs. Skip or force (the existing `stop` callbacks) cancels the run first.
- Limits: the suite's limit counts from the poll that first saw the job taken (persisted in the record); `pickup_timeout` (default 1200 s) counts from the push. No runner in time, a GitHub outage that lasts that long, a refused token, `startup_failure`, a run that ends without the artifact, and a base branch without the workflow are environmental: `run_suite` waits as for a missing device, charged to no task. `fallback = "local"` takes the local path instead.
- Restart: `<id>.remote` (ref, SHA, run id, collected or not) lets a daemon that restarts collect the same run; a collected record answers again without a second run.
- Config: `[remote_runs]` in the registration file (`config.rs`, `RemoteCfg`): `kind = "github-actions"`, `repo`, `token`, `api` (default from `[ci]`), `workflow`, `runs_on`, `pickup_timeout` (seconds), `fallback`.
- `templates/github/mason-run.yml`: the workflow (plan job reads `runs_on` from `.mason/run.json`, run job, `if: always()` upload, rust-cache note with `cache-on-failure: true`).
- Adapters: `GitHub::{runs_for_sha, run_changed, remote_run_jobs, cancel_own_run, download_artifact}`, `may_cancel` extended to `mason/run/**`, and `Http::download` (binary-safe; `Curl` uses `-o`).
- Tests: `remote.rs` (snapshot, green, red with results file, skip while queued and running, pickup timeout and fallback, outage and refused token, missing artifact, limit from pickup, restart collects the same run), `suites.rs` (`remote_tests`: same `Ran`, same verdict green/red with names/vacuous), `config.rs`, `crates/adapters/tests/github.rs`. `scripts/exit/s706.sh` starts `masond` against the extended `fake-github`.

**Judged by the same code.** A remote run returns the same `Ran` (or `CheckOutcome`) that a step host does, so `judge_ran_with`, evidence, reruns, flaky, baseline and known-red handling are unchanged and untouched. The snapshot's workflow file and run spec come from the base branch and the pinned definition, never from the task's tree.

**Trust.** `crates/daemon/src/suites.rs` is protected (verdict logic: running suites). The change there is only where output is obtained: a `project` argument on `run_hosted`/`run_hosted_resuming`, a dispatch at the top of `run_hosted_resuming`, `run_remote`/`remote_ran`, `Ran::ran_on` (a note), the environmental arm in `run_suite`, and a test. No verdict, limit or gate was changed. `landing.rs` is not touched.

**Not verified.** Nothing was compiled or run: the owner skipped testing for this task and `cargo` is refused in this worktree, so the Rust, the tests and `scripts/exit/s706.sh` were only read, `rustfmt`-parsed and `bash -n`-checked. The workflow template was never run on GitHub (`jq`, `tar`, `eval` of the env block, `timeout-minutes` with an expression, `fromJSON(runs_on)` for an array value). `unzip`'s exit code 11 for an absent optional member and the Linux runner's `unzip` were assumed. The check seam (`hostedcheck::remote_check`) has no test of its own. A run lost on GitHub is run again, not resumed; a remote check gives no live counts. Large outputs are held in memory (as a local run's output already is).
