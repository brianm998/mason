# Stage 158: a refused push holds landing; the owner chooses the SSH key

Summary: A push the host refuses for credentials no longer fails the task: masond honours the repository's `core.sshCommand`, holds that project's landing with a `push-auth:<project>` alert naming the account GitHub saw, and the owner picks (and unlocks) the right SSH key from either monitor or `mason ssh-key`.

**What was built.** `git.rs`: `core.sshCommand` is the base of masond's ssh command; `auth_failure`. `ssh_keys.rs` (new): hold, lift, alert, key list, choose, unlock. `landing.rs`: a refused batch delivers `Verdict::Held`; `jobs.rs` waits out the hold and resubmits. Routes `GET /projects/{p}/ssh-keys`, `POST /projects/{p}/ssh-key`. `mason ssh-key list|use`; `mason doctor` probes each remote. `packaging/mason-askpass.sh`. Both monitors: a `push_auth` banner with **Choose SSH key…** and a key sheet; `[feature.push-auth-key-picker]`; the demo's checkpoint 12 holds `web-api`. Decision 0153.

**Files, and why.** `crates/daemon/src/landing.rs` is PROTECTED (batch end and verdicts): **it needs the owner's approval**; the change is one check at the end of a batch and one verdict. `store` gets `remove_pauses_of` so only the push-auth hold is lifted. `views.rs` shows the hold as its own banner. `conformance.rs` and both `Items` files list the action as an item.

**Tests.** `crates/landing/tests/ssh_config.rs` (fake ssh sees the base command and the appended options); `auth_failure` unit tests on the real #171 stderr. `crates/daemon/tests/push_auth.rs`: a pre-receive hook refuses with the #171 text, the task stays out of Failed, landing is held for that project only, the alert names `brian-preffect`, a failing probe keeps the hold and returns the reason, a good probe lifts it and the held batch lands. `tests/ssh_keys.rs`: `on_owner_account` from a stubbed `.keys`, `encrypted` with and without a passphrase, the unlock through a fake `ssh-add` and askpass with the passphrase absent from every result. Exit test `scripts/exit/s158.sh`.

**Not verified.** The Swift and Compose code was not built or run here, and the conformance run was not made. The osascript dialog and the Keychain were not exercised (no `ssh-add --apple-use-keychain` run); `ssh -T` against GitHub and the live `.keys` page were not called. The Homebrew formula's `mason-askpass.sh` install line assumes the release tarball carries the script.
