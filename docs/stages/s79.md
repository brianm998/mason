# s79: a resizable left panel, with Home and search pinned

Summary: Both monitors let the owner drag the divider between the left panel and the main view (220 to 640 before text zoom, the main view keeps 360, remembered per device), and Home and search stay pinned above the scrolling list.

## What changed

- `clients/tokens.toml`: `sidebar_width_min`, `sidebar_width_max`, `main_width_min`, `sidebar_handle`; generated token files regenerated.
- `MonitorModel` (Swift and Compose core): stored base width (`sidebarWidth` preference, default 300), clamp on set and restore, zoom factor `min(scale, 1.5)`, `fit`.
- `SidebarLayout` (both cores): the scrolling entries and the pinned ids; both views render from it.
- Views: pinned header (Home, search with name/title/body) above the scrolling list; an 8-wide handle drawn as a thin line with a horizontal-resize cursor; main view reflows live. Phone layouts untouched.
- `clients/features.toml`: `sidebar-resize`, done in both. Decision record 0065.

## Checked

- Compose: `gradle test` passes, including the new tests (clamp, restore, default, zoom, fit, pinned/scrolling split, tile target).
- `conformance tokens --check`, `conformance features`.

## Not verified

- **Swift was not compiled or tested here**: the sandbox cannot fetch swift-protobuf, so only `swiftc -parse` (syntax) was run on the Swift files. The Swift tests are written but unrun.
- Neither monitor was run against `masond --demo`; drag, cursor, relaunch, scroll-with-pinned-header and tile click are hand checks (`scripts/exit/s79-manual.sh`). The conformance accessibility-tree runs (s12, s13) were not run here either.
