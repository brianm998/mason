# s651: the ten-compiles test failure on develop was the Debug-string check, already fixed

Summary: The red `ten_compiles_behind_a_waiting_exclusive_lease_all_name_it` at 386e8e4b was the test matching "510" in epoch-ms text, which 159f33a7 already replaced with a task-id check; this stage records that and adds a repeat-run exit script.

**Cause.** At 386e8e4b, `crates/daemon/src/sched.rs:3772-3774` did `format!("{:?}", v.tasks)` and asserted it did not contain "510". The CI run's `since_ms: 1795105312602` contains "510" (`...9 5 1 0 5...`), so the assertion failed by chance. The wait view itself was right: cause `exclusive`, the lease `holding: true` in the dump is the state after the holder #510 was released, when the lease had acquired the machine.

**Fix.** Already on develop as 159f33a7 (decision 0637): the test compares the `task` field of each holder, blocker, chain party and hold entry. No production code changes here, and the test's assertions are unchanged. `scripts/exit/s651.sh` runs the test repeatedly.
