# s385: short work runs while the machine drains for an exclusive request

Summary: when a request for the whole machine (`exclusive`) waits for the current holders to finish, later work that is sure to be done by then may run in the meantime. "Sure" means a suite build or run whose recorded times say it will finish before the latest expected end of the machine-class holders. Everything else still waits, as before: work with no estimate, work that would run past the drain, and all work if any holder has no estimate. Suites now record how long their builds and runs take.

## Why

On 2026-11-14 the CPU idled for long stretches with 40–50 requests waiting. Each time a whole-machine request (star's `test-gui`, `test-gherkin`, `test-StarCpp-qos`, a `--needs exclusive` job) came first in line, every later machine-class request waited until the holders drained, even with compile slots free. Drains waited on test suites running 10–20 minutes, so the machine sat mostly idle while compiles that take a minute or two queued behind. This is the gap that backfill in a batch scheduler fills: run what cannot delay the reservation.

## What changed

- `crates/scheduler/src/plan.rs`:
  - `Request` and `Holder` carry `expected_ms`.
  - When the first exclusive request blocks, `Blocked` records `drain_end`: the latest expected end of the machine-class holders, or unknown if any lacks an estimate.
  - A later request may pass it (`touches`) only if `now + expected ≤ drain_end`.
  - Reserved units and every other rule are unchanged.
- `crates/scheduler/src/ledger.rs`: `Ledger::set_expected`. Holders keep their request's estimate.
- `crates/store`: migration 36 (`suite_times`), `record_suite_time` and `suite_estimate`. The estimate is the longest of the last five times plus a quarter, and only with at least two on record.
- `crates/daemon/src/suites.rs`:
  - Each finished build and run records its time, from the step host's own `started_ms` and `ended_ms`, so a run collected late after a restart is not counted as instant.
  - Suite leases pass their estimate (build phase, run phase, side-by-side builds).
- `crates/daemon/src/sched.rs`: `Broker::acquire_expecting`.
- `crates/daemon/src/jobs.rs`: `acquire_needs_expecting`, which replaces `acquire_needs_beside`.
- Tests:
  - `short_work_runs_while_the_machine_drains_and_long_or_unknown_work_waits` and `nothing_passes_a_waiting_exclusive_request_when_a_holder_has_no_estimate` (`crates/scheduler/tests/properties.rs`). The aging starvation property still holds.
  - `crates/store/tests/suite_times.rs`.
  - `a_suites_run_time_is_recorded_and_gives_an_estimate_after_two_runs` (`crates/daemon/tests/scheduling.rs`).

## Not verified

On the live queue. `mason run` jobs (agents' own builds, star's `starpipe heavy` jobs) have no estimate, so a drain whose holders include one lets nothing pass. Suites build up estimates from their next two runs after this lands.
