# s705: an update no longer abandons a red landing batch's search; results are kept

Summary: A landing batch's run results are kept in the store (by base tip, task heads and filter) and reused by the next batch over the same tree, a draining update stops a batch at the next run boundary instead of abandoning it, and `mason status` shows an update waiting on a batch.

See docs/decisions/0698-keep-batch-run-results-and-yield-to-an-update.md.

Tests: `a_batch_run_is_found_again_only_for_the_same_base_and_task_heads` (store);
`a_draining_update_stops_a_red_batch_between_runs_and_the_next_batch_reuses_its_results` (daemon `it`).

Not verified: a real `masond` restart over a red batch (the test sets the draining flag itself); the monitors' view of the rewritten progress line; the exit script was not run to the end here.
