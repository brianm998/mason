# s65: Tracker imports start proposed; refused imports are visible; hand-filed tasks are adopted

Summary: a tracker import now starts as a proposed task waiting for the owner's approval (`[tracker] import_as = "queued"` restores the old behaviour), proposed filings are never refused by a self-hosting limit, an issue a limit kept out raises an alert and shows in `mason task list --pending-issues` and both monitors, and a hand-filed task titled `(GitHub #N)` is adopted instead of duplicated.

Task #39. Decision 0046 records the readings and the trust holds: `selfguard.rs` and `clients/features.toml` are protected and this waits for the owner's approval.

## Built
- **Config**: `[tracker] import_as = "proposed" | "queued"` (default proposed), read from the machine-side project file only; any other value is refused at load, naming the key.
- **Selfguard**: `check_filing_proposal` (cooldown only). `POST /tasks` with `proposed: true` and `mason task add --proposed` use it; they were refused at `max_open` before.
- **Tracker**: imports as proposed or queued; `Summary.refused`/`adopted`; the `tracker-pending` alert and `Hub::pending`; adoption of `(GitHub #N)` tasks; the relink alert for an open issue whose task was cancelled; `tracker::relink`.
- **Daemon/CLI**: `GET /pending-issues`, `POST /tasks/{id}/relink` (owner only), `mason task list --pending-issues`, `mason task relink <id> --issue N`. `/tasks/{id}/refresh` also returns `refused` and `adopted`.
- **Views/protocol** (additive): `TaskRow.issue`, `issue_url`; `HeaderView.pending_issues`; sidebar section `proposed_imports`; `why_waiting` "Proposed, held behind #N".
- **Monitors** (Swift and Compose, in parity): the section with the issue link and Approve, a "not imported" tile and a list with reasons. Conformance items (Rust, Swift, Kotlin) and `clients/features.toml` `tracker-imports`.
- **Docs**: `docs/self-hosting.md`, `docs/DESIGN.md`, decision 0046.

## Tests
- `crates/daemon/tests/tracker.rs`, listings from the recorded GitHub JSON `tests/fixtures/github_issues.json`: proposed by default, `queued` still queues, proposed never refused by a limit, the refusal alert names the issues and clears, adoption, the relink alert and `relink` (and its refusals, owner only over HTTP), a closed issue cancels its proposed task, a proposed task with blockers. The older tests that need queued imports set `import_as = "queued"`; the two polling tests no longer have a tracker section (the poll thread would otherwise raise its own alerts); nothing else changed.
- `crates/daemon/tests/selfguard.rs`: proposed filings are not refused by the limits and are not counted; the cooldown still refuses.
- Config parse test; `adopted_number` unit tests; Swift and Kotlin core tests for the tile, list and section rows.
- `scripts/exit/s65.sh`: a real masond with fake GitHubs (see the header of the script).
