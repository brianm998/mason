# s681: a converted all-compile request gets the exclusive freeze bound and backfill

Summary: A non-person `--exclusive` converted to all `compile` units (s552) now freezes only compile, gives up the freeze after `order.exclusive_max_wait_s`, and lets compile work done before the compile holders drain pass it.

## Problem

On 2026-11-19 16:55 star #669's `starpipe heavy -- ./gradlew createDistributable` became
`mason run --needs exclusive --exclusive`, queued as `compile=6` first in line. One unit was held
by #658's exit-script check for 2 h 7 min. For 88 min compile sat at 1 of 6 and 11 tasks waited.
s552 bounded and backfilled only a request that is still `exclusive`.

## Changes

- `Request::drains_compile` / `Ledger::set_drains_compile`: set by `Broker::open_lease` when
  `bound_exclusive` converted the request. A person's request and one from an
  `exclusive_origins` origin are never converted, so they behave as before.
- `plan.rs`: such a request no longer reserves all compile units (that reservation made every
  later compile request wait whatever was free). Instead, like `machine_all`, it sets
  `compile_drain` with `compile_drain_end`, computed by the same `drain_end` over compile
  holders only. Compile work whose expected end is no later than that may pass (backfill); other
  compile work waits behind it. After `exclusive_max_wait` it is `thawed` by the same code: a
  holder with no estimate counts as ending that long from now, so work with an estimate runs
  again, and the request keeps first place and starts once compile is free. Only one rule
  changes in each case: the reservation is replaced by the drain rule.
- Wait text: "converted exclusive request waited 10 min: work runs again until compile drains"
  (`Wait::thawed_compile`). A held waiter names the converted request as its blocker.

## The 16:55 case

Before: 1 holder (2 h), all-compile request first, 11 one-unit waiters: 11 waiting, 5 units
idle, for 88 min. After: waiters with an estimate done before the holder's expected end are
granted at once; any other after 10 min (test
`converted_request_gives_up_its_freeze_after_the_bound_then_goes_first`). The request starts
first once the holder ends. Waiters with no estimate still wait the 10 min, then are held
(as exclusive-path waiters without an estimate are, s552) until the holder drains.

## Not verified

The exit test with a scratch daemon and a real `mason run --exclusive` was not run; the exit
script runs the scheduler property tests and `origin_rank` instead. The unit tests use an
injected clock.
