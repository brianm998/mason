# s877: an analyst result is read once and ends the task

Summary: An analyst task ends when its develop step's result file has been read (no test, review or land, no commits kept), ingests once per task, gets no stage or decision numbers, and the digest's flaky map is per project.

Reading the result is the task's result. `finish_agent` ingests only after an accepted develop step: a parsable file files the findings, keeps a copy in the task's log directory (`analyst-result.json`, marker `analyst-ingested`), resets the worktree to the base and closes the task with no change. A missing or unreadable file sends it back to develop with the reason. A later step finds the marker and files nothing, so rewording cannot duplicate findings. The prompt for an analyst task omits reserved numbers, and its body says "Commit nothing." The digest maps flakes to projects through the task that recorded them.

Not verified: the full pipeline path (finish_agent closing the task in a pipeline with a review step) is not driven by a test; the tests cover `ingest_analyst` outcomes and the digest filter. Nothing was compiled locally; the build ran only through run_check.
