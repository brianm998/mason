# s312: MASON's own checkouts run the worktree setup

Summary: every checkout MASON makes for itself now runs the definition's worktree setup steps before it builds. That covers base profiles, base checks, negative controls, debt payments, ledger runs, scheduled checks, post-land suites and the landing worktree after each assembly. The setup steps are the `command` steps a task meets before its first change: from `start` and from `explored_entry`, past exploring agents, up to the first step of another kind (`Definition::worktree_setup`). For star that is `setup` (`.mason/scripts/link-artifacts.sh`), so star's definition needs no change.

## Why

On 2026-11-14 star task #259 failed on `test-cli`, which is red on develop as well (the suite sets `STAR_USE_GPU_FOR_MERGE=0`, and a cli test expects GPU merge on by default). The base profile should have pinned that red on the base, but its checkout had no OpenCV (`opencv2/core.hpp` not found): the links star's `setup` step makes in a task's worktree were never made there. So no red on star's develop could ever be pinned on the base. The landing worktree (`l/star-b0`) was missing the links too.

## What changed

- `crates/definition/src/model.rs`: `Definition::worktree_setup`.
- `crates/daemon/src/jobs.rs`: `setup_checkout`, which runs each setup step's command in the checkout with `MASON_WORKTREE` set and the step's `budget` (default 10 minutes) as its timeout.
- Called by `suites/base_red.rs` (profile), `suites.rs` (`baseline`, `run_new_tests_at_base`, `pay`, `ledger_run`), `basecheck.rs` (`run_at_base`), `schedule.rs` (`run_check`) and `landing.rs` (post-land and after each assembly).
- If setup fails at a base, the result is unknown, not red, and it is not cached. A debt payment or ledger run that cannot be set up fails with the step's output. In landing, a failed setup is logged and landing carries on, as it did before.
- `crates/plugins`: two clippy lints from s292 (`manual_contains`, `too_many_arguments` on `run_step`), so the workspace passes `clippy -D warnings` again.
- Tests: `worktree_setup_is_the_command_steps_before_the_first_agent_change` (unit, `model.rs`) and `paying_a_debt_runs_the_worktree_setup_first` (`crates/daemon/tests/testing.rs`). The integration test fails without the change.

## Not verified

No star base profile has run with the change yet. The next star task that hits a red on develop will show it.
