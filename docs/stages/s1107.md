# s1107: agent sessions are refused destructive git and rm commands

Summary: Every Claude agent MASON starts is refused `git` commands that destroy uncommitted or shared work, and any recursive `rm` outside what it owns, with a reason it can act on.

Task #1126, decision 1096.

## What changed

- `crates/cli/src/guard.rs` (new): reads a Bash command line (compound commands, `cd`,
  subshells, substitutions, here-documents, `bash -c`, `mason run --`, `xargs`, `find -exec`)
  and denies:
  - `git reset --hard`, `git clean -f` (not a dry run), `git checkout -- <paths>`,
    `git checkout .`, `git restore` without `--staged` (or with `--worktree`);
  - `git stash` / `stash push` without a message, `save`, `pop`, `drop`, `clear`, `branch`;
  - `git branch -D` (and `--delete --force`), any `git push`;
  - a recursive `rm` whose target is not strictly inside the worktree, MASON's agent state
    directory (`<data>/a`), the task cache or `$TMPDIR`, or cannot be worked out.
- `mason hook guard` (new) is the refusal alone. `mason hook bash` refuses first when
  `MASON_STEP_KIND` or `MASON_TASK` is set, then rewrites builds exactly as before.
- The Claude adapter writes `settings.json` beside `mcp.json`, passes it with `--settings`,
  and sets `MASON_GUARD_WORKTREE` and `MASON_GUARD_STATE`. The hook runs the `mason` next to
  `mason-mcp`; if it cannot run, Bash is refused (exit 2).

`git checkout <commit> -- <file>` stays allowed (it is the way out the message names), unless
the paths name everything (`.`, `:/`, `*`).

## What it does not stop

It reads command lines, so it prevents mistakes and is not a boundary. Not covered: scripts
and other interpreters, git aliases, `git checkout -f`, `git switch --discard-changes`,
`git checkout <path>` without `--` (other than `.`), non-recursive `rm`, `find -delete`, and
Codex or generic agents, which take no Claude hooks.

## The sandbox (owner's config change, not made here)

To try the OS boundary on one project, add `sandbox = "sandbox-exec"` at the top level of
`~/.config/mason/projects/<P>.toml`, then `mason project reload --project <P>`; `"none"` (or
removing the line) turns it off. Writes are then limited to the worktree, `<data>/a`, the
CLI's directories in `$HOME`, the project's `.git`, `/private/tmp`, `/private/var/folders`
and `/dev`. Watch:

- `syspolicyd`: `/usr/bin/pgrep -x syspolicyd` and its CPU; the sandbox changes how new
  binaries are launched, and a syspolicyd crash hangs every new non-Apple process.
- `/Volumes/sp`: a build or tool writing elsewhere on that disk (shared caches, a target
  directory, the task cache outside `<data>/a`) will fail with "Operation not permitted";
  compare with file-create stalls on the same disk before blaming either.
- The first few steps' logs for denied writes.
