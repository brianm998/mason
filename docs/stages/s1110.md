# s1110: actions pinned by commit SHA

Summary: Every GitHub Action in MASON's workflows is pinned to a full commit SHA, Dependabot proposes the moves weekly, and CI's lint job refuses an unpinned `uses:`.

## Change

- The 72 `uses:` lines in `.github/workflows/*.yml` and `.github/actions/ios-setup/action.yml` that name a third-party action now name a commit, with the release in a trailing comment. Only those lines changed in these files, apart from the new lint step in `ci.yml`.
- `dtolnay/rust-toolchain@master` is pinned to the commit `master` pointed at. Both uses still pass `with: toolchain: 1.96.0` as before.
- `.github/dependabot.yml`: `github-actions`, weekly, for `/` (the workflows) and `/.github/actions/*` (the composite actions, which `/` does not cover).
- `scripts/check-action-pins.sh` fails on any `uses:` without a 40-hex commit SHA, except local `./` actions, naming file and line. CI's lint job runs it.

## Owner approval

`.github/workflows/**` (gates: CI) and `scripts/check-*.sh` (gates: the repository checks) are protected, as is `scripts/exit/**`. The workflow edits replace moving refs with fixed commits and add one check; no gate is weakened.

## How to treat Dependabot's pull requests

They arrive on GitHub, not through the pipeline, so merging one is the approval of a CI gate change.

- Check that the new SHA is the commit of the release in the comment, on the action's own repository (`gh api repos/<owner>/<repo>/commits/<tag> --jq .sha`), and read the release notes.
- Merge only with CI green. Dependabot's runs get a read-only token and no repository secrets, and a pull request does not run `release.yml`, so a change to a release-only action is not exercised before a release.
- A major version bump needs the same care as any hand-made workflow change; close it if unwanted.

## Tests

`scripts/exit/s1110.sh` runs the check on temporary files (a tag, a branch and a 39-hex pin fail and name the line; a SHA pin and a `./` action pass), then on the repository and on a copy of `pages.yml` with one tag pin. A remote run made before this change lands carries the base branch's workflows (the trust overlay in `crates/daemon/src/remote.rs`); there, recognised by `.mason/run.json` and a `ci.yml` without the check, the script checks the composite actions only.

The check run of 2026-11-25 (on node marmot, with this tree's workflows) passed `cargo-workspace` as narrowed to the change, and `s1110`. Its `exit-scripts` run was red on s723, s724 and s727 (31 passed). This change touches none of those scripts or the code they build. s724 expects `mason doctor` wording that `crates/cli/src/doctor.rs` no longer prints; the other two were not diagnosed. They are filed separately and were not changed here.
