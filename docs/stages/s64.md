# s64: Record and show LLM usage

Summary: MASON now keeps each provider account's latest limit windows (across restarts), a bounded history of window readings, and per-attempt tokens and cost by project, task, step and model, and shows them with their age in both monitors, the top bar and `mason usage`.

## What was built

- **Store** (migration 15): `usage_latest` (one JSON snapshot per account), `usage_readings` (one per window per account per 5 minutes unless state or reset changed; rows older than 8 days dropped on write), `usage_runs` (per attempt: project, task, step, account, model, input/output/cache read/cache write, cost; NULL = not reported).
- **Recording** (`crates/daemon/src/jobs.rs`, `usage.rs`): after each attempt (the first, and each retry-ladder attempt) the snapshot becomes the account's latest and its windows become readings; tokens are stored under the attempt's run key. A snapshot is also stored when a hold begins.
- **Words** (`crates/core/src/usage_text.rs`, pure): "as of 12 min ago", "resets in 2 h 14 m, at 15:00 UTC", trend, overage, blocked.
- **View and protocol** (additive): `ProviderStatus` gained windows, overage/blocked text, age, spend, tokens for the current window and the last 7 days, `doing` ("nothing"), `adapter_name`; new messages `UsageWindow`, `SpendView`, `TokenLine`, `UsageTokens`; `UsageView.top_bar`; `TaskDetailView.step_tokens`. No number reused.
- **`GET /usage`** and **`mason usage [--account a] [--json]`**.
- **`probe_usage`**: optional, default `None`; the daemon refreshes every 5 minutes only where an adapter returns a snapshot. None does (decision 0045).
- **Demo**: five accounts (subscription with both windows, windows with no percentage, blocked, api with spend and budget, codex reporting nothing), seeded straight into the store.
- **Monitors**: the usage page draws bars, resets, trend, overage, blocked, spend against budget, tokens, and the age of each; the task page lists its steps' tokens; the top bar shows the most constrained window per account. Both clients, `features.toml` entries `usage-windows`, `usage-tokens`, `usage-top-bar`.
- **Conformance**: `conformance usage-expected` and usage items (account, adapter, billing, sessions; window label, percentage or "no percentage reported", state). Checks only; ages and countdowns are not compared.
- The fake Claude agent's `rate_limit` action can carry several windows.

## Exit test

`bash scripts/exit/s64.sh`: the word tests, the store tests (migration from 13, thinning and pruning, per-attempt tokens), `crates/daemon/tests/usage.rs` (a real daemon and the fake agent: both windows with percentages and resets after a session; the same figures with their age after a restart; a window with no percentage shows none; an `api` account shows spend against its budget and no windows; tokens attributed to project, task, step and model; `mason usage --json` equals `GET /usage`), the demo test, then `monitor-tool usage` and the Compose tool against the demo daemon compared with `conformance usage-expected`. Ends `s64 OK`; both client comparisons printed `conformance passed at 1 checkpoints` here.

## What testing found

- The Compose monitor had been showing the adapter column as a Wire `ProtoAdapter` object: Wire's Kotlin messages have a member called `adapter`. Fixed with `adapter_name` (decision 0045).
- swift-protobuf names `has_*` boolean fields `has…_p` (`hasPercent_p`); the Swift code uses those.
- `unifiedWindows` for an Opus window would show a third bar only when the stream carries it.

## Not done or not verified

- **Idle refresh**: no documented usage command was verified for Claude Code or Codex (none installed for Codex); `probe_usage` is unimplemented everywhere. Reading the CLIs' stored login tokens was deliberately not done.
- **No live provider**: nothing ran against a real Claude or Codex account. Real overage shapes (in use, used up, with a start time or cost) were not seen; "in use since when, with cost" shows only what the stream reports, which is nothing today.
- The two monitors were compiled and their usage items compared headlessly with the daemon's; the screens were **not looked at** by a person, so layout (many accounts in the top bar, bar styling) is unchecked. The Swift tests (54) pass; the Compose build and tests pass.
- Ages are fixed when a view is built and can lag until the daemon next pushes it.
- Clock times are UTC.
- "What MASON is doing about it" is always "nothing" until ticket 4.
