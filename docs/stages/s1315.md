# s1315: a test daemon does not inherit the test step it runs in

Summary: The in-process test daemon's hosts no longer see the variables of the pipeline step
that runs the test suite.

Task #1348, decision 1305. `exit_scripts_beside_the_cargo_suite_are_told_its_tests_ran` and
`exit_scripts_without_the_cargo_suite_run_their_own_cargo_parts` were red in every pipeline test
step: the test process has `MASON_STEP=test`, a host of the in-process daemon inherited it, and
the check's exit-scripts run read as a test step.

- `crates/daemon/tests/support/mod.rs` has one list, `STEP_ENV`: the step's variables and the
  exit runner's.
- A spawned `masond` has them removed from its environment, as before.
- `Scratch::start_with` now removes them from the test process, once, before `Daemon::start`.

No product code and no test expectation changed.
