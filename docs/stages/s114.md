# s114: a sound or spoken alert is delivered when a monitor plays it

Summary: Sound and speech deliveries are now recorded when a monitor (or the daemon's speech command) takes the announcement, not when it is queued, so an announcement that expires unheard stays undelivered and a monitor that claims later gets one catch-up announcement per live, unacknowledged, never-heard alert.

- `tick` still queues the announcement but no longer records `sound`/`speech` deliveries. `claim` and daemon speech call `record_played`, which reads the sound/speech flags from the announcement key (`alert:<key>:<since>:<delivery>:<flags>`) and records them. The daemon records speech only: it cannot play a sound. `landed` announcements and tests have no alert key and are unchanged.
- An expired row records nothing, so `due` still sees the initial notice as undelivered and gives no reminder for that channel. The same key stays in the table, so nothing is queued twice.
- `catch_up` runs when an unmuted speaking monitor claims: each live, unacknowledged alert with no successful sound/speech delivery and no fresh waiting announcement gets one `...:catchup:<flags>` announcement (once per alert by key), however old; if the reminder time has passed it is worded as a reminder and counts as both the initial notice and the reminder. A muted claim, a non-speaker, and a cleared alert get nothing.
- `tick_at` and `claim_at` take the time; `tick` and `claim` pass the clock.
- Status (`GET /notify`, `mason notify status`) now has `last_played`, `deliveries` (recent sound/speech rows) and per-announcement `taken_at`, `taken_by`, `played`. Store: `AnnouncementRow::played`, `last_played`, `recent_audible_deliveries`.
- Existing reminder test now has a monitor claim between the initial notice and the reminder, since a reminder follows only a heard notice.
- Tests: store (taken vs expired), core (`due` after an expired initial), daemon (no monitor records nothing; late claim gets one and records it; repeat gets none; cleared gets none; muted gets none); `scripts/exit/s114.sh`.

Not verified: the exit script and full workspace run beyond the run_check result; a real macOS monitor playing the sound; the daemon's speech is recorded when taken, before the command finishes (a killed command still counts as delivered). Catch-up honours quiet hours and per-channel delay but only for sound and speech. Coordination with #65 (thread move) was not exercised: this changes `tick` as it is on this branch.
