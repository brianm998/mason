# s240: Universal macOS .pkg and notarization script

Summary: `scripts/package/macos-pkg.sh` builds a universal (arm64 + x86_64) `mason-<ver>-macos.pkg` of the CLI, daemon, step-host, mason-mcp and askpass in /usr/local/bin, signed with `SIGN_APP`/`SIGN_PKG` when set, and `scripts/package/notarize.sh` notarizes and staples a .pkg or .dmg.

What changed
- `scripts/package/macos-pkg.sh`: reuses `pkg_build` for both targets, `/usr/bin/lipo -create`, re-signs (hardened runtime + timestamp with `SIGN_APP`, else ad hoc), `pkgbuild`, `productsign` with `SIGN_PKG`.
- `scripts/package/notarize.sh`: `notarytool submit --wait`, notary log on failure, `stapler staple`.
- `scripts/exit/s240.sh`, decision `docs/decisions/0235-macos-pkg.md`.

Not verified
- Signing, `productsign`, notarization and stapling need the Developer ID secrets; the release workflow's dry run is the check. Only the unsigned path was run here.
- `notarize.sh` parsing of notarytool's JSON (`plutil -extract status`) was not run against the real service.
