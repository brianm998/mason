# s644: the "holder is gone" check in the ten-compiles test no longer matches the clock

Summary: `sched::tests::ten_compiles_behind_a_waiting_exclusive_lease_all_name_it` compares task ids on the wait view instead of searching a Debug string that holds epoch-millisecond timestamps.

## Why

The test searched `format!("{:?}", v.tasks)` for "510". The string carries `since_ms` values, so it can contain "510" by chance and fail with no scheduler fault.

## What changed

- `crates/daemon/src/sched.rs`: after the holder is released, no row's holders, blocker or chain, and no queue hold's tasks, holders or party, has task 510. Other assertions are unchanged; no production code changes.
