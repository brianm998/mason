# s781: the idle debt pass runs each suite once per tip and settles from develop CI (#774)

Summary: The idle debt pass now picks suites instead of debts, so a suite runs at most once per base tip however many debts need it, a red suite waits for a landing that touches its red tests' modules (or `debt_red_backoff`, 24 h), and a develop CI run whose mapped `ci_jobs` all succeeded records the suite green at its commit.

**Cause.** `run_idle_debts` remembered `(project, scope, tip)` for one pass, so `tests:all`, `step:test` and `suite:cargo-workspace` each ran the same suites, and every new tip ran them again. A red marked only one debt, so the next debt ran the same suite on the same tip. `suite_proof` never read develop CI.

**Change** (`crates/daemon/src/suites.rs`, `ci_watch.rs`, store migration 45, `ci_jobs` suite key).
1. `next_pick` chooses a suite some landed debt still needs (no `suite_proof`) that has not run in this pass at this tip. `pay_with(.., Some(suite))` runs just that suite; the green is recorded and the next `settle_debts` closes every debt it covers.
2. A red is recorded in the new `suite_red` table (base, failing tests, time). Until `debt_red_backoff` (config, default 24 h) passes, the suite is held at the same tip, and at a later tip unless `git diff --name-only <red base> <tip>` has a path component named like a module of a red test (each `::`, `.` or `/` segment but the last, `-` read as `_`). A red with no test names is held until the backoff. A green clears the record. Debts a red covered get `tried_at`.
3. `[suite.X] ci_jobs = ["test (ubuntu-latest, *)", ..]`: `record_ci_greens` looks at the newest ten finished base runs; when every pattern matches a job and all matched jobs succeeded, it records `suite_green` at the run's `head_sha` and settles. The CI-watch loop calls it at most every five minutes, with or without `[watch.ci]`.
4. With remote on, a pick waits while the `gha` pool has no idle unit. A debt run already holds `gha` units at the lowest rank (#761) and shards through the suite's own `shards`.

**Not verified.** The tests were not run by me locally (`cargo test` is refused in this shell); they run through `run_check`. The module match for red tests is a heuristic on names. Nothing was run against GitHub; no suite in `.mason/mason.toml` has `ci_jobs` yet, so no mapping is live until the owner adds one (that file is protected). The debt-record red path records only tests a `Product` red named; other reds wait out the backoff.
