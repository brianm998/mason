### The GPU rule, in detail

`adapter_star.py` never sets `useGPUForMerge` (confirmed: it is not in the file). In star's code, the default is
on when Metal finds a device (`Config.swift` 387), `PixelatedImage` falls back to `true` (1038), the `star`
command line has `--no-use-gpu`, and only two tests pin it false. **No environment variable exists.** star's
`CLAUDE.md` names `~/.star.userprefs.json`, but the only reader of that file is the gui's own preferences; the
key is read from `config.json`. So the key the draft sets, `STAR_USE_GPU_FOR_MERGE=0`, does nothing until a star
change makes `Config` read it. That is decision 0119-4, and **no MASON suite may run on this Mac until it is
done.** `s27.sh` checks only that every suite carries the key, not that star honours it.

## Correction (stage 136)

This draft assumed the label alone decides what MASON imports. It never did: an issue by one of the owner's names was imported with or without the label, and the label only mattered for an outsider's. On 2026-11-11 the first poll with `[tracker] label = "mason"` imported all 34 of the owner's open star issues, none labelled `mason`. Stage 136 adds `[tracker] require_label` (default false); the star registration sets it to `true`, so an issue is imported only if it carries `mason`, whoever filed it, and starpipe's `pipeline` issues are left alone. The draft also had no `test` key (the loader requires one) and `env:` tokens (not set under launchd); both are fixed in the example. The owner still sets `require_label = true` in the installed `star.toml` and turns `[tracker]` back on.
