# s960: the Swift monitor holds redraws and page subscriptions while its window is hidden

Summary: The Swift monitor no longer publishes sidebar, header or progress to its observed model while the window is hidden or minimised, and subscribes to only header and sidebar until it is visible again.

`MonitorModel.visible` (set from the occlusion notification on macOS and the scene phase on iOS, through `SharedTick`, so there is one notion of visible) holds the newest header and sidebar in `@ObservationIgnored` slots. Side effects (`noteAttention`, `settleAfterView`, `noteMonitorBuild`, `progress.reset`) still run; `isKnownTask`, `sidebarRow`, the progress base cells and `attention` read the held value. Progress is held as the newest message per task and step. Becoming visible publishes the held values and progress once and resubscribes. `Connection.sendSubscription` names only `.header, .sidebar` while hidden.

Tests: `VisibilityTests.swift` (the four tests from the ticket); the swift-clients check passed on GitHub.

**Not verified.** The CPU time of a hidden monitor from `ps -M` before and after (10 minutes) was not measured on the pipeline host. Minimise on macOS is covered only through the occlusion notification. The Compose monitor is unchanged; it needs its own ticket.
