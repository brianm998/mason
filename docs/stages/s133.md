# s133: the compile CPU gate no longer opens when the CPU cannot be read

Summary: The CPU gate reads macOS CPU ticks with `host_statistics` instead of spawning `top`, and when there is no fresh reading it gates on the load average (and on "busy" if that fails too) instead of opening; the source and failed-read count show in the health JSON, `mason resources`, an alert and both monitors.

**Cause.** On 2026-11-11 the primary reading (`top -l 2`, 10 s deadline) failed under load, `Sampler::busy_pct` went `None` after 30 s, `cpu_gate` turned that into no gate, and 12 `cargo test --workspace` checks were admitted together.

**Change.**
- `crates/daemon/src/cpu.rs`: macOS reads `host_statistics(HOST_CPU_LOAD_INFO)` twice 250 ms apart (user+system+nice busy, idle) through `nix::libc`, via `pct_between`; `top` stays as a fallback for the primary reader only. The two `unsafe` blocks (host_statistics, getloadavg) carry a local `#[allow(unsafe_code)]` and a SAFETY comment; the workspace lint stays `deny`.
- `Sampler` takes an injected primary and fallback reader. No fresh primary reading (`MAX_AGE`, 30 s, now applies only to it) gives `getloadavg()/logical CPUs` capped at 100 (`loadavg`), and if that fails 100 (`assumed-busy`). `busy_pct()` of the sampler is never `None`.
- Each failed read is counted (`failed_reads`) and logged at warn with the cause and elapsed time, at most once a minute. An `environment` alert `cpu-reading` appears when the primary has been missing over 2 minutes.
- Health JSON: `cpu.source`, `cpu.failed_reads`. `Compilation` (proto) gained `cpu_source = 9`; the Swift code was regenerated with `scripts/gen-clients.sh`.
- `mason resources` prints `[source X, N failed reads]` and, for a fallback, says so instead of "no gate now".
- Swift and Compose: the Health and home-page CPU lines name `loadavg` / `assumed-busy`; same wording in both.
- Test hooks for the exit script: `MASON_CPU_TEST_PRIMARY_FILE` and `MASON_CPU_TEST_FALLBACK_FILE`. `MASON_CPU_FILE` and `cfg.cpu` still take precedence over the sampler.
- `sched.rs`: `cpu_gate` logic is unchanged; only the health JSON, the `Compilation` field and a small `cpu_missing_ms` accessor were added.

**Not verified.**
- The real-load case (a dozen workspace builds at once) was NOT observed after the change. Only unit tests with injected readers and `scripts/exit/s133.sh` (no load) were run.
- That `host_statistics` is fast under syspolicyd saturation is from its being a syscall, not measured.
- The Swift/Compose monitor tests were added; see the submission for whether they were run.
