# s67: Act on LLM usage

Summary: A usage limit, outage, plan limit under `overage = "hold"` or reached api budget now holds the whole provider account (kept in the store across restarts) until the reset the provider gave or a backoff probe succeeds, tells the owner once per event, warns before a window's limit, and the owner can hold or release an account from the CLI and protocol.

## What was built

- **Reset texts** (`crates/core/src/reset_text.rs`, pure): `epoch N`, clock times with `UTC`/`GMT`/`Z` resolve to an epoch; a named or missing zone is *unknown* (decision 0049).
- **Store** (migration 17): `account_holds` (account, kind, why, since, until, backoff, next probe, by) and `account_warnings`.
- **`crates/daemon/src/holds.rs`**: observe a session's usage-limit/outage end and each snapshot (blocked, overage in use under `hold`); the gate (`Open`, `Wait(text)`, `Probe`); the one-probe claim; backoff (`hold_retry` doubling to 30 min); warnings with a projection from the readings; the api budget check after each attempt's tokens; owner `hold`/`release` recorded through `attention::intervene`; alert and banner text.
- **`jobs.rs`**: an agent step waits on the gate before taking a lease and re-checks after; `settle_holds` records the hold, gives the slot back, waits on the gate, re-takes a slot and resumes with the existing hold note (`WaitStarted`/`WaitEnded` kept, so no task time is charged); the retry ladder's next session passes the gate too.
- **Telling the owner**: `attention::alerts_now` appends `holds::alerts` (one item per event); header banners come from the same list; `GET /usage` carries `status` (`ok`/`blocked`/`outage`), `doing` and the overage text (allowed/held, cost).
- **Owner actions**: `POST /account/hold`, `POST /account/release`, `mason account hold <name> [--for 2h] [--reason R]`, `mason account release <name>`.

## Trust

These change when steps may start or are protected, so they wait for the owner's approval:
- `crates/daemon/src/jobs.rs`: a gate before a lease is taken, lease release/re-acquire during a hold, a gate before the retry ladder's next session. That is the ticket: the account, not each task, decides when sessions start.
- `crates/daemon/src/attention.rs`: one call in `alerts_now` so provider alerts take part in the existing sync (a second `sync_alerts` would clear the others).
- The budget hold is a limit the owner lifts by `mason account release`.
No test, gate or default was weakened; `hold_retry` stays 60 s. One existing store test asserted the schema version was exactly 16 after opening; it now asserts the current version (a new migration cannot satisfy the old number), and a migration-17 test was added.

## Exit test

`bash scripts/exit/s67.sh` runs the reset-text tests, the migration-17 store test, the hold-model unit tests and `crates/daemon/tests/holds.rs` against real daemons with the fake agent (one is a real `masond` process killed with `kill -9`). Output: see the end of this file.

## What testing found

- The daemon runs two tasks at a time; with three tasks the third is `Queued` (not in a wait) during a hold, and starts at the reset with the others. The test checks exactly that.
- A snapshot stored as `blocked` kept the usage page at "blocked" after its reset had passed; the page now ignores a block whose reset is past.

## Not done or not verified

- **No live provider**: nothing ran against a real Claude or Codex account; real reset texts other than the two fixtures were not seen. Overage in use was exercised with a built snapshot, not a real stream.
- **Named time zones** ("3pm (America/Los_Angeles)") and zone-less times are not resolved; they back off (decision 0049).
- **Monitor buttons** for release/hold are not built; the Swift and Compose monitors were not changed or run. The `outage` status and the new banner kinds appear as text.
- The waiting text on a task is fixed when the wait begins; its countdown does not tick.
- A probe session that is accepted keeps other tasks waiting until its step ends (decision 0049).
- Falling back to another account is out of scope.
