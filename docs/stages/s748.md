# s748: a check that goes to GitHub takes no local slot (#759)

Summary: A develop agent's check that runs on GitHub no longer queues for or holds a local `compile` or `test-suite` slot, so it skips the CPU and heat gates too.

`hostedcheck::goes_remote` decides the executor (the same `executor_for` / `executor_global` call `remote_check` uses, now shared through `runs_on_github`) before the agent queues. The four `swap_for` call sites in `jobs.rs` (build and test phase, both check paths) pass `queue = false` for a remote check. The agent's own slot is still given back while it waits. `where_ran` already says "on GitHub Actions".

Checked, not changed: the test step's own suite runs (`suites.rs`) already lease the `gha` runner pools instead of local slots (s723). I did not audit landing batches or debt payments: those stay local until #702 and I did not touch `suites.rs`.

Not verified: `scripts/exit/s748.sh` (new) has not been run here, and no local build was possible beyond the shared run_check. I did not add a separate `remote = N` resource: GitHub concurrency is already capped by the `gha` pools.
