# s453: the settings API says why a monitor-only condition cannot be routed

Summary: s430's exit script now routes `failed` (routable) and checks that routing the monitor-only `paused` is refused with a message saying so; the settings API refuses `MONITOR_ONLY` conditions with that message and still refuses unknown ones.

**Problem.** s430 routed `paused`, which `notify.rs` leaves unrouted on purpose (`MONITOR_ONLY`), so the API's "unknown condition" refusal failed the script.

**Change.** `settings.rs` gives monitor-only conditions their own clear refusal; `scripts/exit/s430.sh` uses `failed` and asserts the `paused` refusal; `tests/settings.rs` does the same (the tick test writes its `paused` route in the file).
