# s226: GitHub Pages download page

Summary: A static `site/` download page reads the visitor's user agent in the browser, offers the GUI and CLI+daemon packages named in `docs/RELEASING.md` for their system with a picker for others, and `pages.yml` deploys it.

What changed
- `site/pick.js`: pure `detectPlatform(userAgent, userAgentData)` and `pickAssets(platform, release)`; a missing file is `null` and the status says `unavailable`/`partial`, never another system's file.
- `site/index.html`, `app.js`, `style.css`, `assets/` (banner, icon, art NOTICE copied); light and dark, phone width, no-JS link, no-release state, phone note, All releases link.
- `?release=test/fixture.json` hook (and `&ua=`), documented in `site/README.md`.
- `.github/workflows/pages.yml` (protected path: waits for the owner's approval).
- Tests: `scripts/tests/pick.sh` (node, else jsc), `scripts/exit/s226.sh`. Decision: `docs/decisions/0221-download-page.md`.

Owner action: set Settings > Pages > Source to GitHub Actions.

Not verified: the deployed page, the real GitHub API response (fixture mirrors its fields), Safari/Firefox rendering (only headless Chrome), the Windows ARM and iPadOS cases, and that the release workflow publishes the asset names or `install.sh` (the page links the raw develop URL for the installer).
