# s998: impact-map test counts the unit-level suites

Summary: masons_own_impact_map_selects_suites_by_path now expects the eight unit-level suites bound to run_check and the test step, instead of six.

## Cause

`guards` and `exit-guards` were added to `.mason/mason.toml` as unit-level suites. `bound()` filters by binding level, so it returns eight; `[step.test] suites` still lists six. The impact picks are unaffected because `select` filters by the step's list.

## Change

Only the expected bound counts and their comment in `crates/definition/tests/testing_tables.rs`.

## Owner question

Should `guards` and `exit-guards` be added to `[step.test] suites`? `.mason/mason.toml` is protected, so this change leaves it alone. See decision 0991.
