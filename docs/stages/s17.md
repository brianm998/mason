# Stage 17: Self-hosting and gate protection (completes M4)

## Built
- **`protect.rs`**: the compiled-in rule set (gates, verdict logic, guards, budgets, trust, and the self-change rules themselves, as path globs with a reason each), a glob matcher, and a **line-based weakening scan** of a unified diff: removed assertions or tests, deleted test files, ignored tests, broadened skips, raised limits and lowered floors (matched by name between a removed and an added line). `inspect` returns what a change touches and weakens, `diff_hash` identifies an exact diff.
- **`selfguard.rs`**: **holds** (before a self-change joins the landing queue, the running daemon inspects its diff; a flagged task waits, says why, and raises an alert; only the owner's identity approves, and the approval is for that diff), **limits** (open self-tasks, tasks per week, agent steps per period; refused with the number and the limit), the **rollback cooldown**, and the **one proposal** a rollback files.
- A project with a `[self]` section is MASON's own (`SelfCfg`: extra protected globs, limits, cooldown). Store migration 9 (`self_holds`). `GET /self`, `mason self`, `mason task approve` sending the caller's identity, `self_hold` in the task's JSON.
- **MASON's own `.mason/`** (`mason.toml`, `landing.toml`), `docs/self-hosting.md`, `docs/examples/mason-self.project.toml`, `docs/decisions/0014-self-hosting-readings.md`, `scripts/exit/s17.sh` and the manual `s17-real.sh`.
- The loader records a rollback (`runtimes/rollback`); the daemon starts a cooldown from it.

## Exit test
`bash scripts/exit/s17.sh` passes (real `masond` and `mason`): a harmless change to the repository lands freely; a planted change to a gate file (`crates/testing/src/verdict.rs`) and a planted change that **removes an assertion in a file nobody listed** (`crates/engine/tests/matrix.rs`) both stop, with their reasons, are absent from the remote, and show in `mason self` and `mason alerts`; `mason --as mallory task approve` is refused ("not the owner's identity"); the owner's approval releases that change and not the other; a change that edits `protect.rs` and adds `.mason/protect.toml` claiming nothing is protected is held all the same; after a recorded rollback a restarted daemon files exactly one proposal (waiting for the owner) and refuses to file a self-task ("cooling down after a rollback").

### Tests
- **`protect` (9)**: globs, the protected and unprotected paths, the check protecting itself, each weakening rule and what it does not flag, the explanation, the diff hash. **`selfguard` unit (2)**: each limit's message, the cooldown first.
- **daemon `selfguard` (8)**: a harmless change lands; a gate change waits, shows its reasons and alert, and is released only by the owner (a stranger and nobody get 403, a second approval 409); weakening outside the protected files (a removed assertion, a raised limit) is held; a change cannot switch the check off; the owner's extra globs; limits and the cooldown; the single rollback proposal; a project that is not MASON's own has neither holds nor limits.

## What testing found
- **`mason task approve` sent no identity**, so the owner could not approve their own held change (the daemon rightly refused a blank identity). It now sends the caller's (`--as` to change it).
- **The repository's own landing config made the manual run sit for ten minutes**: `.mason/landing.toml` collects a batch for ten minutes, which is right for real use. The scratch copy, only, sets the window to zero.

## Not done or not run
- **MASON is not turned on for this repository.** That is yours to approve (the owner checkpoint below). Nothing here registers it.
- **The manual run used the scripted agent, not a model**, and a trivial test command (`cargo check -q -p mason-core`) rather than the whole suite, to stay quick; a real run with a model on this repository is exactly what turning it on would be.
- **The weakening scan is blunt** (see decision 0014): it will hold some harmless changes and miss clever ones. The protected list is mine and should be read.
- **Spend is counted in agent steps**, not money: token cost is not recorded yet.
- **Nothing publishes self-tasks anywhere**, so the privacy rule holds by absence; if upstream publishing is added later it needs the redaction review the design describes.
