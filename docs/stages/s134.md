# s134: the macOS monitor's start image is no longer squashed to a square

Summary: The AppKit mascot loader now sizes each image from its bitmap's pixel aspect (`points` is the width), so the 1536 x 1024 start image is 768 x 512 points instead of 768 x 768; square art is unchanged.

**Cause.** `Mascot.image(from:points:)` (AppKit) built the `NSImage` and every rep as `points x points`, so every image was square whatever the PNG was. `StartView`'s `scaledToFit` was right and faithfully fitted a square.

**Change.** `Mascot.nsImage(from:points:)` takes height = `points * pixelsHigh / pixelsWide`. The first readable file sets the size; a later rep whose aspect differs by more than a pixel is skipped, so all reps report one point size. Documented on the function. `selfCheck` (`--mascot-check`, `monitor-tool mascot-check`) prints the start image's point size. No call site changed; no `.aspectRatio` workaround added.

**Other platforms and call sites (read, not run).**
- UIKit branch: `UIImage(data:scale:)` keeps the real aspect. Fine.
- Compose `Root.kt`: `ContentScale.Fit` on the decoded bitmap. Fine.
- `StateIcon` (Components.swift), `bannerImage` (TopBar.swift), `Phone.swift:77` icons: fixed square frames, art square by manifest (icons, banner icons). `Pages.swift:148`, `Phone.swift` illustrations: `scaledToFit`, art 512 x 512. Compose `MascotPicture` and `BannerImage` use `Image`'s default `ContentScale.Fit`; `StateIcon` likewise. None can stretch a non-square image (the square-frame ones would only ever fit one if a non-square file were added to those groups).

**Tests.** MascotTests: start image is 1536 x 1024 px, 768 x 512 pt, each rep the same; an illustration and the state icons stay square at 512 / 20 / 24; a rep of another aspect is skipped. Compose MascotTest: `brand("start_image")` decodes at 1536 x 1024.

**Not verified.** No screenshot of the running app was taken. Exit script `scripts/exit/s134.sh` prints the sizes instead. See the check results in the submission for what ran.
