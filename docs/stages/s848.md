# s848: count every job on the account's GitHub runners (#819)

Summary: The `gha` and `gha-macos` pools now count every other workflow's running and queued jobs in every GitHub repository the projects name, with a macOS ceiling beside `gha_ceiling`, one ETag poller, and `mason resources` naming unreadable repositories and the age of a stale count.

- `sched.rs`: `set_other_workflows` became `set_other_jobs(OtherJobs)` (gha, macos, label, not_counted, read_at_ms, stale). `refresh_other` makes the `Meta::Other` holders for both pools; `gha_macos_ceiling` (default 5, `mason resources limit gha_macos_ceiling N`, saved in limits.kv). A macOS job counts against `gha` and `gha-macos`.
- `remote.rs`: `AccountJobs::poll` replaces `OtherWorkflows`: repositories come from every project's `[remote_runs]`, `[ci]` (GitHub Actions) and `[tracker]`, read with that section's token; MASON's own workflow file is skipped. Lists of `in_progress` and `queued` runs are read with ETags, jobs only when a list changed and with the run's own ETag. A failed look keeps the last count and marks it stale; a never-read repository is `not_counted`.
- `github.rs`: `runs_with_status`, and jobs carry their runner labels.
- `resources.rs` (CLI): the `gha` line shows other jobs, the macOS ceiling, repositories not counted and the age of a stale count. The snapshot's `gha` object carries the same fields.

Not done / not verified: the `MASON 11 (landing 1, check 8, test 2)` breakdown by kind is not shown (#818 owns the lines by kind). The monitor's GitHub section (#767) was not touched. Nothing ran against the real GitHub API; a fake Actions API is used. A project whose `[tracker]` names a non-GitHub host would be tried as GitHub and named as not counted. Tests were run through `run_check` only.
