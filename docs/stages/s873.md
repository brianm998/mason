# s873: a remote run cut off at its limit keeps its output (#776)

Summary: A GitHub run cut off at its limit now keeps the artifact's output, names the tests that never finished, and its `run` step stops two minutes before MASON cancels.

- `remote.rs` `execute`: on the limit it cancels, waits up to 3 min (fake-clock driven) for the run to complete, downloads `output.log` alone (a cut-off run may lack `result.json`), then writes it plus the cut-off line and a "Tests that started and never finished" line (`suites::still_running`). No artifact: today's line.
- `run_json`: `timeout_min` is the limit minus 2 minutes (at least 1). The workflow already reads `timeout_min`, so no change to `.github/workflows/**` was needed and no trust file is touched.

Not verified: a real GitHub run being cut by `timeout-minutes` and its upload step running; only the fake GitHub tests. #771 was not checked for overlap.
