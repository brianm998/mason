# s480: spike on caching workspace crates with sccache

Summary: A measurement spike (decision 0473) shows `CARGO_INCREMENTAL=0` lets sccache hit workspace library crates across per-task target dirs, `SCCACHE_BASEDIRS` does not help, and run_check's edit rebuild gets about 60% slower, so nothing is switched on.

## What changed

- `scripts/spike/sccache-workspace.sh`: the measurement script (cold builds in two worktrees per variant, plus the one-line-edit rebuild).
- `docs/decisions/0473-sccache-workspace-crates.md`: the numbers and the recommendation.
- `scripts/exit/s480.sh`: checks the record exists with its ten measured rows and a recommendation.

## Not verified

Timings were taken on a heavily loaded machine, one run each; see the decision record.
Nothing in `~/.cargo/config.toml` or the project file was changed.
