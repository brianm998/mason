# s647: a red base freezes landing instead of failing every batch with the same reason

Summary: When splitting a red batch shows every task red alone (the base's own red), landing now freezes with one urgent fix task, so later batches wait instead of re-verifying and failing their tasks' land step with the same reason; the next green union lifts the freeze.

**Cause.** `settle_pin` returns `Settled::Base` and `raise_base` only raised an alert (`crates/daemon/src/landing.rs`). The batch failed with "landing failed: batch #N is red in lint and every task in it reproduces the red alone", each task's land step failed, and the next batch re-ran the same verification and failed the same way (6 times for #556 and #574).

**Change.** `raise_base` also calls `freeze_base`: it files one urgent fix task and sets a post-land freeze naming it (only the fix passes), unless a freeze is already in force. A batch whose union verifies green clears the post-land freeze.

**Not verified.** No fix task was observed landing against a real red base; the existing freeze tests cover the freeze mechanism.
