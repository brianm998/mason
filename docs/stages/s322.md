# s322: the monitor says what each landing task is doing

Summary: The landing view lists each task as queued (position and why: behind N batches, frozen until the fix, paused, window) or in a batch with its phase, "phase N of 4" and CI state, and both monitors group them as "Landing now" and "Queued" on Home and the Landing page.

`LandingView.items` (`TaskLanding` in `schemas/mason.proto`) is built in `views.rs` from the store's live batches, `landing().queued`, the freezes and `load_config`. `landing.rs` is only read through existing accessors.

**Needs the owner's approval:** the `clients/features.toml` row (a `PROTECTED` gate), marked done in both clients, was not added.

**Not verified.** The pure parts (phase mapping, why-text) have unit tests, and the Swift/Compose layout tests were written but not run here. No test builds a daemon with a real running batch plus a queued task, so the exit script only covers the pure functions. "Time in phase" is time since the batch formed, because the store keeps no phase start. The window is named ("waiting for the 30s window"), not the closing time, since no existing accessor gives it. I did not compile the Swift or Kotlin.
