# s433: pair a device with a QR code, and list or revoke paired devices, in both desktop monitors

Summary: Both desktop monitors' Settings pages have a Devices section (LAN on/off from `GET /lan`, paired devices from `GET /devices` with Revoke after a confirmation) and a "Pair a device…" sheet that calls `POST /pair/codes` and shows the `mason://pair` URL as a QR code with the 8-digit code, hosts and an expiry countdown.

**Problem.** Pairing a phone meant `mason pair` in a terminal and typing the code or turning the URL into a QR code by hand; listing and revoking devices was CLI-only.

**Change.**
- Swift core (`Devices.swift`): `LanStatus`, `DeviceList` (live devices most recently seen first, never-seen last; revoked ones in a separate list, newest revoke first), `PairOffer` (the code, URL, hosts and the time it arrived; `state(nowMs:)` is `valid(secondsLeft)` or `expired` on an injected clock). `QRCode.swift` draws the URL with CoreImage's `CIQRCodeGenerator` (level M) and can decode an image back with `CIDetector`. `MonitorModel` gets `loadDevices`, `issuePairCode(role:)`, `revokeDevice`.
- Compose core: the same model in `Devices.kt`, and `QrCode.kt`, a dependency-free QR encoder (byte mode, level L or M, versions 1 to 40) because no QR library is in the build.
- UI: `DevicesSection` in both Settings pages. The sheet makes a code on open (owner or viewer), re-reads `/devices` every 3 s and ticks the countdown every second while open; an expired code shows "New code".
- `clients/features.toml`: row `settings-devices`, done in both clients.

**Tests.** Both cores: list sorting and revoked-apart, last-seen text, countdown and expiry on an injected clock. Swift: the QR image decodes (CIDetector, offscreen) to the same URL. Kotlin: encoder capacities against the standard and the finder patterns.

**Trust.** `clients/features.toml` and `scripts/exit/s433.sh` are protected paths; the new feature row and the script wait for the owner.

**Verified by hand.** The Kotlin `QrCodeTest` and `DevicesTest` and `:app:compileKotlin` passed. The Kotlin encoder's output for 6 texts (levels L and M, versions 1 to 13) was decoded by CoreImage's `CIDetector` back to the same text. The Swift core files (`Devices.swift`, `QRCode.swift`) were compiled with `swiftc` and their checks, including the QR round trip, passed.

**Not verified.** The full Swift package was not built (no network for swift-protobuf), so the `MonitorModel` changes, `DevicesSection.swift` and the XCTest file were read, not compiled. `run_check` ran nothing (testing skipped by the owner), so fmt, clippy, the workspace tests and `scripts/exit/s433.sh` were not run (no Rust changed). No view was rendered and nothing was scanned with a real phone; that stays an owner check. The sheet's polling and countdown timers have no automated test (the pure state is tested).
