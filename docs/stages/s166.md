# Stage 166: The weakening scan, narrowed and moved to submit

Summary: The weakening scan no longer flags Rust closures, iterator `.skip(`, `grep -c`/`reap`/descriptor-close/failure-handler idioms or files a change adds, and `submit_change` runs it so a finding comes back before the test step.

## Built
- **`protect.rs`**: `|| true` and bare `exit 0` apply only where a shell runs the line (`.sh`/`.bash`/`.zsh`, YAML, Makefiles, TOML, extensionless files with a shell shebang or in `scripts/`/`bin/`). `.skip(`, `xit(`, `xdescribe(` apply only in JS/TS test files. Harmless `|| true`: after `grep -c`, `... reap ...`, `exec N>&-`, and inside a function that only writes to stderr and exits non-zero. `[ ... ] || true` and `test ... || true` stay flagged. `|| true` in a file the change adds is a note (`Inspection.notes`, `scan_notes`), not a finding.
- **`selfguard.rs`**: `submission_scan`, `describe_finding`.
- **`jobs.rs` `change_validator`**: runs the same scan on `submit_change` for projects with `[self]`. `holds = "review"` refuses with each finding as `file:line: rule (text)`; `holds = "owner"` accepts and writes the findings to `weakening-note-r<run>.txt` in the task directory. Landing keeps its scan.
- `docs/decisions/0161-weakening-scan-at-submit.md`, `scripts/exit/s166.sh`.

## Findings no longer raised
`|| true` in Rust, Swift, Kotlin and other source; `.skip(` outside JS/TS tests; the grep-count, reap, fd-close and failure-handler idioms; `|| true` in newly added files. Every rule still fires in existing shell and workflow files.

## Not verified
- The hold-action note is a file in the task directory, not text shown to the agent or owner: the validator's return type has no room for one and `contract.rs` is protected.
- Failure-handler detection reads only the added lines of the diff (`-U0`): a handler whose lines are not all added in one hunk is not recognised.
- Extensionless existing files are judged by directory since the diff shows no shebang.
