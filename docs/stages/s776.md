# s776: a reused or zombie host pid is not a running host

Summary: A step host reads as Running only when its pid is alive, its start time matches `host_start` and it is not a zombie, the sweep files `orphan_host` once per host id, and the sweep reaps children of masond that exited and were never waited for.

What changed
- `crates/step-host/src/registry.rs`: `status_of` uses `host_is_running` (pid alive + `kv_matches` on `host_start` + not `is_zombie`); otherwise `Lost`.
- `crates/daemon/src/sweep.rs`: `orphans_filed` (one bug per host id; the stop is still retried); `reap_stale_zombies` (a zombie child seen on two consecutive passes is `waitpid`ed).
- `crates/daemon/src/daemon.rs` `stop_hosts`: a `Lost` host with the prefix gets `reap_dir_by` (kills only the verified recorded process); the sweep's host archive then moves the directory.
- Decision: `docs/decisions/0769-reused-host-pid.md`. None of the files is in `PROTECTED`.

Tests: `status_tests` in registry.rs (different start time is Lost, own start time is Running, zombie is Lost); `an_orphan_host_is_reported_once`, `an_exited_child_nobody_waits_for_is_reaped_on_the_second_pass` in sweep.rs; `scripts/exit/s776.sh`.

Not verified
- The zombie's origin is inferred, not observed: step hosts the daemon spawned before an in-place `mason update` (exec keeps the pid and children) lose their reaper threads; every `spawn`/`spawn_group` site in the daemon that I read waits for its child. I did not reproduce it.
- No full-pipeline test of the sweep (a closed run with a lost host files no bug and a second pass files nothing): a Lost host is skipped by step 3 by construction, and the once-per-id rule is tested on its own.
- Not run on the owner's machine: that `h/t583r3688-1` goes away relies on the existing host archive.
