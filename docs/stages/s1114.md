# Stage 1114: the last round's findings survive a failed step

Summary: a red round that uses up a step's last chance now keeps its feedback, so the diagnosis, the owner's session and the develop round after a retry see why the task failed.

## What changed (`crates/daemon/src/jobs.rs`)

- One helper, `save_feedback`, writes `feedback.txt`, `round-reason.txt` and the `## After run N (step): reason` entry of `feedback-history.txt`.
- `conclude_round` calls it on both the send-back and the fail arm, for a red outcome with feedback. On the fail arm it runs before `StepFailed` is emitted and before the diagnosis starts. A failure with no feedback writes nothing.
- An owner's rejection (`conclude_approval`) uses it on both arms, so it is now in the history and sets the round reason to `fix`.
- An approving review removes `feedback.txt`.

`retry_task`, the prompts and `usersession.rs` are unchanged, and so is what the diagnosis reads: they read these files already. A retry from `review` reaches the findings only through a prompt pack that places `{feedback}`; the built-in review prompt does not.

## A diagnosis mark per daemon (`crates/daemon/src/diagnose.rs`)

The mark saying a diagnosis is running was process-wide and keyed by the task number. The daemon tests run many daemons in one process, each with a task #1, so one refused another's diagnosis: the test waited 900 s for it (or got 409 asking for one), holding its world slot. The mark is now keyed by data directory and task. A running `masond` is one daemon, so it behaves as before.
