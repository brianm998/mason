# s582: machine-wide scratch-world limit and one resolved git

Summary: Daemon test worlds are capped across every process on the machine by flock lock files, and git is resolved once per process to the real binary instead of the xcrun shim.

Task #567. Decision: docs/decisions/0575-machine-wide-world-slots.md.

What changed
- `crates/daemon/tests/support/slots.rs`: `limit` lock files in `/tmp/mason-test-worlds`, each taken with `flock`. A scratch world holds one for its life; a killed process frees it. `world_limit()` is now a machine total (`cpus/4`, clamped 2..8; `MASON_TEST_WORLDS` overrides). A world's deadlines still start after it holds a slot. After 600 s a waiter goes ahead, as before.
- `landing::git::program()`/`command()`: `MASON_GIT`, else `xcrun -f git` on macOS (rejected if relative, not executable or `/usr/bin/git`), else `git`. Cached in a `OnceLock`. All `Command::new("git")` in `crates/landing/src` and `crates/daemon/src` use it, so `run_for` and the fixtures do too.
- nix gains the `fs` feature (for `flock`).

Tests: `crates/daemon/tests/world_slots.rs` (two child processes each try to take more slots than the limit; the total held, counted from lock files, equals the limit and never exceeds it); `program_tests` in `crates/landing/src/git.rs` (override, shim rejection, fallback, macOS result is not the shim).

Not verified
- Step 3 (measuring and cutting idle polling) was not done: no per-subcommand git counts before or after, so there are no numbers to report and no polling was changed.
- The exit test (xcrun-shim exec rate under 2,000/min with two suites at once) was not run. `scripts/exit/s582.sh` only checks the lock limit and the resolver tests.
- `test-suite` in `limits.kv` should stay at 2 until the exit measurement is taken.
- `Command::new("git")` in `crates/platform/src/shell.rs`, `crates/cli`, `crates/adapters` and `crates/daemon/tests/it` is unchanged.
- No fixture binaries are copied, so no new signing was needed.
