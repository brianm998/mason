# s1092: the review agent is told the task's reserved files

Summary: the review prompt now names the task's reserved stage note, decision record and exit script as required files, so a reviewer does not ask for them to be removed or renumbered.

## Cause

Only explore and develop prompts carried `numbers::prompt_block`. The reviewer saw the pipeline-required files in the diff with no explanation; task #1104 (project trd) failed after two review rounds on 2026-11-24 for this.

## Change

- `numbers::review_block` words the reserved files for a reviewer.
- The review branch in `jobs.rs` appends it after the diff and the replaced-lines block, to built-in and pack prompts alike. It reads stored reservations only; if the world cannot be read, nothing is appended.

## The analyst's submission is not validated as a change

`scripts/exit/s22.sh` is chosen for this change (it names `crates/daemon/src/jobs.rs`) and was red. Since cb040fac3 the analyst's findings are read only after an accepted `submit_change`, but the change validator refused that submission: the analyst is told not to commit its `analyst-result.json`, so the tree is dirty and has no commits. The develop step of the analyst's task (known by its schedule row, `introspect::is_analyst_task`) now gets no change validator. Its branch is never merged, so the proofs (clean tree, commits beyond the base, head is the tip) had nothing to protect. This is a change to which submissions are refused, so it waits for the owner's approval.

## Tests

- Unit test of `review_block` in `numbers.rs`.
- `prompt_packs`: a pack review prompt names the reserved paths, and the task holds one number of each kind afterwards.
- `scripts/exit/s1092.sh`: the built-in review prompt against a real daemon and the scripted agent.
