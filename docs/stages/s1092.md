# s1092: the review agent is told the task's reserved files

Summary: the review prompt now names the task's reserved stage note, decision record and exit script as required files, so a reviewer does not ask for them to be removed or renumbered.

## Cause

Only explore and develop prompts carried `numbers::prompt_block`. The reviewer saw the pipeline-required files in the diff with no explanation; task #1104 (project trd) failed after two review rounds on 2026-11-24 for this.

## Change

- `numbers::review_block` words the reserved files for a reviewer.
- The review branch in `jobs.rs` appends it after the diff and the replaced-lines block, to built-in and pack prompts alike. It reads stored reservations only; if the world cannot be read, nothing is appended.

## Test harness: no wait for a second world

The first verification run of this change ran out of time on one GitHub runner (2 world slots). Tests such as `tracker::require_label_off_…` passed after 600.5 s: each held one scratch world and waited the full patience for a second, while other tests queued behind them. `slots::take` now tries once, without waiting, for a thread that already holds a slot, and the caller goes ahead as it did before after 600 s.

## Tests

- Unit test of `review_block` in `numbers.rs`.
- `prompt_packs`: a pack review prompt names the reserved paths, and the task holds one number of each kind afterwards.
- `scripts/exit/s1092.sh`: the built-in review prompt against a real daemon and the scripted agent.
- `world_slots`: a thread holding a slot gets no wait for a second one (a wait would hang the test).

## Not verified

- No real model was run: that a reviewer now accepts these files is not shown.
- Numbers are reserved when a task is first claimed, so the tests do not reach a review of a task with no reservations; so that such a review reserves nothing rests on the code calling only `numbers_of`.
- The unreadable-world path has no test.
- That the 600 s waits caused the whole overrun is inferred from the run's times; the workspace may still exceed the run limit when it is not sharded.
