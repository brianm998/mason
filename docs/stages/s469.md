# s469: the Android phone app builds

Summary: The Android module is now a real app in the Compose project (`-Pmason.android=true`): phone screens over the shared core, NSD discovery with the extra-host fallback and a pinned `wss` link, QR or typed-code pairing with tokens sealed by the Android Keystore, and `android` is a fourth column in the parity gate.

## What changed

- `clients/compose/settings.gradle.kts`, `build.gradle.kts`, `gradle.properties`: `:android` is included only with `-Pmason.android=true`; the Android Gradle plugin is on the root classpath only then. Other builds are unchanged and need no SDK.
- `clients/compose/android`: `AndroidManifest.xml` (internet, Wi-Fi state and multicast, nearby Wi-Fi devices, camera not required, portrait, `mason://` links) and the launcher icons from `packaging/make-android-icons.py`.
  - `Secrets.kt`: `SecretBox`, `AesGcmBox`, the Keystore key, `KeystoreTokenStore` (keyed by fingerprint).
  - `PairedStore.kt`, `PairingScreen.kt`: the paired record, the pairing screen state (same rules and words as the iPhone's), `PairingFlow`.
  - `RemoteDiscovery.kt`, `RemoteSession.kt`, `Net.kt`, `Nsd.kt`: the order to try addresses (`Reach.order`), the lifecycle (close in the background, resume from the last sequence number, 401 clears the pairing), the pinned `wss` socket and `POST /pair`, the NSD source.
  - `ui/`: the pairing screen (Scan with CameraX and ZXing, Nearby, typed code), the sidebar as first screen (tiles, Home, sections, Landing, Usage), pages pushed with `PhoneNav` and Back, Home with the session-limit stepper, section pages, Landing (Land now), Usage, task detail (decision options, multi-select, Other, Cancel with confirmation, Skip testing, Land now, plan, log tail), the paired-daemon page with Forget, Mute.
- `crates/core`-free: nothing in Rust except the gate. `clients/compose/core`: `DaemonInfo.host`, `SocketFactory.open(DaemonInfo, …)` (default: the port-only open), `MonitorSocket.refusal`, and `onAttemptEnd` / `onRefused` on `MonitorConnection`. The desktop path is unchanged.
- `crates/conformance`: `CLIENTS` has `android`; see decision 0462 for the rules. `clients/features.toml` has an `android` entry on every feature.
- `.github/workflows/android.yml`: path-filtered, cancel-in-progress, builds the debug APK and runs the unit tests.
- `scripts/exit/s469.sh`; `s469-real.sh` is the owner's checklist. `s351.sh`: its "android must stay out of settings" line now says "not included unconditionally", because the module is in the build on request.
- Tests: `SecretsTest`, `PairingScreenTest`, `RemoteDiscoveryTest` (includes `PhoneNav`), `RemoteSessionTest` (Android, JVM, no emulator); `RefusedLinkTest` (core); the Rust tests of the gate.

## Trust

`clients/features.toml`, `crates/conformance/src/features.rs`, `.github/workflows/android.yml` and `scripts/exit/s469*.sh` are protected and wait for the owner. The gate change adds a column and does not loosen an existing rule; an Android `todo` or `n/a` needs an `android_reason`, and 56 features are recorded that way. The owner should read that list: it is the Android app's real debt. The one changed line in `s351.sh` is needed because the module is now in settings; it still refuses an unconditional include.

## Deliberate differences

`[phone.graph-editing]` (the pipeline editor), `[phone.agent-sessions]` (the two session features) and the log tail only (`[phone.log-deep-dives]`) are off, as on the iPhone. Android has no `[ipad.*]` side.

## Not verified

- **Real phone**: pairing over Wi-Fi, real NSD, the camera and the QR read were not run; that is `s469-real.sh`, the owner's check.
- **Screens were compiled, not looked at.** No emulator ran, and no Compose UI test was written: Robolectric is not available offline, and the task asks for nothing on screen.
- ZXing reads the luminance plane of CameraX frames; rotation handling of the frame was not tested on a device.
- NSD uses the deprecated `resolveService` (it works on API 29 to 35); a link-local IPv6 answer is cut at `%`, which may not connect.
- Background alerts on Android are not built: native push needs FCM and a Firebase project the owner has not chosen (decision 0462). The ntfy channel remains.
- Scroll position is not restored on Back, and the project filter, search, add task, speech and the other desktop features are the recorded `todo` entries.
- The Rust tests, `cargo clippy` and `bash scripts/run-exit-scripts.sh` are run by the test step.
