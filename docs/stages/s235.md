# s235: the task page finds one task's step hosts by name

Summary: `log_signature`, run on every task-page rebuild, now reads only the task's own host directories (live and moved, via `hostarchive::task_hosts`) instead of every host's files.

**Cause.** `http::log_signature` ran `Registry::scan()` (reads `host.kv` and `exit.kv` of every host: 1,378 directories on 2026-11-13) and filtered by task afterwards.

**Change.** It calls `task_hosts`, which filters on the `t{task}r` directory-name prefix before reading anything and includes archived hosts, the same set `render_logs` reads, so the cache still invalidates when the sweep moves a host. The other `scan()` callers: `http.rs:210` (status, wants all hosts), `sweep.rs`, `hung.rs`; `logs`, `task_progress` and `open_session` no longer scan the whole registry.

**Not done.** `hung::check` on the compile-watch thread still scans every host each tick; worth its own task.

**Tests.** `log_signature_names_only_the_tasks_hosts_and_follows_its_journal` (tasks 7/70/700 plus an archived host, an unreadable other-task host, journal growth). Not verified: the test passes without reading counts, since an unreadable host is skipped by scan too; the name filter is shown by the code, not by the test. The machine's real daemon was not run.
