# s698: CI watch dedupe on the job and on what failed

Summary: The CI watch now lets a ticket cover a red job on a run only if it cites the run and names the job (or its shard group), reads the failing exit scripts and tests from the log, files the shards of one matrix job once under a group key with those names in the title, attaches a red to an open task or issue that names one of its failures, and says in the body when landed tasks already changed the same script or test.

**Cause.** `step` treated any recent task citing a run as covering every job red in it (#640 `CI/lint` hid `CI/test (ubuntu-latest)`), and dedupe keyed on the exact job name, so each exit-script shard, and each reshuffle of shards, got its own ticket with no word of earlier ones.

**Change.**
- core `ci_watch.rs`: `signatures(log)` (`FAILED: scripts/exit/sNN.sh`, `test x ... FAILED`, `error: test failed, to rerun pass '...'`), `group_key` (`CI/exit-scripts (ubuntu-latest, *)`), `mentions`/`short`. `JobRec`/`JobState` carry signatures; `File` carries signatures, `also` (other shards filed with it) and `repeats` (landed tasks that named the failure, landed at or before the red run).
- `step`: citation covers a job only when the task also names its key or shard group; a red whose failure an open task/issue names is attached (ticket, `covered = run`); shards of one group in a pass give one `File`; `filed` records the ticket against every shard and a single `Filed` entry under the group key; `held_back` lists a group once.
- daemon `ci_watch.rs`: reads `log_long` of a newly failed job for signatures, stores them (`signatures` in the saved JSON), looks up open tasks/issues naming them, and writes `CI/exit-scripts (ubuntu-latest, *) red on develop: s299, s486` plus a "Repeat failure" paragraph into the filed task.

**Not verified.** No run against live GitHub logs; the log formats are taken from the task text and fixtures. An open task counts as naming a failure by title, or by body only if the watch filed it (so a task that merely quotes a script name is not taken for the ticket). The held-back status line's timeout note is looked up by key, so a shard group shows without it.
