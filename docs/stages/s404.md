# s404: `mason report` gives throughput, send-backs, waits and interventions on demand

Summary: `mason report [--days N] [--project P] [--json]` and `GET /report` read the event log and store tables once and show landed and failed per day and project, lead time (median, p90), send-backs by normalized reason and suite, task failures by reason and class, waits by class (count, total, median), owner interventions by kind, host losses, flaky sightings and open debts.

## What it is

`crates/daemon/src/report.rs`. A `Collector` is fed the events one by one (its own `World`, so project names and waits resolve as they did at the time); `Rows` carries the store tables (interventions, host losses, flaky, debts). Reasons are normalized by lowercasing and replacing numbers with `N` and backtick-quoted names with `_`, so equal causes count together. Suites behind send-backs are the backtick names in the reason. Lead time is first admission to landing, for tasks that landed in the window. Waits still open count up to the end of the window. Interventions leave out `pipeline` and `refused_answer`, as the digest does.

## Tests

- `report::tests::every_section_counts_a_small_synthetic_log`: known counts for every section.
- `tests/report.rs`: a daemon's report prints and parses back as JSON with every section present.

## Not verified

- The CLI text output (`print_report`) was not read against a live daemon.
- Host losses under `--project` use the project the task is in now; a loss of a task no longer in the log is not counted.
- Send-back suites come from backticks in the reason text; a reason that names no suite adds to none.
- The monitors' health page does not show it yet (a later task).
