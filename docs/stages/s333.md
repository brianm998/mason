# s333: the monitor sidebar lists tasks that are not waiting first

Summary: in every sidebar section except Queued, tasks that are not waiting (running or idle) are listed above those that are waiting, held or paused, each group newest first.

## What changed

- `crates/daemon/src/views.rs`: `is_waiting` (true for `Waiting`, `Held`, `Paused`, the activities `why_waiting` explains) and `sort_unqueued`, used by `section_of` for every section but Queued. Queued keeps its admission order.
- Home's stage sections are built from the same `section`, so they follow automatically.
- Queued's sort moved unchanged into `sort_queued` so it can be tested.
- Test: `tasks_that_are_not_waiting_come_first_then_newest_first` (unit, `views.rs`) covers the Testing example (C, A, B) plus held and paused tasks.

## Not verified

Queued's order is covered by `queued_keeps_slot_waiters_first_then_rank_order` through `sort_queued` with a stand-in rank; the real `queued_rank` was not exercised in a test. The Swift client was not run; it draws the daemon's order unchanged.
