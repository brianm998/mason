# s817: debts rank behind all task work

Summary: a debt payment now asks for machine slots and runner units in a new debts band (`Rank::debt()`), behind every task's work and the landing band, oldest debt first, so a debt never holds a task in development, testing or landing back.

Task #835. Decision 0810.

## Built
- `Rank::debt()` / `is_debt()` (`crates/scheduler/src/rank.rs`): band 255, after all steps and `landing()`; aging and priority-first do not lift it; debts compare by arrival then id; a person keeps first place.
- `suites::hold_for_debt`: ranks in the debts band (arrival = the debt's `at`); label reads `debt #N (behind task work)`. Its runner-unit request (`pool_needs`) uses the same rank.
- `remote::fallback_rank` / `fallback_lease`: a task in a step keeps `rank_for(t, def, &t.step)`; a landed, failed or canceled task, or none, gets the debts band, never the landing band.
- A held or running debt is not stopped; only who is granted next changes.
