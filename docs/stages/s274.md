# s274: release checksums signed with minisign and verified

Summary: `release.yml` signs `SHA256SUMS` with minisign, and `scripts/install.sh` and the release update channel refuse an unsigned or badly signed release once the owner's public key is pinned (a placeholder until then).

Change: `publish` signs and uploads `SHA256SUMS.minisig` (skipped with a warning without `MINISIGN_SECRET_KEY`). `install.sh` verifies the signature before reading SHA256SUMS; `release.rs` (`trusted_key`, `verify_signature`, `fetch_and_unpack(.., pubkey)`) does the same for `mason update`. With a key set, no signature, a bad one, a malformed key, the placeholder given as a key, or no `minisign` binary all refuse. `docs/RELEASING.md` has a Signing section.

Tests: unit test `the_placeholder_is_never_a_key`; `update_release.rs` signature tests (good, missing, wrong key, tampered; skip without minisign); `scripts/exit/s274.sh` for install.sh.

Not verified: `minisign` is not installed on the build machine, so the signature tests and s274.sh skipped here; the unpinned, no-minisign and placeholder paths of install.sh were run by hand. The workflow step has never run.

Owner: `.github/workflows/release.yml` and the pinned key are trust files; the key is a placeholder for you to replace in `scripts/install.sh` and `crates/daemon/src/release.rs`.

Decision: `docs/decisions/0269-release-signature-verification.md`.
