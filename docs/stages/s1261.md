# s1261: heavy exit scripts are no longer killed as red in checks (#1291)

Summary: A check and a test step now set `MASON_TESTS_ALREADY_RAN=1` for the exit scripts when the cargo-workspace suite runs beside them, a check reports a script killed at the 900 s limit as `NOT RUN` instead of a failure, and the seven heavy scripts are weighted 900 s in the shard plan.

**Cause.** s06, s11, s14, s15 and others run whole-crate cargo tests unless `MASON_TESTS_ALREADY_RAN` is set. Only GitHub CI set it, so in MASON they ran into the per-script limit and the kill read as a code red.

**What changed.**

- `jobs.rs` `run_suites` (a check): the exit-scripts run gets the variable once the cargo suite earlier in the same check has run (a result, or a red build). Not when the cargo suite is not selected, skipped as reading none of the change, filtered to named tests, or under a fast track.
- `suites.rs` (the test step): the same, from the outcomes of the suites before it (proven, reused, flaky or excused). The landing exit tier, debt runs and full CI are unchanged.
- A check also sets `MASON_EXIT_IN_CHECK=1` (not under a fast track). `run-changed-exit-scripts.sh` then prints `NOT RUN sNN (over N s, too slow for a check)` for a script killed at the per-script limit, counts it as not run and does not exit red for it. The check's answer names those scripts and says not to chase them. A test step still prints `FAIL`.
- The runner does not pass `MASON_EXIT_IN_CHECK` on to the scripts. A script exiting 124 on its own, or cut short by the run's time budget, stays a `FAIL`.
- The key of a kept pass includes whether the variable was set.
- The runner no longer passes `MASON_EXIT_CACHE`, `MASON_EXIT_TREE_KEY` or `MASON_EXIT_PASSES` on either: s759 drives the runner itself and failed in a check on a node, because its inner run printed `MASON-EXIT-KEY` lines.
- `weights.txt`: s06, s11, s14, s15, s16, s158 and s1058 weigh 900.

**Not verified.**

- The running daemon does not have this change yet, so in this task's own check s14 and s686 were killed at 900 s. s686 has no cargo guard and repeats a test ten times; it stays slow after this change.

- No real s06 run was timed with the variable set, here or on GitHub; the exit test of the task is covered by the daemon tests with a stand-in runner and by a static check of s06's guard.
- The weights are the kill limit, a lower bound: no measured duration of these scripts was found (the check runner prints none, and a search of the local task logs for `sNN: N s` lines did not finish).
- `refresh-exit-weights.sh` rewrites the file from CI logs, where these scripts are fast, so a refresh would drop the seven entries.
