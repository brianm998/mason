# s1069: a remote run gives back a runner unit as each GitHub job finishes

Summary: a remote run now gives each `gha` (and `gha-macos`) unit back to the broker when its `run` job completes, rewrites its hold file with what is left, and asks again, at its own rank, for the shards it runs again.

## Change

- `Ledger::shrink` and `Broker::shrink` give back part of a holder's units and run a pass; shrunk to nothing is a release.
- `Giver` (from `Lease::giver`) lets a run give units back and ask again without owning the lease. `Grant` uses it: `give`, `ask_again`, `note_hold`.
- `execute` gives back one unit per completed `run` / `run (k)` job (nothing while only `plan` exists) and rewrites the hold file. Sharded runs re-read their jobs every 60 s instead of 120 s.
- `execute_sharded` asks for the units of the shards it runs again before pushing, with the lease's original rank and wait start.
- A lease already emptied by an earlier run (a retry, a flaky rerun) asks again before the next run is pushed, after the too-few-runners refusal, so a refused run asks for nothing.
- Merged with the step-limit and too-few-runners change (6268b01b5): a refused or fallen-back run gives back its units correctly (new test).
- The test step (`suites.rs`) and checks (`hostedcheck.rs`) pass their lease down.

## Not verified

- Compiled and tested locally after the merge with develop (scoped tests only: `remote::`, `sched::`, `remote_runs::`, the scheduler test, s1069, s06). The full workspace suite and the other exit scripts were not run here.
- Only a task's test step lease and leases owned by a `Grant` are passed down. A landing batch's run through `run_remote` with no step lease still holds its units whole.
- Not run against real GitHub; the tests use the fake GitHub's jobs API.
- A lease whose units were all given back asks again before its next run (a retry or flaky rerun); `a_refused_or_fallen_back_run_with_an_emptied_lease_asks_for_no_units_and_holds_none` covers a refused or fallen-back run meeting such a lease.
