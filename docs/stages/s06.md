# Stage 6: Walking skeleton

## Built
- **`masond`** (`crates/daemon`): the orchestrator. Events go in the log; the effects the reducer asks for are carried out on worker threads and come back as events. One job per open step run, resumable. Bounded blocking pool (`pool.rs`), event-loop stall watchdog, loopback HTTP API (axum), a reconcile sweep, FIFO admission, startup recovery.
- **The fixed graph** (`jobs.rs`): explore (agent, read-only), develop (agent; submissions are proven: the commit must be the branch tip, the tree clean, the branch ahead of the base), test (one command, under a step host), review (pass-through), land (`direct`). Red tests loop back with their output as feedback; bounded rounds.
- **`mason`** (`crates/cli`): `task add | list | show | cancel | retry`, `logs [--follow]`, `status`, `doctor`.
- **Plain git** (`crates/landing`): idempotent worktrees, catch-up with conflict detection, and `direct` landing: fast-forward in a persistent landing worktree, plain push, fold in a moved base and re-verify (bounded), and a no-op when the branch is already in the base.
- **The agent runs under a step host** (`crates/adapters/src/hosted.rs`): the Claude adapter launches the CLI under a host and follows its journal; a restarted daemon reattaches by run key. `step-host` gained `--stdin` and `--clear-env`.
- **Task body in the event log**, a `bugs` table, and **failure reasons** on tasks (`mason task show` says why).
- **The local tracker**: tasks are filed straight into the log; no service.
- **Crash injection** (`crash.rs`, `MASON_CRASH_AT=<point>[@n]`) and the harness `tests/crash.rs`.
- `docs/decisions/0003-walking-skeleton-readings.md`, `scripts/exit/s06.sh`, `scripts/exit/s06-real.sh`.

## Exit test
`bash scripts/exit/s06.sh` passes locally (about 1 minute). It lands a task on a scratch repository (bare "origin" plus clone) with the scripted agent, sends **`kill -9` to the daemon in the middle of the agent's session**, checks the agent's step host is still running, restarts the daemon, and requires: landed exactly once on the remote, one develop step, no bugs filed. Then it runs the whole crash-injection harness and the landing, daemon and CLI tests.
```
agent is mid-session: its branch has the commit, the submission is 5 s away
daemon killed with kill -9; the agent's step host (pid 47670) is still running
daemon restarted; waiting for the task to finish
landed exactly once; one develop step; the same agent session carried on; no bugs filed
#0 Add a hello file
  state     landed
  landed    merged
steps:
  run 0 exploring   attempt 1  succeeded
  run 1 developing  attempt 1  succeeded
  run 2 testing     attempt 1  succeeded
  run 3 review      attempt 1  succeeded
  run 4 landing     attempt 1  succeeded
... test results: 9, 4, 10, 6, 3, 5, 12, 2 passed, 0 failed ...
s06 OK
```

### Crash injection
The real `masond` is killed uncleanly (SIGKILL at a named point) and restarted. In every case the task lands, **exactly once**: one commit on the remote, the task's events are exactly one pass through the graph (filed, admitted, five successes), no step run left open, log and projections consistent, no bugs filed, and the landed task's branch and worktree cleaned up.
23 points: `after_append:TaskFiled`, `after_append:Admitted`, `job_started:{Exploring, Developing, Testing, Review, Landing}`, `accepted_persisted@1` and `@2`, `before_event:{Exploring, Developing, Testing, Review}`, `after_append:StepSucceeded@1..5`, `land_after_fetch`, `land_after_ff`, `land_after_push`, `land_before_event`, `land_after_event`. Plus real `kill -9` mid agent session (twice in a row, the second straight after a restart), mid test run, and a task that finished while the daemon was down.

**What the harness found** (all fixed, all now tests):
1. An accepted submission lived only in the dead daemon's memory, so a step that had succeeded was failed after the restart. Acceptance is now made durable before the agent is told. Verified necessary: with the restore disabled, four boundaries fail.
2. A reattached session was given a spec whose "accepted" flag was not wired to the contract, so it could never see a restored acceptance.
3. The tests' own cleanup killed the step hosts that must survive, which hid (1) at first.
4. Nothing cleaned up a task's worktree and branch if the daemon died between recording "landed" and cleaning; recovery now does, idempotently.
Other things found on the way: a macOS socket inherited non-blocking (Stage 4) cousin in the contract server; a second daemon started recovering jobs before noticing the first; a multi-threaded runtime cannot show a stalled loop (now one current-thread loop); the CLI's `retry --from` silently accepted nonsense.

### CI
Green on Ubuntu and macOS (`cargo test --workspace` and every exit script, including `s06.sh` with the full crash harness; the macOS job takes about 5 minutes, inside the 10-minute budget). CI found one thing local runs did not: on GitHub's macOS git, a push refused because the remote had moved reports its reason on *stdout* under `--porcelain`, so recognising a lost push race by reading git's message failed. `direct` landing now asks the remote instead (re-fetch and compare the base tip), and a push refused for another reason (a hook) is tested to be an error, not a race.

### Real run (manual, `s06-real.sh`, run twice)
Claude Code 2.1.317, haiku, a scratch repository with a bare origin, the real MCP bridge, everything through `masond`: "Add goodbye.txt next to hello.txt". Second run, after the settings fix below:
```
#0 Add goodbye.txt   state landed   landed merged   failures 0
steps: exploring, developing, testing, review, landing, each attempt 1, succeeded
what reached the remote:  d2d85f7 Add goodbye.txt  (goodbye.txt | 1 +)
goodbye.txt on main:      goodbye
s06-real OK            (about 45 s end to end; first run the same)
```
The first run exposed that the agent inherited the owner's **personal global CLAUDE.md** via `HOME` (it talked about "the attribution reminder"). Agents are now started with `--setting-sources project,local`; the second run showed no trace of the personal notes. It still adds a `Co-Authored-By` trailer: Claude Code's own default. The agent also found its first compound Bash command refused under `dontAsk` and worked around it with the Write tool; not investigated further.

## Not run
- **Real provider failures** (usage limit, outage) end to end; the hold path is tested with a synthetic fixture only.
- **A real `claude` mid-session `kill -9`**: the crash tests use the scripted agent. (The reattach mechanism is the same, and the real agent's contract bridge retries for 30 s, but a 30 s+ daemon outage with a real agent was not tried.)
- **Questions** (`ask`) cannot be answered yet (Stage 10), and a restart loses a pending ask.
- Multi-project sharing, resources and ranking (Stage 8); exit-code-only test verdicts (Stage 9); the sweep's real two-minute cadence (tests drive it by hand).
- First execution of freshly built binaries on macOS takes seconds (Gatekeeper); not a product issue.

## Differences from the design
None in behaviour. Readings are in decision 0003 (notably: the review step is a pass-through, one current-thread event loop, projects as local-overlay files, durable acceptance, `--setting-sources`).
