# s1089: the unchanged-view test allows the usage view to change with the clock

Summary: the protocol test an_unchanged_view_is_not_sent_again_and_a_changed_one_is no longer fails when the usage view's clock-based text changes while it runs; an identical resend still fails it.

## Cause

`views.rs` builds the usage view from the real clock, and it renders ages, reset countdowns and hold text (`crates/core/src/usage_text.rs`, `crates/daemon/src/holds.rs`). The demo daemon seeds its snapshots relative to `now`. When one of those strings moved on between the first view and the end of the test, the server rightly sent the view again, and the test asserted that no usage view arrived.

## Change

Only the test in `crates/daemon/tests/it/protocol.rs`: every usage view that arrives after the first must differ from it. The sidebar assertion is unchanged. No product code changed. See decision 1078.
