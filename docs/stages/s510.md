# s510: dropped-line send-backs hand over ready-to-paste removes entries

Summary: a dropped-line send-back now includes a ready-to-paste `removes` JSON block for each listed line the task's own diff replaced in place.

## Why

#363 was sent back three times for lines it had replaced on purpose; the message left the agent to build the JSON.

## What changed

- `crates/landing/src/audit.rs`: `removes_block` and `feedback_with`.
- `crates/daemon/src/landing.rs`: `check_dropped` finds the replacements (`audit::replacements`) and uses `feedback_with`.
- Test: `a_replaced_dropped_line_yields_a_removes_block_that_parses`.

## Not verified

The pre-queue path (`asm.unkept`, landing.rs) still uses the plain `feedback`; it has no repository at hand. The daemon change was not exercised end to end. The scoped run_check failed in daemon e2e tests with "host never came up", which I did not investigate.
