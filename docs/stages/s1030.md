# s1030: Land now freeze test no longer races the freeze lifting

Summary: The Land now freeze test holds the fix at a gate so the freeze is certainly in force, then waits for the fix and `other` to land instead of asserting `other` never does.

## Cause

A freeze is cleared when the fix's batch is verified, before the fix is promoted. `other` then carries the Land now flag and no freeze, so it lands at once. The old test asserted it never lands, which has no fixed order.

## Change

Test only (`crates/daemon/tests/it/landing.rs`): renamed to `land_now_waits_for_the_freeze_to_lift`; the fix's batch blocks on a gate, `other` is checked while the gate is closed, then both are awaited after it opens. See decision 1023.
