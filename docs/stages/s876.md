# s876: Settings shows and changes where runs go (#891)

Summary: Both monitors' Settings pages have a "Where runs go" section that shows and changes the global placement mode and the selected project's, with the reason for the project's mode, through GET and POST /remote.

**Change.** Swift and Compose: `RemoteSettings` (parse of `GET /remote`), `SettingsPayload.remoteMode`, `loadSettings` also asks `/remote`, `changeGlobalMode` / `changeProjectMode` send `remote-save` and reload `/remote` on success; a refusal goes to `settingsNotice` with the daemon's message. The page section follows "Issue tracker": a choice for All of MASON, one for the project (disabled for `no [remote_runs]`), the source in words, the runner, problem, who changed it, and one line on the four modes. `clients/features.toml` gains `settings-placement` (waits for owner approval, it is a gate file). No daemon change.

**Tests.** Swift `SettingsModelTests`, `RemotePlacementTests` (ImageRenderer, offscreen); Compose core `SettingsModelTest`, app `RemotePlacementTest` (Compose test rule, offscreen). Exit script `scripts/exit/s876.sh`.

**Not verified.** The Compose build fails on the GitHub runner before it reaches my code (JVM target 25 vs 23 mismatch in `:core:compileKotlin`), so the Compose tests have not run. The iOS entry is marked done on the belief that iOS shares `SettingsPage` through MonitorUI; I did not build the iOS target. A "follow the global mode" choice for a project is not added.
