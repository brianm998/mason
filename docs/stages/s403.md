# s403: build failures get stable names, and the flakiest scheduler test is fixed

Summary: the regex parser names a failure from a compiler line `path:line` and any other uncaptured failure `build`, so source lines no longer reach flake records, and the scheduler test waits on the ledger state instead of assuming one pass adopted the outside holder.

## Scheduler test

`a_slot_held_outside_the_broker_is_not_granted_again` asserted `used == 2` right after the pass that granted `first`. That pass changes the holder set while the lock files are read, so it skips adopting the outside holder and leaves it to the next pass. The test now polls (bounded by attempts, not time) until the ledger counts it.

## Parser

`regex_lines` names a fail match: `path:line` for `path:line[:col]: error`, else its first capture, else `build`. Pass names, counts and verdicts are unchanged.

## Not verified

The scheduler race is found by reading, not reproduced: 3 runs of the sched tests were green before the change. The 50-run loop was not run.
