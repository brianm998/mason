# s589: running checks keep their slots across a daemon restart

Summary: A command that runs under a step host and holds slots is counted as holding them by the next daemon (read from the host's own directory before the first grant), so a restart can no longer let the queue grant the same slots again.

**Cause.** The broker grants in the ledger and the caller takes the kernel lock files. For a develop-phase `run_check` the caller is `CheckSlots::acquire`, a thread inside masond, so masond held the locks. A restart released them while the command went on under its step host. `count_outside_holders` adopts only slots the kernel says are held, so those looked free.

**Change.** `hostedcheck::collect` writes `holds.kv` (label, `uses`) into the host directory after the host starts (`CheckSpec::holds` and `label`, set for develop checks in `jobs.rs`). At startup `daemon.rs` calls `Broker::adopt_hosts(running_holds(hosts_dir))` right after the broker is made, before anything can be granted. Each host still `Running` with a `holds.kv` becomes a ledger holder (`Meta::Host`) labelled `#N check (from before the restart)`, so `mason resources` and the Compilation section name the task. Every full pass releases a `Meta::Host` whose host is no longer `Running` (exit record written, or lost). They are left out of the kernel comparison in `count_outside_holders` (there is no lock to find), so they are never double counted or taken for an outside holder.

**Which kinds survive a restart.** Develop `run_check` build and test commands: covered. Landing re-tests and builds (`landing.rs` specs) and test-step suite runs (`suites.rs`, `run_hosted_once`) also run under hosts that survive, but pass no `holds`, so they are still not counted after a restart. Not covered here.

**Not verified.** No full scratch-daemon restart exit test was run. The tests drive the broker with a fake host directory (host pid = the test process) and the real `hostedcheck::run` for the record. A host started by a daemon from before this change has no `holds.kv` and is not counted. Trust: `sched.rs` is budget code. The change only adds holders (it never grants), so limits can only become tighter than before, and a holder is dropped only when its host's command ended.
