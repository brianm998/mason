# s1058: the monitor shows nodes (multi-machine nodes, phase 4)

Summary: The Mac monitor has an "Accept work from other Macs" switch on Home and in Settings (on a Mac that serves as a node) and a Nodes section on a coordinator, the GitHub section is now "Remote runs" and a run on a node is a row in it, and `docs/nodes.md` says how to reach a node daemon of another macOS user.

The views read the daemon's own routes (`GET /node/status`, `GET /nodes`) every ten seconds while Home or Settings is on screen, and send `POST /node/accept` and `POST /nodes/use`; no protocol message changed, so no client regenerates anything. Each view reads its own model property in a view of its own, so the polling does not redraw Home. `node_exec::follow` enters a run in `remote_runs` as "node <name>" and marks it green, red or cancelled when it ends.

`clients/features.toml` (approved for this phase) gets `node-accept-toggle` and `home-nodes`: done in the Mac and iOS monitors, todo in Compose and Android, with the reasons recorded. Which clients must get them is the owner's to settle; the entries say what was done.

Not verified here: the screens were built and their models tested, not looked at (no offscreen render was made), and not run against the real Mac Studio.
