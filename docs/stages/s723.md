# s723: runner pools for GitHub: remote runs lease `gha` / `gha-macos`, not this Mac's slots (#700)

Summary: Two broker pools, `gha` (16) and `gha-macos` (4), exist by default; a test step or suite lease of a project whose runs go to GitHub holds one unit of them (a macOS run one of each) in place of `compile`, `test-suite` and `test-small`, ignores the CPU, thermal, disk and memory gates, explains its wait ("waiting for a GitHub macOS runner: 4 of 4 in use (#701, ...)") and is counted as held after a daemon restart until its run record says it ended.

**What exists.**

- `crates/daemon/src/sched.rs`: `gha = 16` and `gha-macos = 4` are declared as `Kind::Pool` in `Broker::new` unless `[pools]` in `resources.toml` names them; `mason resources limit gha-macos 2` works as for any pool (and survives a restart through `limits.kv`). `Meta::Remote`, `adopt_remote`, `take_over_remote`, `release_ended_remote`: the restart story below.
- `crates/scheduler/src/plan.rs`: `GHA`, `GHA_MACOS`, `is_gha_pool`. The thermal, CPU, stall, syspolicyd and disk gates already apply only to machine-class or `compile` requests, so a pool-only request was not held by them; the memory floor held every request, so a request for the GitHub pools alone is now excused from it. `Wait.pool` carries (held, limit) for the sentence.
- `crates/scheduler/src/explain.rs`: "waiting for a GitHub macOS runner: 4 of 4 in use (#701, #705)" (and "a GitHub runner" for `gha`), with "Nth in line" behind another waiter. The ordinary rank rule applies.
- `crates/daemon/src/remote.rs`: `units_for(runs_on, shards)` (one `gha` per job, plus one `gha-macos` per job for a macOS runner), `pool_needs` (replaces `compile`, `test-suite`, `test-small` and `exclusive` in a lease request by those units when `executor_for` says GitHub), `RemoteHold` / `HoldGuard` (a file in `remote-holds/` beside the hosts directory, written while a run is out), `running_holds`, `record_ended`.
- `crates/daemon/src/jobs.rs` (`acquire_needs_as`): the one place a task's step and per-suite leases are requested; it applies `pool_needs`, so the lease is held from the start of that lease until the run has completed or been cancelled. Pushing the snapshot is git work inside it and takes no further slot.
- Restart: `daemon.rs` adopts the holds whose `<id>.remote` record is still in progress, before the first grant; they are released when the record is collected or gone. A resumed step's lease for the same task takes them over (`take_over_remote("task N")`) so the units are not counted twice.
- `crates/adapters/src/bin/fake-github.rs`: a `run-hold` file in its directory keeps the run queued.
- Tests: `sched.rs` (defaults and limit change; three macOS runs with `gha-macos = 2` and the explained wait; a remote run starts while a hot CPU and thermal reading hold a local compile; a run of three units and its release; units held after a restart and taken over), `remote.rs` (`units_for`, hold records). Exit: `scripts/exit/s723.sh`.

**Not done / not verified.**

- Nothing was compiled or run: the owner skipped testing for this task and `cargo` is refused here, so the code, the tests and `scripts/exit/s723.sh` were only read and formatted with `rustfmt`. The first build may need small fixes.
- `[remote_runs] watch_account` (change item 5, optional, off by default) is not implemented.
- Sharding (#701) does not exist yet: `pool_needs` and the hold file use one job; `units_for` already takes the count.
- Debt payments (`hold_for_debt`) and the landing batch's own leases (`landing.rs`, #702) still ask for the machine's slots. A suite whose `fallback = "local"` takes over after a remote failure runs on the pool lease with no `compile` slot held.
- Nothing runs remotely unless a test forces it (`MASON_TEST_FORCE_REMOTE`) until #698 decides, so none of this has run against real GitHub.

**Trust.** `crates/daemon/src/sched.rs` and `crates/scheduler/src/plan.rs` are budgets: two new pools and their defaults, and remote runs excused from the memory floor (the other machine gates already did not apply to pool-only requests) because they use none of this machine, need the owner's approval. See `docs/decisions/0716-runner-pools-for-github.md`.
