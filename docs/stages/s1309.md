# s1309: `mason init` refuses on the repository before it asks anything

Summary: No commits, or a base branch that does not exist, is said before the first question, so
a missing test command no longer hides either.

Task #1335, decision 1299. `each_refusal_says_what_to_do_and_writes_nothing` was red on
`develop`: `questions::resolve` returned the missing-test-command refusal before `setup` looked
at the repository.

- `mason_onboard::repo_refusal(d, base)` holds the no-commits and missing-base checks. `setup`
  calls it where those checks were, so its order is unchanged.
- The CLI's `init` calls it before `questions::resolve`. At a terminal without `--base` only
  the commits are checked, because the base question has not been asked yet.

Not done: the other failing targets at that base (`mason-daemon`, `mason-pipeline --bin mason`)
are outside this change. The daemon's Add Project does not call `repo_refusal` early.
