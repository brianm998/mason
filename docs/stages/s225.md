# s225: Compose monitor installers (.deb, .msi)

Summary: The Compose monitor builds a `mason-monitor` .deb and a per-user, upgradeable .msi with the brand icon, renamed to the release asset names by `clients/compose/packaging/name-installers.sh`, via `make package-deb` and `make package-msi`.

What changed
- `clients/compose/desktop/build.gradle.kts`: target formats, Linux and Windows settings, `upgradeUuid`.
- `clients/compose/packaging/`: icons (PNG, generated ICO), `make-ico.py`, `name-installers.sh`.
- `clients/compose/Makefile`: `package-deb`, `package-msi`, version passed to Gradle.
- Decision: `docs/decisions/0220-compose-installers.md`.

Not verified
- Nothing was built: Gradle is only reachable through the build queue here, and `.deb`/`.msi` need Linux and Windows (WiX) anyway. The release workflow's dry run proves them. `createDistributable` on this Mac and `s13.sh` were not run by me.
- The Gradle DSL names (`iconFile`, `menuGroup`, `perUserInstall`, ...) are written from memory of the Compose plugin, not compiled.
- `mason://` is not registered (see the decision). `name-installers.sh` was not run.
