# s924: a run GitHub has not picked up comes back only when this machine has room

Summary: see decision 0917. With `fallback = "local"`, 16 runs came back from GitHub at once into a
heat-held Mac on 2026-11-22 and queued for 50+ minutes while GitHub was nearly idle.

## Built
- `place::LocalLoad::no_room(covered)` and `place::no_room_for(reading, uses, covered)`: pure; why
  a run holding `uses` cannot start here now, or `None`.
- `remote::RoomFn` now returns the reason (`Option<String>`), not a bool. `site_for_run` builds it
  from `Broker::load_reading` (an existing read-only query; `sched.rs` is not touched) and takes
  `covered`. `RoomCache` asks it at most every 2 s per run.
- `remote.rs` wait loop: the pickup timeout and the favor-remote spill share one decision. With a
  room function and no room, the run keeps waiting on GitHub; one INFO line per run says why. With
  room it falls back (spill message before the timeout, the usual message after). With no room
  function: as before.
- `suites::run_remote` takes `covered` and passes it to `site_for_run`.
- Tests: `place::tests::room_needs_no_hold_and_a_free_unit_of_each_slot`; in `remote::tests`
  `an_unpicked_favor_remote_run_comes_back_early_when_this_machine_has_room` (changed: no room no
  longer falls back at the timeout), `a_run_past_the_pickup_timeout_waits_on_github_until_this_machine_has_room`,
  `a_run_held_back_for_room_that_gets_a_runner_runs_on_github`,
  `a_run_with_no_room_function_falls_back_at_the_pickup_timeout`; integration
  `fallback_lease::room_for_a_fallback_reads_the_broker_and_a_covered_run_is_not_blocked_by_its_own_hold`
  (real broker, covered batch hold). Exit test `scripts/exit/s924.sh`.

## Needs the owner's approval
- `crates/daemon/src/suites.rs` is in `PROTECTED`: the change is a `covered: bool` parameter on
  `run_remote`, passed through to `site_for_run`. Nothing else in it changed.
- `scripts/exit/s924.sh` is a new gate under `scripts/exit/**`.
- The existing test above had its expectation changed (it asserted the old fallback at the timeout
  with no room). That is the behaviour this stage changes.

## Checked and left alone
- `crates/scheduler/**` and `sched.rs`: untouched. Limits, gates, ranks, `pickup_timeout` and
  `spill_after` defaults: unchanged.
- The GitHub-outage branches (unreachable for `pickup_timeout`, `startup_failure`): see 0917.
- Callers of `site_for` (covmap, the sweeps, remote.rs ~492/1031/2360) have no room function.
- `hostedcheck::remote_check` passes `covered = false`: landing checks hold nothing locally, so
  their `holds` are empty and only a hold can block them.

## Not verified
- No run against real GitHub and no live heat hold; the broker read is covered by the integration
  test and the loop by the fake GitHub and clock.
- The room check uses the suite's `uses`; the fallback lease uses the definition's test step
  `uses`. They can differ for a suite with its own `uses`.
- The full workspace tests and the other exit scripts were not run.
