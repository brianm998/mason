# s56: LLM provider accounts

Summary: LLM provider accounts are real configuration (`providers.toml`: adapter, billing, sessions, warn_at, monthly_budget_usd, overage); a project names its account and its agent steps take that account's sessions, and the usage view, ProviderStatus, both monitors and `mason doctor` list every account.

Task #25, the first of four usage tickets. Later tickets read, show and act on usage; this one makes the account exist.

## Built
- **`crates/daemon/src/providers.rs`** (pure parsing; `load` reads the file): `Account`, `Billing`, `Overage`, `parse_providers`, `resolve_account`, `check_llm_conflict`, `default_accounts`.
- **Config:** `account` overlay key (`AgentCfg.account`), `ProjectCfg.account` resolved in `load_projects`.
- **Scheduling:** `Broker::new` seeds one `llm:<account>` capacity per account; `acquire` uses the project's account; `llm_free(w, account)` and `next_admission` are per account.
- **Views and protocol:** usage lists every account; `ProviderStatus` 5 to 9. `mason.pb.swift` regenerated with `scripts/gen-clients.sh` (protoc and protoc-gen-swift were installed). Both Usage pages show the new fields; `features.toml` has `provider-accounts`.
- **Doctor:** per account, CLI, billing, projects, login line.
- Decision record: `docs/decisions/0034-provider-accounts-readings.md`.

## Exit test
`bash scripts/exit/s56.sh` (a real masond, fake-claude): two accounts with one session each (`--max-concurrent 1`) and a project each; both tasks were `developing` at the same time and landed; `mason resources` listed `llm:a` and `llm:b` only; `mason doctor` listed both accounts with adapter, billing and project; a project on `account = "missing"` stopped the daemon with `masond: p3: \`account\` "missing" is not in providers.toml (accounts: a, b)`; with no providers.toml, one account `claude` showed and a task landed. Passed.
