# s287: a review's prompt carries the diff

Summary: Every review prompt (MASON's own or a project's `.mason/prompts/review.md`) ends with the change it reviews: `git diff --stat` and `git diff` of `<base>...HEAD`, cut at 60,000 bytes with a note to read the listed files for the rest. A review step has no shell, so it could not run `git diff` itself.

## Why

Read-only steps get Read, Grep and Glob and no shell (since s71), yet the review prompt tells the reviewer to look at `git diff {base}...HEAD`. Reviewers coped by reading files until 2026-11-14, when both reviews of star #255 refused ("Bash is disabled in this session") and failed the task, and two reviews of #305 approved without having seen the change.

## What changed

- `crates/daemon/src/jobs.rs`: `review_diff_block` builds the block; the review prompt gets it after the pack or the built-in text. An empty diff says the branch changes nothing; a base that cannot be read says so instead of showing an empty change.
- Test: `a_review_prompt_carries_the_change_and_cuts_a_long_one` (unit, in `jobs.rs`).

## Not verified

The built-in prompt's own words still say to look at `git diff`; the block below them says the step has no shell and shows it. A review is not given a shell.
