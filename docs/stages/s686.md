# s686: the skipped-batch landing test waits for teardown before paying
Summary: The skipped-batch landing test now waits for the first batch's teardown before paying its debt, fixing a flake where the payment raced the worktree prune.

## Why

The test paid the first task's `step:test` debt as soon as the file was on main, but the push happens inside `run_batch` and the worktree teardown follows. `pay` adds a worktree once, unretried, so it could lose the race to the prune, return Err (discarded), and leave the debt open.

## What changed

The `running_batches == 0` wait moves before the payment, and the `pay` results are kept in the assertion message.

## Not verified

The cause was reasoned from the code; it was not reproduced.
