# s380: a suite already green for the tree does not queue for a slot

Summary: when a test step queues suite by suite, a suite with evidence for the step's exact tree (green for identical code already) takes no lease. `run_suite` reuses that result without running anything, so the suite no longer waits in the resource queue only to learn it has nothing to do. This covers both the side-by-side build suites (s345) and the step's sequential loop.

## Why

On 2026-11-14 star #216's test step showed "no output for 25 min". It had built `build-desktop` and `build-gui` green (evidence recorded at 17:53 and 18:11). Then a daemon update restarted the step, and the restarted step queued both builds for compile slots again. Two exclusive requests (#197, #210) were draining the machine ahead of it, so nothing compiled. When granted, both builds would have been reused without running.

## What changed

- `crates/daemon/src/suites.rs`: `proven(d, tree, suite)`. `run_side_by_side` and the per-suite loop skip the lease for a proven suite.
- Test: `a_suite_already_green_for_the_tree_takes_no_lease_when_its_step_runs_again` (`crates/daemon/tests/scheduling.rs`). A task's test step is retried while another holder has the only compile slot: it must finish and run neither build again. Without the change it waits for the slot.

## Not verified

A step that holds one lease for all its suites (no build, no exclusive, fewer than two build-only suites) still takes that lease before it learns its suites are proven.
