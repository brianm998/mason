# s724: set up and check remote runs

Summary: `mason doctor` checks a `[remote_runs]` project's workflow, other workflows firing on `mason/run/**`, token and push protection; `mason remote setup` writes `mason-run.yml` on a `mason/setup-remote` branch; MASON has its own `mason-run.yml`; the safety sweep deletes stale run refs.

What was done (#703, after #697):

- `mason doctor`, per project with `[remote_runs]` (`crates/cli/src/doctor.rs`, scanning in `crates/adapters/src/runref.rs`): the workflow named by `[remote_runs] workflow` exists on the base branch and runs on pushes to `mason/run/**`; no other workflow there fires on such a ref (a `push` with no `branches`, `branches: ['**']`, `branches-ignore` that leaves it in, `create`; `branches: [develop]` is fine); the token's repository `permissions.push` and `GET actions/permissions` (read only, nothing is written); `security_and_analysis.secret_scanning_push_protection` is enabled, else a warning with the settings link. A missing workflow, trigger, push or Actions read is a FAIL; an unreachable GitHub or an unreadable setting is a warning. #698 can read these findings.
- `mason remote setup --project P [--runs-on L]` (`crates/cli/src/remote.rs`): in a temporary worktree cut from the base, writes `.github/workflows/mason-run.yml` from `templates/github/mason-run.yml`, commits it on `mason/setup-remote`, pushes nothing, and leaves the checked-out branch, index and files alone. The setup block comes from the tree: Rust gives the `rust-toolchain.toml` channel and components plus rust-cache with `cache-on-failure: true`; `Package.swift` or an `.xcodeproj` gives `macos-15` and the Xcode version the project's `test` names (`Xcode_16.4`); Gradle gives setup-java and setup-gradle. It prints what to review and how to land it.
- MASON's own `.github/workflows/mason-run.yml` for the Rust, Swift and Gradle suites. It runs only on `mason/run/**`; no existing workflow changed (`ci.yml` and the others have `branches` filters that leave those refs out, which doctor now checks).
- Sweep (`crates/daemon/src/remote.rs`, called from `sweep::sweep_once`): at most every 30 minutes, on a separate thread, lists `mason/run/*` on each `[remote_runs]` project's remote and deletes those whose commit is over 24 h old and that no live run record (`*.remote`, pushed, not collected, not deleted) names. Each deletion is logged. A ref whose age cannot be read is kept.

Not verified: nothing was run against GitHub (no network, no token), so the API shapes (`permissions.push`, `security_and_analysis`, `actions/permissions`, `commits/{sha}`) are from GitHub's documentation. `permissions.push` describes the user, not a fine-grained token's own scope, so a token limited to other repositories could pass. The workflow scan is text, not YAML: it handles the usual `on:` forms but a YAML anchor or an expression would be misread. MASON's own `mason-run.yml` was not run on a runner (Xcode 16.4 and Gradle 8.12 are copied from `ios-setup` and `android.yml`). `where_to_run` (#698) does not exist yet, so nothing consumes the doctor result. Decision 0717.
