# s1101: a finished batch has left no integration branch

Summary: A landing batch now deletes its disposable integration branches before its row is recorded as finished, which ends a race that turned the daemon's crash test red on CI.

## Cause

`Runner::run` (`landing.rs`) recorded the batch as finished, then removed the pushed refs, and only then deleted `mason/int/<project>/b<id>`. `landing_crash.rs` listed the branches before it read the batch rows, so a batch finishing between the two reads failed it with "integration branches left behind".

## Change

- `Runner::run` detaches the integration worktree and deletes the branch before `record(.., true)`. The success and error paths share this code, and the repository lock is released before `record`.
- The same block deletes the `-half` branch of a split that ran both halves at once; until now it stayed until the next restart.
- After a restart, `coordinate` sweeps the dead daemon's branches before it marks their batches abandoned.
- `landing_crash.rs` reads the batch rows before it lists the branches. The assertion message is unchanged, and no sleeps were added.

`landing.rs` is protected: only the order of cleanup changes, not batching, the red ladder or the freeze.
