# s152: a stalled run is woken, a silent tree is killed, a waiting one never is

Summary: A stall watcher for suites, command steps and `mason run` children sends SIGCONT to stopped processes after `cont_after_s` of silence and kills a silent tree after `kill_after_s` (red, "stalled: no output or CPU for N min") unless a member waits on a lease; both keys default to off.

What changed
- `crates/daemon/src/watch.rs` (new): the pure decision `tick` (silence = no new output bytes and no CPU movement in the tree; SIGCONT every stopped member; kill a silent tree unless its pid set meets `waiting_pids`), and `Watch`, the thread that reads `ps`, signals, counts and stops the host.
- `hung.rs`: `Proc` knows the `ps` state (`stopped`), `tree_of` returns a tree's members; the compile-slot idle stop leaves hosts alone that the stall watcher owns (one watcher to a tree).
- `config.rs`: project keys `cont_after_s` and `kill_after_s`, default 0 (off). `--watch-tick-ms` sets how often the daemon reads a tree (5 s).
- `suites.rs` (protected), `jobs.rs`: a suite or command step starts a watcher beside its time limit; a killed run is red with the stalled reason (not "ran out of time"); a SIGCONT or kill is noted in the step's progress message.
- `sched.rs`, `http.rs`: `POST /leases` takes the requester's pid; `waiting_pids()`; the response carries the task's thresholds; `GET /stall/waiting` and `POST /stall/event` serve `mason run`'s own watcher.
- `cli/resources.rs`: a task's `mason run` child runs in its own process group under the same `tick` (CPU only, since its output goes to the terminal); a person's command is never watched.
- `GET /health` and `mason health`: "Stall watch: N SIGCONT(s) sent ..., N silent tree(s) killed" (in memory, from the daemon's start).
- Decision: `docs/decisions/0147-stall-watch-owner.md` (the watcher is in the daemon, not the step host; defaults off; hung.rs yields; SIGCONT includes the root).

Tests
- `watch.rs` unit tests of the pure decision (continue after silence, output and CPU are progress, a waiter spares a tree, a spared stopped tree is still continued, 0 is off) and `hung.rs` state parsing; a `config.rs` test of the keys.
- `crates/daemon/tests/stallwatch.rs`: a test that stops its own child is continued and the task lands, with one SIGCONT counted; a silent `sleep` tree is killed and the result says "stalled" and not "ran out of time"; a tree holding a pid with a waiting lease is spared (waits on the watcher's own `stall_spared` count, not a sleep) and finishes once released. Thresholds 1 s, tick 100 ms; no timing assertions.
- `scripts/exit/s152.sh`: real masond, a project test that stops its own child; the task lands and `mason health` counts exactly one SIGCONT.

Not run
- No real star run and nothing in starpipe or star's repository: turning the keys on (10 and 30 minutes) and turning starpipe's own SIGCONT and idle kill off for delegated jobs is the paired star ticket (brianm998/starry_timelapse_airplane_remover#550).
- The `mason run` watcher is not covered by a test that runs the CLI; its decision is the same `tick` that is unit-tested, and the CLI loop was only compiled.
- `run_check` and landing's re-test (`hostedcheck.rs`) are not watched; only suites, command steps and `mason run`.
- `mason hold` has no waiting state in this tree, so only lease waiters spare a tree.
- Counts are not stored: they restart at 0 when the daemon does.

Needs the owner: `crates/daemon/src/suites.rs` (verdict logic: a silent run becomes red) and `scripts/exit/s152.sh` are protected paths; both are the feature and its proof.
