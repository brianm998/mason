# s107: an expired agent login is a hold and a credentials alert

Summary: A CLI that cannot authenticate (401/403, "Not logged in", "invalid API key", "authentication_error", also on stderr) is now `Outcome::NotLoggedIn`, a provider hold of kind `credentials` that waits with no time charged, raises the `credentials` alert, is probed like an outage up to the 30-minute cap, and is cleared at once by `mason account release`.

Before, each task reaching an agent step ended `Crash` and failed (after climbing `agent.ladder`, which cannot help). Now `claude::final_outcome` returns `NotLoggedIn` (patterns in one place, `AUTH_FAILURE_WORDS` and `is_auth_failure`, checked before the limit and outage tests); the runner turns it into `HoldReason::NotLoggedIn`; `holds::observe_end` puts the account on a `credentials` hold with no reset, so the existing probe/backoff, gate and `release` apply. It is a hold, so it counts no failed attempt, no `max_rounds` round and no ladder step. `alert_kind` maps it to `credentials`; the sentence says to log in again. The new variant is in `crates/adapter-api/src/lib.rs`, not `contract.rs`.

The test at `claude.rs` that pinned "Not logged in" as a crash now pins the hold: a crash fails the task and every other task the same way, and only the owner can fix it.

Codex: its stream goes through the same `final_outcome`, so the same wording and statuses are recognised. I have no real Codex login-failure capture, so its actual wording is not known to match.

Tests: adapter fixtures and stderr cases in `claude.rs`; `crates/daemon/tests/credentials.rs` (real masond and CLI); `scripts/exit/s107.sh`.

Not verified: the real `claude` CLI's output when logged out beyond the one earlier fixture; the 401/403 fixtures and Codex wording are synthetic; the conformance kit has no scenario for the new outcome.
