# s869: remote runs wait for runner units in the broker (#818)

Summary: A run bound for GitHub (an agent's check, a suite, a landing hold) now asks the broker for the runner units of the jobs it starts, sized by its shards and runner, and is pushed only once they are granted; `mason resources` lists the waiters.

What changed:

- `remote::run_place`, `jobs_of`, `shard_command`, `suite_pool_needs`, `with_units`: one place that says where a run goes and what it holds (crates/daemon/src/remote.rs).
- `remote::Grant` (made only from a lease) is required by `execute`, `execute_sharded`, `run_or_fallback` and `hostedcheck::run`; a fallback gives the units back.
- `CheckSlots::swap_for` takes pool units for a check bound for GitHub (`Want::Pool`), nothing for one attaching to a pending run, local slots otherwise; `acquire_needs_as` places a suite by its own rules.
- `Runner::hold_suites` (crates/daemon/src/landing.rs, protected) splits a landing hold per suite; `suites.rs` (protected) uses the shared sharding rule and passes the suite to `lease_suite` and the side-by-side lease.
- `Broker::take_over_remote_where` lets a check take over its adopted hold by run-id prefix.
- `mason resources`: `gha` waiters in line order with kind and wait.

Tests: `a_check_bound_for_github_waits_in_the_broker_until_a_unit_is_free`, `a_run_that_falls_back_gives_its_runner_units_back_before_taking_local_slots`, `a_check_asking_again_after_a_restart_takes_over_its_adopted_hold_once` (sched.rs), `a_suite_holds_one_gha_unit_per_job_and_a_macos_runner_adds_gha_macos` (remote.rs), `a_hold_takes_runner_units_for_a_github_suite_and_local_slots_for_the_rest` (landing.rs). Exit test: scripts/exit/s869.sh.

Not verified: the code was written without a local build (cargo is refused in this shell), so only `run_check` has compiled it. The tests drive the broker and the pure placement functions, not a whole daemon with the fake GitHub, so "no push is recorded while a check waits" is shown by a stand-in push after the grant, not by `FakeGh`. Not done: the suites' `run_remote`, landing's re-test and lint checks and covmap pass `Grant::unplumbed`; the floor and fast-tier builds and debt payments are not placed per suite; a test step's fallback does not release its pool lease. `landing.rs` and `suites.rs` are guard files and need the owner's approval.
