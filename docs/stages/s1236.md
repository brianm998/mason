# s1236: a node watches every volume its jobs write to

**Cause.** `node_serve::gather` read free space for the data folder only, so a full internal disk
went unnoticed, and `s1123` (a real node under `/tmp`, default 50 GB limit) failed on a host with
less than 50 GB free in `/tmp`.

**Change.** `measure_volumes` reads the data folder, the build cache (links followed), cargo home,
home and the temporary folder, once per volume. Data and build-cache volumes keep
`min_disk_free_gb` (50); the others use the new `min_other_disk_free_gb` (default 10). `why_not`
names the path, free space and need. `mason node status`, `/nodes` rows (`disks`,
`disks_unreadable`) show it; `list`/`show`/alerts/monitors already show `why_not`. An unreadable
volume never stops the node and is listed. `s1123` gives its node `[nodes.default]` limits of 0 in
the coordinator's `daemon.toml`; no assertion changed.

**Default 10 GB:** the internal disk holds the toolchain and short-lived files, and marmot is healthy
at 48 GB there; 50 would stop it.

**Not verified.** `mason node doctor` does not list the volumes (status does). A coordinator sending
the new setting to a node running older code is refused by that node's settings parser until it
is updated. Monitors' node row only shows the reason text.

**Exit test.** `scripts/exit/s1123.sh` (protected; the change only removes its dependence on the
host's free space).
