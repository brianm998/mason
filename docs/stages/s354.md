# s354: long interactive commands show as a short description that opens a copyable dialog

Summary: The monitors' Compilation rows show an interactive command as a one-line description of at most 50 characters, and clicking it opens a dialog with the whole command to select and copy.

Decision 0347 records the choices.

**What changed.**
- `crates/scheduler/src/explain.rs`: `describe_command` and `label_parts`; `short_label` (the waiting sentence) uses `describe_command`.
- `schemas/mason.proto`: `command` on `CompileHolder` (8) and `CompileWaiter` (10); Swift bindings regenerated with `protoc`, Kotlin's come from the Gradle build.
- `crates/daemon/src/sched.rs`: `compilation()`, `compile_reason` and `snapshot()` send the description as label and the full command in `command`.
- Swift `MonitorCore`/`MonitorUI` and Compose `core`/`app`: `Format.commandDialog`, `openCommand`/`closeCommand` on the model, a link-style row label and a `CommandSheet` / `CommandDialogView`.
- Tests: scheduler unit tests, protocol round trip, `scheduling.rs` daemon test, `CommandDialogTests.swift`, `CommandDialogTest.kt`. Exit script `scripts/exit/s354.sh`.

**Not verified.** The Swift and Kotlin code was not compiled or run here and nothing was rendered, so the dialog's look, Escape handling and pointer cursor are untested. The task page has no compile line, so nothing changed there. The exit script drives the in-process daemon of the daemon tests, not a separate `masond` process.
