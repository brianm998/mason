# s478: reuse a baseline across commits that do not touch the suite

Summary: A baseline is reused from the newest ancestor base with the same suite-definition hash when no file changed since falls under the suite's impact paths, and the step's notes say so.

Before, `baseline` (`crates/daemon/src/suites.rs`) was keyed on the exact base commit, so every
develop move (including README status commits) paid a full-suite baseline run.

What changed:
- Migration 42 adds `baselines.def_hash`; `put_baseline_hashed` and `ancestor_baselines` in the store.
- On a miss, `baseline_noted` looks at the newest stored baselines of the suite with the same
  definition hash (hash of the suite's Debug form and its environment), keeps one that is an
  ancestor of the base, and reuses it if `git diff --name-only` between them touches nothing the
  suite's impact map selects. A path the map does not name, or any path under `.mason/`, counts as
  touching. The reused result is stored under the new base too.
- Narrowed runs stay uncached. Rows without a hash (older rows, `basecheck` rows) are never reused.
- The reuse is reported in the suite's notes (excused outcome) or the feedback (product red).

Tests: `reuse_tests` in suites.rs (README-only reuses; `crates/` change, definition change, `.mason/`
change do not; unhashed rows are not reused). Exit script: `scripts/exit/s478.sh`.

Not verified: a live daemon run (no `-b-<suite>` host dir check); the exit test uses a scratch git
repo and the store, not a running test step. A README commit reuses only if the project's impact map
names README/markdown paths as touching no suite; with no such entry it still runs a baseline.
Trust: `suites.rs` is in PROTECTED (verdict logic); the owner must approve.
