# s448: monitor_inplace.rs compiles on Windows

Summary: `monitor_inplace.rs` no longer uses `std::os::unix` directly: the build is started with `mason_platform::process::spawn_group` and cancelled with `signal_group`, and the tests' chmod helper is gated with `#[cfg(unix)]`, so the Windows CI job builds again.

**Cause.** The in-place monitor build used `CommandExt::process_group(0)` and the tests used `PermissionsExt::from_mode` with no `cfg(unix)` gate; the local test step runs on macOS only, so nothing caught it before CI.

**Change.** The existing platform helper (`spawn_group`, `signal_group`) replaces the hand-written unix calls (its Windows side is the job-object/new-group code the step hosts already use). The test module is `#[cfg(all(test, unix))]` because its tests need executable shell scripts; they are kept, not deleted.

**Not done, waits for the owner.** A `cargo check --target x86_64-pc-windows-*` in the landing batch check is a gate change (`.mason/**` is protected). Not added; CI stays the guard.

**Not verified.** The green `windows` job on GitHub cannot be checked locally; `scripts/exit/s448.sh` runs the cargo check only if a Windows target is installed.
