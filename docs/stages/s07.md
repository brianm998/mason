# Stage 7: Definitions and configuration

## Built
- **`crates/definition` (`mason-definition`)**: the `.mason/mason.toml` language. `parse` (every mistake reported with its key; unknown keys refused), `edit` (written with `toml_edit`: a machine edit changes one line and keeps comments and order; checked edits refuse an invalid result), `validate` (every path reaches a terminal state, every loop is bounded, fan-out and joins behave, every reference exists, nothing is used that cannot run yet), `layers` (the five configuration layers with the source of every value), `graph::after` (where a task goes next: the one function the daemon and the dry run share), `dryrun` (scripted tasks walked through the **real reducer**), `clarity`, `filing`.
- **Step types**: `agent`, `command`, `approval` fully; `test` (a command with an exit-code verdict) and `landing` as before. `gate`, `ci`, `pr`, fan-out and `when` are valid language but refused when applied, saying which stage adds them.
- **Events and reducer**: named steps, the definition pin, the route a task started by, `ExploreAnyway`, per-step attempt counts, forward-only `next`. Old logs still decode and replay.
- **Store**: definitions by hash, runtime overrides (owner and expiry required), per-task overrides, step/route/definition on the task projection (migration 4, rebuilt on open).
- **Daemon**: jobs run the step the **pinned** definition names and take the next from `graph::after`; definitions read from the base branch and applied live (invalid edits refused and reported while the old one runs); a change that edits `.mason/mason.toml` is rejected at submission if the new definition is invalid; agent `tools` narrowed per step (through the contract, the adapter and the MCP bridge); the review prompt; approval steps; HTTP endpoints for approve/reject/explore-anyway/overrides/definition/config.
- **Skipping exploration (Part 4)**: `explored_entry`; the flag from `mason task add --explored`, front matter, the `mason:explored` label helper and the `explored` argument docs; `mason help filing`; the deterministic clarity check; the optional classifier behind a project setting; trust rules; the recorded route; "Explore anyway"; `request_exploration` with no failure charged.
- **CLI**: `task approve|reject|explore-anyway|override`, `definition check|dry-run|show|reload`, `config show|set|unset|list`, `help filing`; `task show` says why exploring was skipped; `status` shows definitions, refusals and the exploring numbers.
- `docs/decisions/0004-definitions-readings.md`, `scripts/exit/s07.sh`.

### Tests
- **Property tests (`proptest`)**: *validator soundness*. Over 1,500 generated definitions (51% valid, measured separately so the property is not hollow), every definition the validator accepts ends in `landed` or `failed` within a bound for *any* sequence of step outcomes, on every route, **through the real reducer**; rejected ones always say why.
- **Table tests**: every validator rule with a definition that breaks it and one that does not; the clarity check (each missing ingredient, spellings of headings, prose/URLs/versions, hostile and empty bodies); the layers (each beats the one below and names its source; none can change the graph); filing front matter; scenarios.
- **Outside text claiming `explored`** is ignored (reducer test and daemon end-to-end), until the owner approves.
- **Daemon end to end** (20 tests): flag, clarity, no `explored_entry`, classifier, trust, Explore anyway (before and after a skip), `request_exploration`, two definitions, invalid edit refused and old one running, watcher and overlay refusal, pinning across a change, a change that would break the definition is rejected, approvals (no slot held, reject), unsupported step types refused, runtime and per-task overrides with expiry.
- The whole Stage 6 crash harness (23 kill points and the real `kill -9` cases) passes unchanged on the definition-driven daemon. Recorded event logs: new-format fixtures re-encode byte for byte; the Stage 6 logs still replay.
- 252 tests across the workspace, about 83 s; all exit scripts s00 to s07 pass (about 105 s).

### CI
Green on Ubuntu and macOS (`cargo test --workspace` and every exit script including `s07.sh`; the macOS job takes about 6 minutes, inside the 10-minute budget). CI found two things local runs did not, both in tests: two scripted tasks making the *identical* commit one after the other leave the second with nothing to commit (timing decided whether they overlapped; the scripted commit is now unique per task and a strictly sequential test pins it), and `dash` (Linux `sh`) has no `set -o pipefail`.

## What testing found
- A CLI that **panics when its output is piped to `head`**: fixed (and tested).
- **The daemon never fetched** when someone else pushed a new definition, so a reload saw a stale `origin/main`. Reloads fetch; the watcher fetches on a slower cadence than it polls local state.
- The watcher **remembered the last good overlay hash**, so restoring a good file after a bad one looked like no change and the refusal never cleared.
- The clarity check **lost `./Makefile`'s "pathness"** and **treated `token.rs` as missing** when the file is `src/auth/token.rs` (now matched by file name).
- Several tests exposed an artifact worth knowing: two tasks making the identical commit one after the other leave the second with nothing to commit. Tests give each task a file of its own.

## Not run
- **A real model** as the clarity classifier, and real agents using narrowed `tools` or a review step (the contract, adapter and bridge are tested; the prompts for exploring, developing and review are exercised only with the scripted agent, plus the real explore/develop of `s06-real.sh`).
- **Fan-out, conditions, `gate`, `ci`, `pr`** execution (validated as language only, as the plan says).
- **Daemon restart with an approval pending**: the wait is re-asserted idempotently, but this exact case is not in the crash harness.
- `explored` argument of the `file_proposal` tool (Stage 21 builds proposals; the help text and agent notes describe it).
