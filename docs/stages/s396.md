# s396: MASON's own test step runs only the crates a change touches

Summary: a suite with `narrow_packages = true` (and a `dev_command`) runs, in a task's test step, its `dev_command` for the changed crates and their dependents, as `run_check` does; it records no evidence, the landing batch runs the suite whole, and MASON's `cargo-workspace` suite turns it on.

## Why

488 of 684 compile-wait hours in the 2026-11-10..14 review were MASON's own tasks, each building and testing the whole workspace in its test step.

## What changed

- `crates/testing/src/model.rs`: `Suite::narrow_packages`.
- `crates/definition/src/testing_parse.rs`: the key, refused without `dev_command`.
- `crates/daemon/src/suites.rs`: `narrow_packages_for_step` (via `narrow_for_step`) uses `scope::changed_packages`; the copy is `narrowed` (s386 rules: no evidence, no green-at-base, no run time, baseline uncached) and its note goes in the closing note. Runs whole when no package list is found.
- `.mason/mason.toml`: `narrow_packages = true` on `cargo-workspace`.
- Tests: `narrow_packages_parses_and_needs_a_dev_command`, `a_task_test_step_runs_only_the_crates_its_change_touches_and_their_dependents` (daemon `testing.rs`). Dependents are covered by `scope::tests`.

## Trust

`crates/daemon/src/suites.rs`, `crates/testing/**` and `.mason/**` are protected; each changes because the narrowing is a test-step gate behaviour. The owner approved the change in the 2026-11-14 review.

## Not verified

The running daemon must know the key before `.mason/mason.toml` is read (an old daemon refuses an unknown key). A change outside any crate (e.g. root Cargo.toml) gets whatever `scope::select` answers. Exit script runs the new tests only.
