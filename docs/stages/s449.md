# s449: bring the matrix, codec and sidebar tests up to the Deferred state

Summary: the state-matrix, codec and daemon protocol tests now cover the Deferred state and its two events, which s325 left red.

## What changed

- `crates/engine/tests/matrix.rs`: `expected()` has the Deferred and Undeferred events. Approve, reject and cancel are legal from Deferred as well as Proposed, Undeferred goes back to Proposed, and a tracker edit is legal from Deferred. Blocker events stay illegal from Deferred, which matches the reducer and the decision (0319 names only approve, reject, undefer). The count is `12 * 26`.
- `crates/store/src/codec.rs`: `samples()` already had both new kinds; the asserted count was stale and is now 28.
- `crates/daemon/tests/protocol.rs`: the sidebar lists `deferred` between `proposed` and `failed`, and it starts collapsed (as s325 says). A proposal's allowed actions now include `defer` (that was the failure in `every_entity_carries_...`).
- The reducer needed no change: each transition checked against s325 and decision 0319 matches.

## After merging develop (final round)

While this branch waited, two other tasks (t457, t458) landed their own fixes of `matrix.rs` and
`codec.rs`, and develop took an equivalent APNs cache fix (415d42f9). The merge kept develop's
versions. But both matrix fixes had added the Deferred and Undeferred events to `events()`, so
develop listed them twice: 28 events against an asserted `12 * 26`, which fails. This branch
removes the second copy. What remains of this branch is that fix, the protocol test comments,
this note, the decision and the exit script.

The unscoped run after this merge was green except `-p mason-step-host --test host`, which then
passed when the package ran alone; this branch does not touch that crate, and I did not look
further.

## How s325 landed red

s325's exit script ran only name-filtered tests (`--test behaviour -- deferred_...`, `-p mason-store codec`, one attention test), so it never ran `--test matrix`, the codec round-trip test or `--test protocol`. Its stage note says nothing was compiled or run (the build queue and run_check were unavailable), so the change went in without the workspace test step. Still open: an exit script can pass on a filtered subset, and nothing requires that a change that adds a state or event kind runs the tests that enumerate them. I filed nothing.

## Also fixed: APNs token cache ignored the key (found by the workspace run)

`mason-adapter-api` `apns::cached_jwt` keyed its one cached token on key id and team id only, so
a replaced key file with the same ids kept a token signed by the old key. In the daemon test
binary, `a_push_reaches_owner_devices_with_a_jwt_that_verifies...` failed ("signature verifies
against the owner's key") whenever another test in the process had cached a token first. The
cache now also compares the key file text; a unit test covers it. The `fetch_stall` failure in
the previous attempt passed when run alone (a 5 s cancel timing check that went red under load);
I did not change it.
