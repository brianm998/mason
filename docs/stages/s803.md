# s803: landing checks no longer send the suite's raw build template to GitHub

Summary: Landing's floor, fast-tier and lint checks pass their place's suite without its `build`, and `remote_check` never passes on a build containing `{`, so `{project_test}: not found` can no longer end a floor run.

**Cause.** #815 gave landing checks `place: Some(suite)`; `remote_check` took `suite.build` (the raw `{project_test} --no-run`) as the run's build step, because the floor's `cmd` is the already-expanded build and `starts_with` never matched.

**Change.** `hostedcheck::without_build` is used at the floor, fast-tier and lint-tier `CheckSpec`s in landing.rs; `build_choice` in hostedcheck.rs also drops any template with a `{`. Unit tests cover the choice.

**Not verified.** No landing test with a fake GitHub and no real-masond exit script were written; `s803.sh` runs the unit tests and greps that no landing spec passes a raw suite clone. I could not compile locally (the shell's cargo is routed to the queue); the build rests on run_check. #816 and #785 were not rebased on.
