# s520: run_check says at once when a failing test is red on develop too

Summary: `run_check` names each failing test that also failed in develop's latest recorded result for the suite ("red on develop at <sha> too: not your change; merge develop when it is fixed"), without waiting for the test to be quarantined.

## What changed
- `Store::latest_baseline(suite)` returns the newest baseline row (base, failing tests).
- `knownred::red_on_develop_header` picks the failing tests in that list that the ledger does not already name; `known_header` in `jobs.rs` adds its lines after the known-red ones. Nothing extra is run.
- Tests: `a_test_red_on_develop_is_named` (red there: named; passed there, no baseline, or already known red: not), and a store test for `latest_baseline`.

## Not verified
- Not run against a live daemon. The newest baseline row is taken as develop's, and baselines are written for task bases too, which are nearly always develop commits; a task based on an older commit could name that older commit's reds.
