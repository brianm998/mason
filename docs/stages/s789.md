# s789: a coloured lint red is blamed by file

Summary: Lint and build-floor reds are parsed from the full, ANSI-stripped output, and remote runs are told `CARGO_TERM_COLOR=never`, so the tasks touching the named file are parked instead of the batch being split.

What changed
- `landing.rs`: `strip_ansi`; `lint_files` and `lint_places` strip it; they read `CheckOutcome::full`, not the 40-line tail. The build floor (`build_suites`, batch only) now records files and `(at file:line)` too, and `lint_blame_files` uses them when `floor_red` is set.
- `hostedcheck.rs`: `CheckOutcome::full`.
- `remote.rs`: `run_json` env gets `CARGO_TERM_COLOR=never`, `NO_COLOR=1`.
- Tests: unit `lint_parsers_read_coloured_output_and_the_full_log`; landing `a_coloured_clippy_red_parks_the_task_that_touches_the_file_without_a_split`.

Not verified

- The exit script runs the unit and landing tests; it does not use a fake GitHub artifact.
- Verdict logic in landing.rs needs the owner's approval.
