# s534: Swift monitor lazy sidebar list and one layout per row

Summary: The Swift sidebar list is a `LazyVStack` keyed by `SidebarEntry.id`, so only rows near the viewport are built and laid out, and a row's meta line is one custom `MetaLayout` instead of a four-variant `ViewThatFits`.

Task #518. See `docs/decisions/0527-lazy-sidebar-meta-layout.md`.

What changed
- `MonitorUI/Sidebar.swift`: `LazyVStack` in the scroll view; the section header no longer sets its own `.id`, and the scroll target is `SidebarEntry.headerId(state)` so `scrollTo` reaches a header that is not realised. `MetaLayout` + `MetaFit` give way model, then typical, then wrap the cells under the time. Accessibility identifiers and labels are unchanged.
- `MonitorCore/SidebarLayout.swift`: `SidebarEntry.headerId`.
- Tests: `LazySidebarTests` (517-row fixture in a 600 pt window evaluates under 100 row bodies; scroll reaches the Canceled header; give-way order of `MetaFit`).

Not verified: I could not build or run Swift in this session, so none of the Swift code or tests has been compiled or run. Whether `scrollTo` reaches an unrealised header on the real macOS runtime, and the visual result of `MetaLayout` (dropped pieces are clipped to zero width, not removed from the accessibility tree), are untested. The give-way order is tested on the pure `MetaFit` function, not from snapshot text. CPU was not measured.
