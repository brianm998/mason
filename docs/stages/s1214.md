# s1214: a per-step timeline of the agent's file edits (task 1130)

**Cause.** The Claude stream reports every `Edit`, `MultiEdit` and `Write`, but the adapter kept
only a one-line `ToolCall` summary, so how a change was built (rewrites, reverts, abandoned
approaches) was invisible to the reviewer, the diagnosis agent and the owner.

**Change.**
- `AgentEvent::FileEdit { tool, path, old, new, truncated, turn }` (adapter-api); the Claude
  adapter emits it after the `ToolCall` (one per `MultiEdit` entry); each text is cut to 8 KB.
- `crates/daemon/src/edits.rs`: appends each event to `edits-<run>.jsonl` in the task's log
  directory (4 MB cap per run), reads it back, summarises per file ("edited 3×, reverted") and
  prints compact diffs. Revert: an `Edit` that swaps an earlier edit's text back, or a `Write` of
  text an earlier `Write` of the file had, with a different `Write` between.
- `GET /tasks/{id}/edits[?run=N]` and `mason task show <id> --edits [--run N]`.
- Reviewer step and diagnosis prompts get a fenced "File edit history" block of the per-file
  lines only (`prompts::edits_block`), paths flattened to one line.

**Not done.** The monitor "Edits" tab (Swift or Compose) and its `clients/features.toml` entry:
no client code was written or built. Only the codex adapter and the fake adapter emit no
`FileEdit`. The revert rule is a heuristic on exact text, not on the file's real content. The
tests were not run locally (GitHub `run_check` only).

**Trust.** `crates/daemon/src/prompts.rs` is PROTECTED: the edit block is fenced as data.

**Exit test.** `scripts/exit/s1214.sh`.
