# s232: a CLI stopped by a signal is retried once

Summary: An agent step whose CLI exits 143 (SIGTERM) or 137 with no result is resumed (or restarted if it has no session) once, instead of failing the step.

The same failure "the CLI exited with status 143 and no result" repeated on tasks #169 and #253: something outside the agent stopped the CLI. `cli_was_signaled` in `crates/daemon/src/jobs.rs` recognizes it and the host-loss loop retries once.

Tests: `signaled_tests`. Not verified: the real cause of the SIGTERMs was not found; this only absorbs one.
