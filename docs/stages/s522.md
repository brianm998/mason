# s522: run_check's queue wait no longer counts against the agent's tool call

Summary: A develop agent's tool-call limit now covers the step's whole extended life plus the test timeout, so a `run_check` queued for a slot is no longer cut off while it runs.

Cause: `tool_timeout_for` gave `test_timeout + 60 s` from the call, queue time included.
Change: `develop_tool_timeout` (jobs.rs) sets the limit to max(current, budget, 2 x budget + test_timeout + 60 s); queue waits are already credited to the step deadline (s417), which can grow to twice the budget.

Not verified: no end-to-end test with a gated fake check (the limit is fixed when the agent starts, so the unit test checks the arithmetic only); the real agent CLIs were not run. Reporting queue position to the agent was not done. The scoped test run failed to build on landing.rs:434 (`Ok(found)` on `[Marker]`), code this change does not touch, so the new test has not been seen to run; fmt/clippy were not run either.
