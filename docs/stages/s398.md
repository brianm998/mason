# s398: a queued task waits for in-flight tasks that change the same files

Summary: a queued task whose plan (or, if explored, body) names a file that a task in testing, review or landing changes starts only after that task lands, for at most `hold_back_secs` (default 2 h), never for files matching `hold_back_ignore`.

- `crates/daemon/src/file_hold.rs`: the pure decision (`decide`), file extraction, and `Daemon::file_hold`, used by `next_admission` and shown as "waits for #N (both change <file>)" in the task activity.
- Project settings: `hold_back_secs` (0 turns it off), `hold_back_ignore` (globs).
- In-flight files are `git diff --name-only <base>...<branch>`. The hold clock is in memory, so a daemon restart restarts it.

Not verified: the daemon-level path (git diff of real branches, activity text) has no test; unit tests cover the decision, extraction and time limit, and the exit script runs those. Urgent tasks are never held. No scheduling rank code changed.
