# s553: Skip testing for all reaches tasks waiting in base-red, and every skip says what it did

Summary: The daemon reads a skip with an empty step as the task's test step, and the Swift and Compose monitors (and the Android screen) disable Skip testing for all with a reason when they cannot act and show "Skipped testing for N tasks", "Nothing to skip: ..." or the daemon's refusal on the Testing page.

See `docs/decisions/0546-skip-empty-step-is-test-step.md`.

What changed
- `crates/daemon/src/suites.rs` `skip`: scope `step:` with no name is the project's test step.
- `crates/daemon/tests/base_red.rs`: a skip with no step name ends a base-red wait, clears it and records a `step:test` debt.
- Swift (`SectionPages.swift`, `Model.swift`, `Pages.swift`) and Compose (`SectionPages.kt`, `Model.kt`, desktop `Pages.kt`, Android `PhoneScreens.kt`): `skipNotice`, `skipDisabledReason`, the button always shown on a non-empty Testing page and disabled with the reason; core-model tests in both.

Not verified: the 09:00 failure was not reproduced, so the empty step (daemon refuses "there is no step ``", shown nowhere) is the most likely cause but unconfirmed. Swift, Kotlin and cargo tests were not run by me beyond what run_check does; no iOS/Android UI was run. `clients/features.toml` was not changed (the feature description already covers Skip testing). Per-task "#N: refused" text is not built: a refusal shows the daemon's error without the task number. Only the Testing page shows these messages, not each task page's action buttons.

Exit test: `bash scripts/exit/s553.sh`.
