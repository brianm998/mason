# s1227: a test step without suites follows placement

Summary: a test step with no suites (its `build`, then its `test` command) asks placement as every other run of the task does, and runs on a node or on GitHub when placement says so; it no longer runs on the coordinator while its lease holds a node's unit.

## Cause

`jobs.rs` sent a test step without suites to `command_job`, whose runs always started a local step host. The step's lease was already converted to a node unit or runner units (`remote::pool_needs`), so a `remote` project held the node's unit and then ran the command here.

## Change

- `crates/daemon/src/jobs.rs`: `command_job` asks `executor_for` with the step as a suite named after it (its `uses`, none of a suite's own settings), for the task, so the task's `run_on` comes first, then the project's mode and the global switch, and `exclusive` stays local. When that is off the machine (`placed_test`), the build and the command go out as one `hostedcheck` run (`run_placed`): the same placement, node wait (`remote` never falls back to the coordinator), GitHub path, timeout and restart attach as `run_check` and landing's re-test. The verdict, reruns, flaky note and reuse record are the local loop's own.
- The log is copied to `test-r<run>.log`, and `test-r<run>.ran` says where it ran. A lost or unreachable node gives no result: it is retried for up to 30 minutes and after that fails the step; it is never a red.
- A project with `[remote_runs]` and no suites takes the same path (placement is the same function).
- `command` and `gate` steps stay on the coordinator; `docs/nodes.md` says so.
- No change to `sched.rs`, `suites.rs` or `landing.rs`.

## Not verified

- No real GitHub run, and no run on a second Mac: the tests use two daemons on loopback.
- A script's JSON result file (`MASON_RESULT_FILE`) and a pty are not carried to a node or GitHub: such a run is judged by its exit status. The silence watch (`cont_after`/`kill_after`) is not applied to a placed run; its timeout is.
- After a restart, a placed run that already finished and was handed over runs again rather than being read back (one that was still out is attached to).
- The live line and byte counts of a placed run are read from its finished log, not as it runs.
