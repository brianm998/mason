# s147: monitor sidebar fits every row at narrow widths

Summary: The macOS monitor's sidebar content is pinned to the panel width, and the row metadata line, progress line and section header now shrink, drop pieces or wrap instead of clipping both edges.

What changed
- `Sidebar.swift`: scrolling content `.frame(width:alignment:.leading)`; metadata line is a `ViewThatFits` (full, no model, no typical, two-line); header title truncates, count stays; row key does not shrink.
- `Components.swift`: `ProgressLine` has a last fallback (count and tokens truncate, time stays).
- Compose `Sidebar.kt`: typical and title take the remaining width and ellipsize; key does not wrap.
- Decision: `docs/decisions/0142-sidebar-fits-narrow-widths.md`. `clients/features.toml` unchanged.
- Test: `clients/swift/Tests/MonitorUITests/SidebarFitTests.swift`.

Not verified
- No one dragged the real sidebar to its minimum (the exit test is manual); the unit test measures hosted fitting widths.
- The Swift changes and the new test were never compiled or run (the check runs the Rust workspace; swift test was blocked in this session). Compose was changed by reading only: not built, no Compose UI test added.
