# s747: the landing queue does not wait out its window for nobody

Summary: A landing batch waits out its window only while another task of the project is still moving toward landing; with none moving it forms at once, and `mason landing` names the tasks it waits for.

`plan::form_batch` takes `moving: usize` (0 forms at once; a full batch still forms at once). `landing.rs::moving_tasks` counts, from the world, the project's tasks in exploring, developing, testing, review or landing (not yet queued or in a batch), or queued without a blocker, and not paused. The coordinator caps its wait at one second while it waits, so a task that fails, is cancelled or is blocked is noticed on the next look. `GET /landing` returns `collecting_for`; `mason landing` prints "collecting for N s while #A, #B still moving" or "forming now: nothing else is moving". Land now, `max_size`, freezes and `window = "0s"` are unchanged.

`DaemonConfig.landing_window_always` (off in the daemon, on in the test support's default config) keeps the old behaviour for the many tests that file tasks one after another and expect one batch. The new tests (`it/landing_collect.rs`) turn it off.

Not verified: no run on a real machine; the "still developing" case is a task filed and left queued (claims paused), not one held in develop by a scripted agent. The one-second look is a poll, not an event on leaving a step. Tests ran only through `run_check`.
