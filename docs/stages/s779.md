# s779: the daemon test wait floor is configurable, and remote runs can lower it

Summary: The 900 s floor under every daemon integration-test wait now comes from `MASON_TEST_MIN_WAIT_S` (default 900), and `[remote_runs] test_env` puts `MASON_*` variables into a remote run's `run.json` environment.

**Change.** `crates/daemon/tests/support/mod.rs`: `min_wait_secs()` reads the variable (a positive whole number; anything else means 900). `config.rs`: `[remote_runs] test_env = { MASON_X = "v" }` is parsed (names must be `MASON_*`, values strings) into `RemoteCfg.test_env` and `Site.test_env`; `remote::with_site_env` adds them to the `RunSpec` environment for suite and check runs, never overriding a name the run already sets. `run_json` already forwards `MASON_*` names. `Poll::Never` paths and verdict logic are unchanged.

**Not done: `ci.yml`.** Setting the variable in the `test` job is under `.github/workflows/**`, which is protected, so it waits for the owner's approval: add `env: { MASON_TEST_MIN_WAIT_S: "180" }` to that job. The owner's project file also needs `test_env = { MASON_TEST_MIN_WAIT_S = "180" }` under `[remote_runs]`; I did not edit it.

**Tests.** Helper tests for the floor (set, unset, invalid) and the give-up message with a 180 s floor; a config parse test for `test_env`; a `run_json` test that `test_env` arrives and does not override the run's own value. `scripts/exit/s779.sh` runs the helper tests with and without the variable.

**Not verified.** No test was run locally (cargo test is refused in this shell); results come from `run_check`. No real GitHub run was made with the variable set.
