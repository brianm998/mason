# s980: a task's green count no longer becomes the base's expected total

Summary: A test step's expected total now comes only from runs at the base itself (new `suite_size` table), never from another task's green count, and a live count past an expected total raises it; the monitor shows "N tests" when done exceeds total.

**Cause.** `put_suite_green` (keyed by project, suite, base) is written by every whole green task run, and `expected_total` read it, so the last task's count (178) became the next task's total (181 of 184 shown).

**Change.** New table `suite_size` (migration), written in `suites.rs` only when the run has no task. `expected_total` reads it (this base, else latest), else the declared minimum, else none. `suite_counts` calls `raise_total`, which lifts an expected or minimum total to the live count; reported totals stay. `Format.countText` prints "N tests" when done > total.

**`suite_green` readers checked, unchanged:** `expected_total` (now moved off it), the scheduled-full-test coverage record (`put_suite_green`/`suite_green`, suites.rs ~4733), `suite_green_bases` at the landing/known-green checks (~4272, ~4711, ~5142). None decide anything different; only the displayed total changed. `suites.rs` is protected: owner approval needed.

**Not verified:** no tests were run locally; `mason task show` shares the daemon's figures and has no separate formatter that I found. The exit script s980.sh runs the new unit tests rather than a scratch world with three tasks.
