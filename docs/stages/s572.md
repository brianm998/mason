# s572: the Compose core socket tests wait 30 s, not 5 s, for a loaded runner

Summary: The Compose core tests that drive a real connection thread now wait up to 30 s instead of 5 s for their condition, so a loaded CI runner no longer fails one of them.

CI/monitor-compose went red with "206 tests completed, 1 failed", but the log tail did not name the test and four local runs of `:core:test` (one plus three `--rerun-tasks`) were all green. The failing test is therefore not identified; it is not reproducible here. The timing-based socket tests (MonitorCoreTest Rig, RefusedLinkTest) are the likely candidates, so the `waitFor` deadline in both files is raised from 5000 ms to 30000 ms. No assertion was removed or weakened, no timing assertion was added, and the production timing constants in Connection.kt are unchanged. If the job goes red again, read the TEST-*.xml for the real name.
