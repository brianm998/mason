# s211: a task sent back or retried runs the base's current definition

Summary: a send-back, owner rejection, base-conflict send-back or `mason task retry` repins the task to the project's current definition (with a `Repinned` event), a test-step red in a suite that changed since the pin is rerun once under the current definition instead of sending the task back, and a develop prompt on a project without `[self]` says that `.mason/` changes do not affect the task's own pipeline.

Task #266. Decision 0206 amends 0015.

## Built

- **Event**: `EventKind::Repinned { task, from, to, changed }` (core, reducer, store codec, history summary). Legal in any step state, `needs_attention` and `failed`; it changes only the task's `def`.
- **Daemon**: `Daemon::repin_to` and `def_changes` (`defs.rs`); `repin_for_send_back`, `Ctx::rerun_on_current`, `red_suite_of`, the `.mason/` note (`jobs.rs`); retry resolves its step in the current definition (`http.rs`). `run_inner` now ends in `execute(&Ctx)` so a step can be rerun on a rebuilt context.
- **Tests**: `crates/daemon/tests/repin.rs` (cases a-d of the task, plus the note and reason parsing); the engine matrix and the codec round-trip list include the event. No timing assertions (gate files).
- **Exit**: `scripts/exit/s211.sh`.

## Not done, not verified

- Written without a local compile (cargo is refused in this session); the first compile and test run is the pipeline's `tests` check.
- The suite tests assume the regex parser counts a clean run with only a `fail_regex` as red and a `pass_regex` as green (the star case); they were not run before submission.
- A retry from a step that is still running repins too (the retry supersedes that step).
- `suites.rs` (protected) is not changed; the rerun is in `jobs.rs`. The rerun reads the suite from the red reason's text, so a change to those messages in `suites.rs` must keep `red_suite_of` in step (a test pins the forms).
- The prompt note is added only when the branch already touches `.mason/` when the develop step starts.
