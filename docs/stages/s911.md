# s911: a batch's local fallback runs under the batch's own hold

Summary: on 2026-11-22 the local queue froze for about three hours. A landing batch holds this
machine's suite slots for its whole run (`Landing::hold`), even when a suite is placed on GitHub.
When no runner picked that suite up within `pickup_timeout`, `fallback = "local"` sent it back,
and the fallback (s812) asked the broker for `compile` and `test-suite` again, ranked behind
everything. Another project's exclusive request was already queued and waits for the machine to
drain, that is for the batch's lease; the batch's fallback sat behind it. Batch lease waits on its
own fallback, which waits on the exclusive request, which waits on the batch lease.

Owner approval for the protected files `crates/daemon/src/landing.rs` and
`crates/daemon/src/suites.rs`: given in the session that started this work on 2026-11-22
("Restart and fix").

## Built
- `suites::Who.covered`: the caller already holds this machine's slots for the run. `run_over` and
  `run_alone` take it as a parameter; every other `Who` sets it false (`suites/base_red.rs` only passes `who.covered` through). It is passed through
  `run_hosted` and `run_hosted_resuming`.
- `remote::fallback_lease_unless_covered`: with `covered` it logs one INFO line (running under the
  caller's hold) and takes nothing; otherwise it is `fallback_lease`.
- `landing.rs`: the batch's main suite run, `run_alone` (the failing-tests run) and the post-land
  run pass `_lease.is_some()`: covered only when the batch really holds something (`hold` gives
  `None` for nothing to hold).
- Test: `fallback_lease::a_covered_fallback_runs_under_the_batchs_hold_beside_a_waiting_exclusive_request`
  (batch lease, queued exclusive request, covered fallback proceeds and takes nothing; the
  uncovered one still queues behind it and gets the slot once both are released).
  Exit test `scripts/exit/s911.sh`.

## Checked and left alone
- Landing `CheckSpec`s (re-test, rebuild, fast tier, new tests, lint, floor build) all have empty
  `holds`, so `hostedcheck::collect` already takes no fallback lease for them; there is no cycle
  there and no `covered` flag on `CheckSpec` was needed. Task checks and test steps, which hold no
  slots before going remote, and debts keep today's behavior.
- The re-test of a base-moved batch and the floor build run through `check_through_outage`, not
  `run_hosted_resuming`.

## Not changed
- Limits, ranks, the exclusive-request rule, `pickup_timeout`.
- Possible follow-up: the batch still holds `compile`/`test-suite` slots while its suite waits on
  GitHub, which idles this machine's slots. Not changed here.

## Not verified
- No end-to-end run with a fake GitHub that never assigns a runner; the broker cycle is tested
  directly. The covered hold names the suites' own `uses`, which may differ from the test step's
  `uses` the uncovered fallback would take.
- The full workspace test suite and the other exit scripts were not run.
