# Stage 26: Installer and onboarding

Summary: `mason init` now takes a project from nothing to a merged `mason/setup` branch and a landed first task: the eight Part 21 questions each have a flag (`mason init --workflow solo --yes` runs without a terminal), five MIT example workflows live in `templates/`, suites are proposed and run once with a baseline recorded, the "Filing work" notes are written once into AGENTS.md or CLAUDE.md, `mason adopt`, `mason remove` and a `mason`-on-PATH check in `mason doctor` exist, and `scripts/install.sh` verifies a SHA-256 and names a clashing `mason`; `s26.sh` initialises every template on Rust, Python and Swift samples and lands a harmless task with fake-claude on each, and no real install, release, signature, tap or publish was done.

## Built
- `templates/{solo-fast,reviewed-pr,batched-ci,device-mobile,human-gated}/{mason.toml,landing.toml}` and `templates/README.md`, all `SPDX: MIT`. Each `mason.toml` passes `mason definition check`; each `landing.toml` is parsed by the landing parser in unit tests (every template under every landing choice).
- `crates/cli/src/init.rs` and `init/`: `questions.rs` (pure: the questions in Part 21 order, flags, resolution, and every rendered file), `detect.rs`, `suites.rs`. `mason init` makes `mason/setup` in a temporary worktree (the working tree and current branch are untouched, nothing is pushed), writes `.mason/` (+ `baselines.toml`), the Filing section, the project overlay, and optionally `notify.toml` and `resources.toml`. `--prove-only` files the harmless task once a daemon knows the project.
- `adopt.rs`, `remove.rs`, and `doctor::check_path_command` (asks the first `mason` on PATH what it is).
- `scripts/install.sh`, `packaging/homebrew/mason.rb` (template), `docs/install.md`.
- `crates/cli/tests/init.rs` (14 tests: each flag, each refusal, second init, adopt, remove, CI offer, doctor clash) and unit tests in `init/*`.
- `scripts/exit/s26.sh`, `s26-real.sh`, `s26-manual.sh`; decision 0057.

## What testing found
- First Swift sample failed in `init`: `add` clashed with an `XCTestCase` method (my fixture, not the product). `init` correctly dropped the suite, said why, and warned that nothing proves anything.
- `adopt` first accepted a `.mason/mason.toml` with `start = "nope"` because `parse` does not validate references; it now runs `validate` as well.
- A second `init --force` that regenerates identical files made an empty commit fail; the setup commit now allows empty.
- A cold `swift test` is 40 to 60 s, which made a sequential `s26.sh` ten minutes; hence the per-language parallelism.

## Readings and limits
See decision 0057. In short: `mason/setup` is never merged by `init`, so a first task needs a merge, a push (with a remote) and a daemon restart (projects are read at start); `init --prove-only` is therefore a second command, not part of `init`. `baselines.toml` is for people; the pipeline does not read it. PR workflows were exercised with `--landing direct` because they need a git host. "Opens the monitor" is not done (printed as such). Login to the agent cannot be verified ahead; `init` says so.

## Not run
- **The owner checkpoint**: a real install from nothing on a real project, timed against the 10-minute target (`s26-manual.sh` is the protocol). M7's exit test is not claimed.
- `s26-real.sh` (real GitHub PR landing and issue import, real signature check): written, not run.
- The Homebrew tap: the formula was only syntax-checked with `ruby -c`; no tap, release or checksum exists.
- `cargo install mason-pipeline`: the crate is `publish = false` until Stage 31, and the templates are embedded from outside the crate directory, which `cargo publish` will need fixed.
- Code signing and notarization; the minisign path of `install.sh` (no key, no signed release) is untested.
- `install.sh` was run on macOS x86_64 only, against a `file://` release.
- Interactive prompting on a real terminal: the prompt code is unexercised by tests (they have no tty); the order and flag-skipping logic is unit tested.
- Node, Gradle and Makefile projects are detected but get no proposed suite; `[host]` and `[ci]` for non-GitHub hosts are not written.
