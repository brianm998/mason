# Stage 1308: The recovery tests run, and a failure with no worktree gets a session

Summary: A task that failed before its worktree was made now gets its recovery session, read from a checkout of the base, and the recovery tests' pipeline definitions are valid ones.

**What changed.**
- `tests/it/recovery.rs`: both definitions were refused by the validator (`max_rounds` without `on_red`; an approval step with no `next`). Their tasks failed at once with "the definition ... is not in the store" and no session could be set up.
- `recovery::step_failed_emitters` counts a construction that names `reason` in shorthand, and skips a pattern that binds it.
- `diagnose`: with no worktree and no branch (a job that panicked at its start), the session runs in a detached checkout of the base, removed when it ends. Before, the CLI could not start in the missing directory and the whole project was held (s1287).
- A recovery `repair` of such a task hands off instead of launching in the missing directory.

**Not verified.**
- The repair hand-off for a task with no worktree has no test of its own.
- A session whose step context cannot be built (a definition not in the store) still ends without a row, and its recovery row reads `running`. Filed as a proposal.
