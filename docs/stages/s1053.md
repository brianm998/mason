# s1053: Compose desktop monitor: File > Add Project… and a + under the project picker

Summary: The Compose desktop monitor gains File > Add Project… (Cmd/Ctrl+Shift+N) and a + under the project filter, opening a five-step wizard (Repository, Detected, Questions, Review, Apply) over the daemon's /onboarding endpoints; the Android app has neither.

## Change

- `core/AddProject.kt`: pure wizard state (steps, answers to the flag map, use-recommended, landing choice no/merge/push/pr default no, proof task on by default, apply result).
- `MonitorModel`: `openAddProject`, plan/apply calls through `raw`, and the result handling; a successful apply selects the new project. `addProjectAvailable` is false on Android.
- `app/ui/AddProject.kt`: the dialog; `Main.kt`: `MenuBar` with File > Add Project… and a `JFileChooser` directory picker offered only when the daemon was found through the local daemon.json (a `--port` connection has no pid).
- `TopBar.kt`: the + (`add-project`) shown when `canAct`.

## Not verified

- No window was opened: the menu bar, the shortcut and the JFileChooser were not exercised by hand; tests draw offscreen.
- The Swift client's wizard does not exist on this branch, so step names and copy follow the task text, not a Swift source.
- The `detected` JSON is displayed generically (root, id, branch, languages, ci, remote); its exact nested shapes were read from the Rust types, not a live reply.
