# s1152: write-time rules, checked on every Edit and Write

Summary: A MASON Claude agent's `Edit`, `Write` and `MultiEdit` calls are checked against the project's `.mason/rules/*.toml` from the base commit, which can warn or refuse with what to do instead, and `mason task show` lists every hit.

Task #1137, decision 1141.

## What changed

- `crates/daemon/src/rules.rs` (new): reads the rules from the base commit, works out what an
  edit adds, matches, answers the hook and records hits (`<task dir>/rule-hits.jsonl`).
- `mason hook edit` (new) forwards the `PreToolUse` input over the step's contract socket
  (`hook_edit`, not an agent tool) and prints the daemon's answer.
- The Claude adapter registers it in the `--settings` file for `Edit|Write|MultiEdit`.
- The task detail has `rule_hits`; `mason task show` prints one `rule hit` line for each.
- Rules or input that cannot be read let the edit through and leave one line in the step's log
  (`mason task logs`, "step run N (rules)").
- Seed rules in `.mason/rules/`: `timing-assertion`, `unsigned-binary-copy`,
  `caffeinate-user-active`, `xcuitest-run`, all `block`.
- `fake-claude` has a `write` action that asks the `--settings` hooks, as the real CLI does.

## A rule file

One rule per file:

    id = "no-todo"
    paths = ["src/**"]              # globs; the whole file is checked
    cfg_test_paths = ["lib/**/*.rs"] # optional: only inside `#[cfg(test)]` items
    pattern = 'TODO'                # a match counts when it covers an added line
    unless = 'TICKET'               # optional: found anywhere in the file, clears the hit
    action = "warn"                 # or "block"
    message = "File a task instead."

Limits: 100 files, 32 KiB each; edits of files over 4 MiB are not checked.

## What it does not stop

- Files written through `Bash` (redirections, `sed`, scripts), and Codex or generic agents,
  which take no Claude hooks. Health sessions are not checked either: they have no task to
  record a hit on.
- The seed patterns are textual. A timing assertion on a variable (`assert!(took < limit)`)
  is missed; an `assert!` ordering two `Duration` constants is refused though nothing is timed.
  A copy is recognised by how its source is named (`exe`, `bin`, `current_exe`, `/bin/`, ...),
  and any `codesign` in the file clears it. `xcuitest-run` needs the `UITests` name on the
  command (`-scheme`, `-target`, `-only-testing`, `-testPlan`).
- The base commit is read when the step starts; a rule landed during a step applies from the
  next one.

## Not verified

- No real `claude` session ran: that a `--settings` deny reaches the agent, that
  `additionalContext` on an allow is shown to it, and that the allow does not override another
  hook's deny rest on the CLI's documented behaviour.
- The macOS and iOS monitors do not show the hits.
