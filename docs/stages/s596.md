# s596: monitor-swift step 1 no longer fails on SIGPIPE

Summary: s12.sh step 1 now captures `swift test` output to a file and checks its exit status, instead of `grep | head -1` under pipefail.

The CI log shows step 1 printed its test summary and the script then exited 1. `head -1` closes the pipe after the first summary line, and `grep` writing a later line gets SIGPIPE (141), which pipefail turns into a failure. This was not reproduced locally (no Swift run was possible in this session; the build queue shim refused it), so the cause is inferred from the log.

`scripts/exit/s12.sh` is a protected gate: this change needs owner approval. No assertion is weakened and no test changed.
