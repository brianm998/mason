# s83: A lost or unstartable step host no longer fails an agent step

Summary: an agent step whose step host is lost mid-session, or never comes up, is recorded as a host loss and continued (resumed with a note when the journal gave a session id, otherwise started again) instead of failing the task, at most twice per step run and counted from the invocation directories so a daemon restart does not reset it; a third loss fails the step and names all three.

Task #59. Decision 0069.

## Built
- **adapter-api**: `Outcome::HostLost` and `AdapterError::HostStart` (the host did not come up), distinct from `Crash` (the agent CLI died or would not start).
- **adapters**: `hosted::attach_as` reports a host lost without an exit record as `HostLost`; `hosted::spawn` reports a failed `spawn_host` (timeout, host exits at once) as `HostStart`; `FailReason::HostLost` in the runner. `worth_a_stronger_model` is false for it. `hosted::lost_invocations` counts the lost invocations of a run from `h/`; `spawn` no longer reuses the number of an invocation that never came up (its `.in` file is kept as the record).
- **daemon**: `jobs::settle_all` (after holds): records the loss with `hostloss::record`, reaps what the dead host left (verified pids only), takes the lease again, then `runner.resume` with `hostloss::interrupted_note()` or, with no session id, `runner.run`. A resume that fails because the transcript is gone starts fresh once. The third loss ends the step with `hostloss::agent_lost` (names every loss). Nothing here touches attempts, send-backs or `max_rounds`.
- Comment at the top of `hostloss.rs`, decision 0069.
- **Tests**: `crates/daemon/tests/host_loss.rs` (resume after a kill, three losses, daemon killed with its hosts, `--host-bin` that exits, CLI crash not resumed); `scripts/exit/s83.sh`.
