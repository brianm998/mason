# s722: where runs go: `mason remote on|off`, `remote = false`, `runs_on` (#698)

Summary: One decision (`place::decide`) now says whether a task's test-step suite or `run_check` runs on this Mac or on GitHub Actions, from a global switch (`remote.toml`, `mason remote on|off|status`, read live and recorded with who and when) and per-suite `remote = false` / `runs_on`, with the reason shown in `mason status`, `mason task show` and `mason config show`.

**What exists.**

- `crates/daemon/src/place.rs`: `decide(&Facts) -> Place` (`Local { why }` or `GitHub { runs_on }`, each with its source: task, global switch or suite rule). Order: a task's own choice (#699; `None` until it lands), then the global switch; a run that would go to GitHub stays here, with the reason, when the project has no `[remote]`, the suite says `remote = false`, its environment leases a device, simulator or emulator, it uses `exclusive`, or the remote setup check (#703; always passing until it lands) failed. `runs_on` is the suite's, else the project's `[remote] runs_on`.
- The switch: `<config>/remote.toml`, `default = "local" | "github"`; a missing file, or an unreadable one, is local (the problem shows in `mason remote status`). Edited with `toml_edit` (comments and other keys stay), records `changed_by` and `changed_at` in the file and appends to `remote-changes.log`. Read on every decision: no restart, no `project reload`. Daemon endpoint `GET/POST /remote` (POST owner only); CLI `mason remote on|off|status`.
- Definition: suite keys `remote` (bool) and `runs_on` (non-empty string) parsed in `crates/definition/src/testing_parse.rs`, so `mason definition check` names `runs_on = ""` and `remote = "yes"`.
- `remote::executor_for` now takes the task and suite; only the test step's runs (`run_hosted_resuming` with `place`) and `run_check`'s suite runs (`CheckSpec::place`) ask. Landing batches, bisects, base runs, negative controls and debts pass none and stay here (#702). `MASON_TEST_FORCE_REMOTE` still forces a project remote for tests.
- Builds: a suite with a `build` that goes to GitHub has no local build step; its remote command is `build && command` (also when the remote run falls back to local), so one runner does both.
- Shown: `mason status` (`where:` lines), `mason task show` (`where` lines, newest decision per suite or check), `mason config show` (each suite's effective place and source). The record of decisions is in memory (newest 300): it does not survive a daemon restart.
- Tests: `place::tests` (table of every row), `testing_tables.rs` (parse and mistakes), `scripts/exit/s722.sh` (fake GitHub: `remote on`, two suites with one `remote = false`, pushes for the first only, `task show` places, comments kept across off/on, no push after `remote off`).

**Trust.** `crates/daemon/src/suites.rs` (protected) changes only where a run is sent: a `place` argument on `run_hosted`/`run_hosted_resuming`, the call to `executor_for`, the `build && command` join, and skipping the local build of a suite that goes to GitHub. No verdict, limit or gate changes; the same command, parser and minimum judge it, and `remote = false` keeps a gate on this Mac. `crates/definition/src/validate.rs` is not touched: the new keys are parsed and checked in `testing_parse.rs`.
