# s435: a detail page for each home section

Summary: Both monitors open a page per home section (`mason://section/<name>`: active models, queued, CPU, compilation, exploring, developing, testing, review; landing is the Landing page) from the section title, a '>' icon, the sidebar header's '>' and a count tile's double click (the lone task when the stage holds exactly one).

**Change.**
- Navigation: `Page.section(name)` / `Page.Section(name)`, `Page.sectionNames`, `Page.sectionPage(name)`; `mason://section/landing` parses to the existing Landing page. The CPU page subscribes to the CPU history like home.
- Home: `section(...)` takes an `open` action, drawing the title as a button with a trailing `chevron.right` (Compose: `›`). CPU and Compilation take the same. The sidebar's section headers get the same icon for states that have a page.
- Tiles: `tileDoubleClicked(state)` opens the task when the sidebar section holds exactly one row, else the stage's page when it has one. A single click still reveals the sidebar section. The earlier test that expected a double click on a many-task stage to keep the page was changed on purpose (Swift and Kotlin).
- Pages: `SectionPage` shows only that section. Stage pages draw the sidebar section's rows, in the sidebar's order, wide, with progress cells, step, suite progress ("3 of 8 suites"), why waiting, time in state and model. Testing has Skip testing per row and "Skip testing for all", which send the sidebar's `skip` command per task (`skipTest(id, step)`).
- Tests: Swift `MonitorCoreTests` and Kotlin `MonitorCoreTest` (URL round trip, back/forward, tile double click with one, two and three tasks, Testing rows' order, Skip commands, suite text).

**Not done / differs.**
- Home has no Queued section (the queued page is reached from the sidebar header and the tile).
- The row has no attempt number or CPU share (`TaskRow` has neither; `cpu_permille` is only on the task detail), so the pages do not show them. Adding them needs a schema change.
- The Skip-testing dialog task had not landed in this tree, so Skip testing sends the same command as the sidebar row's button, without a dialog.
- The landing page was not extended; `mason://section/landing` opens it as it is.

**Trust.** `clients/features.toml` is protected: the new row `section-detail-pages` (done in both clients) waits for the owner's approval. `scripts/exit/s435.sh` is under `scripts/exit` and likewise.

**Not verified.** The shared build queue refused `swift build` here, so the Swift files were only checked with `swiftc -parse`; the Kotlin was not compiled by me (the test step compiles it). No UI ran and nothing was seen on a screen; the layout of the wide rows and the '>' icon is unseen.
