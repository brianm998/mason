# s268: release workflow

Summary: A pushed `v*` tag now builds, signs, test-installs on fresh runners and drafts a GitHub release for every package (`.github/workflows/release.yml`), with a dry run by `workflow_dispatch`; a test keeps its asset list equal to docs/RELEASING.md.

**What.** Jobs: `version` (release-version.sh), `linux-package`/`linux-e2e` (tarball + .deb, both arches; dpkg install, `masond --demo` + `mason status`, `dpkg -r`, install.sh from the tarball), `macos-package` (throwaway keychain, star's secret names, tarballs, .pkg, .dmg, notarize; unsigned and marked when secrets are absent) with `macos-pkg-e2e`, `macos-tarball-e2e`, `macos-dmg-e2e` (never launches the app), `compose-package` with `compose-deb-e2e`/`compose-msi-e2e`, and `publish` (tags only; drops assets whose e2e job did not succeed, checksums, draft release, fails on a missing asset). `contents: write` is on `publish` only.

**Not verified.** The workflow has not run: only actionlint and `scripts/tests/release-assets.sh` ran. The Compose gradle task names, the installed layout checked by the Compose e2e jobs (`%LOCALAPPDATA%\MASON`, `lib/runtime/bin/java`), and `--demo` startup timing are written from the repository and Compose's defaults, not observed. The Windows CLI jobs are a marked gap (`WINDOWS-CLI-JOBS`), so `publish` fails its last step until they land.
