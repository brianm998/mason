# s725: CI-watch banners show open tickets only

Summary: The CI watch's home banners now show only red jobs whose ticket is still open (one line per ticket, shards grouped), put jobs whose fix landed and await a finished run on one quiet `ci_watch_quiet` line, and forget jobs absent from `agreement + 2` finished runs.

**Cause.** `held_back` became one `ci_watch` banner per job whatever its ticket's state, and a job that vanished from its workflow stayed in the state for ever.

**Change.**
- core `ci_watch.rs`: `held_lines` groups held-back jobs by shard group and ticket and splits them by whether the ticket landed (`landed_ms`); `HeldLine::open_text` ("CI/lint red; #6 is fixing it", "CI/x (os): shards 1, 4 red; ..."), `unconfirmed_text` (the quiet line). `JobState.absent` counts finished runs without the job; at `agreement + 2` the job (and its freeze) is dropped in `step`.
- daemon `ci_watch.rs`: `held_view` builds `held_back` (open only), `unconfirmed`, `unconfirmed_text`; `absent` is saved. `views.rs`: `ci_watch_banners` builds the banners; the quiet line has kind `ci_watch_quiet`. CLI `mason ci-watch` prints the quiet line.
- A job red again on a run after the landing is not held back (unchanged), so its new ticket gets its banner.

**Not verified.** Nothing was compiled or run: the build queue was closed to this session and the test check was skipped by the owner (debt #325), so the code and tests were only read. "Open" means no landing recorded for the ticket, so a ticket that was closed without landing still shows as being fixed. The Swift and Compose clients were not changed or checked; they receive an extra banner kind `ci_watch_quiet` and may draw it like any banner. The timeout-note wording (`held_text_timeouts`) is no longer used by the view.
