# s1176: diagnose outside failures like #1003 and ask the owner for a fix-now and a fix-later (#1105)

Summary: a landing failure, a repeated outside failure, a stuck batch or a burst starts one read-only diagnosis per cause, with the batch's CI jobs, the base's runs of the same jobs, the suspect tasks and open tickets gathered first, and it ends in a decision card whose recommended option pairs a fix-now action with a fix-later ticket (`file_task`, `land_now`, `wait_for`, `open_session`), announced as a `diagnosis` alert.

## What changed

- `crates/daemon/src/diagcause.rs` (new): triggers (`on_step_failed`, `pass` for `ci-stuck` alerts and `autoretry::bursts`), one diagnosis per cause (`start_cause`: keyed `sig:<project>:<signature>`, `batch:<project>:<id>` or `burst:...`; a later failure with the key, or of a listed task, joins the running session or the open card), at most 4 cause diagnoses per project per day (a session without a verdict counts), the auto-retry hold (`held`: a running session until its 900 s deadline, an open card that does not recommend a lone `retry`, a `wait_for`), the facts (`gather`, `gather_ci`, `render`), the prompt section, the actions' code and the `diagnosis` alerts.
- Facts gathered before the session, read-only, with no network for the session: the batch's CI jobs with state, log tail and annotations (through `ci_watch::Source`, the same `log_long`/`annotations` reader), the base's newest runs of the same workflows, "same on the base" marks (newest base run red, cancelled at the time limit by `job_conclusion`, or unfinished), the commits and `mason/<p>/tN` merges since the job was last green, `base_red` / `persistent_red` rows, the retry schedule, open alerts, and open tasks of the project and of MASON's that name the same job or test. A single task is looked at in its worktree, several in a detached checkout at the base.
- `crates/daemon/src/diagnose.rs`: an option may carry `actions` (`option_action`; one is that action itself, several are `compound`); `apply_args` runs `compound`, `file_task`, `land_now`, `wait_for`, `open_session`; the answer and `apply` paths act on every task a cause card lists; `pending_for` serves a cause card on each task it lists; alerts and `row_text` read cause rows.
- `crates/adapter-api/src/contract.rs` (protected, stricter only): the new actions and their fields, `actions` (1 to 4), `cause`, and the rule that when `cause` is `outside`, `base` or `pipeline` the recommended option holds a fix-later action (`file_task`, `wait_for`) and a fix-now action (`land_now`, `retry`, `wait_for`, `open_session`). A card with no `cause` is #1044's, as before.
- `crates/daemon/src/attention.rs` (protected): `card_of` and `answer_with` also serve a cause card to a task waiting in `Landing`, so a stuck batch can be answered before the timeout. Who may answer is unchanged.
- `crates/daemon/src/autoretry.rs`: `pass` calls `diagcause::pass` and skips a held task. `crates/daemon/src/jobs.rs`: a failed step calls `diagcause::on_step_failed` before #1044's `on_failed`.
- `crates/daemon/src/http.rs`: the body of Land now is `mark_land_override`, called by the route and by a card's `land_now`.
- Store: `diagnosis_waits` table (migration), `set_diagnosis_args`, `auto_retry_reasons_since`, `persistent_reds_since`.
- `crates/core/src/notify.rs`: condition `diagnosis`, routed like `needs_you`; its spoken sentence is the line itself, `#<task>: <cause in at most 12 words>. Recommended: <label>.`, `#1003 and 2 more` for several tasks.
- `crates/daemon/src/views.rs`: a Landing task with a cause card has the `answer` action.

## Tests

`crates/daemon/tests/it/diagnose_cause.rs` (fake adapter, fake CI source), unit tests in `diagcause.rs`, `contract.rs`. Two existing tests changed because a landing failure is now a cause diagnosis that holds its retry: `auto_retry.rs` waits for the hold to lapse before each pass (`settled`); `diagnose_retry.rs` no longer asserts the landing-failed task has no row, only that none is a #1044 per-failure row.

## Not verified

- No real model, GitHub or monitor was used; the tests were not run by me (the shell refuses `cargo test`); only `cargo check`, `clippy` and `fmt` ran locally.
- `wait_for` does not use the engine's `blockers`: the engine takes them only on proposed or queued tasks, and a Failed task cannot. It is a daemon-side wait (`diagnosis_waits`) that holds the auto-retry and retries the task when the other task lands; it works on a Failed task only.
- `file_task` keeps `priority` out: `proposals::file` always files at normal priority. `after` is applied as blockers on the filed task.
- Job durations are not in the facts: `ActionsJob` carries no timestamps and I did not widen the adapter.
- `open_session` with `where: base` makes the worktree and branch `claude/diag-<id>` and opens the owner session on the task, whose turns run in the task's worktree; the seed message names the base worktree.
- The land-now rule ("own suites green or the same on the base") is checked when the card is applied (and noted on the card), not at submission, because the contract has no facts. A task's red suite is read from its failure text (`suite `x` is red`).
- A batch's CI detail is in memory (`CiBook`); after a daemon restart a diagnosis says so instead of listing jobs. `landing.rs` was not changed.
- The exit script runs the tests by name; there is no real `masond` run that answers a cause card with `mason task answer`.
