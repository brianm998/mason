# s874: the landing idle reading no longer counts deliberate holds

Summary: Landing idle time (`landing_idle_ms`) now resets while the queue is deliberately held (self-update drain, unreadable configuration, or every waiting task behind a freeze), so a hold is not reported as an idle queue.

**Cause.** `form_and_start` in `crates/daemon/src/landing.rs` counted any look with tasks waiting and no batch running as idle. A freeze that holds everything but its fix, a drain, or an unreadable configuration produced hours of "idle" (19288171 ms) although the queue was doing what it was told.

**Change.** The three holds clear the project's idle spell. Nothing else about landing changes.
