# s1223: Add Project resolves the agent binary and tokens as the daemon sees them

Summary: Add Project writes an absolute agent binary found the way the daemon can find it, refuses to set up a project with none, and warns about an `env:` token the daemon does not have.

## Change

- `crates/onboard/src/questions.rs`: `Machine` (PATH, HOME, known binaries, environment; default is the process), `find_agent`, the `agent-bin` and `token` questions, `Flags.token`, `Answers.token`/`warnings`; `render_overlay` writes the chosen token reference and leaves the GitHub sections out for `none`.
- `crates/onboard/src/lib.rs`: `Plan.warnings`, `Applied.warnings`; `setup` refuses without an agent binary before writing; adopt resolves `claude` the same way.
- `crates/daemon/src/onboarding.rs`: fills `Flags.machine` from the registered projects' agent binaries; both endpoints return `warnings`.
- Tests: onboard unit tests (fake PATH and HOME), daemon onboarding tests, CLI init tests now run with a throwaway HOME holding fake agents.

## Not verified

- The exit scenario with a real launchd-started daemon was not run; the equivalent is covered in-process with a fake PATH and HOME.
- `mason adopt` of a folder that already has `.mason` is refused without an agent but gives no plan warning.
- Windows is not considered (`is_executable` uses Unix permission bits).
