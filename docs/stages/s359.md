# s359: a diagnosis stops calling for the owner once its task moves on

Summary: a pending diagnosis is an alert ("needs you", spoken by the monitor) only while its task is still failed from the failure it diagnosed: the task is in `failed`, and it entered that state before the diagnosis was written. Once the task is retried, lands, is canceled, or fails again later, the diagnosis's alert goes away. The diagnosis itself stays pending and can still be applied or dismissed with `mason task diagnosis`.

## Why

On 2026-11-14 the monitor kept speaking about #197. Its alert was diagnosis #25, written when #197 failed, suggesting "run it again from test". The task had already been retried from test and was running, so the alert was false. `mason alerts` held a dozen more like it, for tasks that had since landed, been retried or been canceled (#198, #211, #212, #213, #214, #215, #241, #254, #255, #259, #306). `diagnose::alerts` listed every pending diagnosis whatever had happened to its task since.

## What changed

- `crates/daemon/src/diagnose.rs`: `still_needs_you(task, diagnosed_ms)`, and `alerts` filters by it.
- Test: `a_diagnosis_needs_you_only_while_its_task_is_still_in_the_failure_it_diagnosed` (unit, `diagnose.rs`).
