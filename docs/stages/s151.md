# s151: suites under a pseudo-terminal (`pty = true`)

Summary: `pty = true` on a suite or command step runs its command under `script` on a pseudo-terminal (macOS), so XCTest writes line by line and `mason task show` shows the current test while a run hangs; off by default, results and exit codes judged as before.

Task #167. Decision 0146 records the choices. `crates/testing/src/model.rs` and `crates/daemon/src/suites.rs` are `PROTECTED` and are edited: the first adds the `pty` field, the second wraps the command at its four run sites. Each only changes how output is captured, never a verdict; the change waits for the owner's approval.

## Built

- **Keys**: `[suite.NAME] pty` and step `pty`, bool, default false; a non-bool is a problem naming the key.
- **Wrapper**: `jobs::pty_wrap(pty, cmd)`: unchanged unless `pty` on macOS, then `script -q /dev/null sh -c '<cmd>'`. Used for command/test steps (build and test) and for suites (run, rerun, baseline, new-tests-at-base), after device substitution.
- **Progress**: `Progress.terminal` marks a stream; its live log lines lose ANSI/CSI/OSC sequences and CRs, and the latest line is the record's `message`. The log file is raw.
- **Tests**: `pty_wrap` unit tests (unchanged without pty; macOS: quoting, exit 3 stays 3, a stopped run leaves no command), `strip_terminal` unit test, `crates/daemon/tests/pty.rs` (a pty suite prints a started line then waits on a file; the test waits on the suite log, the pushed log line and the message, then creates the file and expects a landed, verified task; the same suite without pty gives the same verdict). No timing assertions.
- **Exit**: `scripts/exit/s151.sh`: a real masond, a pty suite that prints a started line and blocks on a file; the line is in `mason task show` before the file is created; then the task lands.
