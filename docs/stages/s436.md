# s436: the cpuhistory minute-bucket test no longer starts on a partial minute

Summary: `minute_buckets_keep_totals_within_rounding` pushes its readings from i=0, so the first minute bucket is complete and the test passes; no production code changed.

**Problem.** The test pushed readings from i=1, so minute 0 held 11 readings (6 at 201, 5 at 100), mean 155.1, outside the 148..=153 range. The rounding in `Bucket::point` was right.

**Change.** The reading loop starts at 0, so every minute holds 12 readings, 6 of each value, mean 151. Assertions are unchanged.

**Verified.** `cargo test -p mason-daemon --lib cpuhistory`.
