# Stage s172: a cache directory MASON owns for each task

Summary: Every step of a task gets `MASON_TASK_CACHE`, a directory under the data directory that MASON creates, removes when the task lands or is canceled, and sweeps for finished tasks; `docs/self-hosting.md` shows using it as `CARGO_TARGET_DIR` with an optional sccache.

- `Config::task_cache_dir` (`c/<task>`), `taskcache::own_dir`, `remove_own_*`, `sweep_own`; the variable is set in `jobs::step_env_pairs` (script, test, plugin steps) and in the agent's environment.
- Removal: `jobs::cleanup` (landed or canceled) and the reconcile sweep. Nothing in `landing.rs`; no PROTECTED file touched.
- Tests: `crates/daemon/tests/taskcache_own.rs`; exit script `scripts/exit/s172.sh`.

Not verified: the owner's project file was not changed, so real cargo builds do not use the directory yet; sccache was not run. A canceled task that keeps its branch is cleaned by the sweep, not at cancel.
