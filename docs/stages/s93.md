# s93: run_check and landing's re-test run under a step host

Summary: `run_check` and landing's re-test now run as step hosts (`t<task>r<run>-check<n>`, `b<batch>-retest<n>`), so a daemon restart finds the run again, a second call attaches to it, and the limit is enforced from the host's start.

New `hostedcheck.rs`: `run` finds or starts a host for a (tree, command) key. A record `<id>.check` next to the log holds the key and whether the result was given to a caller. A call attaches to a same-key run in flight (in this process through a shared slot, after a restart by collecting from the host or its exit record), takes a same-key result that finished while the daemon was away and was never given to anyone, and otherwise starts the next number. The tree key is `HEAD^{tree}`, plus a hash of uncommitted changes when the worktree is not clean (the agent usually runs checks before committing). The limit counts from `host.kv`'s `started_ms`, so queue time is outside it and a restart does not extend it. `stop_hosts` and the orphan sweep already cover `t<task>r...`; `render_logs` shows `check*` as test output and `session_for` skips it. d670ec2 (queueing, slot give-back, mason-mcp re-send) is already in this tree and is kept as is: the queue wait happens before the host is found.

Tests: `crates/daemon/tests/hosted_check.rs` (attach, different tree, hung check, red check, real `masond` killed with `kill -9` mid-check), `parse_host_id` unit test, `scripts/exit/s93.sh`.

Not verified: a check that finishes while the daemon is down is covered by the code path (same collector reads the exit record) but no test arranges it deterministically; the `exec` take-over was not run with a check in flight; landing's re-test has no daemon-restart test of its own; `s93.sh` runs the cargo tests rather than driving the binaries by hand. After a restart the agent's resumed `run_check` queues for the test step's resources again before attaching. A result is marked delivered when the collector returns it, so if the daemon dies between that and the agent receiving it, the agent's retry runs the check again.
