# s730: agents' own test commands are refused when a task's runs go to GitHub (#704)

Summary: When a task's checks go to GitHub, its develop and review agents get a PATH shim directory that refuses `cargo test`, `cargo nextest run`, `swift test`, `xcodebuild test`/`test-without-building` and `gradle test`/`check` with exit 69 and points to `run_check`, while builds pass through to the real tool; the develop prompt gets one line saying so, and `MASON_REMOTE_SHIM=off` turns it off.

**What exists.** `crates/daemon/src/agentshim.rs` (wrapper text, writing, PATH), `place::task_checks_on_github`, and the wiring and prompt line in `jobs.rs` (agent_job). Decision 0723. Exit: `scripts/exit/s730.sh`.

**Not verified.** Nothing beyond the unit tests was run end to end with a real agent. `./gradlew` (a path, not a PATH lookup) cannot be intercepted; only a `gradlew` found on PATH is wrapped. Cargo options that take a separate value before the subcommand (`--manifest-path x test`) are misread. The shims are written when an agent starts and use the daemon's PATH when `agent_env` has none.
