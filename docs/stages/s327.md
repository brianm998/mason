# s327: the monitor's home graphs CPU use over time, and names each task's project

Summary: Home's CPU section gains a stacked area graph of every share over a pickable span (5 min, 1 h, 6 h, 24 h), served by a daemon-side history ring as the `CPU_HISTORY` view and `GET /cpu/history?span=`, and each task in the legend reads `#200 (star) Title`.

**Daemon.** `cpuhistory.rs` keeps the last hour as sampled (720 readings) and 24 hours in one-minute buckets (the mean of each bucket's readings). `CpuShare` gained `project`, filled in `cpu_usage` beside the title. The history is a separate view the monitors subscribe to only while Home shows (`Subscribe.cpu_span_ms`), never part of the home rebuild.

**Monitors.** Both clients build a `CpuChart` (series in the bar's stable colours, biggest total at the bottom) from the history off the main thread, dropping a result when a newer history or another span has arrived. Hover (Swift) or tap (both) shows the time and the share's value.

**Not verified.** The Swift and Compose code was written without being compiled or run here (the shared build queue refused `swift build`, and the test step was skipped for this task); only `swiftc -parse` of the two touched Swift UI/core files was done. The daemon half's tests were not rerun by me. The chart's drawing and hover were never seen on a screen.

**Trust.** `clients/features.toml` (in `PROTECTED`) gets a new row `cpu-history`, marked done in both clients. It waits for the owner's approval.
