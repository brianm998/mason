# s251: the last round the test step will give runs on a stronger model

Summary: when a develop step starts the last round that the test step would allow (one more red fails the task), it launches on the project's `escalate_model` (default `opus` for the Claude provider; an empty value turns it off) in a fresh session that is shown the feedback of every earlier round.

Decision 0246 records the choices.

**What changed.**
- `crates/daemon/src/config.rs`: the project key `escalate_model` (part of the agent keys).
- `crates/daemon/src/jobs.rs`: `last_round_ahead` (the round decision, unit tested) and `Ctx::test_rounds_done` (the test rounds that went red since the owner's last restart, leaving out conflict runs, as `round` counts them). Each send-back's feedback is also appended to `feedback-history.txt` in the task directory. A develop launch that is the last round sets the model to `escalate_model`, adds the history to the prompt, records the model it replaced in `step_launches.moved_up_from` and `escalated for the last round (escalate_model)` as `model_from`.
- `crates/daemon/src/launchview.rs`: the launch's explanation says "was <model> before the last round", which the task page and `mason task show` print with the model.
- `crates/daemon/tests/escalate.rs`, `scripts/exit/s251.sh` (protected).

**Not verified.** It was run with the fake agent only, so what a real Opus session does with the history is unseen. The rule reads the test step's rounds from `max_test_rounds` or the step's `max_rounds`, not from a per-task override of the rounds. The history file holds every send-back of the task, including those before an owner's retry.
