# s530: Swift monitor progress messages redraw only the progress cells they name

Summary: Live progress moves out of `sidebar` and `taskDetail` into a `ProgressStore` with one observed `TaskProgress` per task, so a StepProgress message no longer republishes the sidebar, bumps `sidebarRevision` or redraws any row body; only the named tasks' progress views redraw.

Task #517. See `docs/decisions/0523-progress-store.md`.

What changed
- `MonitorCore/ProgressStore.swift` (new): `TaskProgress` (`cells: [ProgressCell]?`, nil = use the view's own) and `ProgressStore` (per-task entries, a separate entry for the open task page, the merge rule).
- `MonitorCore/Model.swift`: `apply(progresses:)` writes only the store (and `liveLog`); a new sidebar view clears the entries of the tasks it carries, a task-detail view clears the page entry, disconnect clears all. `progressCells(task:)` reads live-else-view cells.
- `MonitorUI`: `LiveProgress` wraps the progress cells and line in rows, stage rows and the task page; `RowView` takes the store (by identity). DEBUG body counters on `SidebarPane`, `TopBar`, `LiveProgress`.
- Tests: core tests assert zero sidebar publishes and revision bumps and the fresh-view rule; `RowRedrawTests` counts bodies for a push and for a burst over a 500-row sidebar.
