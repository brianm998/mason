# s1041: a recovered test step reattaches only to runs of the same tree

Summary: A remote run record and a local suite host are reused only for the tree and command they ran on, and a test step records every attempt it starts so a recovered step reattaches to the latest one and cancels the rest.

## Cause

After a restart a test step builds the same run ids as before (`t<task>r<run>-u-<suite>`), and `remote::execute` and `run_hosted_once` attached by id alone. Retry ids carry `now_ms`, so a retry in flight at the restart was never found again.

## Change

- `remote::execute` compares the record's `tree_key` with the spec's. A different or missing key cancels the run if live, deletes its ref and record, and starts again (under the same id; see below).
- A suite's remote run is keyed `hostedcheck::key_of(tree_key(cwd), command)`, the shape `hostedcheck` files its evidence under. A local host writes the same key to `run.key` in its directory after it starts; `run_hosted_once` stops and discards a host whose key differs or is missing.
- The test step writes `<prefix>-<u|r>-<suite>.attempts` in the suites log directory (`id<TAB>key` per attempt, before the run starts). On the first pass after a restart, `recover_attempts` attaches to the latest attempt for the current key, and cancels (`remote::cancel_record`, the #823 path, which returns the runner unit) and discards every other one. Progress says "reattached to <suite> (same tree)" or "<suite> started again: the tree changed"; both trees are logged.
- A directory that is not a git worktree has an empty key, which is never compared, so nothing changes there.

## Trust

`suites.rs` is protected (verdict logic). The change only tightens which results count: a run is reused only for the same tree and command. Owner asked for it on 2026-11-23.

## Not verified

- No test drives a whole test step across a real masond restart. The suites-level recovery is tested through its pure parts (`plan_recovery`, `host_is_stale`, `discard_host`, the attempts file) and the cancel path (`cancel_hold`, which returns the runner unit) against the fake GitHub.
- The spec asked for a fresh id when a run is superseded; `execute` restarts under the same id and the suite step picks a timestamped id itself.
- A suite that leaves untracked, non-ignored files in the worktree changes the tree key, so a restart after such a run starts it again instead of reattaching.
