# s1256: a skipped or finished test step leaves no untracked GitHub run

Summary: a suite's GitHub run is no longer started after its step was skipped or had a result, a run stopped before GitHub listed it keeps a `cancel_pending` record that the reaper cancels, and a backstop cancels this coordinator's tagged runs that no record names.

## Cause

`remote::execute` saved its record, pushed (with retries that wait up to 130 s) and dispatched with no stop check in between; the first check came in the poll loop. `dispatch_workflow` returns no run id, so a run is found later by commit. A stop right after the dispatch found no run (GitHub had not listed it), `cancel` swallowed that, and `abandon` deleted the ref and record while `HoldGuard` removed the hold: a live run with no record, hold or log line. A dispatch GitHub accepted but whose answer was lost was abandoned the same way. The thread that wrote the 15:25:27 step result was not traced.

## Change

- `execute` checks `stop()` before the push (nothing sent), after the push and before the dispatch (ref and record deleted, no dispatch), and again for a resumed, undispatched record.
- `cancel` says whether a run may still be out; `retire` replaces the cancel-and-abandon pairs. If the run cannot be reached it keeps the record and ref with `cancel_pending`. A dispatch that fails with an outage sets the same mark.
- `settle_pending` (reaper pass `reap_untracked`, every `REAP_EVERY_S`) cancels such a run once GitHub lists it, deletes the ref and record, and gives up after `orphan_after_ms`.
- `reap_unrecorded` (the backstop) cancels queued or in-progress runs on this coordinator's `mason/run/<project>/<tag>-` refs that no record or hold names and that are older than `orphan_after_ms`; it logs each cancel. A failed listing, an empty tag, a young run or an unreadable age cancels nothing.
- Telling coordinators apart: GitHub names none, so new refs carry a tag from `<data_dir>/run-owner`. Runs on untagged refs (older, or another coordinator's) are never cancelled.

## Trust

No protected file changed (`suites.rs` and `sched.rs` untouched).

## Not verified

- Not run against real GitHub: listing lag, the 502 on a lost dispatch and cancel of a queued run are simulated by the fake.
- The thread that recorded the step result at 15:25:27 and then started the run was not found; the fix closes the window from the run side only. A run started by a caller that ignores `stop` is not covered, only the backstop catches it.
- Only the newest 100 queued and 100 in-progress runs are listed; pagination is not done.
- Runs pushed before this change carry no tag and are left to the 24 h stale-ref sweep for their refs.
