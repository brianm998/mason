# s1102: the red exit scripts on Linux shard 2

Summary: The exit script s70 now accepts a suite "minimum" total after a task's green, because only runs at the base size a suite, so it no longer fails on a stale expectation.

## Cause

`CI/exit-scripts (ubuntu-latest, 2)` was red on develop (run 45581279465, commit ff4fae6a6) in s70, s914 and s1068.

- s1068 grepped `Tool.kt` for the quiet-window settle that decision 1026 replaced. s1026 had the same stale greps.
- s70 required a total of source "expected" after a task's green. Only a run at the base itself sizes a suite (#959), so the total is the suite's "minimum", raised with the count.
- s914 is a wrapper. The log tail ends in a `pushes.log` line, which only s777's failure report prints, so s777 is the likely inner failure. This is inferred from the tail; the failing line was not in it.

## Change

Only s70 changed; no product code. s1068 and s1026 were fixed by s1100, which landed while this task was open; the merge takes its versions unchanged. See decision 1091. s914 and s777 are unchanged.

## Tests

`scripts/exit/s1102.sh`. In the development session, on macOS and before the merge with s1100, s70, this task's versions of s1068 and s1026, and s777 passed (s777 without its `cargo test` unit-test line). Nothing was run on Linux there, so s914's red is not shown to be fixed: if it stays red, read s777's `FAILED:` line in the full job log.
