# s804: Landing runs the batch's narrowed tests, with the scheduled full test as the backstop

Summary: a `narrow = true` option on the landing `batch` tier makes a batch run each suite's `dev_command` over the union of its diff plus the smoke set (the whole suite only when the pick is all), refused without a full-test schedule, falling back to the whole suite while the last full test is red or older than `full_test_max_age` with untested commits since.

Task #785. Decision 0797.

## Built

- **Rule** (`crates/core/src/full_test.rs`, no I/O): `narrow_gate` returns `Narrow` or `Whole(why)`. Whole when no full test is on record, when the newest finished full test is red (until a green one is newer; a cut-off run does not count), or when the last green is older than `full_test_max_age` (default 36 h) and commits have landed since (or cannot be counted).
- **Config** (`crates/landing/src/config.rs`): `narrow = true` on the `batch` tier (other tiers refuse it), top-level `full_test_max_age` (at least 1 h), `narrow_problems` (refused without a full-test schedule trigger).
- **Daemon**: `suites::narrow_for_batch` picks the same way a task's test step does (`scope::narrow_for`, `{tests_for_change}`, `it` module selection, smoke set) over `git diff base HEAD` of the worktree; any path that reaches everything (`Cargo.lock`, `Cargo.toml`, `build.rs`, `tests/support/**`) or a suite with no `dev_command` runs whole, with a note. `landing::batch_gate` reads the `full_tests` record. `Landing::run_local` swaps in the narrowed suites (marked narrowed, so no evidence is recorded and target reuse is off); every rung of the ladder runs through `run_local`, so rerun-failed, blame-by-impact and each bisect step narrow to their own subset's union. The kept-red-result keys carry `narrow`/`whole`. `read_config` refuses `narrow` without a schedule trigger. The note of a whole batch says why, and `/landing` shows `batch_tests` per project.
- **CLI**: `mason definition check --project P` and `mason doctor` report a `narrow` without a schedule; without `--project` the check only notes it cannot tell.
- **Tests**: core gate (fresh green, red, missing, red then green, cut off, old green with/without untested commits); config (reads, only on `batch`, needs trigger, `full_test_max_age` bounds); `narrow_for_batch` on a git workspace fixture (one crate, union of two commits, `Cargo.lock` runs whole, empty union and no `dev_command` run whole). No timing assertions. Exit: `scripts/exit/s804.sh`.

## Not verified / limits

- Tests ran on GitHub through `run_check`; the exit script was not run by me.
- Not turned on: MASON's `.mason/landing.toml` carries `# narrow = true` commented out. The mason registration has no full-test schedule, and with `narrow = true` the daemon would refuse landing for the project until it has one. Owner: add the schedule, then uncomment.
- No end-to-end landing test of a narrowed red bisecting to its culprit: the integration harness uses scripted suites, not a cargo workspace. The ladder is covered by construction (all rungs call `run_local`, which narrows per worktree) and by the union test above.
- Docs and exit scripts are sent to the `cargo-workspace` suite by the impact map, so a docs-only batch runs the smoke set alone.
- The landing page change is a JSON field (`batch_tests`); no monitor UI was changed.
