# s591: the Swift monitors show the disk chart beside the CPU chart

Summary: The macOS and iOS monitors show Home's Disk section (free space per volume over time, span picker, hover or tap tip, legend with a show/hide checkbox per volume when there are several) to the right of the CPU section at about 3:2, stacked below it on a narrow width, matching the Compose client.

**What changed.** `MonitorCore/DiskView.swift` holds the same rules as Compose's `DiskView.kt` (`diskChart`, `diskChartIndex`, stable `DiskColors`, `Format.bytes`/`freeOf`, hidden-volume preference `disk.hidden` that drops vanished ids, `DiskModel`). `MonitorModel` gets `disk`, `setDiskSpan`, `toggleVolume`; `Connection` subscribes to `DISK_HISTORY` on home and the `disk` section page and sends `diskSpanMs`. `MonitorUI/Disk.swift` has `DiskSection`, the Canvas chart and `CpuDiskRow`, a `Layout` that sets CPU and disk side by side from 900 pt (never on a phone) and stacks otherwise. The CPU legend title now truncates at lower priority than the heading. `clients/features.toml`: `swift` and `ios` of `disk-history` are `done` (owner approval needed; `platform_reason` removed since only Android differs). `android` stays `todo`.

**Tests.** `DiskViewTests` (core) and `DiskSectionTests` (offscreen hosting views and ImageRenderer; no window, no XCUITest). `scripts/exit/s591.sh` runs them; no script drives the Swift client against a daemon, so these tests are the exit test.

**Not verified.** The code was written without a local `swift build` (the sandbox cannot fetch SwiftPM packages); it was built and tested only by the pipeline's check. The checkbox count test relies on SwiftUI's macOS checkbox appearing as an accessibility `checkBox` NSButton. The iOS app target and a real hover or tap were not exercised. The CPU section's truncation was not measured against a real task title.
