# s1056: runs go to a node (multi-machine nodes, phase 2)

Summary: A suite run, a `run_check` and a landing batch's test runs can go to a paired node: placement picks a node with room before GitHub, the coordinator sends a git bundle of what the node lacks and starts the job, follows its output, and gets back the same `Finished` a local or GitHub run gives, so every verdict is judged as before.

The node (`node_run.rs`) keeps a bare mirror per coordinator and project, checks the snapshot out in a reused slot (`<project>-slot-<k>`, build output kept), runs the pinned build and then the command under step hosts with an environment it builds itself (only `MASON_*` facts from the coordinator; its own `PATH` with shims first, so nothing reaches the screen), and keeps `result.json`, the output and the results files until the coordinator acks. `node_exec.rs` is the coordinator's executor: a record first, snapshot (`remote::snapshot` with no workflow), bundle negotiation, start (a `409` tries the next node, a `412` sends the whole history once), poll (which renews the lease), tail, collect, ack. A step bound for a node holds one unit of the broker resource `node:<nid>`, set from the node's free jobs with `Broker::set_pool_units`; nothing of this Mac's slots.

The artifact is JSON with base64 results files, not a tar: the coordinator writes only plain relative paths under the worktree and never extracts an archive from a node.

Protected paths touched, as approved in the plan (§8): `crates/daemon/src/suites.rs` (`run_on_node`, an arm beside `run_remote`) and `crates/daemon/src/landing.rs` (Phase 0's one line). `sched.rs` is not touched.

Not verified here: a run on the real Mac Studio, and wall time against GitHub; the Xcode and Java toolchain probes were written for the Studio and not run on one.
