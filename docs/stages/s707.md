# s707: skip a cargo test target whose inputs are unchanged since it last passed

Summary: A narrowed test step (and, behind `reuse_green`, a landing batch) leaves out each cargo test target whose dep-info input key matches a recorded green, says so in the step note, and never reuses a key recorded red or flaky; the periodic full run with reuse off checks the keys (decision 0700).

What changed:

- `crates/daemon/src/reuse.rs`: the input key (dep-info of the executable and of the library of every workspace package in its dependency closure, manifests and `build.rs`, files outside `crates/`, `clients/`, `docs/` and markdown, `tests/` fixtures, the inputs of the workspace binaries its package names, the suite's command template and `RUSTFLAGS`-type environment), the plan that rewrites `-p pkg --test x` groups, and the recording of green and red per target from a run's log.
- `crates/store`: table `target_runs` (a new migration) keyed by project, suite, target and key; a red on a key stays red even if a later run on it is green.
- `crates/daemon/src/suites.rs`: the test step builds, plans, rewrites the command to the targets left, and skips lease and run when all were reused; `run_suite` records green on a green verdict and red (the failing executables) on a red one. `run_over` does the same for a landing batch when the project sets `reuse_green = true` (default off), except on a full run (the first batch after a daemon start, then every `reuse_full_hours`, default 24) which reuses nothing, still records, and on a red drops the suite's recorded keys with a note naming the key computation.

Not verified: no daemon was run end to end. The owner skipped testing for this task, so the pipeline compiled and ran only the first `run_check` rounds (the unit tests of `reuse.rs` up to the key and plan tests passed); the later edits (dep-info filtered by package directory, the two-crate cargo scratch test, the landing path `batch_reuse`) were not compiled or run. The landing path has no test. A full-run red does not file a bug itself; it writes the note and drops the keys. `scripts/exit/*` and the smoke file are left out of the key because `affected::ignorable` already says no cargo test reads them; every other file outside `crates/`, `clients/`, `docs/` and markdown is in it. Doc tests always run. A suite with known-red tests reuses and records nothing. Parser counts: the reuse is in the step note and closing note, not in the live progress figures.
