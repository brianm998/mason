# s1093: the nightly pipeline review

Summary: The weekly per-project analyst is now one pipeline review, on by default every night at 00:00 on Opus at medium, that asks the owner's six questions, files at most ten proposals that duplicate no task in any state, and is set from Settings, `mason review` or `GET/POST /v1/review` (`review.toml`).

## What changed

- `crates/daemon/src/review.rs` (new): `review.toml`, the schedule row `review`, when it is due, filing the task, the facts written to `review-facts/` in its worktree, the submission check, the notice and the status.
- `crates/daemon/src/introspect.rs`: the prompt with the six questions, the result file (`analyst-result.json`: `findings`, `duplicates`, `nothing_found`, all six sections answered) and its ingest.
- `proposals.rs`: `lookback: All`. `core`: finding categories, the nightly due rule, the `review` alert kind.
- API `GET/POST /v1/review`, `POST /v1/review/run`; CLI `mason review [status | run | set ...]`; `mason schedule run review`.
- Swift and Compose Settings: the "Pipeline review" section. `clients/features.toml`: `settings-review`.
- Design and the reasons: decision 1082.

## What the owner has to approve

- `scripts/exit/s1093.sh` (new), `scripts/exit/s22.sh` (section 3 now runs the review in MASON's project; `--analyst-ms` is gone), `scripts/exit/s22-manual.sh` (one line) and `clients/features.toml` are protected.
- Review filings skip `[proposals]` caps and the self-task `max_open`, `per_week` and `max_steps` (they only ever wait for the owner; decision 1082).
- Changed tests: two core draft tests give a category; two `introspection_policy` tests file the review in a `[self]` project, and the one that expected a low, small finding to be queued now expects it proposed, as the task requires.

## Not verified

- No real model has run the review, so the quality of its findings and whether the facts are enough for it are unknown.
- The size of the facts on a large store, and the time to write them (the event log is replayed three times), were not measured.
- Swift on iPad and iPhone was not run on a simulator or device; the section is the shared SwiftUI view.
- An analyst task still open when this lands is no longer recognised: its result is not read, and the owner should cancel it.
- A monitor with saved sound settings does not speak the new `review` kind until it is ticked.
- Local daylight-saving changes were not tested.
