# s710: a landing batch whose members all skipped testing no longer waits for a test-suite slot

Summary: A landing batch drops the suites its members have all skipped (or a forced member or Land now stops) before taking the tier's resource lease, so it no longer queues for `test-suite` to learn it has nothing to run.

**Cause.** `Runner::run_local` took `hold(suites_needs(..))` before `run_over` noticed the skip, so a fully skipped `cargo-workspace` tier waited for a `test-suite` slot.

**Change.** `Runner::without_stopped` (landing.rs) asks `Members::stop_running` per suite, records the same note `run_over` writes ("{name}: skipped by the owner (debt #N)") and `note_stopped("suite:{name}")` when Land now is pressed. `run_local` and `run_alone` (rerun/bisect) hold only the needs of the remaining suites; with none left they take no lease and return green with the notes. `run_over`'s own skip handling stays as the backstop. The post-land tier is unchanged: its batch's tasks have left landing, so there are no members to have skipped.

**Not verified.** Nothing was compiled or run: cargo was refused by the shared build queue shim in this session and run_check was skipped for this task (debt #340). No new test was added: the integration tests the ticket describes (a blocked `test-suite` slot, a fake broker for `run_local`) need a fixture with a `test-suite` resource that the shared test world does not have. Exit script `s710.sh` is a regression run of `landing_skip`, not the ticket's machine-level exit test.
