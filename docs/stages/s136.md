# s136: `[tracker] require_label`: import only labelled issues on a shared tracker

Summary: `[tracker] require_label = true` makes the project's label the only thing that decides whether an issue is imported (whoever filed it, trust unchanged), leaves other pipelines' canceled issues out of the relink list, files an issue again once the label is added after its task was canceled, and says the rule on `mason doctor`'s tracker line; the star example is corrected.

Task #146. Decision 0131 records the choices. Not under `PROTECTED`: `tracker.rs`, `config.rs`, the store, the doctor and the docs. `scripts/exit/s136.sh` is a new file under the `scripts/exit/**` glob, which the task requires; a new file is not held by its path.

## Built

- **Config**: `[tracker] require_label` (bool, default false); a non-boolean is refused naming the key.
- **Store**: migration 24 adds `tracker_items.labelled` (NULL, 0, 1); `TrackerItemRow.labelled: Option<bool>`.
- **Tracker**: `admitted()` used at the three sites; `sync_with_rule` (`sync_with_deps` delegates with the key off); the waiting list skips unlabelled issues when the key is on; labelled-after-cancel re-files as a new task.
- **Doctor**: the tracker line ends with "imports only issues labelled `mason`" or "imports the owner's issues and outsiders' labelled ones".
- **Docs**: `docs/self-hosting.md`, `docs/examples/star.project.toml` (`require_label = true`, a `test` key, `file:` tokens), a correction in `docs/stages/s27.md`.
- **Tests**: config, store round-trip, doctor (both wordings), and in `crates/daemon/tests/tracker.rs` the rule off/on, trust, blocked-by in both directions, the canceled-issue listing, and labelled-after-cancel. No timing assertions.
- **Exit**: `scripts/exit/s136.sh`: a real masond, two fake GitHubs each with three open owner issues (labelled `mason`, labelled `pipeline`, unlabelled). With `require_label = true` one task, from the `mason` issue; with the key absent, three.
