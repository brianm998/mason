# s765: crash test host window, and test helpers build where they look

Summary: The kill -9 agent-session crash test keeps its agent asleep for 60 s and waits for a running step host before the kill, and the daemon tests' `bin()` helper now builds the `mason` CLI into the suite's own target directory, so narrowed runs no longer find no binary or a stale one.

## Crash test window

The agent slept 4 s after its commit; on a busy ubuntu runner the host had exited before the
SIGKILL, so no running host remained. The develop script now sleeps 60 s (like the other kill tests),
the test waits for a running step host before the kill, and the landing wait is 240 s. Assertions are
unchanged.

## `bin()` and `--target-dir`

The project's suite passes `--target-dir $HOME/.cache/mason-target/<worktree>` on the command line
(not in the environment, for sccache). `crates/daemon/tests/support/mod.rs` `bin()` ran a nested
`cargo build -p <package> --bin <name>`, which does not inherit that flag, so it built into the
worktree's `target/` and returned a path under the suite's target directory. A whole-workspace run
had built the binary there already and passed; a run narrowed to `-p mason-daemon --test it -- crash::`
did not, and every scenario panicked with `mason runs: ... NotFound` (GitHub run 44887171724). With a
restored cache holding an old `mason`, the same tests instead drove a new daemon with an old CLI, and
their waits ran out the 3600 s job limit (runs 44870379006 and 44881519391). `bin()` now passes
`--target-dir` set to the directory its own test executable came from.

## Not changed

`limits::a_hot_die_holds_further_machine_work_but_never_what_runs`,
`remote::tests::a_skip_while_queued_or_running_cancels_the_run_and_deletes_the_ref` and
`remote::tests::iso_times_and_ref_names` pass on ubuntu-latest from this branch (scoped run on GitHub);
their red on develop had no panic line in the task, so no cause is named and their code is unchanged.
