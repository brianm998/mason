# Stage 18: Graph editor

## Built
- **`mason_definition::editor`**: operations on the pipeline text with `toml_edit` (insert after, remove, connect, set field, rename, set start, bind a level, set a suite's level, move), the refusal rule (never add a problem), the picture (lanes, laid-out nodes with problems on them, edges, the test grid), step palette, JSON Schema for each step type and the values a form shows, a unified diff and "what changed" in words. **`extends`** is a real key of a step now.
- **`mason_landing::edit`**: the landing editor's operations on `landing.toml` (settings, tiers, the red ladder), refused if invalid, and the form that shows them.
- **The daemon**: a draft per project with undo and redo, the `EditorView` model, simulation through the draft, the impact preview (the diff, the changes, which tasks finish on the old version), and **apply** (owner only; commits to the base branch, or opens a PR where landing uses them; refused if empty, broken, or the base moved). `/projects/<p>/editor/...`, `mason editor show|op|undo|redo|discard|simulate|apply`.
- **The protocol**: `EditorView` grew (lanes, nodes, edges, grid, inspector, landing, palette, draft state, diff, changes, affected, simulation, last error); `Subscribe` carries the selected step.
- **Both monitors**: the same editor page. A canvas with swimlanes by category, draggable nodes with their problems on them, success and red edges (the loop bound on the red edge), a palette (add after the selected step, or copy it with `extends`), an inspector with the step's edges, rename, start, remove, and a form built from its JSON Schema; a **Tests** tab (the grid), a **Landing** tab (mode, batch rules, tiers, ladder), a **Preview** tab (what changes, which tasks are affected, simulate, the diff); undo, redo, discard, apply with a message.
- `conformance editor-expected` and `monitor-tool editor` in both clients; the feature check now has `pipeline-editor` done in both. `docs/decisions/0015-editor-readings.md`, `scripts/exit/s18.sh`.

## Exit test
`bash scripts/exit/s18.sh` passes (real `masond`, `mason editor`): a step is inserted, one created with `extends`, one removed, one renamed and a field edited, and **all five comments of the hand-written TOML survive**; eleven invalid edits are each **refused with the reason** (an edge to nowhere, zero rounds, removing a loop's bound, an unknown suite, an unknown key, an edge as a field, a bad name, a wrong category, removing the only way in, cutting the only way out, an unknown operation) and change nothing; undo and redo; the diff is eight changed lines; simulate walks the draft through six scenarios, and a custom one (`test` red three times) fails as it should; the test grid and the landing editor (and their refusals: an unknown binding point, a level no suite has, an unknown mode, a CI tier under a mode without CI, zero parallel batches); `--as mallory editor apply` is refused; the owner's apply lands a commit on `main` with the comments, the new step, the binding, the landing change and the layout, and the daemon reloads. **Conformance runs in both clients**: the daemon's list of what the editor shows (22 items with no step selected, 45 with one) equals SwiftUI's and equals Compose's, and the two clients' equal each other.

## What testing found
- **Validation already says a lot**: my first tests inserted a review step between develop and test and the editor refused it ("`test` is a testing step, which is before this review step; going back is what on_red is for"). Correct, and the palette now picks the lane at or after the selected step.
- **Replacing a key lost its comment and alignment** (`toml_edit`'s `insert` swaps the key's own spacing too): the first edit of `mode     = "direct"   # no PRs` dropped both. Values are now set in place.
- **A suite's level cannot be renamed under a binding that names it**: the daemon refuses ("no suite has level ...") rather than silently orphaning the binding; the grid asks for the level first.
- **A first draft of apply had a retry loop that never looped** (caught by clippy); it is one attempt with a plain message.

## Not done or not run
- **The editor was driven by operations and compared item by item, not clicked.** Dragging a node, picking from the menus and typing into the forms are not exercised by a test; they call the same model functions the tests do.
- **The environment-failure edge** is not in the definition, so it is not on the canvas (decision 0015).
- **Phones**: the plan says the graph is read-only there at first; there is no phone client yet, so nothing was done.
- **Plugin step types** have no palette entries until Stage 19; their forms would come from schemas, which is built.
- **Fan-out** (several success edges from one step) can be created (`add_next`) but the canvas offers no control for it; the pipeline is a line with loops back today.
- **Applying through a pull request** was run against the fake host only.
