# s261: stopping a step also stops descendants that left the command's process group

Summary: When the step host stops its child (skip, timeout, cancel), it now signals every descendant it noted beforehand, found by parent pid and by process-group membership, not only the command's own process group. Descendants that called `setpgrp`/`setsid` no longer outlive the step.

## Why

On 2026-11-13 `mason task skip 199 --step test` stopped the step host and the task moved on, but five `xctest` workers (children of `swift test --parallel`) kept running for minutes at about 380% CPU each. They had moved to their own process groups, so the group SIGTERM/SIGKILL in `stop_child` never reached them, and once `swift-test` died they were reparented to launchd and could no longer be found by parent pid. Every stop that goes through the step host had the same leak.

## What changed

- `crates/platform/src/process.rs`: `ProcEntry`, `parse_table`, `read_table` (`ps -axo pid=,ppid=,pgid=,lstart=`, same on macOS and Linux), the pure `descendants(table, root, exclude)` (walk by ppid and by group membership to a fixed point; never pid 0 or 1 or an excluded pid), `still_running(snapshot, now)` (same pid and same start time), and `TreeSnapshot` (`take`, `refresh`, `signal`).
- `crates/step-host/src/host.rs` `stop_child`: take the snapshot before signalling; SIGTERM the group and each snapshot member (and the group of each member that leads one); after the grace period re-snapshot (the child is still there, so new descendants are findable) and SIGKILL; after the child exits, SIGKILL once more what is left of the snapshot. Only a pid whose start time still matches is signalled, and the step host itself is never in the snapshot.
- Windows: unchanged. `read_table` returns nothing there, so only the existing group calls (which are unsupported stubs) remain.
- Tests: the platform unit tests for the walk, exclusions, parsing and pid reuse; step-host integration tests `stop_terminates_a_descendant_that_moved_to_its_own_process_group` and `a_descendant_in_its_own_group_that_ignores_terminate_is_killed_too`. Both fail on `origin/develop` and pass now. They poll by attempts, not elapsed time.
- `scripts/exit/s261.sh` runs them.

## Not verified

- Not run against a real `swift test` / xctest tree, and nothing was done to the running daemon; the fix is live only after it reaches GitHub `develop` and the daemon updates.
- Linux and Windows were not run. `ps -o lstart=` on Linux is expected to behave the same.
- A descendant that is started between the last snapshot and the child's death, and that escapes its group, is missed. Only a sweep when the grace period ends and the exit-time one cover that window.
- Start times have one-second resolution, so a pid reused within the same second would be signalled; the window is negligible but not zero.
- Under load two older tests (`killing_the_controller_*` in the step-host `host` test) failed in the full-crate run and passed alone; they are unrelated to this change but were not run on the unmodified tree.
