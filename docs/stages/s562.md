# s562: Compose monitor disk chart beside the CPU chart

Summary: The Compose monitor's home page shows a Disk section (free space per volume as a line chart with a span picker, a legend and per-volume checkboxes that are remembered) to the right of a narrowed CPU section, stacked below it on a narrow window, and has a `Disk` section page.

- Core: `DiskView.kt` (`diskChart`, `diskChartIndex`, `DiskColors`, hidden-volume preference helpers), `Format.bytes`/`freeOf` (decimal units), `MonitorModel.diskHistory/diskSpan/pickDiskSpan/hiddenVolumes/toggleVolume`, `Connection.kt` subscribes to `DISK_HISTORY` on home and the cpu and disk pages and sends `disk_span_ms`.
- UI: `ui/Disk.kt`, `CpuDiskRow` in `Pages.kt` (side by side at 900 dp or more of page width, CPU:disk 3:2; stacked CPU first below), `Page.Section("disk")`.
- `clients/features.toml` gains `[feature.disk-history]` (protected file: needs the owner's approval).
- Tests: `DiskViewTest.kt` (core), `DiskSectionTest.kt` (offscreen UI).
- Daemon test fix: in whole-workspace runs the `notify::` tests in `crates/daemon/tests/it` failed with doubled counts. `launch-frozen` is raised from the step-host launcher's process-wide list, so a step host that another test in the same `it` executable was launching, stuck past 120 s on a loaded machine, raised the alert in every daemon then running. The notify tests now count and index only the alert kind they raise (`paused`, `disk`). No daemon code changed (`attention.rs` is a trust file). The extra alert is confirmed in the failing logs; that the fix holds under load is shown only by the whole-workspace run.

Not verified: a live daemon with two real volumes (no `scripts/exit` Compose script exists, so the unit and UI tests are the exit test); the look of the chart on a real screen; the Swift, iOS and Android clients are untouched.
