# s1218: cap when full-CI runs start, by a share of the gha pool

Summary: a scheduled full-CI dispatch is deferred while gha use is above `gha_full_share` percent
of the limit or task work waits for gha units. See decision 1208.

## Cause

Full-CI jobs filled the gha pool while task steps waited (#1228); dispatch looked at nothing.

## Change

`full_start_deferred` in ci_schedule.rs gates `dispatch_as`; sched.rs holds `gha_full_share` and
`gha_task_waiting`; `mason resources` shows the share.

## Owner question

Mid-run capping (`max-parallel` in `.github/workflows/ci.yml`) is not done and needs owner
approval, because the workflow is protected. Should it be filed?
