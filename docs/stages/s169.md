# Stage 169: the two flaky update tests wait for conditions

Summary: The build-crash rollback and update-during-agent-session tests now wait on a marker file, the boot log and the daemon's own pid record instead of sleeps.

## What raced

- `an_update_while_an_agent_session_runs_does_not_interrupt_it`: it waited for *any* running step host, which can be the explore step's host (it exits soon), then slept 1 s hoping the develop step had reached its wait. It then compared hosts before and after the update. The gated agent now touches `gate/started` right before waiting; the test waits for that file, then reads the host. The sleep is gone.
- `a_build_that_crashes_is_rolled_back_by_itself_with_an_alert`: (1) a 3 s sleep stood in for "c1 recorded healthy"; it now waits for the `<sha> healthy` line in `runtimes/boots.log`. (2) Each restart was judged alive if it had not exited after 800 ms; a crashing start that took longer under load was taken for the daemon, which changed the crash count. It now waits until the process exits (a crash) or `daemon.json` holds its pid (the daemon is up), with a 120 s limit that only stops a hang.

No assertion was removed or loosened; nothing in `crates/daemon/src/update.rs` changed.
