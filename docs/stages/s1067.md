# s1067: `mason project rename` sends the daemon's owner identity

Summary: `mason project rename` now sets MASON_AS from USER, LOGNAME or "owner" like the daemon's default owner, so s965 passes where USER is unset or differs.

## Cause

The `project` branch of the CLI never set an actor, so the daemon answered 403 `"" is not the owner's identity`. Other owner commands set MASON_AS from USER first.

## Not reproduced here

s193/s219 (Windows type-check), s40 (features.toml now has a platform_reason for notification-details) and s777 were not established as defects in this change; s914 only wraps s40 and s777.
