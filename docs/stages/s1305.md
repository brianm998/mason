# s1305: the outage-or-refused-token test follows s1256

Summary: `remote::tests::an_outage_or_a_refused_token_is_environmental` now expects a 503 on dispatch to keep the pushed ref and a `cancel_pending` record, and a 401 to leave neither.

## Cause

On `origin/develop`, `dispatch` marks `cancel_pending` on an `ErrorKind::Unavailable` error (`crates/daemon/src/remote.rs:2271-2274`; 503 maps to it at `crates/adapter-api/src/service.rs:109`). `retire` (`remote.rs:1539-1551`) then keeps the record and ref when `cancel` cannot list runs, which it cannot while every request answers 503. A 401 maps to `ErrorKind::Auth` (`service.rs:108`) and sets no mark. The test (`remote.rs:7051`) still asserted that no ref was left for either code, so it failed on 503.

## Change

Test only: the test's body and comment in `crates/daemon/src/remote.rs` (decision 1295). No production code changed.
