# s267: Windows port 5, `mason service` and the CPU/memory probes

Summary: `mason service` installs a per-user logon Scheduled Task for masond on Windows, and the CPU and memory gates read GetSystemTimes and GlobalMemoryStatusEx there, with the generators and arithmetic tested on every platform.

See docs/decisions/0262-windows-service-and-probes.md. Changed: `crates/cli/src/service.rs` (Kind::Task, `task_xml`, schtasks calls through the injected Runner), `crates/daemon/src/cpu.rs` (`windows_ticks`, `read_windows`), `crates/daemon/src/sched.rs` (memory), `crates/daemon/Cargo.toml` (windows-sys). Not verified on Windows: nothing was built or run there.
