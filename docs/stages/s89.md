# s89: MASON's own batch window is 30 seconds

Summary: MASON's own landing batch window is now 30 seconds instead of 10 minutes, so a task no longer waits ten minutes to land for a batch that saves almost nothing.

`.mason/landing.toml` had `window = "10m"`. Of 42 tasks with both times recorded, the median wait from the land step to batch start was 10.0 minutes (8.9 hours in all); 34 batches landed 47 tasks (1.4 per batch). MASON's own landing has no landing suites, so a batch shares no verification. Now `window = "30s"`; `max_size` and `parallel` are unchanged, and tasks finishing together can still share a batch. `docs/self-hosting.md` does not give the figure, so it is unchanged.

Trust: `.mason/**` is a gate. This shortens a wait and removes no check; the test step each task passed still runs before landing.

Exit test: a one-line configuration change needs no new script; `scripts/exit/s89.sh` only greps the value.

Not verified: that the landing tests do not read this file is from a grep, not a run; `mason definition check` and the full test suite were not confirmed by me (the shell refused my command and the test check timed out); I did not observe a real landing with the new window.
