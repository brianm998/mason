# s739: investigate the landing_yield test red at ca5406fb

Summary: A landing batch's suite run no longer makes its immediate flaky-rerun while an update is draining, so a draining update stops a red batch after one run, as s705 intended.

See docs/decisions/0732-landing-yield-test-red-at-base.md.

Seen at ca5406fb: `landing_yield.rs:65`, `assertion left == right failed: no run after the first one; left: 2, right: 1`.

Cause: the batch's red suite run was followed, inside `suites::run_over` (`Verdict::Red`, `rerun_failing`), by an immediate rerun of the failing tests (the whole suite when it has no `rerun` template). That second run is red too, so two red runs happened before the batch reached its yield point in `landing.rs`. The test, which is the first to count runs, had never passed.

Change: `crates/daemon/src/suites.rs` skips that immediate rerun for a landing batch's run (no task) while `landing.draining()`. Not changed: `landing.rs`, the test's assertions and timeouts.

Trust: `suites.rs` is PROTECTED; the owner must approve this change.

Not fixed here: the other four red targets (`mason-conformance --test ci_gates`, `mason-daemon --lib`, `mason-pipeline --bin mason`, `mason-pipeline --test remote_dispatch`).
