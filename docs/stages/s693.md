# s693: a landing batch merges the head a task submitted

Summary: A landing batch merges each task's pinned head instead of its live branch, drops members whose run ended, and refuses to land a task whose head differs from the tested one.

A `Wait` records the branch head when the task joins the queue; `BatchTask.head` carries it
into `assemble`, which merges and tests ancestry on that commit. Between rounds and split
runs a member whose landing run is no longer the task's open run is dropped with a batch
note ("#N left the batch: retried or canceled"), neither landed nor parked; the next round
verifies the smaller union. Before promotion each task's pinned head is compared with the head
sent to verification; a mismatch parks it ("its branch moved after testing"). `mason task
retry` on a task in landing says it leaves the batch.

Not verified: the daemon integration test (two-task split with a mid-split retry) was not
written; coverage is the landing-crate unit tests. The tested-head comparison is a guard: heads
are pinned, so it cannot differ today. #684 should reuse `BatchTask.head`.
