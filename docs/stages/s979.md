# s979: one-line notifications with a "?" button for the details

Summary: Every notification row in both monitors is one line, and a row with more to say has a "?" button that opens a dialog with the full reason, the choices and an "Open task #N" action for each task it names; `Banner` gained a `detail` field.

**What changed.**

- `schemas/mason.proto`: `Banner.detail = 7` (additive). Swift binding regenerated with `protoc`; Rust (prost) and Kotlin (Wire) generate in the build.
- Daemon (`views.rs`): `landing_frozen` and the CI-watch banners now write a short summary in `text` and the reason, jobs and task numbers in `detail`. A final pass `one_line` runs over every banner in `header`, so the kinds not split by hand (health, holds, push_auth, definition, paused, the update rows) also reach the clients as one line of at most `BANNER_TEXT_MAX` (80) characters, newlines removed, with the whole original text in `detail`. `holds::banners`, `health::banner` and `update.rs::daemon_banner` are not rewritten by hand; they go through that pass, and the clients apply the same rule to client-made rows and to an older daemon's long text.
- Swift: `NotificationRow.detail`, `hasDetails`, `taskNumbers`; `MonitorModel.oneLine`; `BannersView` rows use `lineLimit(1)` with tail truncation, a "Details" "?" button before the dismiss X, and a sheet with summary, detail, the inline action, Resume for a pause, the daemon-update confirmation text and "Open task #N" (`mason://task/N`). The row's accessibility label carries the full text.
- Compose: `NoticeText` (core), `DetailsButton` and one-line rows in `TopBar.kt`, with the same dialog. The Compose bar has no dismiss X, so the "?" sits at the end of the row.
- `clients/features.toml`: `feature.notification-details` (swift and compose done; ios and android todo, with reasons). **This file is in `PROTECTED`: the owner must approve it.**
- The divider test in `NotificationBarTests` asserted that a long row wraps; it now asserts the row stays one line.

**Not verified.** Nothing was compiled or run locally (the shell refused local builds); only `run_check` ran the tests. The Swift dialog test only renders the sheet and checks it has a size; it does not read the dialog's text or buttons back. The phone layouts (iOS, Android) were not changed. "Open task" is offered only for task numbers written as `#N` in the text or detail. The protocol conformance tests were not edited: none of them listed `Banner` fields.
