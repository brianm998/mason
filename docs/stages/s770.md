# s770: the Compose conformance run waits for the views of each step

Summary: The Compose monitor's conformance run now waits for the daemon's sequence number after each demo step (read from `/status` after the step), and the model drops a view older than one already applied, so a slow runner no longer samples stale views.

**Not reproduced.** The failing log shows Compose holding items the server did not list at checkpoints 8, 10 and 12, which means it sampled views older than the step. The 300 ms quiet-window `settle()` alone cannot tell "no more views" from "views not yet arrived" on a slow runner. I had no Linux run to diff checkpoint JSON against, so the stale-view cause is inferred, not observed. Running `MASON_NO_GUI=1 bash scripts/exit/s13.sh` in CI and diffing `expected/` against `compose/` settles it if it stays red.

**Change.** `Tool.kt` `step()` reads `seq` from `/status` after `/demo/next` and waits until `lastSeq >= seq` before settling (no daemon change); `Model.kt` ignores a per-kind view whose seq is lower than the last applied. `compare()`, `visible()` and the planted-difference check are unchanged.
