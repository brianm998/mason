# s527: what each task waits on is obvious: the real blocker, a queue-held banner, leases with no task

Summary: the monitors now say what really holds each waiting task (a named blocker and a cause badge), show one line at the top of home when most waiting work is held by one exclusive request, gate or red test, and list `mason run` leases that belong to no task with their origin.

## Why

On 2026-11-16 at 18:46, 31 tasks sat in develop with 5 of 6 compile slots free and CPU at 13%. First in line was an exclusive `mason run` from `starpipe heavy`, waiting for #510's compile slot; nothing passes a waiting exclusive request, so everyone queued behind it. Each row said "Waiting for compile slot: 12th in line, held by #510", which named the wrong thing, and the lease appeared nowhere but in `mason resources`.

## What changed

- `crates/scheduler/src/explain.rs`, `plan.rs`: a `Wait` carries `blocker`, the first waiter ahead that it may not pass by the passing rule (an exclusive request, or the one that set aside what it needs), and `Ahead` / `HeldBy` carry request ids. `Wait::reason_code()` is the cause as a code (`full`, `behind`, `behind-exclusive`, `exclusive`, `cpu`, `settling`, `disk-stall`, `syspolicyd`, `memory`, `disk-floor`, `too-big`, `unknown`). The sentence is made from the same `Wait` and now reads "behind an exclusive request interactive `starpipe heavy`, which waits for #510 for 8 min".
- `crates/daemon/src/waitview.rs` (new, pure): builds, from one plan and the ledger snapshot, each waiting task's `WaitInfo` (code, resource, place in line, holders, blocker, the whole chain, the sentence), the leases that belong to no task, and the one `QueueHold` when more than half of the waiting tasks (and at least two) are behind the same exclusive request or held by the same gate.
- `crates/daemon/src/sched.rs`: the view is published with the sentence snapshot in `publish_waits`, so a released holder is gone from every row on the next pass; `Compilation.leases`; `lease_set_origin`.
- `crates/daemon/src/views.rs`: `TaskRow.wait`, `HomeView.queue_hold` (a red base from `base_red` is a hold too, when it holds more tasks), the row sentence comes from the view.
- `crates/store`: `base_reds()`.
- `schemas/mason.proto`: `WaitParty`, `WaitLink`, `WaitInfo`, `QueueHold`, `TaskRow.wait = 27`, `HomeView.queue_hold = 10`, `Compilation.leases = 11`. All additive.
- `mason run --origin O` (with the existing `--label`); the daemon records "O in <cwd>", or "cli in <cwd>"; `mason hook bash` passes `--origin hook`.
- Swift and Compose: banner, badge, chain on the task page, lease rows in Compilation; Android: banner, badge and chain (no Compilation section there). `clients/features.toml`: three features.

## Tests

- `sched::tests::ten_compiles_behind_a_waiting_exclusive_lease_all_name_it`: all ten rows carry `behind-exclusive` naming the lease, one summary names the lease and #510, and #510 is in no row after it releases.
- `sched::tests::a_gate_holding_most_waiting_work_is_the_queue_summary`.
- `explain::tests::the_sentence_and_the_structured_wait_agree_for_every_cause`.
- Swift `QueueWaitTests`, `QueueHoldBannerTests` (offscreen hosting controller); Compose `QueueWaitTest`, `QueueHoldBannerTest` (offscreen test rule).
