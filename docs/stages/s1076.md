# s1076: exit-script watcher no longer holds the output pipe

Summary: the macOS exit-script watcher's `sleep` is killed and detached from the output pipe when a script ends, so shard 1/6 no longer stalls for the whole limit after a passing script.

## Cause

Without timeout(1), `run_limited` (scripts/run-exit-scripts.sh:71-79 on origin/develop) starts a watcher subshell running `sleep "$limit"`. When the script finished first, only the subshell was killed (line 77); its `sleep` child lived on holding the stdout pipe to `tee` (line 106), so the pipeline could not end. Run 45361042086: `s62 OK` at 09:59:12, nothing until the cancel at 10:58:30.

## Change

The watcher's stdio goes to /dev/null and `pkill -P "$watcher"` runs before killing it. The timeout(1) branch and the `FAILED: ... (over N s)` message are unchanged.

## Tests

scripts/exit/s1076.sh runs the runner with no timeout on PATH: a passing script returns (a hang is caught by the job limit; no clock assertion), and a script over a 1 s limit gives exit 1, `(over 1 s)` and no surviving child.

Protected paths: scripts/run-exit-scripts.sh and scripts/exit/** need owner approval.
