# s1076: exit-script watcher no longer holds the output pipe

Summary: the macOS exit-script watcher's `sleep` is now detached from the runner's output pipe as well as killed, so a leftover one cannot stall a shard.

## Cause

Without timeout(1), `run_limited` (scripts/run-exit-scripts.sh:71-79 at 0de921ce) starts a watcher subshell running `sleep "$limit"`. When the script finished first, only the subshell was killed (line 77); its `sleep` child lived on holding the stdout pipe to `tee` (line 106), so the pipeline could not end. Run 45361042086: `s62 OK` at 09:59:12, nothing until the cancel at 10:58:30.

## Change

c1e58b9b7 (s1079, decision 1068) landed on origin/develop first and added `pkill -P "$watcher"` before the watcher is killed (scripts/run-exit-scripts.sh:77-80 on origin/develop). This stage keeps that and also sends the watcher's stdio to /dev/null (line 74): if the watcher forks its `sleep` between the `pkill` and the `kill`, the orphan does not hold the pipe. The timeout(1) branch and the `FAILED: ... (over N s)` message are unchanged.

## Tests

scripts/exit/s1076.sh runs the runner with no timeout on PATH: a passing script returns (a hang is caught by the job limit; no clock assertion), and a script over a 1 s limit gives exit 1, `(over 1 s)` and no surviving child.

s1079 also fixed the three-digit ceiling in scripts/exit/s101.sh; the merge keeps that, and this change only updates the two remaining "899 left" messages to 9899.

Protected paths: scripts/run-exit-scripts.sh and scripts/exit/** need owner approval.
