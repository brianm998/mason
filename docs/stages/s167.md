# s167: a task that conflicts only with batch-mates waits for the next batch

Summary: A task whose merge conflicts only with earlier members of its landing batch, not with the base, stays in landing and waits for the next batch (first in line if its mate did not land) instead of going back to develop.

**Built.**
- `crates/landing/src/batch.rs`: `Assembled.deferred` (`Deferred { id, with, files }`); a task that cannot be merged is tried against the base tip alone with `git merge-tree --write-tree`.
- `crates/daemon/src/landing.rs`: deferred tasks get no verdict, their activity reads `waits: conflicts with #N in batch #B`, and when the batch ends their `Wait` goes back in the queue unchanged.
- Decision 0162.

**Tests.** `crates/landing/tests/batch.rs`: mate-only conflict is deferred (with the mate named); a base conflict is still ejected with files; a deferred task assembles cleanly when its mate did not land. Existing tests for the resolver failing were updated, since the second task conflicts only with its mate.

**Exit test.** `scripts/exit/s167.sh`.
