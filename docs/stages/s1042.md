# s1042: a recovered step keeps its tree

Summary: A step run recovered after a masond restart no longer merges the base into its worktree; a recovered test step keeps its tree so finished suites are reused.

## Cause

`jobs::prepare` ran `git::catch_up` at every job start, and `Daemon::recover` restarts every open step run's job, so a restart folded a moved develop under live agents and test steps.

## Change

- `jobs::prepare_locked` writes `prepared-r<run>` (HEAD, tree) in the task directory once the run has prepared.
- `jobs::prepare_for` finds that record and skips the merge. A develop, explore or review job never moves HEAD; a test step does so only while the worktree still has the recorded tree, otherwise it says why and starts over as a fresh run. A later pass of a test step in the same job (`pass > 0`) merges as before.
- The task's progress file says "resumed after a restart on <tree>; base not merged".
- `suites.rs` (protected) changes one line: it calls `prepare_for(c, pass == 0)`. No verdict logic changed; every suite without evidence for the tree still runs.

## Not verified

The new test `a_recovered_develop_step_keeps_its_tree_when_the_base_moved` (crash.rs) covers the agent case. Recovered test steps with a green suite, and the fresh-step-after-restart case, have no test of their own here. s1042.sh only checks the pieces are present and runs that test. #1051's work on `run_check` replay was not merged with this.
