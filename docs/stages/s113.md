# s113: plugin kit tests survive a slow first exec

Summary: The plugin kit tests now run each script once, untimed, before any kit call, so a slow first exec of a fresh file (macOS syspolicyd) no longer eats the initialize timeout.

Cause (from the task, not reproduced in this session): the first exec of a newly written executable took about 12 s, longer than the 10 s kit timeout, so broken-copy tests failed with "initialize: no answer within 10s". Fix: `prime` in `crates/plugins/tests/kit.rs`, called from `broken()` and the example test. The kit, host and conformance CLI are unchanged.

Not verified: the exact phase of the stall (execve in spawn or child startup); priming covers both.
