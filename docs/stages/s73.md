# s73: the monitor's left panel in queue order and newest entry first

Summary: The daemon now sorts the monitor's left panel by purpose: Queued shows the real admission order (the same rank `next_admission` uses, tasks that can go before held ones), and every other section shows the task that entered it most recently on top, using a new `Task.state_entered_at` set in one place in the reducer.

## What was built

- `Task.state_entered_at` (`crates/core/src/task.rs`), set at filing and, in `reduce()`, whenever a task's state differs before and after an event. Rebuilt by replaying the log; no backfill.
- `section_of` (`crates/daemon/src/views.rs`): Queued sorts by `(not Waiting(Slot), queued_rank)`; other sections by `(Reverse(state_entered_at), Reverse(id))`. `queued_rank` is `pub(crate)`.
- Comments and docs: `DESIGN.md`, `docs/DESIGN.md`, `clients/features.toml`, `schemas/mason.proto`, the generated Swift comment.
- Tests: `crates/engine/tests/state_entered.rs` (filing, each kind of transition, same-state, replay); `the_sidebar_is_in_queue_order_and_the_rest_newest_entry_first` in `crates/daemon/tests/protocol.rs` (renamed; the old assertions are unchanged and a new part follows them).
- Exit script `scripts/exit/s73.sh` with a helper `scripts/exit/fixtures/s73/sidebar.py` that reads the sidebar from the daemon's websocket view.

## Exit test

`bash scripts/exit/s73.sh` ended with `s73 passed`. Output of the daemon part:

```
   queued: #4 #3 #2
   testing: #1 #0
   canceled: #5 #6
(after a restart: the same three lines)
```

The script runs the cargo tests, then a real `masond` with the scripted agent and checks Queued (urgent, normal, low though filed low, normal, urgent), Testing (entered last on top), Canceled (by cancel time), before and after a restart.

## What testing found

- The exit script had to start `masond` with `--port 0`: the owner's own daemon holds the default port.

## Not done or not verified

- The Queued check in the exit script uses tasks held by a blocker (all held, so ordered by rank among themselves); ordering of tasks that can go versus held ones, and agreement with `next_admission`, is covered only by the protocol test, and there the `next_admission` comparison runs only if the demo daemon has a free session.
- The Swift and Compose monitors and the conformance run were not run separately here beyond `cargo test --workspace` and the exit-script runner.
- `row()`'s "time in state" display is still time since the last step start (see decision 0059).
