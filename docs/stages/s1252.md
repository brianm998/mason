# s1252: a red run_check names the failing tests and their panics (#1258)

Summary: A red suite result, a red or timed-out test-step send-back, now starts with the names of the failing tests (up to 30, then a count of the rest) and the panic text of the first 3, read from the whole log; the 40-line tail follows as before. A scoped run in which the suite ran 0 tests is reported `NOT GREEN`.

**What changed.**

- `rerun.rs`: `failure_digest` (pure, bounded, fenced, backticks in log text neutralised) and `ran_no_tests` (libtest `0 passed; 0 failed` summaries, pytest `no tests ran`).
- `jobs.rs` `run_suites`: the FAILED line carries the digest; the log is read from the daemon's log file, falling back to the outcome's full output (`o.full`), which is what node and GitHub runs fill. The old fallback was only the 40-line tail, which may be why "the test(s) your change adds failed" never appeared for those runs; this is a likely cause, not reproduced. Failing names for the narrowed rerun use the same fallback.
- `jobs.rs` test step: the same digest before `Last output:`, also when timed out.
- Scoped 0-test run: a suite that passed with a scope but ran no test is not recorded as passed and the result says nothing matched. This changes what counts as green for scoped runs (verdict logic, owner approval needed); a green with no test proves nothing.

**Not verified.** Nothing was run locally beyond `cargo check`; tests ran via `run_check` only. The `run_check` reports `hostedcheck.rs` still cut `output` to 40 lines; the digest is added at the consumer. Test binaries other than libtest/pytest are not judged for 0 tests. No node-versus-GitHub equality test was added: both fill `o.full` and go through one function. Cause for #1111's missing adds-line was not confirmed.
