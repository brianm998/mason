# s552: a waiting exclusive request must not idle free slots or freeze the queue

Summary: A waiting exclusive request no longer freezes the queue: its drain end follows overrunning holders, it gives up its freeze after `order.exclusive_max_wait_s` (600), and a `mason run` with no terminal or from an agent is ranked as pipeline work with `--exclusive` bounded to all compile units.

## Problem

On 2026-11-17 09:22 an agent's `starpipe heavy` became `mason run --exclusive`. After 13 min,
first in line, with 3 of 6 `test-suite` slots used and `compile` at 0 of 6, the queue behind it
still waited. The same happened on 2026-11-16.

## Changes

- `crates/scheduler/src/plan.rs`: `drain_end` no longer falls into the past. A holder past its
  expected end counts as one more expected run from now, so backfill (s385) keeps working while
  holders overrun.
- `World::exclusive_max_wait` / `Ledger::set_exclusive_max_wait`: a waiting exclusive request
  that has waited that long gives up its freeze. A holder with no estimate is then taken to end
  that long from now, so work with an estimate runs again. Work is still only admitted if it is
  done by the drain end, so the request keeps first place and starts when the machine drains.
  Its wait text says "exclusive request waited 10 min: work runs again until the machine
  drains" (`Wait::thawed_ms`).
- `crates/daemon/src/sched.rs`: `Broker::lease_open_from(.., origin)`. A person (no origin, or
  `person`) is ranked first as before and keeps `--exclusive`. Any other origin is pipeline
  work (the task's standing, or fewest steps remaining, which is next after landings), and its
  `--exclusive` becomes all `compile` units unless `[order] exclusive_origins` names the origin.
  This applies to `--pipeline` requests too. The conversion is shown on the request label.
  New `resources.toml` settings: `[order] exclusive_max_wait_s` (default 600, 0 = no bound) and
  `exclusive_origins` (default none).
- `mason run --origin O` and the lease body's `origin`, `rank`, `converted` fields (shared with
  #512). Without `--origin` the CLI picks `pipeline` (`--pipeline`), `task` (`MASON_TASK`),
  `agent` (`CLAUDECODE`), `no-terminal` (stdin not a terminal) or `person`.

## Tests

`crates/scheduler/tests/properties.rs` (overrun backfill, freeze bound, the 09:22 replay),
`crates/daemon/tests/origin_rank.rs` (origin rank, conversion, person, allowed origin).
No timing assertions. Exit: `scripts/exit/s552.sh`.

## Measured freeze, before and after

The 09:22 replay (3 holders overrun, waiters expect 30 min): before, the old rule left
`drain_end` in the past, so no waiter was granted until all three holders ended; after, all
three waiters are granted at the first plan. The "before" figure comes from reading the old
rule, not from running the old code against the new test.

## Not verified

- The "before" figure was not replayed on the old code.
- No scratch daemon run with real processes; the exit script runs the scheduler and broker
  tests only.
- Overrun holders are assumed to need one more expected run (the typical time); the history is
  not consulted for the remaining time.
- Monitor display of the origin (#512) is not done.
