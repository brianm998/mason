# s1117: who lifted a pause, and expiries rounded up

Summary: Every recorded override names the client that made it, a pause or resume also names the pause rows it made or lifted, a lift is shown for ten minutes, and `mason pause list` no longer drops the partial hour.

Task #1144, decision 1106.

- An intervention's detail is now `<path> via <client>`: `cli`, `monitor`, `agent:<task>`, or
  `unknown` for an HTTP request that names none. The command line and the monitors name
  themselves in the WebSocket hello (`Hello.client`); `ws.rs` passes that on as
  `x-mason-client`.
- `/pause` adds `: paused #<id> <mode> for <project>, expires <UTC>`. `/resume` adds
  `: lifted #<id> ...` for each pause in force that it removed (or `lifted nothing`), then
  `cleared expired #<id>` for rows already past their expiry. Both are written before the
  request is answered.
- `Store::take_pauses` returns the removed rows.
- `/pauses` has `last_lift`; `mason pause list` prints `lifted HH:MM by <who> via <client>` and
  the monitors get a `pause_lifted` banner, for ten minutes after the newest lift.
- `ago_until` rounds up and shows `in Xh Ym` below 48 hours. It also formats quarantine
  expiries. The monitors format no pause expiry, so nothing changed there.

Tests: `tests/it/pause_record.rs`, `ago_until_tests` and `a_tasks_step_names_its_task` in the
command line, `scripts/exit/s1117.sh`.

Not verified: the banner in either monitor (no Swift or Kotlin change; it is an ordinary
warning banner to them, with no mascot icon); a monitor over the LAN; the Swift and Compose
hello names against a live daemon (both start with `mason-monitor`, read from their source);
the exit script was not run on the developing machine.
