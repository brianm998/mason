# s689: a suite that runs whole again later is not run whole by the test step

Summary: A suite can say `whole_later = "batch"` (or `"ci"`) and list `narrow_smoke` units, so the test step runs only the smoke units plus its pick, or nothing, where it used to run the whole suite.

New suite keys `whole_later` and `narrow_smoke`. In `narrow_units_for_step` (suites.rs), a suite whose claim holds gets `narrow::select_later`: an empty pick runs only `narrow_smoke` (with none: "not run: nothing in this change reaches its tests; runs whole at batch", outcome `NotSelected`, no command); a `narrow_never` hit runs smoke plus the picked units; a pick over half runs the pick plus smoke. Without `whole_later`, `select` and the step behave as before. The claim is checked when the landing config is read (`whole_later_problems`: `batch` needs a non-post-land tier listing the suite, `ci` needs a `[ci]` section) and again by the step, which runs whole if the claim does not hold.

Not verified: `run_check` during development does not use `narrow_*` keys (it uses `dev_command`), so I left it unchanged; `narrow_packages` suites ignore `whole_later`. The `ci` claim is the owner's word: nothing checks that the CI workflow runs the suite.
