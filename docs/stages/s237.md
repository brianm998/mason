# s237: Mac monitor sidebar rows redraw only when their own data changes

Summary: Sidebar rows now take their data by value and are `Equatable`, the sequence number, live log and clock offset live in a separate `LiveState`, rows and entries are keyed by task id, and one shared one-second tick that stops when the app is hidden replaces a `TimelineView` per running row.

What changed
- `MonitorCore/Model.swift`: new `LiveState` (`lastSeq`, `liveLog` published; `clockOffsetMs` plain). `MonitorModel.lastSeq`, `liveLog`, `clockOffsetMs` and `daemonNow` forward to `model.live`, so they no longer fire `MonitorModel.objectWillChange`.
- `MonitorCore/SidebarLayout.swift`: `SidebarEntry` is `Identifiable` (`h:<state>`, `r:<task id>`, `rule`, `p:<title>`).
- `MonitorUI/Sidebar.swift`: `RowView` holds the `TaskRow`, `selected`, `canAct`, the clock and `go`/`approve` closures, not the model; it is `Equatable` and applied with `.equatable()`. The `ForEach` uses the entry id. A DEBUG-only `RowView.evaluations` counter.
- `MonitorUI/Components.swift`: `ProgressCells` and `ProgressLine` take the `LiveState` (not observed). `SharedTick` is one timer for all progress lines; it runs only while a line is on screen and the app is not occluded.
- `MonitorUI/Pages.swift`: the task page log and the Health sequence line observe `LiveState` in small views.
- Compose: `SidebarEntry.key` and `items(entries, key = ...)` in `Sidebar.kt`. Found: the list was index-keyed. `RowView(model, row)` there reads `model.page` only, and Compose recomposes by state read, so no whole-model observation to fix.
- Decision: `docs/decisions/0232-sidebar-rows-by-value.md`.

Tests: `MonitorCoreTests` (a progress push leaves another row equal and does not change `sidebar` for seq/log changes; entry ids stable across a section move), `MonitorUITests/RowRedrawTests` (offscreen: seq and log changes evaluate zero rows, one push evaluates its row only, a 2,000-message recorded stream stays at or under 2x the row-changing messages), Compose `sidebarEntryKeysAreUniqueAndNotPositional`. Exit: `scripts/exit/s237.sh`.

Not verified: I could not build Swift or Kotlin in this sandbox (no network for swift-protobuf, build queue), so none of the Swift or Kotlin code or tests has been compiled or run. The 99.9% CPU figure was not re-measured. Progress cells' "quiet" amber colour now updates when the row redraws, not every second. Occlusion-based pausing is untested.
