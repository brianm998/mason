# s1052: Swift monitor Add Project

Summary: The macOS monitor has File > Add Project… (⇧⌘N) and a + under the project picker that open a five-step wizard (Repository, Detected, Questions, Review, Apply) over the daemon's `/onboarding` endpoints; iOS shows neither.

`MonitorCore/AddProject.swift` holds the wizard as plain state (`AddProjectWizard`: answers as the flag map, step, last plan, land choice default `no`, proof task default on, progress); `MonitorModel` sends `/onboarding/candidates`, `/plan` and `/apply` and feeds the results back (`onb-*` command ids). "Use recommended for the rest" answers each following question with its recommended option as plans come back. On apply success the new project is selected; on refusal the wizard returns to Review with the reason. `MonitorUI/AddProjectSheet.swift`, the menu item and the + button are `#if os(macOS)` (the + and menu need `canAct`: owner and not read-only). Choose… (NSOpenPanel) shows only when `localDaemon`.

Not verified: no Swift test or build was run in this shell (run through run_check only). The sheet was not looked at on screen; the Compose desktop wizard is a separate task, so the two clients' copy was matched by the task text only. The daemon's JSON for `agents` was read from the serializer (pairs of name and path), not from a live response.
