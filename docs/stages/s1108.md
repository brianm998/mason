# s1108: context-window fill and compactions per agent session

Summary: MASON records each agent session's peak and final context-window fill and its compactions, shows them on the step row in `mason task show` and the monitor task page, and `mason report context` gives the send-back rate by peak fill.

## What changed

- `AgentEvent::Context { used, window }` and `AgentEvent::Compacted { subtype, before, after }`.
  Only the Claude adapter emits them. `Context` is sent when the fill moves by a percentage point
  or the window changes, so a recorded peak or final figure can be under the true one by less
  than a point.
- The step runner sums them (`ContextStats`); the daemon writes one `context_runs` row per
  session (a new migration).
- `mason task show` and both monitors print a line such as
  `context peak 62%, final 40%, 1 compaction` on the step row (`context` in the JSON and in
  `StepLine`). `clients/features.toml` has `step-context-fill` (Android: todo).
- `GET /report` has a `context` section; `mason report context --days N [--project P]` prints
  it.
- Decision 1097.

## Not verified

- No real compaction was captured. The `compact_boundary` subtype and the
  `compact_metadata.pre_tokens` / `post_tokens` names in `synthetic_compaction.jsonl` are
  assumptions. If one compaction produces two `system` lines with `compact` in their subtype, it
  is counted twice.
- The assumed windows for models other than Haiku 5.5 were not checked against a run; they are
  replaced by the stated window once a `result` arrives. A session that never reaches a
  `result` keeps the assumption.
- If the CLI compacts and no message follows, the final figure is the one from before.
- The Codex adapter reports nothing, so its steps show nothing.
- No live agent step was run through the daemon: the daemon wiring (runner to store to step row)
  has no end-to-end test.
- The monitors' new line was not looked at on a screen or rendered to an image.
