# s154: Watch the base branch's CI: file a task for a new red, freeze landing on a red gate

Summary: `[watch.ci]` in a project's definition (off unless `enabled = true`) makes MASON read the CI host's own runs on the base branch, file `<workflow>/<job> red on <base>` for a new red (a gate job at once and urgent, other jobs after two red runs, long reds after a threshold, deduped against open tasks and issues, `proposed` past a cap, excluded workflows never), and freeze the project's landing until a red gate job is green on the base again.

Task #164. Decision 0149 records the key names and the freeze-source choice.

## Built

- **Rules**: `crates/core/src/ci_watch.rs`, no I/O, the clock a parameter (seeding, infrastructure conclusions, gate, agreement, long red, dedupe, cap, exclusions).
- **Definition**: `[watch.ci]` parsed in `crates/definition/src/watch.rs`; `Definition.watch_ci` is `Some` only when enabled. Unknown keys get a hint.
- **Store**: migration 25: `ci_watch` (state per project) and `freezes.source`. `set_freeze` / `clear_freeze` act only on `post-land` rows and never replace a `ci` row; `set_ci_freeze` / `clear_ci_freeze` for the watch. `landing.rs` is unchanged.
- **GitHub adapter**: `base_runs(branch)`, `run_jobs(run)`, `job_log_tail(job, n)` (follows the logs redirect without the token). `fake-github` serves `runs.json`, `jobs-N.json`, `log-N.txt`.
- **Daemon**: `crates/daemon/src/ci_watch.rs`: one `ci-watch` loop (a project without `[watch.ci]` costs no call), `pass()` over a `Source` (GitHub, or a fake in tests), filing through `TaskFiled`, setting and clearing the CI freeze.
- **Status**: `ci_watch` in `/status`, a block in `mason status`, banners for the freeze and for reds waiting for agreement (both monitors render the header banners), `source` in `/landing`'s freezes.
- **Tests**: 12 rule tests (core), the definition parse test, 2 store tests (source-aware clear; state), 2 adapter tests (recorded runs, jobs, log redirect, time parsing), 9 daemon tests in `crates/daemon/tests/ci_watch.rs` (seeding files nothing; a gate red files one urgent task and freezes, a post-land clear does not lift it, green lifts it; freeze off; non-gate red once then green; red on two runs files one; cancelled/timed_out/startup_failure and the excluded workflow file nothing; an open task or issue naming the job stops a filing; the cap files `proposed`; the long red on an injected clock; state round-trip; GitHub over recorded responses). No timing assertions.
- **Exit**: `scripts/exit/s154.sh`: a real masond against `fake-github` serving base-branch runs: seed (nothing filed, not frozen), a red gate run (exactly one urgent task with run link and log tail, landing frozen), a further red run (still one task, still frozen), a green run (freeze lifted).
