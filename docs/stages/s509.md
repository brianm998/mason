# s509: a fast unit tier for landing batches whose testing was skipped

Summary: a landing batch whose every task had its testing skipped is built and then runs a fast unit tier declared in the project file (`fast_command`), so a merge that breaks a quick test is parked naming it.

## Why

On 2026-11-16 develop went red because two tasks each added `Deferred`/`Undeferred` to the event list in `crates/engine/tests/matrix.rs`, and the merge kept both. Each was green alone. Their batch had its testing skipped, so the build floor only compiled the tests and the 0.02 s test that would have caught it never ran.

## What changed

- `crates/testing/src/model.rs`, `crates/definition/src/testing_parse.rs`: a new suite key `fast_command`.
- `crates/daemon/src/landing.rs`: `tests_skipped` is computed before the batch is verified. When it is true, `verify` runs each impact-selected suite's `fast_command` after the build floor (`fast_tests`), in the first verification and in every rerun and bisection step. A red puts the failing test names (read with the suite's own parser) in the batch's failed set, so the ladder bisects for the task and the parked reason names the test. After a moved base (s429's rule: rebuilt, not fully re-tested) the fast tier runs again, as it is small.
- `.mason/mason.toml` is NOT changed here: the submission check validates it with the running daemon, which does not know `fast_command` yet, and rejects it. After this lands and the daemon updates, add to `[suite.cargo-workspace]`: `fast_command = "cargo test --workspace --lib && cargo test -p mason-engine -p mason-scheduler --tests"` (owner approval, `.mason/**` is protected). Until then the tier does nothing for MASON itself.
- Tests: `crates/daemon/tests/landing_fast_tier.rs`, `crates/definition/tests/fast_tier.rs` (the key parses). Exit script: `scripts/exit/s509.sh`.

## Not loosened

The skip debts stay open and the full run is still owed. A batch with any task whose testing was not skipped is verified as before.

## Not verified

- The tier's real duration (the task estimates about a minute) was not timed.
- Whether the fast tier would have caught the 2026-11-16 merge was reasoned from the matrix test being an integration test of `mason-engine`, not replayed.
- A suite whose `fast_command` output its parser cannot read is red under the suite's own name, not a test name.
- Trust: `crates/daemon/src/landing.rs` and `.mason/**` are in `PROTECTED`; the owner's approval is needed.
