# s1103: the flaky unchanged-view test was fixed by s1089

Summary: The flaky protocol test for unchanged views is already fixed on develop by s1089, so this task adds only its record and an exit test that runs that test.

## Cause

`protocol::an_unchanged_view_is_not_sent_again_and_a_changed_one_is` asserted that no usage view arrived after the second subscribe. The usage view holds text computed from the wall clock ("resets in 1 h 10 m", "as of 12 min ago"; `core/src/usage_text.rs`), so a rebuild after that text moves on rightly sends a new view. This matches the failed run's panic.

## Change

No code change. s1089 (decision 1078) landed the fix while this task was open: each usage view that arrives must differ from the one sent before it, on a non-demo daemon whose dedupe is the production one. This branch's own version of the same fix was dropped in the merge in favour of that one.

## Not verified

The failure was not reproduced; the cause comes from reading the code against the failed run's message.
