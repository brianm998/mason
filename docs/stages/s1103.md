# s1103: the unchanged-view test allows for the usage clock

Summary: The protocol test for unchanged views now fails only when a usage view identical to the last one is sent again, so a clock-driven text change no longer makes it flaky.

## Cause

`protocol::an_unchanged_view_is_not_sent_again_and_a_changed_one_is` asserted that no usage view arrived after the second subscribe. The usage view holds text computed from the wall clock ("resets in 1 h 10 m", "as of 12 min ago"; `core/src/usage_text.rs`). The demo seeds reset times a whole number of minutes ahead, so the countdown text changes at the first second boundary after seeding, and again each minute. A rebuild on the far side of such a boundary rightly sends the new view.

## Change

Test only: every usage view received, in order, must differ from the one before it.

## Not verified

The failure was not reproduced; the cause comes from reading the code against the failed run's message.
