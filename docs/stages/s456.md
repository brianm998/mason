# s456: iOS connects to the paired daemon over LAN or an extra host

Summary: The iOS app now connects to its one paired daemon through `RemoteSession`, trying a matching Bonjour record first and then each paired host, connecting when the scene is active, closing in the background, resuming from the last sequence number, and clearing the pairing on a 401.

## What changed

- `MonitorCore/Remote.swift`: `PairedStore` (`DefaultsPairedStore` keeps host, port, fingerprint, role and extra hosts in `UserDefaults`; the token stays in the Keychain by fingerprint), `RemoteDiscovery` (endpoint per attempt: Bonjour record with the paired fingerprint, then `Reach.order`; others ignored), `RemoteSession` (lifecycle, link status, revocation).
- `Connection.swift`: a generation counter so `stop()` then `start()` never leaves two loops; `suspend()`; `onAttemptEnd` and `onRefused` hooks; a socket's `refusal` of 401 stops retrying.
- `Reconnect.swift`: `DaemonInfo.host`; `MonitorSocket.open(info:)` and `refusal` with defaults, so existing sockets are unchanged. `PinnedSocket` opens the chosen host and port and reports the upgrade status.
- `Discovery.swift`: `BonjourServiceSource` resolves `_mason._tcp` records to an address.
- `MonitorModel.linkStatus` is shown by the start views and the connection banner ("Looking for <instance>…", "Reached through <host>").
- `MasonIOSApp` starts on `.active` and suspends on `.background`; when unpaired it shows a placeholder until the pairing-screens task lands.
- `monitor-tool remote`; `RemoteTests`; exit script `scripts/exit/s456.sh`.

## Not verified

Nothing was built or run in this session (the build queue was skipped for this task), so none of the Swift, the tests or the exit script has been compiled or run. `BonjourServiceSource` resolution, the Info.plist local-network permission flow and a real 401 from `URLSessionWebSocketTask.response` were never exercised on a device. An IPv6 link-local address has its scope stripped, so it may not connect; the `.local` name follows it in the order. The pairing placeholder is not the pairing screen.
