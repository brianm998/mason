# s351: the Kotlin monitor has the MASON app icon

Summary: the Compose monitor sets the macOS Dock icon at startup with `Taskbar.setIconImage` and ships a generated `.icns` for macOS, and the Android module has a manifest and adaptive launcher icon resources, all derived by script from `MasonMascot/Art/brand/` and checked against it by tests.

## What changed

- `Main.kt`: `setDockIcon()` (guarded on `Taskbar.isTaskbarSupported()` and `Feature.ICON_IMAGE`) using `Mascot.dockIcon()`, which picks `macAppIcon()` on macOS and null elsewhere. `Window(icon = ...)` stays for Windows and Linux.
- `desktop/build.gradle.kts`: `macOS { iconFile }` naming `packaging/icons/mason-monitor.icns`.
- `packaging/make-icns.py` writes the `.icns` (one `ic10` 1024 px entry holding `app_icon_macos.png`); `packaging/make-android-icons.py` writes `android/src/main/res/**` (foreground inset of `app_icon.png`, background the art's corner colour). Both take `--check`. `android/src/main/AndroidManifest.xml` is new. The android module is still not in `settings.gradle.kts`.
- Tests: `MascotTest` (dock icon choice, 1024 px icons, packaging files equal their source art); exit script `scripts/exit/s351.sh`.

## Not verified

- I did not run `make run` or look at the Dock, window or app switcher, so I cannot say which surfaces were wrong; from the code, the Dock and app switcher on macOS were (no Taskbar call, `icon` has no effect there). The window icon on Windows/Linux was already set.
- The Gradle tests and the Android build were not run by me; the Android resources were never compiled with aapt. The `.ico` is the existing file and cannot be derived byte-for-byte (it is scaled with `sips`), so the exit script only checks its structure.
