# s1238: Add Project: no silent `true` test step, unpushed setup or default placement

Summary: Add Project proposes suites for packages one folder down, refuses a `true` test step the owner did not ask for, warns (and files no proof task) when the remote base lacks `.mason/`, and asks where runs go when nodes are on.

Decision record: docs/decisions/1228-add-project-no-silent-true-or-unpushed-setup.md.

## Change

- `crates/onboard/src/suites.rs`: `propose_below` adds `swift-<dir>`, `rust-<dir>`, `go-<dir>`, `gradle-<dir>` suites (`cd <dir> && ...`) for folders one level down, when the root has none of that language.
- `crates/onboard/src/questions.rs`: `--test` and `--placement` flags, the `test` and `placement` questions, `Machine.nodes_enabled` / `recent_node_only_mode`, `[placement]` written last in the overlay, the unpublished-setup warning in `Answers.warnings`.
- `crates/onboard/src/lib.rs`: `setup` refuses a `true` nobody asked for before writing; plan and adopt carry the test command and placement; a refused push adds the warning.
- `crates/onboard/src/land.rs`: `remote_base_has_setup`, `unpublished_warning`.
- `crates/daemon/src/onboarding.rs`, `http.rs`: fill the machine's node state; no proof task (and `proof_hold` in the answer) while the remote base lacks `.mason/`.
- `crates/cli/src/init.rs`: prints warnings; `--prove-only` with a remote looks at the remote base only. `crates/cli/src/doctor.rs`: warns on an unpushed setup.

## Not verified

- Gradle suites were proposed from the output form `<test> PASSED`; no Gradle project was run (the one-run check drops a suite that finds no tests).
- The monitor (Swift) was not changed; it shows the new questions through `next` and the warnings through `warnings`/`proof_hold`, which was not looked at on screen.
- The CLI does not know whether nodes are on, so `mason init` does not ask the placement question; only the daemon's Add Project does.
- Tests were run through `run_check`, not locally.
