# s1138: two timing races in exit scripts (#1160)

Summary: Exit scripts s723 and s727 no longer race the daemon: s723 waits for the run lookup, and s727 sets its held task to local while the task ahead of it cannot land.

## Causes

- `scripts/exit/s723.sh` grepped the fake's `requests.log` once, as soon as the `gha` holder
  appeared. The daemon leases the pool before it dispatches the run and looks it up, so the log
  could still be missing.
- `scripts/exit/s727.sh` step 3 filed task 2 with `--after 1` after task 1 had landed. Task 2 was
  not held and could start its test step before `task run-on 2 local` arrived.

## Changes

- s723 waits up to 120 s for `head_sha=` and fails with the same message if it never appears.
- s727's local `checks.sh` waits while a hold file in the script's temporary directory exists. The
  script holds task 1 that way, files task 2 and sets it to local, checks that task 1 has not
  landed, and only then releases it.
- Every assertion is kept.

The causes were established by reading the scripts, together with the evidence on #1160.
