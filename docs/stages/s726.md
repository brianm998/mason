# s726: a debt payment can no longer wait for ever

Summary: Debt payments take a per-daemon lock and a lease wait that both end when the daemon shuts down or the debt is closed, and the landing fast-tier test is turned back on.

Task #727. `suites::pay` waited on a process-wide `PAYING` mutex and on a lease wait whose keep-waiting closure was always `true`. In a test binary one world's stuck payment blocked every later `pay`. Cause is inferred from the code; no `sample` of a hung binary was taken (no local testing was running).

- `PAYING` and `IDLE_RUN` moved from statics to `Daemon` (`paying`, `idle_run`), plus a `shutdown` flag (`Daemon::shut_down`, set when `serve_until` is told to stop).
- `hold_for_debt` and the `PAYING` wait (a `try_lock` loop, no fixed timeout) end when the daemon shuts down or the debt is no longer open; `pay` returns `Err(PAY_CANCELLED)` and the idle pass does not mark such a debt tried.
- `debt_interval = 0` turns the idle debt pass off; `world_built_fast` uses it so the test's explicit `pay` cannot race it. The fast-tier test is switched back on.
- New tests in `tests/it/testing.rs`: a shut-down world's waiting payment ends and a second world pays; a payment ends when its debt is closed elsewhere (`store.pay_debt`, not `settle_debts`) and is not marked tried.

Trust: `crates/daemon/src/suites.rs` is PROTECTED (verdict logic). No verdict changes; a cancelled payment leaves the debt open. Needs the owner's approval. Not verified by me: `scripts/exit/s06.sh` was not run, and the tests ran only through run_check.
