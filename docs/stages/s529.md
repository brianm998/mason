# s529: disk space history

Summary: The daemon samples free and total space per physical volume every 30 s (data dir, caches, each project's path and worktrees), keeps it like the CPU history (`disk-history.txt`, 24 h of minute buckets) and serves it on `GET /disk/history?span=`, as `ViewKind.DISK_HISTORY` and `Subscribe.disk_span_ms`.

**Change.**
- `disk::relevant_paths` is the one list of paths (data dir; each project's `task_cache` parent and `~/.cache/mason` if present; each project's path; its worktrees dir `<data>/w/<project>`). The floor and the stall prober take it at start; the history takes it afresh on each sample, so a project added later appears in the next one. The floor still compares the least free space over those paths; it now also covers the project and worktree volumes, because they are in the list.
- `DiskSource::volume(path)` gives id, name, mount, free and total bytes. `Statvfs` reads them (`mason_platform::disk::volume_of`: device id on Unix, drive on Windows; mount point = highest ancestor on the same device; name = last component, or the `/Volumes` entry linking to `/`, e.g. `Macintosh HD`). `FakeDisk::set_volume(prefix, name, free_gb, total_gb)` is one fake volume per path prefix. `FileDisk` also reads one volume per line (`name gb_free gb_total`); a path is on the volume named by the last of its components that matches, else the first line.
- `diskhistory.rs`: `DiskRing` (fine ring of `FINE_CAP` readings, minute buckets keeping each volume's last reading, saved to `disk-history.txt`, `query(now_ms, span_ms)`, `parse_span` reused). A volume unreadable in a reading is absent from that point; `volumes` lists every volume seen in the span.
- Sampler: `disk-history` loop through `bg::spawn_loop`, started when the disk is not injected in process and either the machine is measured or `MASON_DISK_FILE` is set. `MASON_DISK_HISTORY_EVERY_MS` shortens the period for scripts.
- Protocol: `DiskVolume`, `DiskReading`, `DiskPoint`, `DiskHistory`, `DISK_HISTORY = 9`, `disk_span_ms = 6`, `View.disk_history = 9`; Swift regenerated by `scripts/gen-clients.sh` (Kotlin is generated by Gradle from the schema). `Client::subscribe_spans` added for tests.

**APFS.** Volumes are grouped by device id, not by container: two APFS volumes of one container show as two entries although they share free space. `nix` does not expose `f_mntfromname`, and reading it would need `unsafe` libc calls.

**Not verified.** The Windows branch of `volume_of` was written but not compiled or run here. The Compose and Swift builds were not run beyond the scoped checks. No real-disk reading of a macOS `/` volume name was exercised in a test.

**Trust.** `scripts/exit/s529.sh` is under protected `scripts/exit/`; it needs the owner's approval. `sched.rs` and `scripts/gen-clients.sh` are untouched.
