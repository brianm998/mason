# s424: a command host that does not come up is started again, not failed

Summary: A command or test step whose host timed out starting (`Spawn(TimedOut)`) was failed on the first try; it is now started again in place up to three times, each failed start recorded as a host loss.

## Why

Finding 1 (repeat failure on a host `TimedOut` spawn error, 4 times) was closed abandoned and the repeat failure rate rose from 0.078 to 0.32. Agent steps already treat a host that never came up as a lost host (s83); command steps failed with "cannot start the command".

## What changed

- `crates/daemon/src/hostloss.rs`: `spawn_retrying`, `SPAWN_ATTEMPTS`.
- `crates/daemon/src/jobs.rs`: `run_command_on` starts its host through it, recording each failed start.
