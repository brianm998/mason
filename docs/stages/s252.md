# s252: a new timing-dependent test is refused at submit

Summary: the weakening scan that runs at `submit_change` now has a `timing-dependent-test` finding for added lines in test code that sleep a fixed time and then assert, assert on elapsed time against a constant, or use a fixed sub-second timeout as synchronisation, unless the line carries an unexpired `// timing: owner <name> expires <YYYY-MM-DD>` marker.

Decision 0247 records the choices and what the scan does not catch.

**What changed.**
- `crates/daemon/src/protect/timing.rs` (new; `protect.rs` is protected): the rules, over the added lines of Rust files under `tests/` (and Rust test code after an added `#[test]` / `#[cfg(test)]` / `mod tests`), Kotlin `src/test/`, Swift `Tests/`. Rust: `thread::sleep`/`sleep(` with a literal duration followed by an assertion within five lines; an assertion on `elapsed()` or an `Instant` difference compared with a constant; `recv_timeout`, `wait_timeout`, `wait_timeout_while`, `park_timeout` with a literal under one second. Kotlin: `Thread.sleep(` or `delay(` followed by an assertion. Swift: `sleep(`/`usleep(` and `wait(for:timeout:)` under one second. A sleep inside a loop opened within the ten lines above is a poll and is not flagged.
- `crates/daemon/src/protect.rs` (protected): `scan_full` calls it for each file; the finding is refused at `submit_change` with file, line and rule, as every finding of this scan is.
- `scripts/exit/s252.sh` (protected).

**Not verified.** The scan was tested on constructed diffs only, not on a replay of past submissions, so its false-positive rate on real work is unmeasured. The submit path itself (`submit_change` refusing with the finding) is the existing wiring, covered by the existing weakening tests, not re-tested for this rule.
