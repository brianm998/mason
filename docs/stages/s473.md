# s473: self-updates wait out a gap and build under a compile lease

Summary: An automatic self-update (`mason update --auto`, or `"auto": true` on `POST /update`) now waits out `min_gap_s` (default 2 h) since the last takeover unless it is urgent, no step is running or a quiet moment comes, and the release build runs under a low-ranked `compile` lease; `mason update status` shows "update waiting since ... (next window ...)".

**What changed.**
- `update.toml` `min_gap_s` (default 7200; 0 turns the gap off). `gap_decision` is a pure function: urgent, no step running, no earlier update, gap over -> take; from half the gap on, a quiet moment (no pipeline task has held a resource for an hour, no landing batch running) -> take; else wait until last takeover + gap.
- Urgent: a commit in `running..target` with an `Update-Urgent:` line in its message. The owner's `mason update` (no `--auto`) never waits.
- `build_leased` takes a `compile` lease through `lease_open_outside` (most steps remaining, lowest priority), so the CPU gate and the queue count the build. `mason update --check` builds the same way.
- A held update is not a failure: phase goes back to `idle`, `Daemon.update_held` keeps (since, next window), shown by `mason update status` and `GET /update` (`held_since_ms`, `next_window_ms`).
- `Broker::task_work` counts the pipeline tasks holding resources and the oldest one's age.

**Not verified.** Nothing in this repository starts an automatic update: `check_once` only looks. The follower that does (the monitor's update phase, or a script) must pass `auto` for the gap to apply; I did not find or change it. "Quiet" uses broker holders and `busy_projects` as stand-ins for "agent past its first hour" and "landing verifying". No end-to-end run with a real daemon; the exit script runs the unit tests only. The urgent-marker test checks only the negative cases.
