# Stage 1209: s06's host search tolerates a vanished host.kv

Summary: `scripts/exit/s06.sh` read each candidate `host.kv` with an unguarded `sed` under `set -e`; a file that vanished after the `[ -f ]` test aborted the script (CI run 45922280578, ubuntu, `sed: can't read .../t0r1-1/host.kv`).

- Cause: the read at `scripts/exit/s06.sh:76` (host-discovery loop). It now uses `2>/dev/null) || continue`, so an unreadable record is skipped; only a host whose pid was read and is alive is chosen. The failure message for a missing agent host is unchanged.
- `scripts/exit/s1209.sh` runs the real loop (extracted from s06.sh) with a `sed` shim that removes the first `host.kv` before it is read, and checks the live host is selected. No sleeps, no timing.
- Ruled out as the deleter: the daemon (dead during the loop), `hostarchive::pass` (sweeper only, sweep-ms 3600000, host_grace 24 h), `write_kv` (renames, never deletes), launcher `discard_unused` (empty directories only).
- Not identified: the code that removes `host.kv`. A follow-up is needed to find it; this change only removes the script's dependence on the file staying put.
- Not run here: the CI run itself; only `s1209.sh` was run locally.

Second flake, found by the verification run: `orphans::owner_killed_leaves_nothing` failed with
"the dead root was not removed". The test sweep probes each `owner.lock` with a non-blocking
flock, so two sweeps running together (parallel tests) each saw the other's probe as a holder
and skipped a dead root. Sweeps now take a process mutex and a `/tmp/.mason-test-sweep.lock`
flock for their whole run (`crates/daemon/tests/support/mod.rs`).
