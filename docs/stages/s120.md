# s120: alert when git fetch keeps failing

Summary: Each project records when its fetches began failing and the last error, and after 15 minutes of failures (`--fetch-alert-after-ms`) a `fetch:<project>` alert of kind `tracker` says how long, git's first error line, and that tasks are working from the old base; a good fetch clears it.

- `Daemon::fetch_remote` records the failure (first failure time kept, error updated) or removes the record on success. A fetch skipped because another began meanwhile changes nothing. A fetch that times out is an error, so it counts.
- `attention::fetch_alerts` reads only that record; no git, no repository lock.
- Test: `crates/daemon/tests/fetch_alert.rs` (below limit none, past it names the error, a good fetch clears). Exit: `scripts/exit/s120.sh`.

Not verified by me: the build tool is behind the shared queue in this worktree, so I did not run the new test or exit script by hand; they were exercised only through the `tests` check. The startup read in `load_definitions` does no fetch, so nothing is recorded there; the watcher's first pass does the first fetch. `attention.rs` is a trust file: one alert added, nothing about who may answer changed. No gate, guard, budget or verdict changed.
