# s870: cancel a GitHub run as soon as nobody will collect it (#823)

Summary: A check's GitHub run is cancelled, its ref deleted and its hold removed as soon as a newer check supersedes it, its step ends or its task is skipped, and the restart reaper also reads the check records on disk.

**Change.**
- `hostedcheck.rs`: a superseded record with a run left on GitHub (from before a restart) is cancelled through `remote::cancel_record`.
- `jobs.rs`: agent checks get a stop hook (`CheckSlots::run_over`) that fires when the task's open run is no longer the check's; `execute` then cancels the run.
- `remote.rs`: `unwanted` also names adopted checks whose `.check` record has `superseded` or `delivered=1`; `holder_views` feeds `mason resources` (`gha.runs`: label, kind, task, wanted); the CLI prints one line per run.
- Item 4: a run another thread is collecting has its caller blocked on it, so the caller is gone only when its step ended (`cancel_task`, now also the stop hook) or a newer same-task, same-suite call superseded it (`live_checks`). Both cancel; no further case found.

**Not verified.** Nothing was compiled or run locally (cargo is refused in the shell); tests ran only through run_check. No test drives a real `Daemon` for the stop hook or the post-restart `cancel_record` path: they cover `cancel_hold`, `unwanted` and the hook's decision function. The broker's `gha` drop is tested through `record_ended` (what the broker's release reads), not a Broker. Nothing reaches `sched.rs`.
