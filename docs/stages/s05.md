# Stage 5: Agent runner and step contract

## Built
- **`crates/adapter-api`**: `AgentAdapter` / `SessionHandle` traits with normalized `AgentEvent` and `Outcome`; the **step contract** (`contract.rs`): per-step tool sets, validation that replies "accepted" or lists precisely what is wrong, `ContractHandle` with a JSON-lines unix-socket server, the standing preamble; **`netguard`** (test mode refuses non-loopback addresses); and the **conformance kit** (`conformance.rs`, eight scenarios) usable by external adapters.
- **`crates/adapters`**:
  - `claude.rs`: the Claude Code adapter. Pure command construction (read-only vs develop tool sets, no remote git, preamble, prompt on stdin, `--resume` with a note), a sanitized environment, and a `stream-json` parser classifying outcomes (accepted, no result, usage limit, outage, crash). Deadline watchdog and process-group cancel.
  - `fake.rs`: the scripted fake agent (in-process).
  - `runner.rs`: the step runner: nudging, holds, ask and suspend as step ends, resume notes, token attribution.
  - `bin/mason-mcp`: the MCP bridge for the contract tools.
  - `bin/fake-claude`: a stand-in CLI that speaks the real stream format and replays captured fixtures.
  - `fixtures/claude/`: **two real captures** (`real_plain`, `real_tool_suspend`, sanitized) and three clearly labelled synthetic ones.
- `docs/decisions/0002-agent-runner-readings.md`, `scripts/exit/s05.sh`.

## Exit test
`bash scripts/exit/s05.sh` passes locally. It runs the adapter-api and adapters tests and requires each named scenario to have run and passed:
```
ok: accepted_in_one_turn
ok: rejected_then_fixed_in_the_same_session
ok: no_result_is_nudged_with_a_note_then_fails
ok: timeout_fails_the_step_and_is_not_nudged
ok: usage_limit_is_a_hold_not_a_failure_and_keeps_the_figures
ok: a_crash_fails_the_step
ok: the_fake_agent_passes_the_conformance_kit
ok: the_claude_adapter_passes_the_conformance_kit_against_the_standin_cli
ok: a_real_address_call_fails_in_test_mode
s05 OK
```
Also tested: ask and answer resume; long check suspend and resume (with a result note, not the original prompt); `request_exploration` (no failure charged); wrong-step tools rejected; token totals only from what the stream reported (a provider reporting nothing shows nothing); the MCP bridge over stdio, including riding out a controller restart; a captured real run replayed through the Claude adapter reports its real cache figures.

### Real runs (manual, not in CI)
`cargo test -p mason-adapters --test real_claude -- --ignored --nocapture`, run once each, Claude Code 2.1.317, haiku, scratch repos, real MCP bridge:
- **explore**: `submit_plan` accepted on the first call; tools used `Read`, `mcp__mason__submit_plan`; the tree was left untouched; tokens in 6, out 632, cache read 17,278, cost $0.0023; the stream's rate-limit event passed through (`allowed`, five_hour, utilization 0.31).
- **develop**: created and committed `goodbye.txt` with `Bash`, then `submit_change` accepted with the real commit hash; no nudges, no rejections.

## Not run
- **Providers misbehaving for real.** The usage-limit, outage and not-logged-in fixtures are synthetic (labelled so), modelled on the real event shapes and Claude Code's documented `api_retry` event; the real thing could not be provoked. The "not logged in" `result` text is from a genuine run.
- **Agent running under a step host** (see decision 0002): the adapter launches the CLI directly. Stage 6 composes it with the host.
- **A live attempt by an agent to push or fetch** was not made; the protections (no credentials, `GIT_ALLOW_PROTOCOL=file`, disallowed tools) are unit-tested as command and environment content only.
- **Suspend across long waits** beyond the 330 s measured in Stage 1, and Codex (Stage 20).
- Linux run of the new tests until CI reports.
