# s807: the `it` coverage map is built on GitHub

Summary: With remote runs on, the daemon asks GitHub for the `it` coverage map (a `covmap` run on the base tip, once a day and only when `crates/daemon/src` or the target's `main.rs` changed), keeps it after checking its commit and `main.rs` hash, and `mason doctor` says when `llvm-tools` is missing locally.

See docs/decisions/0800-covmap-on-github.md.

- `masond covmap-job` runs the existing job (`covmap::run_job`) in the current checkout and writes `covmap.kv`; the run's command is `covmap::REMOTE_COMMAND`.
- `covmap::make_remote` applies the existing `due` rule, pushes one run, reads `covmap.kv` from the artifact and accepts it only if its commit and `main.rs` hash match.
- `covmap::pass` leases `gha` (priority 3, below every task) instead of a local `test-suite` slot when the project's runs go to GitHub, and waits when `gha` is full. Remote off: the local job is unchanged.
- Tests: `remote.rs` (`a_due_map_pushes_one_covmap_run...`, `a_map_of_another_commit_is_not_kept`) with the fake GitHub; `doctor_reports_missing_llvm_tools` in the CLI.

Not verified: no real GitHub run was made, so whether `rustup component add llvm-tools` and the instrumented `it` build succeed on a runner, and how long they take, is untested. The 2-hour limit is a guess. No local test run (tests run on GitHub via run_check). The workflow was not changed (see the decision), so the owner has nothing to approve there; `scripts/exit/s807.sh` is a protected path and is new.
