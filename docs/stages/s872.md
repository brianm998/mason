# s872: the sidebar starts fresh after a project change

Summary: The Swift monitor's sidebar scroll view gets a new identity per project (`.id(model.project)`), so a project change starts at the top with no stale offset or content-height estimate, and a new offscreen test checks the list can still be scrolled to its last entry.

Change: `Sidebar.swift` (`.id(model.project)` on the `ScrollView` inside the `ScrollViewReader`; a DEBUG-only set of realised page links for the test). New `SidebarScrollAfterProjectChangeTests`; exit script `scripts/exit/s872.sh`. Decision: `docs/decisions/0865-sidebar-scroll-identity.md`.

Not verified: the bug was never reproduced offscreen. The new tests were run only through `run_check` (the shell refuses the Swift test runner). I did not measure a plain `VStack` against #518's budget, and did not implement a placeholder for the cleared sidebar (see the decision).
