# s673: the stuck and proposed tiles open a page

Summary: Double-clicking (or tapping on the phone) the stuck or proposed tile with several tasks now opens a page listing them, because `needs_attention` and `proposed` are section pages in the Swift and Compose clients.

What changed
- `Page.sectionNames` (Swift `Navigation.swift`, Compose `Navigation.kt`) gains `needs_attention` and `proposed`; `sectionTitle` gives "Needs you" and "Proposed".
- `tileDoubleClicked` and `PhoneLayout.tileTarget` needed no change; the phone and iOS pick this up through the shared Swift core. The sidebar reveal and scroll are unchanged and still happen first.
- The generic stage rows page shows Approve on the proposed page for rows that allow it (`StageRows.showsApprove`, and the Compose `StageRows`), the sidebar's rule.
- Tests: Swift `MonitorCoreTests`, `PhoneNavTests`, `ProposedPageTests` (offscreen ImageRenderer); Compose `MonitorCoreTest`. Exit: `scripts/exit/s673.sh`. Decision: `docs/decisions/0666-stuck-proposed-section-pages.md`.
- `clients/features.toml` is untouched.

Not verified
- The exit script does not start a real daemon with the scripted agent: it checks the page names and runs the Swift tests with built view-model rows.
- The offscreen test checks the Approve rule through a helper and that the page renders; it does not inspect the rendered Approve button.
