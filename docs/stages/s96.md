# s96: the mascot art and one way to load it

Summary: The approved mascot art (110 PNGs) lives once under `clients/swift/Sources/MasonMascot/Art/`, listed in `clients/mascot.toml` and checked by `conformance mascot --check`, with a loader in each monitor (`Mascot` in SwiftUI, `mason.monitor.ui.Mascot` in Compose) and `bundle-monitor.sh` now carrying the resource bundle into MASON.app.

- Art copied unchanged from `images/final/`; a brand `NOTICE.md` (DRAFT, awaiting legal review) sits beside it and README points to it.
- `conformance mascot --write` generates `MascotManifest` (Swift in `MasonMascot`, Kotlin in `core`); `--check` also fails on a listed file that is missing and on a file not listed. CI runs it.
- Swift: `MasonMascot` SwiftPM target (`.copy("Art")`), a dependency of `MonitorUI`, `MonitorPhone` and both executables. Loader looks for `MasonMonitor_MasonMascot.bundle` in the app's Resources, beside the executable and beside the test bundle; it never touches `Bundle.module`, which traps once the build directory is gone.
- Compose: `resources.srcDir` on the same folder; `Mascot` in the app module.
- `bundle-monitor.sh` copies the `*.bundle` directories into `Contents/Resources` and fails if the mascot one is missing. `MasonMonitor --mascot-check` and `monitor-tool mascot-check` load every file and exit 0/1.
- `tokens.toml` gains `mascot_icon_small`, `mascot_icon`, `mascot_banner_icon` (no view uses them yet). `features.toml` gains `mascot-art` (done in both).

Tests: `MascotTests` (Swift), `MascotTest` (Compose), unit tests in `mascot.rs`, `scripts/exit/s96.sh`.

Not verified: the Compose MascotTest passed (3 tests); nothing was drawn on screen (no UI in this ticket); iOS (`UIKit` branch) was not compiled; the bundle was not code-signed or notarised; the in-app update itself was not run.
