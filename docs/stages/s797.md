# s797: a transient push rejection no longer fails a landing

Summary: A remote run's push is retried (10 s, 30 s, 90 s) when GitHub rejects it, and a landing waits out a GitHub outage (up to 30 minutes, charged to no task) instead of failing; such failures are classified outside the code.

## What changed

- `remote.rs`: `push` retries up to 3 times on a remote rejection, 5xx or reset connection; a refused credential is not retried and still fails at once as environmental.
- `landing.rs`: `check_through_outage` wraps every remote check of a landing (lint, build floor, fast tier, re-test and its rebuild). An outage error ("the check could not run on GitHub") raises a `waiting for GitHub: <why>` alert and retries after 30 s doubling to 5 min, up to 30 min; then it is the usual service failure.
- `core/task.rs`: those reasons classify as `outside`, not `code`.

## Not done / not verified

- The test step (`jobs.rs`) and debt payments are unchanged: their remote errors still end the check as "no result", which an agent re-runs. Not moved onto the helper.
- The tests use a real bare remote with a rejecting hook and a pure retry function; no real GitHub. Nothing was compiled or run locally (cargo is refused in this shell); run_check is the first build.
